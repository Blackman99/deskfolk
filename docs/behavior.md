# 行为说明

[English](behavior.en.md)

这里存放的是原来写在 [`CONTEXT.md`](../CONTEXT.md) 词条里的行为细节；CONTEXT.md 是领域词汇表，只保留每个词条是什么、以及它和其他词条的关系，细节挪到这里，一条不丢。以下小节按词条在 CONTEXT.md 里出现的顺序排列，每节标题就是那个词条的名字。

<a id="plan"></a>
## 规划（Plan）

一个会话里正在推进的一件事，由应用自己整理出来，不用你先定义。代码里沿用 `tasks` 表和 `task_id`（历史名，注释里叫 plan）。它有**要点**：类别（用来找先例）、目标（现在到底要做什么）、验收（怎么算完成）、规则（你定过的口径、约束、改善意见，只从你自己的话来）、流程与分工、进展（已完成 / 待做 / 卡住）、状态（进行中 / 已完成 / 搁置）；另记着开它的那条要求的原文（最初的要求）。要点由整理跳在你每条消息之后、以及规划静下来之后更新，每改一版留痕（哪条消息或哪一轮引起的，或是你改的），你也能在流程图里直接改。一个会话同时只有一个当前规划：整理跳判成换了一件事就新开一个、原来的搁置，判成回到以前那件就把它接回来，判成做完或搁置就空出来；没有时钟会替你切事。你叫停时它搁置，之后只有你说继续（或在流程图里改）才回到进行中。到了叫停这一级，是那条叫停扣着它（见叫停），只是催着停的话（「你没停」「还在进行」）由应用照实况回答，不经过整理跳（混着别的要求的照常归档），整理跳也不再按自己的理解搁置规划；这一级之前靠整理跳：催着停的话不会被当成继续，规划静下来后的整理也不会把它改回进行中。回看、批注叫醒的一轮在里面干活也不会：开一轮从不改规划的状态。每一轮的局面里都有它的要点、任务清单、本轮任务和同类先例，交接到别的 Bot、别的会话、回看醒来也一样，所以原始目标不靠转录窗里还留不留着那一句。规划有个名字：开它的那句话的前几个字，开了就不变，应用里和局面里是同一个。一个会话里常同时有好几件事，所以 Bot 读到的每一句都说得出是哪件事的：转录和听进的话里，属于另一件事或另一个任务的那一行，在说话人后面带着 `〔规划「…」· 任务 03〕`；局面里写出这件事的名字，在别的会话开的写明开在哪，此刻别的会话里也在做它的轮、这个 Bot 手上别的活轮都列出来，「经过」里在别的会话做的那一步标明在哪。第一轮在局面里标出来，是唯一还能先对齐要求再动手的那一轮。

<a id="ticket"></a>
## 任务（Ticket）

规划下一个有交付物的最小单位：序号、标题、说明与验收（要交出什么、怎么算完成；不写进展，也不写 Bot 给自己定的禁令）、状态（待做 / 进行中 / 待验收 / 已完成 / 搁置）、谁在做（整理跳开任务时按「流程与分工」先填，之后按观察到的更新；是记录，不是派工）、产物。整理跳和你改任务：整理跳按 id 引用已有任务、只写变了的字段（没写标题、状态或谁在做，就是不变），新任务用 new-N 开，不能删，只能改成已完成或搁置；你在流程图里改状态。应用自己也按看到的往前推一格，不调模型：归到这个任务的轮开始写文件、跑命令，待做变进行中；它交出了文件，变待验收；没人在做就记上这个 Bot。只往前，不会替谁标已完成或搁置。整理跳要等规划静下来才整理，这一步让流程图在几个 Bot 首尾相接地干活时也照实显示谁在做什么。每个任务在规划目录下有自己的文件夹 `NN-<标题>/`，被归到这个任务的轮次默认就在里面干活，没归到任务的轮次落规划目录。一个 Bot 被交接叫醒时，交来的任务是别人的、而它在这个规划里恰好只做一个没收口的任务，这一轮就落在它自己那个任务上，而不是跟着叫醒它的那一轮落在别人的任务里；交来的任务是它的、或者还没人做，就照交来的。产物按任务归属：消息带着 `ticket_id`，它引用的文件就是这个任务的产物，不搬文件。流程图旁边列出任务清单，点一条点亮它的卡片。

<a id="organizer"></a>
## 整理跳（Organizer）

替会话整理规划和任务的一次无工具短调用，跑在默认端点的默认模型上。两个时机：你的消息进会话之后、开轮之前，判这条消息是接着当前规划（continue）、换了一件事（new）、回到以前那件（resume），还是在说在场 Bot 正在别的会话推进的那件事（join：比如你在私聊里跟它说它在群里做的那件事；那件事开在别的会话时留在那里，这个会话的当前规划不变），更新要点和任务，并标出这条消息说的是哪个任务——消息盖上规划和任务后，它开的每一轮（点名、判断下场、分叉）都落在同一处；规划的活轮全部结束、静下来 30 秒之后再整理一次（你 Stop 掉的那一轮不引起这次整理：Stop 是要它停下，整理之后的叫回会让它接着做；同一个规划里前一轮结束后已经排着、还没开始的整理，和规划停下后等着到点再看一眼的那次，也随这次 Stop 取消，已经在跑的整理跑完也不再叫回谁，别的规划不受影响），把这几轮交出的东西归到任务上、更新任务状态、谁在做和进展。它看的是当前规划的要点和任务（每个任务附上落在它目录里、被引用过的文件）、上一版之后发生的事（谁说了什么、交出了什么、经过，以及这些轮真正跑过的命令和退出码）、这个会话之前推进过的规划、在场 Bot 正在别处推进的事（完整要点、任务、开在哪、谁在哪做、这个会话之前归到它的几句）、已有的类别标签和同类先例。它还看这件事里你说过的每一句：上一版之后那些之外更早的话和你对提问的回答（同一句只算一次；太多时留最早几句和最近的，总长有上限），以及目标、验收、规则和任务说明里哪些是你在流程图里亲手写的（这些也算你的话，清理时不动）。每一行都标着是你说的、Bot 说的还是应用的提示，提问的回答算你的话。规则只收你的话：你说的、你答的、你在流程图里写的。Bot 说的决定不是规则，分三种放：它给自己定的暂停、冻结、不再重试、只做一部分，写进流程与分工并写明是谁定的，因此停着的写进卡住、写明等什么能解开；要你给东西（授权、密钥、确认花钱）才能往下做的，写进卡住、写明要你做什么；做法上的约束（不覆盖原文件、交付放哪个目录）写进流程与分工。你新说的话盖过旧规则时，旧的那条改写或删掉，不并列追加；你说继续推进、不要停下来，Bot 自己定的暂停和冻结不管写在规则、流程与分工、进展、验收还是任务说明里都撤掉，因此停着的挪回待做，但等你给东西的那种要你给了才撤，做法上的约束也不撤。只在你发消息那一次、看得到你说过的全部话时，它才把在你的话里找不到出处的旧规则挪走、把被 Bot 收窄的目标按你的话放回去。进展里的待做只写还没做的事，已经交出、只等你看的不算。先例只作参考，它的规则不抄进这件事。任务说明写要交出什么，不写进展。规划静下来之后那次整理，要是上一版之后你没说过话，目标、验收、规则和已有任务的说明原样不动，也不把规划搁置（改了应用也退回），它只记交出了什么、进展到哪、谁在做；这次整理的调用期间规划被改过（你的话被归进来，或你自己改了），这次什么都不落。Bot 说「已完成」「测试通过」不算依据：标待验收要有这个任务交出的文件，标已完成还要有跑过的记录。验收写你自己能检查的结果，要做出能用的东西时必须有一条「照着启动方式能在本机跑起来并走通主流程」；几个人各做一块、合起来才能用时，另开一个「联调并给出启动方式」的任务。它判规划做完时还有待做或进行中的任务，规划就不算做完：这次的其它改动照收，规划仍是进行中（你在流程图里手动标完不受这个限制）。失败即不改：没配默认模型、端点拒绝、答得不成形、库拒绝这次改动，规划照旧，轮照开。判成回到以前那件或在说别处那件事，而读到答案时那件事已经不在可选的里面（比如它在别处的那一轮在这次调用期间结束了），也什么都不落，这条消息照原样留着：答案是照那件事写的，落到当前规划上会盖掉当前规划的要点，会话没有当前规划时照着它另开一个，就是一份没人要的副本。点的那件就是这个会话的当前规划时例外：那只是换了个说法的 continue，照 continue 落下。整理的这几秒里没有轮，但这条消息要叫醒的 Bot（私聊那一位；群里点到的，没点名就是在场的每一位）已经在它下面显示思考中，列表、顶栏里也是；整理完各自交给自己的轮或判断，中间不断档。花费单列一类「整理」，归决策路由，不归任何 Bot。

<a id="work-dir"></a>
## 工作目录（Work dir）

一个规划的文件夹，在工作区的 `work/` 下，名字是目标（或开头那条要求）的前 12 码点 + 一小段 id，没有日期，也不带 `@`（换成 `-`，引用里面的文件时才不会被读成点名；旧的带日期或带 `@` 的目录不动）；它下面每个任务有自己的 `NN-<标题>/`，标题里的 `@` 同样换掉。一轮的工作目录是它所在的任务目录，没归到任务就是规划目录；壳默认在里面跑，文件工具的路径仍相对工作区根。谁继承：交接、点名、判断下场、Bot↔Bot 私聊、中断续跑和回看都用唤醒方那一轮的规划和任务，所以一件事跨 Bot、跨会话仍是同一处；你的消息由整理跳盖上规划和任务，它开的轮都落在那里。不按时钟切目录：一个会话的当前规划一直开着，直到整理跳判成换事、回到旧事、做完或搁置。日程有自己的常驻规划，每次到点新开一个任务。第一次真被用到才创建，只说话的轮次不留空壳。交付物不进来：你点名了路径就写在那儿，没点名的落本轮任务目录。两层都有保留子目录：`tool-results/` 是守护进程存的大工具结果（关闭够久后自动清掉），`scratch/` 是纯过程文件——都不会挂成产物；`map.md` 和 `ticket.md` 是应用的镜像文件，同样不算产物。删掉工作目录是你的事，应用只清 `tool-results/`。这件事在应用里按叫醒关系从上到下看经过，卡片上标着它干的是哪个任务，产物挂在交出它的那一轮上，点开走预览。

<a id="closing-check"></a>
## 收尾自检（Closing check）

一轮要把交付物交给你之前的一次核对。时机不变：Bot 准备发出的消息引用了工作区文件，或者说自己「正在做」「结论随后」这类还没做完的事，目标会话里有你，这一轮属于一件事。从 2026-09-29 起（ADR 0037）它不再调模型，而是看三条确定的规则，任何一条不满足就把一段应用提示退回给 Bot：一、这件事有验收检查（ADR 0036）没过——文件类检查当场重新判一次，这一轮刚改好的文件不会因为旧结果被退回；命令类检查看最近一次运行，这一轮已经把同一条命令跑成功的不算；最多列三条，提醒改交付物、不改检查，做不到就在收尾里说明原因；只对真的交付（引用了文件）的回复看这一条。二、说了稍后还有下文，却既没有在这里约回看、也没有点名交给谁——这一轮一结束就没人会接着做，要么现在做完，要么约一次回看，要么点名交出去。三、说已经跑过、测过、验证过，而这一轮一条命令都没跑（写明「未验证」的不算）。走 send_message 的，那次调用不执行，结果是这段提示；直接回复的，提示作为一行进回路。一轮只核一次，第二次不再拦；退回不算工具错误，复盘不把它当失败；没有模型调用，也就不记花费。发到没有你的 Bot↔Bot 私聊不核，没引用文件、也没说还在做的回复不核。原来用默认模型拿要点逐条对照交付物的那一步删掉了：黄金路径消融里关掉它不掉完成率、省下约四分之一的花费和时间，机器能判的验收交给验收检查去跑。
<a id="acceptance-check"></a>
## 验收检查（Acceptance check）

规划的要点里，验收是一句句你能检查的结果；验收检查是把其中能机器判定的那几条交给守护进程自己跑，不靠 Bot 自称、也不靠模型读 Bot 的收尾。四种：文件存在（且不是空的）、文件包含某段文字（可以反过来要求不包含）、文件匹配某个正则（同样可以反过来）、一条命令（期望的退出码，默认 0，可选期望的输出，比较前去掉行尾空白和末尾空行）。文件路径和命令没写目录时都相对工作区根，和文件树看到的一样；工作区外的路径和越界的命令写不进来，跑的时候再判一次，判到区外就记「越界」、不跑，从不替你批准。命令在自己的进程组里用 `/bin/sh` 跑，结束或超时（默认 120 秒，最长 600 秒）时整组杀掉，环境只带终端那份白名单（不带 `SSH_AUTH_SOCK`，也不带守护进程自己的变量）。每次运行记下结果（通过、没过、越界、出错）、一行说明（按应用的语言写）和输出的末尾一段；一条检查最多留最近 5 次。什么时候跑：规划静下来时先跑过期的（定义后还没跑过，或者之后这件事又有轮动过），整理跳整理完再跑它刚加的；你新建或改了一条就跑那一条；流程图上「跑检查」随时跑全部。每个规划同一时间只跑一次，命令检查整台 Mac 一次一条，一段静默最多跑 15 分钟。谁能写：你在流程图上加、改、删；改了整理跳加的那条，它就归你，整理跳不能再动；整理跳在答案里可以加、改、删它自己的（每次最多新加 3 条，一个规划最多 10 条），命令只能是这件事里某一轮在那个目录跑成功（退出码 0）过的、或你在归到这件事的消息里原话写过的，你删掉的不会再被它加回来；Bot 没有写检查的工具，只在局面块和 `map.md` 里看得到。检查挂在验收的那一句上，按文字对应：整理跳或你改写这一句时检查跟着走，这一句删掉了，检查就列在「对不上验收条目的检查」里，照跑照算。结果回到哪里：流程图每条验收后面挂着检查的结果，点开看说明、最近一次和输出；整理跳读得到每条检查的最近结果，有没过的（或定义后还没跑过的）就不能把规划标成做完，对应的任务也不能标完成，越界和出错不算依据，写进进展的卡住里；你手动把规划标完不受这个限制。规划静下来时，还有任务没收口或有检查没过，应用叫回一次，叫回的话里带着最多 3 条没过的检查和输出末尾，提醒修交付物而不是改检查；再叫之前要有进展（有任务交出或收口，或者有一条在上次叫回前就有的检查第一次通过），没有就说一次「这件事停下了」；你最近一句话之后叫回的次数不超过任务数加检查数。每一轮的局面块里列着这件事的检查和结果。

衔接一致（`continuity`）是第五种，给几个 Bot 分头做、合起来才是一件交付的活：每个 Bot 只审自己那一块，接缝上的问题谁也看不见。各部分按顺序来自三处之一：一条列出各部分的命令（一行一个，最准）；一个通配路径（全部匹配按自然顺序排，C2 在 C10 前面；只有全是视频、又没给命令时，才当成反复重剪的成片，取最新的那个）；或一份文件切开——Markdown 和纯文本按一、二级标题切，HTML 按 h1、h2 切，视频按场景检测找剪切点（画面相近的镜头之间会漏判，实测 11 个交界只找到 6 个）。每条接缝取两边的证据：视频取前一镜尾帧和后一镜首帧、图片直接用两张图，并排拼成一张图存在规划目录的 `checks/<检查>/`（保留目录，不算产物），要能看图的模型；文字取前一部分末尾和后一部分开头各约 700 字，不需要看图。文字另有一次整体检查：每部分的标题、开头和里面带单位的数字、专有名词合成一份摘要，看同一个对象在所有部分里是不是同一种说法和口径。判的是默认端点的默认模型，提示里写着这条验收、规划的规则和一张通用清单：与规则一致；前后接得上（缺的过渡要点名）；同一对象前后一致（人物、产品和专有名词、术语、数字与单位、方位与方向）；风格一致（画面看画风、渲染、配色、角色设定，文字看语气、格式、编号）；重复或遗漏（看不出来就不要判）。图片和视频的接缝两侧几乎一样是好事，说明接得严丝合缝。它只答 JSON，读不出来重问一次。每条接缝和整体都没问题才算通过；不通过时说明写「N 处衔接里 K 处有问题：02-市场分析→03-渠道对比：……」，输出逐条列出（有对照图的带上路径），最后一行是整体结果。看图或读文字的调用记成花费里单独的一类「验收检查」。代码之间的衔接不用它，用一条联调或启动命令的检查。整理跳也可以提出这种检查，但各部分必须是这件事交出过的文件，或者清单命令这件事里真跑成功过。

<a id="pane"></a>
## 窗格（Pane）

桌面窗里的一块内容区。一块窗格是一组标签页；一个标签可以是一条会话（它的产物预览、流程图都跟着它；它自己的设置从这个标签里的对话右侧滑出、带一层只盖这块窗格的遮罩，不另占标签），也可以是一个终端（一个标签一条 shell 会话）、日程图、工作区或花费。窗里可以纵横任意分割出多块窗格，分隔条和交汇处都能拖；标签可以在自己的标签栏里拖动排序、在窗格之间拖、拖到边缘就地分割、按住 ⌥ 拖出来变成浮在上面的窗格。在窗格里任意位置右键，可以向上、下、左、右就地分出一块空窗格；里面本来有右键菜单的（消息、代码编辑器）和输入框仍是它们自己的，按住 ⌥ 右键是网页视图的原生菜单；浮动窗格不就地分，右键提供停靠回布局与关闭窗格。有别的窗格时，空窗格右上角可直接关闭（只剩一块平铺窗格时不显示：关掉它也只是再留一块空的，这时标签条上什么都没有，整条收起）；每块窗格的右键菜单也可关闭整块窗格及其标签，工作区和产物预览有未保存编辑时先确认。最后一块平铺窗格关闭后留下一块空窗格。**窗里分成多块窗格，那仍然是同一个窗口进程**，浮起来的也不是第二个系统窗口。同时只有一块是当前窗格——键盘在哪块就是哪块，在哪块里点一下或滚一下也换到哪块：Stop 打它那一轮，点通知先找已经开着那条会话的窗格。摆着不止一块时，当前那块四周描一圈强调色，一眼看得出是哪块；只有一块时不描。侧栏里点一条会话：只有一块窗格时，它替换这块窗格正看着的那条会话（终端、工作区这些不被顶掉，新会话在旁边开标签）；摆着不止一块时，已经开着它的那块切到前面，哪块都没开就在当前窗格里新开一个标签，不替换任何一块正看着的东西。会话设置同时只在一条会话上开着，在别处打开就把原来那处收起；日程图同时只有一块。每条会话只有一块产物预览、一块流程图：在这条会话里、它的预览文件树里或它的流程图上再打开别的文件、别的那件事，是那一块转过去，不另开一块。这两块的标签名是固定的，跟会话标题走：「<会话名>流程」「<会话名>的产物」，不跟打开的文件或这件事改。流程图标签换到后面再换回来，停在你离开时的地方：拖到哪、缩放多少、折起展开的轮、筛选和点亮的任务都照旧；在它的切换器里换一件事再换回来也一样；只有一条消息新要它去某张卡片时才会移开。会话窗格不再另画顶栏：头像（Bot 在干活、等你或出错时带状态点，空闲不带）和名字始终在标签上，顶栏的第二行成了标签的提示；鼠标移到标签上才出现 ⋯，里面是置顶、经过和设置，右键会话标签也在分割前面给出这几项。右键任何一个标签（会话标签的 ⋯ 里也有），可以关闭这个标签、同一块窗格里的其他标签、它右侧的标签或全部标签；全部关掉就和关掉最后一个标签一样，这块窗格跟着关掉，工作区和产物预览有未保存编辑时先确认。其他标签（终端、工作区、日程、花费、流程、产物）也始终在名字前带上各自的图标。窄屏（≤680px）和手机上没有窗格，仍然是一次一屏、一层层盖上去。

## 模型（Model）

某个端点认的一个补全名字。每个端点有自己的名单和默认，名单上的名字可带选路参考价、可选计费单价、支持的思考等级和擅长领域。选路参考价是应用挑模型时用的相对数；计费单价是 USD / 百万 token，输入和输出一起配，缓存输入可单配，留空沿用输入价。计费单价用于缺实报金额的花费估算；探测模型名单不会自动填单价。用户发消息开一轮时，应用只在 Bot 钉的端点（没钉端点就是默认端点）的名单里选模型和思考等级，不会因为设置里多了一个端点就把它的模型算进别的 Bot；Bot 钉了仍在名单上的名字则模型名受约束，钉的名字只在别的端点上时照钉的用。Bot 也可以钉思考等级（补全的 `reasoning_effort`）：档名以该模型名单为准（常见 none / low / medium / high，端点广告了还会有 xhigh、max 等）。探测 `/models` 时若对象带了思考档就自动写进该模型的 `thinking_levels`，设置里仍可手改。思考等级和模型一起钉，不单独存在：要么两个都不钉、模型和等级都由应用每条消息挑，要么钉一个模型并同时定下它的等级。钉模型时没给等级就落到该模型的默认档（应用对普通消息的偏好顺序）；换成不支持原档的模型会落到新模型的默认档；清掉模型一并清掉等级；没钉模型却给等级会被拒。你在 Bot 面板里点一下就能改，Bot 也能用工具改自己的。空钉不是「永远用端点默认模型」，而是应用可从该端点名单里挑；要用别的端点必须显式钉端点。谁来挑：每开一轮先由 agent 挑一次，它看这条消息、这个 Bot 的人设、候选名单、这个 Bot 最近的复盘结论（带当时那条消息和类别，对不上就当没看见）和最近干净做完的例子，答出模型、思考等级和一句理由；它自己固定跑在默认端点的默认模型上，答不出或答了不存在的东西就落回规则兜底，不让用户卡在选路上。用户后续说的每一句都原样留着（不按关键词筛），落在被引用的那一轮、`@` 的那个 Bot 最近的一轮，或会话里最近可见的一轮上；连着围绕同一件事的若干轮算一条纠正链。链结束时（换了话题或静默一段时间）复盘一次；没有后续发言，但这一轮是端点拒绝、回复不完整或工具错误不少于两次，也复盘一次。复盘看的是整段加上这一轮实际做了什么：这到底是模型不行、事情本身难、还是需求没说清，只有判成模型不行才留成这个 Bot 的经验，并说明该往更强 / 更轻 / 更快 / 更便宜哪个方向调。留下的是结论不是分数，没有权重、抵扣和封顶；被照做两次仍没有更干净的结论退出选路，记录还在。经验归 Bot 自己，删除 Bot 一并删掉。每轮选了什么、怎么结束、做了多少、收到哪些反馈都留有记录。用户不每轮自选。判断调用和轮次补全用同一个解析结果。

## 叫停（Hold）

你叫的停落成的一条记录。**范围**：全部、某个 Bot（跟着它到它在的每个会话）、某个会话（连带以这个会话为主会话的规划，哪怕活在 Bot↔Bot 私聊里做——那条私聊里做的仍是这个群的事）、某件规划（连同它的任务）、某个任务、某个 Bot 在某件规划里的活、某一轮（覆盖这一轮约的回看）；另可带上建立时就定下的额外覆盖，比如这个 Bot 交出去的活所在的私聊，之后不再随着变。只有你能解除：用你的一句话，或一个按钮；别的调用方没有解除的入口，Bot 和整理跳都不行。记录从不删除：清空聊天、删群只把它指向的那句话置空，叫停本身还在；叫停点名的规划（叫停在这件规划、某个 Bot 在它里面的活、它的某个任务上，或额外覆盖里有它们，已解除的也算）清空聊天时也留着，不会让叫停指着一件已经没了的事。删群时，群上的叫停搁置着、群删后还留着的规划（别的会话里有它的轮次或消息）不再属于这个群，群上的叫停也就够不着它们，所以每件先各得一条自己的规划叫停（来源 `migration`），带着解除后怎么恢复；叫停之前就按旧办法搁置了的（状态和要点都是搁置）也一样，解除后回到进行中，和启动时接管旧搁置的做法相同；这件规划本来就有规划上的叫停的不用。

**建立时**：记下叫停的同一次写入里，它覆盖的在跑的轮都结束为 stopped；写入落库后，这一轮的补全、它的 MCP 调用（告诉服务器这次调用取消了）、它跑的命令的进程组（先让它们退出，3 秒后还在就强行结束）一起中止。每一轮做到了哪一步——写过的文件、最后几次调用——记在这条叫停上（`effect.stopped_turns`），同时记下同一件规划里它没覆盖、仍在做的别的 Bot 的轮（`working_beside`），以及结束之后它覆盖的还在跑的（`still_running`，除非出了错否则是空的）。你说的或按的叫停还连带被覆盖的 Bot 交出去、还没交回的活：由被覆盖的轮写的话开出来的别的 Bot 的轮——或者由这样的轮写的话再开出来的，往下最多三层——只要还在跑或还有待响的回看。每一个都作为额外覆盖记在那一轮上：覆盖那一轮本身、它约的回看和它的话会叫醒的人，不覆盖那个 Bot 自己的别的活；上游的一概不停。叫停放行开出的只读轮让它把回答说完。工作记录里记一条 `control.hold`。

**规划状态**：规划或会话上的叫停把它覆盖的进行中规划改成搁置，状态和要点里的状态一起改——流程图每次编辑都把要点里的状态原样送回，整理跳也在要点上改，只改一处就会被改回进行中。规划仍是会话的当前规划，只是停住了，不是被别的事挤开。已经被新规划挤下当前位置的（状态已是搁置、要点里仍是进行中）也一样把要点改成搁置，解除后回到被挤开的样子：要点里是进行中、状态仍是搁置，不当成回到进行中，免得不在当前位置的规划被叫回去干活。叫停期间整理跳或接回要它进行中，它仍是搁置，只记下解除后回到进行中；叫停期间被新开或接回的规划挤下当前位置的，解除后也回到被挤开的样子；在这个会话里新开的规划一开就是搁置；标已完成照样生效。叫停把要点改成搁置、解除时改回去，各算要点的一个版本：流程图拿着之前的版本再提交会被拒（`409 revision_conflict`），不会把刚叫的停送回去，也不会在解除后又叫一次停；这两个版本不算你写的，也不算整理，整理跳照样读叫停之前的话；修订历史里它们带 `cause: "hold"`。解除后回到原来的状态，空着的话也回到会话的当前位置；还有别的规划或会话上的叫停扣着它，就仍是搁置，由那一条记着解除后怎么恢复。Bot、任务、某一轮上的叫停不改规划状态，规划里别的 Bot 的活照常；全部上的也不改（否则要改遍每一件规划），规划详情的 `held_by` 列出覆盖整件事的叫停（规划上的、它所在会话上的、全部上的）。

**旧的改状态入口**：引擎级别到了叫停这一级之后，把规划状态改成搁置（`PATCH /v1/tasks/:id/spec`，旧客户端和手机的做法）就是在这件规划上叫停；改回进行中或标成已完成，解除这件规划上的叫停。会话或全部上的叫停还在时，改回进行中之后它仍是搁置（会话的）或状态照旧（全部的），`held_by` 说明是哪一条。算不算改状态，拿要点里的状态比：流程图显示并送回的是它，一次只改目标的编辑把它原样送回，不算叫停也不算解除；被挤开的规划状态列是搁置、要点里是进行中，按状态列比会把这样的编辑当成继续。在这一级之前，改成搁置就只是状态。

**回看**：被覆盖的待回看挂起，同时标作废，这样不认识叫停的旧版本也不会让它响；叫停期间新约的也一样挂起。解除后没有别的叫停覆盖它，就恢复待响，已经过了时间的随后补响一次。挂起期间会话被清空或删除、Bot 被删除，或者在有叫停之前约它的那一轮被 Stop，它就真作废，解除也不回来；Bot 在同一会话又约了一次，就以新约的为准，旧的不再恢复。

**叫醒和工具**：叫停覆盖到的，什么都叫不醒——你的话（只开一段只读的轮，见下），别的 Bot 的话（点名它，或 Bot↔Bot 私聊里的每一句），它约的回看到点，它开的 Bot↔Bot 私聊静下来后的回报，规划静下来后的叫回，日程到点，中断后点「继续」，都不开轮；被叫停覆盖着的、正在跑的那一轮也不再听到新来的话：说的是叫停范围外的事的，在它旁边另开一轮，不打断它；你在别的会话里说、归到这件事的话也不转给它。被叫停的 Bot 自己说的话也叫不醒别人，它在 Bot↔Bot 私聊里的对方静下来时也不会把发起方叫回来，也不留到以后：解除后它在私聊里再做完一轮，私聊再静下来，就会叫回发起方。你在群里不点名说的话，被叫停的 Bot 不参与判断（不花那次判断调用）。每一次被挡下的叫醒都记进工作记录（`work_events` 里的 `wake.suppressed`），写明是什么叫醒（你的话、别的 Bot 的话、回看、规划叫回、日程、继续……）和是哪几条叫停。回看被挡下时挂起，解除后恢复；正在跑的一轮听到了、却没读就结束的话逐条看叫停：说的是被叫停的事的，每条记一次被挡下的叫醒，留在转录里等解除，其中最新的回看挂起，解除后再响；其余的照常在最新一条上再开一轮，只带上这些没被叫停的；开私聊的 Bot 被叫停时，私聊静下来后给它的回报也挂起，解除后再叫它回来；规划静下来后的叫回不留，等这件事下次有一轮结束、再静下来时再看；日程到点只记一次、不算已跑，解除后按最近一次补跑一回；「继续」返回 `409 held`，手机上也是这个错误码。被叫停覆盖着的轮次，有副作用的工具调用一律不执行，结果是 `held`：壳、写和删文件、发消息、约回看、向你提问、改人设、技能、记忆、日程、端点或 MCP 服务器、没有标只读的 MCP 工具；只读的照常（读文件、列目录、各类 `list_*`、`read_skill`、`end_turn`，以及服务器标了 `readOnlyHint` 的 MCP 工具，比如查一个视频作业）。等你批准的调用，你点允许时它已被叫停，也不执行。库本身再兜一层：turns 表上的触发器拒绝写入被叫停覆盖的活轮（不认识叫停的旧版本写的、没有 `mode` 的行一样拒绝——叫停优先于兼容），也拒绝把一轮活着的原地挪进覆盖范围、或改掉它的 `mode`。唯一放行的是你的一句话开的只读一轮（`mode = readonly`）：你对被叫停的 Bot 说话——在它的私聊里，或在群里点它的名——就在它原来的活旁边开这样一轮，不挂在任何规划上，只给它看不改东西的工具，开头一行写明你叫停了这件工作（带你的原话）、这一段只能回答。它的回复照常发出，不叫醒任何人；别的 Bot 这时点它的名，在它旁边另开一轮，不打断它。

**你的话**：你的一句话在进度询问之后先按控制句读一遍（见 CONTEXT 的控制句）。纯控制句由应用照办，不再去任何别处——不整理、不开轮、不调模型：
- 叫停：按话里的范围每个建一条叫停（来源 `user_text`，`source_message_id` 是这句话），应用在你说话的会话里回一条回执：不进 Bot 上下文的 `system` 行，带 `control: {kind: "receipt", verb: "stop", hold_ids, offer, scopes}` 供按钮用（撤销；扩大到所有 Bot；你同时说了「算了」时加「作废这件事」）。里面每一条都来自叫停的记录：停下的轮，各自的规划、会话和最后一步；挂起的回看；搁置的规划；这些规划里仍在做的别的 Bot；此刻在跑的。
- 继续：解除话里点到的叫停——对一个 Bot，是它自己的，扣住它全部的活或其中一部分的都算；对一件规划，是它上面的，以及某个 Bot 在它里面的活上的；在私聊里说，这两种还解除在这条私聊里用一句话建的其他叫停，别的 Bot 身上的除外；对群，是群上的，以及在群里用一句话建的每一条；对全部，是你建的每一条，启动时接管的不算。不越过话里的范围：在群里说「@X 继续」只解除 X 自己的，不解除群上的。被解除的叫停停下的每一轮，都在它原来的会话里带一条系统行重新开始：你的原话、它的规划和任务、写过的文件和最后几次调用；这一行只说发生了什么，不催它做什么。它是应用写给这个 Bot 的，和回看自己那一行一样只给它：只有它叫醒、或在那里被听到的那一轮读得到，流程图照样画出这一轮从被停下的那一轮接上；会话、手机、别的 Bot、整理跳、搜索、未读和会话列表的最后一条都看不到它，你看到的是回执。在你的私聊里，它在 Bot 这期间接手的别的活旁边另开一轮；在群里或 Bot↔Bot 私聊里，一个 Bot 同时只做一轮，由它在那里已有的那一轮听到这一行，不另开第二轮（回答你的只读轮不算）。Bot 已经在那里接着做了的不再开；还有别的叫停覆盖着的也不开，交给那一条（`held_over`，有不是 Stop 建的就交给那样的一条），那一条解除时再开。回执写明解除了什么、哪些重新开始、恢复了几个回看、哪些规划回到原状。什么都没叫停时，「继续」就是一句普通的话，照常交给 Bot。只剩它解除不了的叫停（全部上的；或你在群里点名一个 Bot 时，群上的，以及它这句会落到的那件规划上的）时，应用回一条状态行，给出「只让它继续」和「全部继续」两个按钮（`continue_only`、`continue_all`）；解除之后还剩这样的叫停时，回执也给这两个按钮。Stop 建的叫停跟着你关于那件事的下一句话走：只有它挡着、这句「继续」又落在那件事上时，「继续」就是一句关于这件事的普通的话，照常交给 Bot，像别的这种话一样解除它（见下）。对一个 Bot 说的「继续」（在它的私聊里，或在群里点它的名）也说到了它在别处被 Stop 的活，比如它在和别的 Bot 的私聊里做的那件事：你在那里说不上话，这条叫停就由这句解除。说到全部的「继续」（「所有 Bot 继续」「全都继续」）说到你在它之前按过的每一个 Stop，在哪里按的都算，哪怕别的都没叫停也一样被用掉，回执发在你说话的地方。「继续」这样、或因为解除了别的叫停而被用掉时，它说到的 Stop 叫停一起解除，它们停下的轮也带着同一条系统行重新开始——你的话只能这样到它那里。对一个 Bot 说的「继续」只说到这个 Bot 的 Stop：它这句会落到的那件规划上别的 Bot 的 Stop 不动，等你对它们那件事再说话。
- 「停了吗」「你没停」——以及规划的进度行接不住的、问被叫停 Bot 的进度询问——由应用回答：问到的范围上每一条叫停和当初那句话，以及其中此刻还在跑的（`control.kind` 为 `status`）。回答之前先把这些叫停下还在跑的停掉，记成违规（`effect.violations`，工作记录里的 `hold.violation`）；正常应当一条都没有。没有叫停时说「没停」，回答末尾给一个停下按钮；问能不能停（「能停么」「停下好吗」——没对 Bot 说「你」、没说「先」「一下」「请」，就是在问，不是在请它停）也这样回答、给这个按钮。关于一件规划的进度行，也照样列出这件规划和在里面干过活的 Bot 身上的叫停，之前做同样的核对。
- 带着控制词、还有别的内容的话照常投递，带上 `control: {kind: "possible_control", offer, scopes}` 供按钮用，其中什么都不执行。单说「算了 / 不做了 / 取消」也一样，按钮是停下或作废。

**卡片上的 Stop**：有了叫停之后，它是一条叫停——私聊和群里都能按，群里只停那一个 Bot 的这一轮，别的 Bot 照常（ADR 0016 的「群里不能停」由 ADR 0040 P2 推翻）——扣住这个 Bot 在这一轮的规划里的活（这一轮没有规划就只扣这一轮），来源 `user_button`，你的下一句话解除（`lift_on_next_user_message`）。这一轮照上面那样结束，它约的回看挂起而不作废，你在这一轮的会话里时回执也发在那里。你关于这件事的下一句话——归到这件规划，或落在它上面——在叫醒任何人之前解除它，Bot 从你这句往下，不另带说明重开：Stop 的意思是「不是这样」。不在它和你的私聊里说的（比如在群里），只算对它说的：点了它的名（回复它的话会自动带上）、@所有人，或在它在的群里谁都没点；只对别的 Bot 说的同一件事不解除它，它挂起的回看也照旧挂着，免得它没听到你一句话就被回看叫回这件事。只算按下 Stop 之后说的话：之前发出、按下时还在整理中的那句不算。单说「继续」也是这样一句话；对这个 Bot 说的「继续」，不在那件事所在的地方说也解除它，这时停下的轮带着说明重新开始（见上）。挂着按钮的像控制句的话，以及别的范围的叫停，都不会这样解除。

**按钮**：应用读过或写出的关于叫停的话（`control`）带的按钮，每条话只按一次：按过的记在 `control.acted`，之后这一行只说做了什么，再按（连按两下、手机重发的请求）什么都不做。应用自己写的这些行——回执、状态行、重启后的那一句，还有进度询问的进度行（`control.kind` 为 `status`，不带按钮，引擎级别不到叫停这一级时也这样）——在对话里显示成应用的话：头像处是 Deskfolk 标识，名字是「Deskfolk」加「应用」标签，不是它归在的那个 Bot 的头像和名字，读屏读作「来自 Deskfolk 应用的消息」；按钮照旧在下面。你的话上挂的按钮仍在你的话下面。
- 叫停的回执：「撤销」按按钮解除它的叫停，停下的活带说明重新开始，Stop 建的也一样——撤销就是当它没按过；叫停来自你的一句话时，这句话随后照常交给 Bot（整理、叫醒，像从没被读成叫停一样，不再按控制句或进度询问读）；这句话是在你和一个 Bot 的私聊里说的时，停在那里的活不另带说明重开，由这句话交给 Bot：私聊里你的话总会给它开一轮，再重开就是同时做两轮。在群里，这句话只叫醒它点到的（不点名、又没有谁还在做时，只换来各 Bot 的一次判断），所以停在那里的活照样带说明重开，这句话随后像你在群里说的任何一句那样交给 Bot。「扩大到所有 Bot」建一条全部上的叫停，回执发在同一个会话。「一起停下《…》」在叫停时还有别的 Bot 在做的那件规划上建一条规划叫停（`effect.working_beside` 里的规划）。「只停《…》」给回执里每条 Bot 上的叫停先建一条这个 Bot 在那件规划里的叫停（引用同一句话），再解除原来那条：它在别处被停下的活带说明重新开始，在那件规划里的交给新建的这条；应用另回一条回执，写明解除了什么、什么仍在叫停。每件规划各一个按钮，最多三个；「一起停下」也是。「作废这件事」把回执里生效的叫停记为作废（`action: cancel`）：它们照样扣着，解除就重开这件事；真正把一件事作废要等工作项。
- 状态行和「继续」的回执上的「只让 X 继续」：挡着的每条更大的叫停先拆成其他每个 Bot 各一条，引用建它的那句话——全部上的拆成每个 Bot 上的；规划上的拆成每个 Bot 在这件规划里的；会话上的拆成每个 Bot 在它搁置的规划和会话当前规划里的，外加其余 Bot 被它停下、不在这些规划里的每一轮上的叫停——然后连同 X 自己身上的叫停一起解除：X 的活带说明重新开始，别人的交给拆出来的那几条。「全部继续」把挡着的全部解除。两个按钮都回一条回执；回执的 `held_ids` 是这两个按钮针对的叫停。
- 你的话上的按钮：「停下」就是这句话要的叫停（来源 `user_button`，`source_message_id` 是这句话，回执引用它）；「作废」同样，记为作废；「继续」解除这句话会解除的叫停，解除不了时回一条状态行。状态行上的「停下」叫停问到的范围。

**停止菜单和列表**：会话里有 Bot 在做事时（私聊里是对面的 Bot 在任何地方做事，群里是有 Bot 在这个群里做事），Stop 或发送旁边有一个停止菜单：私聊里是「停下 X 的全部工作」「停下这件事」（它最新在做的那件规划，这个会话里的优先）和「停下所有 Bot」；群里是「停下这个群里的工作」、在这个群里做事的每个 Bot、「停下这件事」和「停下所有 Bot」；已被生效的叫停覆盖的项不列。流程图标题行有「停下这件事」「停下所有 Bot」。工具菜单有「全部停下」，已经全部叫停时换成「全部继续」（解除全部上的叫停）；菜单栏的「全部停下」建全部上的叫停，守护进程还没有叫停时退回停下最近有活动的私聊里的那一轮。菜单叫的停走 `POST /v1/holds`，带上菜单所在的会话，你在那个会话里时回执发在那里。守护进程拒绝的叫停或解除在按下的地方说「没做成，再试一次」；工具菜单的这句写在列表上方，到你再按一次、或全部上的叫停被别处建起或解除为止；连不上守护进程时这些按钮显示但按不了。生效中的、你建的叫停（启动时接管的旧搁置除外）列在会话列表上方：范围、时间，作废的标出来，各带「解除」（按按钮解除，见接口）。群上的叫停、私聊对面 Bot 上的叫停、Bot↔Bot 私聊里任一个 Bot 上的叫停，让那一行在没有别的状态时显示「已叫停」；全部上的只在上方列一次。流程图在标题下列出覆盖这件事的叫停——这件规划上的、某个 Bot 在它里面的、它所在会话上的、全部上的——各带「解除」。叫停建立或解除时，打开着的流程图重读规划，之后的编辑从叫停写出的那个版本起，不会被 409 拒；万一还是 409，它照旧重读。要点底部和修订历史把叫停写出的版本标为「叫停改的」（修订的 `cause: "hold"`，规划详情的 `revision_cause`）。这些都要守护进程到了叫停这一级：快照里有 `holds` 才出现。

**启动时**：引擎级别到了叫停这一级后，每次启动都核对一遍。在有叫停之前就被搁置的规划——状态和要点里的状态都是搁置，你或整理跳叫停时就是这样——接成一条来源为 legacy 的规划叫停，此后只有你能让它回到进行中；只是被新规划挤下当前位置的（要点里仍是进行中）不动。然后把叫停覆盖着、却没有搁置的规划和没有挂起的回看补上，记进 daemon.log。

**接口**：`GET /v1/holds`（默认只列生效中的，`?status=all` 连已解除的一起，新的在前）、`GET /v1/holds/:id`、`POST /v1/holds`（你从按钮或菜单叫停，记作 `user_button`；它覆盖的轮照上面那样当场结束）、`POST /v1/holds/:id/lift`（解除，它停下的轮像说「继续」一样重新开始，Stop 建的除外；已解除的原样返回）、`POST /v1/messages/:id/control`（上面的按钮：`{action, task_id?}`，`task_id` 给「一起停下」「只停」指明规划；返回 `{made, lifted}`；这句话没有按钮或不提供这个按钮时 422）；手机上同样可用。`POST /v1/holds` 可带 `session_id`：回执发到那个会话（你在里面时）。快照的 `holds` 是生效中的叫停，新的在前，到叫停这一级之前没有这个字段；叫停的 `plan_title` 是它点名的规划的标题。用 `PATCH /v1/tasks/:id/spec` 把规划改成搁置，也照样结束在里面跑的轮。`POST /v1/turns/stop` 就是上面的卡片 Stop。应用读过或写出的、关于你的叫停的话带着 `control`（`MessageControl`）。叫停的建立、解除和记下的效果都作为 `hold.upsert` 事件推给客户端。规划详情的 `held_by` 是读取那一刻的：全部上的叫停之类不改规划那一行，建立和解除时只推 `hold.upsert`，显示 `held_by` 的客户端收到它就重读规划。

<a id="terminal"></a>
## 终端（Terminal）

你自己在这台机器上开的一条 shell 会话，守护进程持有。和 Terminal.app 同权：cwd 默认落在工作区，但不关在工作区里，也不走批准——批准管的是 Bot 的危险动作，你不需要向自己申请。用来跑你自己的活，包括启动项目这类一直开着的进程。关窗不停。它在哪个目录，以 shell 自己报告的为准（zsh 开箱即用，每个提示符前报一次）：`cd` 之后标签名跟着变；从没报告过的，就是开的那个目录。退出或守护进程自己停掉时，里面的进程一起停，但它在哪个目录、屏幕上有什么会留下来，下次启动在那个目录重新开一个。结束会话才忘掉它。屏幕也在守护进程那里：接回时拿到的是它现在的样子，全屏程序也原样；程序问终端的问题只由它回答，窗格不答，所以几个窗格同时看一条会话也只答一次。shell 拿到的环境按 Terminal.app 那样配，但只放行一份白名单，守护进程自己的其他环境变量（包括密钥）不带进去。桌面和手机同时看一条会话时，它的行列按你最近在看、在敲的那一端来。配对过的设备同权，手机上看得见也敲得动。Bot 看不见、用不了，也不知道它存在。桌面上一个终端标签就是一条会话：新开一个终端标签就是新起一个 shell，标签里不再有一排会话可切。关掉标签只是从窗里拿走，进程照跑；没被任何标签摆出来的会话在「＋」和空窗格里可以「接回」。手机和窄屏上没有窗格，所有会话收在终端那一页里当它的标签。要停必须显式「结束会话」并确认。守护进程那份会话列表才是真的；同一个文件夹里开的几条按开的先后编号，桌面标签和手机上叫法一样。

<a id="interrupted"></a>
## 中断（Interrupted）

守护进程重启时，进行中的轮次都被标成中断，那一行写在这一轮所在的会话里。长活的轮多半在你不在的 Bot↔Bot 私聊里：2026-09-26 一件视频活被重启打断，中断只写在那条私聊里，停了 7.6 小时，直到你自己发现去点了继续。所以重启之后，引擎一起来、调度器走第一拍之前（停机期间到期的回看和日程不会抢在它前面叫醒 Bot），被打断的活每件各发一句，发在这件事所在、有你的会话：规划的轮发在规划所在的会话；你不在那里时，依次找这一轮所在的会话、这条 Bot↔Bot 私聊往上开出它的那个会话、你和这个 Bot 的私聊。同一件事、同一个地方的几轮（比如一件规划在两条 Bot↔Bot 私聊里各断了一轮）合成一句。这一句是应用写的系统行，不进 Bot 的上下文，显示成应用自己的话（见[叫停](#hold)的按钮）：
- **为什么重启**：这一次是开发版（`bun --watch` / `--hot` 跑的，或带 `REAL_BOT_DEV=1`），说「开发版守护进程重新启动了」，不管上一次怎么结束的：`--watch` 每次保存代码都先发 SIGTERM、不等进程退出就原地重启，收到 SIGTERM 的停机又先写下了「有意停下」，在那里这个标记分不清改代码和退出；不是开发版、上次是有意停下的（退出、更新、你让它重启，写了 `last_shutdown = clean`），说「守护进程停下后重新启动了」；其余是「守护进程意外退出后重新启动了」。
- **断在哪**：每一轮的 Bot、所在的任务（没有任务就是规划）、不在这个会话时它在哪、最后一步（执行记录里最后一条命令或 MCP 调用）。
- **接下来**：不会自己接着做。点「继续」，这件事被打断的每一轮都照它自己那条中断行的「继续」接着做：新开一轮，触发条是那条中断行，同样受叫停管——叫停把这几轮全扣住时这次按下不算，解除后再按；只扣住其中几轮时，其余的照常接着做，按钮旁说接着做了几轮、还有几轮被叫停扣着，这一句不算按过，解除后再按接着做剩下的；已经接着做了的、Bot 已经在那里干活的、会话或 Bot 没了的跳过，都已经接着做了时按下就算按过，什么也不多做。点「不续」就先放着，中断行自己的「继续」回来。每句只按一次。
- **通知**：一件事一条（`interrupted`），这几轮各自中断行的通知作废；同一个会话里被这一句覆盖的中断行，在你按下按钮之前不再各带一个「继续」。

哪些轮算被重启打断：守护进程开始一次停掉所有轮时（退出、应用更新或远端重启时的强制排空、守护进程自己停掉），以及启动时收拾上一次留下的活轮时，把那一刻的活轮记下来；下次启动只取仍是中断、中断行还没被接着做的。只有紧接着的那次启动取：中间另有一次运行开过库却没取（没起来就挂了），或者中间跑过一个不认识这条记录的旧版应用、又开过轮，这条记录就过时了，只清掉，不拿这一次重启的原因去说那次早先的停机，那些轮的中断行和通知照旧。发这几句时出错只写一行 daemon.log，守护进程照常起来。卡住被清扫中断的轮不算；强制排空之后又取消的，取消时忘掉。每次启动在工作记录里记一条 `daemon.restart`（原因和被打断的轮），有被打断的再写一行 daemon.log。这些不看引擎级别。按原因自己续跑（有意停下立即续，意外退出稳定后续一次，开发版等你按）要等 ADR 0040 的 P4c：先得能核对最后一步的副作用有没有落地，否则最后一步是送审或渲染时会付两遍钱。「继续」「不续」走 `POST /v1/messages/:id/control`（`{action: "resume" | "leave"}`，手机上同样可用），这一句的 `control` 是 `{kind: "restart", cause, notes, offer, acted?}`，`notes` 是这几轮的中断行；只接着做了一部分时回答带 `partial: {continued, held}`。

<a id="completion"></a>
## 补全（Completion）

每一跳请求都带 `max_tokens`：取这个模型在端点名单里的 `max_output`，没填就是 32768，推理 token 也算在里面。没有上限时，2026-09-29 有三跳把同一句话写到了端点默认的 128,000 token（其中一跳写了 17 分钟，同一句 3,457 遍），被当成收尾发了出去；在 Bot↔Bot 私聊里还叫醒了对方，对方的下一跳又把整段读了一遍。32768 是看过花费记录定的：正常的一跳输出最多三万出头，超过 32768 的只有那三次复读，再低就会截断写大文件的正常跳。端点不认 `max_tokens`、在 400 里点名要 `max_completion_tokens` 的（OpenAI 的推理模型就是这样），马上换这个字段重发一次，这个模型之后都用它。模型能写的比这少的（DeepSeek 的 deepseek-chat 最多 8192，OpenAI 的 gpt-4o 最多 16384），端点会用 400 拒掉这个上限：报错里写了模型自己的上限，马上按那个数重发；没写，就不带上限重发；这个模型之后都这么发。没有上限时这些请求本来能过，所以这种拒绝不能让这一轮失败，而上限在设置里也改不了。提示词加上上限超过了模型的上下文（报错里写着「32768 in the completion」，或者点名上限、说的却是上下文长度，vLLM 就是这样）时，只有这一次不带上限重发，下一跳照样先带上限。

流式输出时，应用只看正文，不看工具参数、代码块和表格：在最近 6000 字符里按句切（句号、问号、感叹号、分号、省略号、换行，英文句点后面跟空格），每句只比字母和数字、不分大小写，数字照比（「镜头 11」和「镜头 12」是两句）。同一句（8 个字以上）连着出现第 5 次，或者最近至少 20 句里不同的句子不到两成，就当场掐断这次补全，记为复读，通常只要几秒。「连着」是说两次之间没有新句子，只隔着前面出现过的句子：复读的两遍之间只有复读本身；逐项的审片结论（每行一句「Shot 03：通过。画面稳定，无需返工。」）两遍之间隔着这一项自己的名字，不算复读。不同句子占比这一条不看句子长短，20 行一模一样的「- [x] 完成」、哪一行都没写是哪一项，照样算复读。写完的回复发出之前，再按同样的规则看一遍。

这几种补全算失败，不算回复：
- **复读**：见上。
- **拒答**：端点给的结束原因是 `content_filter` 或 Gemini 的 `SAFETY` 一类；或者整条回复不超过 300 字、没有工具调用，又是一句套话式的拒答（自称语言模型并说做不到，或者只有一句「I can't help with that」「抱歉，我无法协助处理这个请求」）。Bot 自己说明哪一步做不了、为什么，不算拒答。之前 Gemini 的拒答有两次被当成 Bot 的消息发了出去。
- **不完整**：没写完就关了连接（既没有结束原因，也没有 `[DONE]`；端点或中间的代理半路断开连接就是这样），结束原因说要调用工具、却没有一个完整的工具调用，或者工具调用的参数不是完整的 JSON。客户端先把同一个请求最多试三次，还是不完整才算失败。
- **超时**：一次请求从发出到流结束最多这么久：10 分钟和「`max_output` ÷ 这个模型实测的 p10 吞吐 × 1.5」里较大的那个。吞吐取名单里的 `stream_tps_p10`，没测过就是 10 分钟。等端点空位的时间、工具执行的时间、合盖睡着的时间都不算。

失败的补全什么都不发出、不进回路，也不叫醒谁。同一个模型带一句说明原因的提示再来一跳（复读的那句是：别复述，也别写收尾话，要做的事直接调用工具去做）；连着再失败，这一轮以失败结束，会话里留一行「这一轮没写完：……」，你在场时还有一条失败通知。中间只要有一跳正常，下一次失败就还能再来一次。连不上端点、端点忙、端点报错、流中途没了下文（连接还开着，却等不到下一段）这几种不在此列：客户端已经把同一个请求重发过，这一轮直接结束。没了下文要等满空闲时限（3 分钟）才知道，三次就是 9 分钟，再来一跳会再翻一倍；连接半路断开几秒就知道，所以算不完整，多来一跳也不贵。流中途没了下文或者断开时，前半截以前会当成回复发出、或者拿去执行里面的工具调用，现在一概不用。

结束原因不分大小写，经代理转来的 Gemini 原样结束原因也认：`STOP` 就是 `stop`，`max_tokens`、`MAX_TOKENS` 和 Mistral 的 `model_length` 都当作 `length`。空字符串不算结束原因：有的端点每个数据块都带一个 `""`，直到最后一块。客户端不认识的结束原因（比如 `eos`）说明模型自己写完了，这条流是完整的，不会当成半截流重发，回复照样按上面的规则判断。`error` 例外：OpenRouter 在它后面的模型半路出错时用它结束，前面到的只是半截，算不完整。结束原因到了之后流没了下文（端点没发用量和 `[DONE]`，也没关连接），等过空闲时限就当回复收下：模型已经写完，缺的只是端点最后那几个包。

写到输出上限被截断（结束原因是 `length`）、又没有复读的，接着写一跳：截下来的那部分不发出，但留在回路里让它接着写，提示它要做的事直接调用工具、长内容写进文件并分块写；截断发生在工具调用的参数里时，那次调用不执行，提示它分块写。接着写的那一跳又写到上限，这一轮以「写到输出上限」失败结束。

流式输出不再算作这一轮在推进：以前每来一段就刷新一次这一轮的动静，一跳写多久都不会被当成卡住。现在补全由自己的时间上限管，卡住清扫（20 分钟没有任何动静）只管补全之外的时候。

名单里的 `max_output` 和 `stream_tps_p10` 在设置里看不到；从设置再保存名单时，这两个值照旧保留，通过接口传 `null` 才会清掉。存着的名单里这两个值哪个不合法（比如 0 或者字符串），只忽略这一个值，模型照常留在名单里，用它的 Bot 也不受影响。

<a id="artifact"></a>
## 产物（Artifact）

一条消息里引用的工作区相对路径，或 `http`/`https` 链接。文件本体在工作区（或远端 URL）上。本轮写入的区内文件会自动出现在最终消息里。点开后在聊天右侧预览面板查看（图 / 音视频 / PDF / 文本 / 单文件 HTML / Word / Excel / PowerPoint）；其它种类（字幕、压缩包……）写明不支持预览：本机窗口给「用系统默认应用打开」，手机和浏览器里给下载按钮。远程打开的每个文件都能下载：手机在预览顶栏右端，宽屏在文件上方那排按钮里，流程图的文件卡片在卡片头部。远程打开、下载和发附件都不限文件大小；桌面端这条预览也可以拖成自己的一块窗格。面板左侧的树列的是**这件事**引用过的全部路径——不是只有这一条消息的，也不是工作目录里的全部文件，相关指的是被引用过；树以工作目录为根，这件事在目录之外引用的路径和它并列平铺，本条消息自己引用的那几个标出来，面板与聊天共用一栏、中间拖条改宽度；同一条消息多个路径或打开工作区时左侧是文件树，树和内容之间可拖。拖过的预览栏宽度和文件树宽度，退出后再开还在。文本用 Monaco + Shiki 编辑（行号、查找 / 替换走 ⌘F、匹配括号·标签·标题折叠、换行）；预览自己不再放查找、换行、复制、保存、关闭这些按钮。Markdown 和单文件 HTML 默认看渲染结果，内容顶部正中有一个浮动按钮，不随正文滚动，在预览和源码之间切换。PDF 用内置的 pdf.js 渲染（翻页、缩放、适合宽度 / 整页、页内查找），不走系统的 PDF 查看器。区内 UTF-8 文本可 Cmd+S / 保存写回同一路径；未保存切文件或关面板先确认。桌面端预览没有自己的标题栏，文件名和关闭都在工作台标签上；窄屏和手机留一条返回加文件名。文件树每一项右键是「在 Finder 中打开」和「用系统默认应用打开」，本机窗口才生效。树里的文件和文件夹（⌘ / Shift 多选的一起）可以直接拖到聊天框，停在框上时框会亮起，松开后在输入框上方排成附件，随下一条消息发出：挂的是工作区里的原路径，不上传、不复制进 `inbox/`，Bot 读到的是「附件：路径」，图片照常按像素交给模型；拖动时按 Esc 取消。文件投递那条会话、只读的会话和正在发送的聊天框不收；手机和触屏上不拖。交接时把路径写进给对方的那条消息，不另建种类。种类按扩展名在预览时推导。区内的产物可以批注（见「批注」）。

<a id="annotation"></a>
## 批注（Annotation）

你对某个产物的某一处写的一句意见。挂在一个工作区相对路径、一个锚点和交出这个产物的那条消息上。先是草稿，Bot 看不见；攒够一批一起发出，合成一条引用交付消息的回复，并 @ 交出它的 Bot。发出后是「待处理」，Bot 或你把它标成「已处理」；已处理的可以重新打开。一标成已处理就从文件上撤下——图上的框、代码页边的点、Markdown 里的标记、PDF 页上的框、HTML 的编号、时间轴上的标记——留在文件上的就是还没处理的；列表里照旧列着。预览栏的「显示已处理」勾上才画回来，只对这块预览有效；从列表点一条已处理的去定位，那一条在定位期间画出来，再点一下取消选中就撤下来；对话里点它的卡片只打开列表停在那一条，不画回文件上。文件改了、锚点对不上时标「原文已变」，状态不变；文件不在了标「文件不在了」。批注不是产物的快照：只记下当时的引文、位置和文件哈希，不保存旧文件（选区长过引文上限时，另记整段的长度和指纹，用来判断这一段还在不在、变没变）。挂到谁：从某条消息打开的预览，就挂到那条消息和交出它的 Bot；交付消息在你不在的 Bot↔Bot 私聊里时，这批发到你和交付 Bot 的私聊里，消息上记着来源。只批工作区内的文件，链接类产物不能批注。批注消息叫醒的每个 Bot 沿用它自己交出产物那一轮的工作目录（这批里它最近的一次交付），哪怕会话已经静默够久、那件事已经关了——改的是同一件交付物；这一轮只是在那个目录里干活，不把那件事重新打开，也不换掉会话的当前规划，那件事属于别的会话（Bot↔Bot 私聊交出的）时也一样，两边会话各自接着的事都不受影响。它就是一条普通的后续发言：落在交付那一轮上、进纠正链，不加权。一批最多 50 条，一条正文最多 2000 字。群里一批可以同时交给几个 Bot：上下文里每条批注都写明交给了哪个 Bot（交出那个产物的 Bot，删了就写「已删除的 Bot」），`list_annotations` 也带上；每个 Bot 只处理交给自己的，交给别的 Bot 的留给那个 Bot，可以提一句；交给已删除的 Bot 的没人接，归这批叫醒的 Bot 处理。Bot 能做的：逐条处理交给自己的，改了的用 `resolve_annotation` 标成已处理并写一句怎么改的（任何 Bot 都可以标——Bot 不是权限边界——记下是谁标的），用 `list_annotations` 查还没处理完的（路径和 `read_file` 一样解析，工作区外的路径直接报错），`read_file` 读到还有待处理批注的文件时会被提醒。Bot 不能做的：重新打开、删除、新建批注。清空历史、删会话时挂在这些消息上的批注一起删掉；删了文件不删批注。锚点种类：文本 / 代码行区间、Markdown 渲染态划词、图片框选、PDF 页内区域、HTML 元素、音视频时间点。

<a id="context-window"></a>
## 上下文窗（Context window）

一轮里模型实际看到的：人设、启用中的技能目录、系统指令、本轮 MCP、这个 Bot 的记忆、局面块（群里有在场成员、活轮、谁叫醒、用户最近一句；每一轮都有这件事的名字和规划要点（目标、验收、规则、流程与分工、进展）、任务清单、本轮任务、同类先例、已交出的文件、经过（在别的会话做的那步标明在哪）、自己待回看的那一次，规划开在别的会话时写明开在哪，还有此刻别的会话里做这件事的轮和这个 Bot 别的活轮，还没整理出要点时退回最初的要求，第一轮标「这是这件事的第一轮」；全部从库里已有的行读出，轮次本身不叫模型摘要）、最近一段转录（别人的行属于另一件事或另一个任务时，在说话人后面带 `〔规划「…」· 任务 NN〕`，Bot 自己的行不带，免得它学着写；含栅格附件的像素，只取最新的一份额度；带批注的用户消息在正文后面逐条展开每条批注的 id、交给哪个 Bot、路径、位置、引文或裁图和意见（页面和你写的文字折成一行或逐行缩进，冒充不了下一条），裁图和栅格附件花同一份额度、作为像素发给模型，额度用完的裁图只留批注的文字），以及本轮的工具回路。完整历史只存在库里，给你翻、给搜索，不整段塞进模型；判断调用用另一套更短的窗口，不含图。过大的工具结果先把完整 JSON 留在工作区，窗口里只放受限预览和 full_result_path；Bot 可继续用 shell 提取所需字段或解码文件，不把预览截断当作原始结果丢失。

<a id="spend"></a>
## 花费（Spend）

本机只增不减的调用账本。七类端点调用各记一行：轮次补全、判断、开轮前选路、纠正链复盘、复盘后的每一跳学习、输入建议、整理。选路和整理属于决策路由；复盘与学习跳合为反馈路由；判断单列，输入建议归其他；输入建议和整理都不归任何 Bot。每行存实际模型、端点、思考等级及写入时的会话和 Bot 名称；删会话、清空历史、删 Bot 都保留，已删除对象用名称快照并标「已删除」，迁移时找不到模型的显示「未记录模型」。token 只用端点 `usage`，缺了显示「—」。供应商给出 `cost_in_usd_ticks` 时记实报；没有实报、输入与输出 token 齐全且配置了计费单价时算估算；估算跟着现在配置的单价走，设、改或清空某个模型的单价会重算它在该端点上所有没有实报的调用，从名单里去掉的模型保留原有估算。缓存输入使用缓存单价（留空沿用输入价，缓存 token 缺了当 0）；推理 token 已含在输出里，不重复加。实报与估算分开合计，覆盖不全会说明。应用里有独立花费视图：桌面一个窗格标签，窄屏和手机一个浮层，可按时间、模型、会话、Bot 及调用类别筛选、看趋势与逐次明细；明细可跳回触发消息。会话顶栏、列表行、设置和模型选择记录都不放花费数字。时间范围和维度只保存在本机。
