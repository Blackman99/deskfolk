# 行为说明

[English](behavior.en.md)

这里记录 [`CONTEXT.md`](../CONTEXT.md) 词条的行为细节；词汇表只定义概念，版本、工具、接口和迁移边界写在这里。

> **P4b 范围**：下面的新工作项、桌面段、确定性归属和负责人投递以 `engine_level >= 2`（`ENGINE_LEVELS.work_items`）为界，启用时数据库兼容地板也是 2。级别 0/1 仍保留旧的消息时整理、任务继承及改道路径；这些代码没有物理删除。2 级不再为消息归属调开轮前整理，但这不代表所有开轮前模型调用都已删除：未确认负责人的旧群仍有参与判断，现有模型选路仍在。静下来后的交接整理（settle）也仍在。
>
> **P4c 部分实现（本轮）**：`ENGINE_LEVELS.delegation = 3`，启用时兼容地板是 3；3 级已有结构化委派、同 Bot 对 × 规划的私聊复用、普通私聊发言不叫醒、非终止的 `send_message`、只读委派视图和结束原因域函数/引擎接入。下文明确区分已接入与待完成；0–2 级保留旧私聊/发言/结束路径，3 级也尚未退掉 settle、plan-watch 和 report_back。
>
> **P4c 监督器（4 级）**：`ENGINE_LEVELS.supervision = 4`，启用时兼容地板是 4（[ADR 0045](adr/0045-supervisor.md)）。4 级有[监督器](#supervisor)：持球者、没人推的任务的叫回、需要处理的工作续跑、I6 核对、按原因的重启续跑、副作用记录，以及 blocked 的[工作提问卡](#work-question)；同时不再运行 plan-watch/plan_nudge 与 report_back。settle 和收尾正则各级都还在。
>
> 不能据此宣称 P4c 全部完成：真正隐式交付仍缺；完整结束契约尚在专项验收。P4d 作业轮询、P4e 的 `submit`/`review`、审查者指派与已通过交付/分件审查、P5 模型策略和学习也不在本轮。新开卡片操作已完成专项验证，不把单项通过等同全阶段验收。

<a id="direct"></a>
## 私聊（Direct）

你和一个 Bot 的私聊长期复用；Bot↔Bot 私聊你仍只读，可以查看工作记录和操作已有安全控制，不是能发普通消息的第三位参与者。**3 级委派**按无方向的「两个 Bot × 规划」复用一条有且仅有这两个在场 Bot、未归档的私聊：反向交接同一规划也复用，不同规划不复用，没有新会话种类。协作私聊在代码仍叫 direct，领域里的「协作线程」不等于主转录里一条消息的引用回复。

3 级 Bot↔Bot 私聊的普通消息（包括纯文字收尾和对在场对方的点名）只留下 `peer_note`，`wakes=0`；已有段可读到，没在做的 Bot 不因此醒来。通知不是委派结果，不会解除等待。点名不在这条私聊里的第三个 Bot、未知名字或全员点名时，`send_message` 在落消息前返回 `use_delegate`「要它动手用 delegate」；需要实际处理走[委派](behavior.md#delegation)。`create_direct` 在 3 级不再提供，强行调用也返回 `use_delegate`，并未物理删除旧实现。

0–2 级仍是旧的一次发起一条 Bot↔Bot 私聊，普通收尾/私信会叫醒另一方（短回执接回执的识别仍有保留），静下来后的旧 report_back 可能叫回发起方。3 级也还有 report_back/plan-watch/settle，所以普通消息的非叫醒语义不等于所有旧静默回报已经消失；4 级起 report_back 和 plan-watch 由按持球者叫醒的[监督器](#supervisor)接替，settle 仍在。

引用回复继续只是一层、仍留主转录：回复 Bot 可自动带它的点名，已经点名/全员点名不重复，不自动点名用户；参数仍是 `parent_id`。

<a id="delegation"></a>
## 委派（Delegation）

**3 级已接入**：`delegate({to,ask,expects,ticket?,parts?,requirement_ids?,continue?})` 要求调用方是未被叫停、精确绑定工作项的运行中工作段，不接受桌面或只读段伪装。`to` 是 id 或准确名字，必须是未归档的另一个 Bot，并在本段、工作项主会话或规划主会话之一在场；任务/分件属于同规划，引用需求对该工作生效才收。不放低此校验来兜底未知目标。

应用记录请求、发送/接收工作项和发起轮，创建或复用接收方在同规划/可选任务的工作项及精确 Bot 对协作私聊，投一条 priority=3 的叫醒请求收件。默认 `continue` 不为 true 时，委派方转 waiting，记 `delegation_wait`，本段结束；`continue:true` 不建立等待，本段继续，委派关系仍在；委派方之后可做独立工作并以 answered/idle 收尾，迟到的回答仍会把符合准入的原委派方排队叫醒，不靠假造等待。接收方的开段/听进/排队仍过 I1/I1b、名额和叫停，不因为被委派就另做一遍同规划。

**当前交回只覆盖回答型**：接收方用 `end_turn({reason:"answered",answer:"…"})` 给精确绑定的、`expects="answer"` 的未关闭委派交回，代码只解决这类请求；普通收尾或 `send_message` 不算交回。结果一次落地为 priority=2 的持久 `delegation_reply` 收件，原委派变 replied、对应等待作废，允许的委派方转 queued 再被叫醒；被叫停的结果收件保持 held，不绕过叫停。已有底层 submission 引用校验是后续接口接缝，当前没有 Bot 的 `submit`/`review` 交回路径；`expects=deliverable/review` 可记录，但其真正结构化交付仍待 P4e，不能拿一句话冒充已通过审查。

**事件等待不是时间回看**：`delegation_wait` 不由 due 扫描触发（各级别都排除），只因这项委派的回复/取消解决。3 级定时回看按精确工作项/去重键替换，不替换同 Bot 同会话的另一工作项或委派等待；叫停挂起、解除恢复对应记录，不让不相干的新 timer 覆盖旧事件等待。没有真正到期时间的委派，视图的 `due_at` 是 `null`，不把内部占位时间显示成倒计时。

**叫停连带范围**来自仍打开、规划/任务绑定一致的委派边，建立时捕获为下游 Bot × 规划目标；不只看单个 `delegated_by`，同一接收工作项可有几个上游。停 owner 的这一件事会覆盖它委派的 helper 同件事，但 helper 的另一规划照常；后续新委派不偷偷扩充已建的覆盖快照，解除仍只接受用户动作。

归档/删除 Bot、清空/删除相关会话会取消相关未关闭委派并记录结果。接收方归档时，仍存在且符合准入的原委派方得到一次可叫醒的取消结果；委派方自己归档时不叫醒自己。清空/删除会话的取消结果一律 `wakes=0`，不因为清空聊天重启工作。结果/请求保留在记录中，不把取消说成完成。归档同时关闭该 Bot 的工作项、结束在跑的执行并在提交后中止引擎；副作用闸再核对 Bot 是否仍有资格、工作项是否关闭及是否仍持有执行权，完成中的补全也不能在归档后继续写文件。

**只读视图**：`GET /v1/tasks/:id/delegations`、`GET /v1/sessions/:id/delegations` 本机及远端白名单返回已记录的 `DelegationView`：谁向谁提什么、期待什么、open/replied/cancelled、请求/结果、waiting/held 和真实的可空到期时间。`delegation.changed` 实时事件及补拉追上变化；协作私聊显示结构化「委派/交回/等待」，不是从正文猜状态。界面是只读投影，不新增用户发起委派按钮；组件已接入，父任务已确认两个浏览器的合成场景验证通过；这验证只读视图和操作，不是付费真实模型的整个协作闭环验收。

**发言与收尾分开**：3 级 `send_message` 成功不结束本段，可通知后继续做。面向有用户的会话、本段不带 `parent_id` 的进度发言最多 3 条，第四条返回 `progress_limit`；当前以 `parent_id` 为豁免标记，没有已实现的「真实问题语义分类」，不要把任意引用回复说成经过验证的回答型豁免。群里点名仍可叫醒，协作私聊普通消息不叫醒。先发进度后才写出的文件仍由未引用路径跟踪，结束时可附到收尾消息，不会因为先说过一句话就丢掉后来产物；这只是消息引用，不是隐式提交。

**结束契约已接入、24b 尚未完整**：3 级 `end_turn` 的 reason 是 done/answered/nothing_new/blocked/gave_up，校验仍运行、工作项/规划/任务精确一致且未被叫停，并记录已读用户/批注收件的处置和 `turns.end_reason` / `work.ended`。用户收件未逐条处置会退回。纯文字路径先完成仍保留的收尾执行记录核对，核对退回时不提前写 work.ended，再执行结束契约；desk/readonly 的纯文字按 answered，工作段纯文字经过同一契约；还有待做/进行中/待验收任务、打开的委派或等待而没有真实等待时，done/纯文字先退回一次，第二次按 nothing_new 收住，不把文字当交付；两次无进展且仍有义务可 blocked 并通知；真实观察到的任务阶段变化以匹配 turn id 的 `ticket.stage_changed` 记录为进展，不把本轮刚开始实际工作的一次收尾算成空转，后续静默才累加。当前未处置收件/未完成义务的契约退回、归属退回，以及 `work_on`/`end_turn` 抛出的非法参数错误共用预算，预算用尽 needs_attention；reason 不认识、blocked 缺少 needs_from_user、gave_up 缺 note 也会计数，同一跳后面的副作用被压住。`delegate` 的直接返回失败和抛错也计入，但不会给同一次错误重复计数。因此当前已实现的 `work_on`/`delegate`/`end_turn` 共用两次退回预算；未来尚未实现的 submit/review/wait_for 仍须接入同一约束，不把本轮说成已覆盖那些工具。

有真实 timer/委派等待的工作项保留 waiting；无义务的任务或桌面可 closed，其余 answered/nothing_new 可 idle。blocked 必须给 `needs_from_user`，gave_up 必须给 note，并记录通知/事件。**缺口仍在**：3 级 blocked 只显示应用系统行；可答的持久提问卡在 4 级（[工作提问卡](#work-question)）；I5 已有 3 级库触发器：绑定工作项的 completed/stopped/interrupted/redirected 行在 INSERT 和每次 UPDATE 时都必须有非空白 end_reason（不限制成一个枚举），旧 0–2 级豁免；已有历史终态一次回填 status，不覆盖显式原因。旧收尾自检正则仍被调用。`implicitSubmission.implemented=false` 只列本段已引用、落任务目录的候选产物元数据，尚未验证存在/新哈希、跑绑定检查或保存交付，没有 submitted/approved 的推进。监督器 24c（孤儿任务阈值、I6 周期核对、每小时恢复预算、按原因自动续跑、旧 timer 的退场）在 4 级实现，见[监督器](#supervisor)；3 级没有这些。

<a id="check-back"></a>
## 回看（Check-back）

回看是 Bot 给自己的定时提醒，不是委派的事件等待。现有 `check_back(after_minutes,note)` 仍是一分钟到七天；3 级没有借本次改名启用设计里的 `wait_for(minutes>=5)` 或外部作业轮询。到期给被叫醒的 Bot 一条私有触发，挂在原工作规划/任务，不由提醒本身改规划阶段，叫停挂起、用户解除后才允许响。

**3 级范围变化**：timer 替换/恢复按精确工作项和去重键，不再「一个 Bot 一个会话只能留一次」，并且不覆盖 `delegation_wait`。0–2 级仍按旧会话范围去重；各级别都不按 due 扫描触发委派等待。0–3 级旧群/私聊静默后的 plan_nudge/report_back 仍在；4 级起它们不再运行，之前订下、还没响的在到点时作废，由[监督器](#supervisor)按持球者叫醒。排队派发时 Bot 自己约的回看和日程排在最后（优先级 4，你的话 1、委派结果 2、监督器叫醒和委派请求 3）。

<a id="supervisor"></a>
## 监督器（Supervisor）

4 级起（[ADR 0045](adr/0045-supervisor.md)），调度器每 15 秒一拍，在到期回看之前跑一次监督器，一次写入里做三件事；3 级及以下什么都不做。每次叫回或续跑记一条已触发的 `check_backs`（`kind = supervisor`，`wait_spec` 写原因、第几次、进展周期或重启），修复、重启和通知记工作记录 `supervisor.*`；时间都按库里的记录算，重启不丢期限、不重复叫醒。委派的回复和取消、你对提问卡的回答、排进收件的话照旧在各自那次写入里排队并立即派发，不等这一拍。

- **I6 核对**：工作项是 waiting，等的对象却不在了（委派被取消、对方工作项已关闭、回看没了），转「需要处理」（`supervisor.wait_invalid`），同一拍里给它排一条只给 Bot 看的说明「这一等不再成立」。被叫停覆盖的等待算有效等待。
- **需要处理的工作**：执行段被中断（重启、排空）、失败（同模型重试一次仍失败、卡住超时、运行时出错）、结束契约两次退回用尽，或等待失效，工作项转 `needs_attention`（中断和失败在写下终态的同一次写入里；运行中却没有活段、最后一段又是中断的，在这一拍补上）。监督器接着做：有那一段自己的「中断」或失败行就照它的「继续」做——同一个会话、同样受叫停和名额管，那一行记为已接着做，对应通知解决；没有就排一条只给 Bot 看的说明，写着上一段怎么了、最后一步、这是第几次。**每个工作项每小时最多 3 次**，之后在你在场的会话里留一行、发一条通知，不再自己续。叫停覆盖、任务已收口、球在另一个委派接收方手里时不续；被重启打断的先按重启原因（见[中断](#interrupted)）。
- **没人推的任务**：任务没收口、[持球者](#ball-holder)是它的 owner、规划负责人或未回复委派的接收方，而那个 Bot 在这件事上没有活段、没有有效等待、没有排着的收件，规划 active、没休眠、不是日程的，依赖的任务都已完成——静过门槛就叫醒它，说明里只写事实（哪张任务、静了多久、它是 owner/负责人/欠哪项请求的回复）和结束契约的选择。门槛默认 **2 分钟**，从这件事最后的动静（归到它的话、它的执行段活动、工作记录）算；在你在场的会话里，这件事的最后一条是 Bot 说的、晚于你在这件事里的最后一句时为 **10 分钟**，从这件事最后的动静和你在那个会话的最后一句两者中较晚的算——不判断是不是问句。**每个进展周期最多叫 2 次**，之后在你在场的会话（规划所在的那个优先）留一行「这件事停下了」，发一条通知，每个周期一次。
- **进展**只认工作记录：任务阶段变化（看板、整理和观察到的工作都记 `ticket.stage_changed`）、检查第一次通过（`check.first_passed`，模型判的衔接检查要连续两次通过才算）、任务目录下内容哈希新的产物（执行段结束时对写过的文件流式算 SHA-256，记 `artifact.changed`；保留目录和单个超过 2 GB 的不算）、交付与审查（P4e 写入后）。改说明、`updated_at` 变了、说了话都不算。
- **从打开那一刻起**：库升到 4 级时工作记录记一条 `engine.level_raised`。之前就已经静下来的任务、之前就在等待或需要处理的工作，不会在第一拍里被一下子全叫醒或续跑（升级时开着几十件旧规划也一样）；它们里一有新动静（你的话、看板上改任务、新的执行段），就归监督器管。被这次升级时的重启打断的活不算「之前」，按重启原因续跑。
- **它的行**：应用的系统行，不进 Bot 的上下文，`control` 是 `{kind: "supervisor", code: "stalled" | "retry_budget" | "unknown_effect", task_id, ticket_id, work_item_id, offer: []}`，不带按钮；附一条通知（`failure`，标题「停下了」）。接着做的办法写在行里：@ 它、点那一段的「继续」，或在看板上改任务。
- **副作用记录**（`tool_executions`）：`write_file`、`delete_file`、`shell` 和非只读的 MCP 调用动手前记开始（同一调用只开始一次，重复的不再执行、回 `repeated_effect`），结束记成功、被拒、失败或不明；中止时、MCP 调用发出后报错、超时、执行段结束时还没结束的都记不明。监督器把 shell 和 MCP 的不明当作「结果不明的外部调用」：那一段不自己续，留一行告诉你（重启的通知已经说了的不再说）。更早的段没有记录、只有执行记录里的 shell/MCP 运行，续跑中断的段时同样按不明处理。
- **不做的**：没绑任何任务的规划级检查失败时不叫人（0–3 级的规划叫回会；绑在任务上的会让球回到 owner）；外部作业的轮询（P4d）、审查者指派与 submitted → approved（P4e），每一拍的结果里列为 `unsupported`；看板上还不显示「球在：…」。

<a id="ball-holder"></a>
## 持球者（Ball holder）

对每张没收口的任务按顺序推导，第一条成立的就是：
1. 有未关闭的委派，接收方还能接活：球在接收方的工作项。
2. 有待你回答的提问：活轮的提问卡，或 blocked 工作项留下的[工作提问卡](#work-question)。
3. 有 blocked 的工作项：球在你。
4. 叫停覆盖它，或覆盖它依赖的任务：球在你（已暂停）。被扣住的工作不算停滞，也不改派。
5. 待验收：球在你；绑在这张任务上的检查（`ticket_id` 是它，或路径/目录在它的文件夹下）上次跑失败的除外，那就回到 owner。
6. 否则任务的 owner，再否则规划负责人，都没有就是「没人认领」（你）。外部作业（交给轮询器）在 P4d。

**Owner** 是 `tickets.owner_bot_id`，和 `worker` 一起写；升级时一次性从仍能接活的 worker 导入，没有就取这张任务上执行段最多、仍能接活的 Bot。**规划负责人**读出来、不写回：存了 `lead_bot_id` 用它，否则开出这件事的 Bot、群里你确认的负责人、规划里执行段最多的 Bot，都要还在规划的会话里、没归档。写回会改变群里没点名的话交给谁，所以不写。能接活是没归档、没删除，并且在规划的会话里。

**依赖**（`tickets.depends_on`）只来自你：`PATCH /v1/tickets/:id {depends_on: [...]}`（本机和远端），只能是同一规划的其他任务、不能是自己、不能成环，最多 39 个；依赖没全部完成时不叫醒，依赖被叫停时球在你。看板上还没有编辑入口。

<a id="work-question"></a>
## 工作提问卡（Work question card）

4 级起，`end_turn({reason: "blocked", needs_from_user})` 留下一张提问卡（`control.kind = "work_question"`，带工作项、规划和任务），发在这件事的会话、否则规划的会话、否则你和这个 Bot 的私聊里，作者是这个 Bot，显示成应用的卡片，附一条「等你回答」通知；工作项 blocked，`waiting_on = {kind: "user"}`，球在你。同一段重复同一问题只留一张。

`POST /v1/messages/:id/work-answer {body}`（手机远端同样可用）写下你的原话，一次：同一个请求 id 重发不会再排一次，换一个请求再答已答的卡会被拒。回答作为你的一行进这件事的收件（优先级 1，原话也进[原话](#user-quote)），工作项排队并立即派发，卡片记下回答和时间、通知解决。叫停覆盖这件事、或覆盖那一段所在的会话时，回答只被扣住、照常保存，叫停不因此解除；解除之后再接着做。已答过、之后又有新的提问、那一段还没结束、工作已关闭、Bot 已归档、会话已归档或已清空的，一律拒绝，草稿留在卡上。3 级及以下，blocked 只发一行文字。


<a id="work-item"></a>
## 工作项（Work item）

工作身份是「Bot × 规划 × 可选任务」，没有规划的桌面工作项是「Bot × 会话」。新工作路径给每一段执行绑定工作项；工作项不是轮次，任务也不是工作项。同一个工作项最多一段活执行（I1），同一个 Bot 在同一规划上也最多一段（I1b），包括正在执行、等批准和等提问回答的轮。规划级和任务级工作项不能绕过第二道限制；别的 Bot 在同一规划上仍可各做自己的工作。

同一 Bot 正在做这件事时，后来归到这件事的消息送进已有段的持久收件箱，不因为来自另一个会话、不同任务或用户在群里点名就改道或开副本。不同规划才开自己的段，受名额和叫停限制。**当前名额口径**：每个 Bot 全局默认最多两段工作；桌面不占工作名额，每个 Bot × 会话最多一个活桌面段，没有「每个 Bot 全局仅一个桌面」的约束。代码读取 `bots.parallel_limit` 中有效的正整数，缺省/无效值回到 2；本次没有新增调整它的界面。超过工作名额的收件和工作项落库为排队，会话回「排在第 N 位」；有名额后，调度器按优先级和收件顺序尝试开启，没有正在跑的目标也能从冷队列开启。目标仍被叫停或规划休眠就不启动。清空转录不自动恢复工作；用户明确恢复使目标重新符合准入后，来源消息已清空的排队项可用原正文快照建只给 Bot 的系统触发，再次过名额与叫停闸。这不是重启后的自动监督续跑。

`work_on` 选择的规划已经被这个 Bot 的另一段执行占用时，把本段实际触发消息（不只是文字摘要）送给那一段，本段以 `merged` 结束。任务身份仍然可以分别记录，但不能据此同时做两遍同一规划。未读收件被新段接收时会保留正文快照和处置记录；纠正已读归属不会把旧段的历史改写掉。

<a id="desk-segment"></a>
## 桌面段（Desk segment）

确定性信号未能决定归属时，被叫 Bot 自己开一段 `mode=desk`：这是该段的第一跳，不是整理员的旁路猜测。候选 id 集合在准入时捕获；桌面提示逐个展示这份集合里的规划 id/名字、最后活动时间、最多 3 条最近产物路径，以及最近一句未抹掉的用户原话（显示截到 300 字符；没有产物或原话时不列那一项）。这些说明可随每跳读取最新数据，不重新计算或扩充可选 id；候选已经不可用时标明不可用，不替换成新候选；`work_on` 只能选这份候选里的规划，或引用本会话中真实的用户消息新开一件事。候选后来增多不让旧段悄悄选上新规划。

选定前只读：读文件、列目录、无副作用的查询和标为 `readOnlyHint` 的 MCP 工具，外加回复、`ask_user`、`work_on`、`end_turn`。第一次要求有副作用的调用时，先完成归属，后执行：
- **0 个候选**：只有用户请求能自动新开规划，并给自己建一个产出任务；先显示「新开：…」，再执行调用。Bot 或系统行不能靠这条兜底自造新事。
- **1 个候选**：局面先写明默认归到哪件事；无关就先 `work_on({plan:{new:{title,quote_message_id}}})` 拆出。这次调用绑定后才执行。
- **2 个以上候选**：拒绝调用，列出候选，等 `work_on` 或向你确认；不能先写文件或跑命令再补归属。

选定不等于已有工作名额：工作名额已经占满时（默认两段），桌面仍能回答，但它把第三件事选成工作后只入持久队列，本桌面段收住、请求的副作用不执行；等有名额再开始，不会把桌面豁免变成第三段工作。中断的工作按「继续」时同样受名额限制，可先排队，本次准入段记 `end_reason=queued`，实际工作稍后才开启。

`work_on` 可以指定该规划里的任务（或新建任务），也能用 `also` 追加这个 Bot 的、仍打开且在候选里的工作项归属。锁定或用户纠正的目标不能由 Bot 丢掉；默认目标可以在第一次动作前拆到引用用户原话的新规划。归属退回预算为本段两次，耗尽以 `needs_attention` 收住，同一跳后面的副作用也不执行。

**工作目录（I8）**：公开约束是每段最多一次变化，完成归属后才允许副作用；典型是桌面无目录 → 任务目录。默认归错的新请求在尚未动手时可拆出一次，但不能把它当成工作中反复换目录的许可。工作段已经绑定到别的目录、写过文件或跑过调用，不能靠 `work_on` 换事继续写。中断后的「继续」保留桌面模式、捕获的候选和已用的目录变化次数，仍过归属和叫停闸；它不会自动变成可写的普通工作段。被叫停后回答你的 `readonly` 段不是桌面段，不能用 `work_on` 接手工作。

**新开卡片操作**：2 级的新事显示一张持久的「新开：…」卡，记录开启段和引用的用户消息，带「撤销」「并入…」；因工作名额已满而排队的新事也可以有卡，不因此多开第三段工作。新事仍是 active 或 delivered 时可操作，快速交完也不让按钮失效；用户已接受或新事已作废时，旧卡返回 `409 plan_changed`，应走另一个明确的人类操作，不借旧卡重开。按钮成功操作一次，再按不重复执行。

「撤销」先在新规划上明确建叫停、停掉在跑的执行，再记 abandoned；不是把过去的执行抹掉。文件、旧轮的执行记录、原话正文和需求保留，引用消息仍归在这件已作废的事上，不自动清理或删除；解除叫停也不会把 abandoned 自动改回 active。已经开始的写文件、命令、MCP 等副作用只能如实标为保留，外部已发生的操作不承诺撤销；停止之后不再放行后续副作用。

「并入」同样先停下并作废新事，但只把**卡片引用的那条用户消息**中指向新规划的归属改到卡上提供的、同一项目（主会话）的 active/delivered 已有规划；那句话的其他归属保留，原话正文不抹掉。它走消息改归的收件/出处纠正规则，不改旧轮的规划或工作目录，不搬产物，不合并整个规划，也不解除目标规划的叫停。引用消息已经改归过而不再指向新事时，拒绝为 `409 attribution_changed`；目标不在卡上、不是同项目或已不符合阶段时拒绝。

普通归属标签的「改」只纠正消息关系，不停下、作废原规划；新开卡的「并入」另有停止/作废这件新事的明确用户动作，二者不能混用。卡片调用沿用本机及远端的 `POST /v1/messages/:id/control`：`{action:"undo_plan"}` 或 `{action:"merge_plan",task_id}`。专项验证已覆盖运行中停止、保留文件、快速交付后操作、排队卡片、改归及过期保护；这不代表完整 P4b 阶段验收或后续 P4e 提交审查已完成。

<a id="attribution"></a>
## 归属（Attribution）

`message_filings` 保存一条消息的全部目标（规划、可选任务、可选分件）和来源；旧的 `messages.task_id`/`ticket_id` 只投影第一个主目标，不再代表全部。`filed` 是有目标，`undetermined` 是还没判定，`none` 是你明确不归或控制行等不参加归属。同一句可以同时涉及几件事，也可以在同一任务里涉及几个分件；多归属不把同一 Bot 的规划执行唯一约束放宽。

确定性信号按以下顺序读取。锁定来源 1–5 指向不同目标时累积，去重后都保留；已有锁定来源时不用默认来源覆盖。默认来源 6–8 决定一个规划，但可带该规划中几个对得上的分件：

| 顺序 | 来源 | 性质 |
|---|---|---|
| 1 | 界面/卡片上明确选的目标 | 锁定 |
| 2 | 已发出的批注，按目标产物路径及交付消息/轮继承 | 锁定 |
| 3 | 引用回复，继承被引消息的全部归属 | 锁定 |
| 4 | 附件或正文路径落在已有规划/任务目录下 | 锁定 |
| 5 | 已有工作项或叫醒记录的绑定；Bot 输出用自己的当前工作项 | 锁定；3 级显式委派绑定已接入，不等于未来作业/提交工具已生效 |
| 6 | 非休眠候选只有一个 | 默认，可改 |
| 7 | 分件编号在候选里唯一对得上 | 默认，可改 |
| 8 | 群为主会话的非休眠 active 规划只有一个 | 默认，可改 |

候选包括当前会话及共享在场 Bot 能看到的会话、来源会话里的非休眠 active/delivered 规划，目标 Bot 未关闭工作项所在的规划和它近 24 小时执行过的规划；显式引用、批注已验收或休眠的规划时仍可选它。默认候选不含日程常驻规划、休眠、accepted 或 abandoned。句首「另外 / 再帮我 / 新做 / 顺便」且不带已有分件编号或路径时，规则 6/8 不自动接旧事：先到桌面。这个提示是窄启发式，不是语义识别的准确率保证。

分件编号支持「前三镜」「第 3 镜」「Shot 12」「C02」和编号范围；交付文件名里的 `shot_07`、`C07`、`镜07` 可补出分件身份，旧任务标题的编号范围仅作兼容。歧义不选；只补身份和关联产物，不把分件推进到已通过。`plan_items` 与完整分件审查阶段仍属于 P4e。

消息下方可以显示并列归属标签、修改入口和「未归属」选择。`GET /v1/messages/:id/attribution` 返回手动纠正可选的规划和任务（可含未接触或休眠的规划，读取不会叫醒它）；`PATCH` 接受 `{filings:[{plan_id,ticket_id?,part_key?},…]}`，空数组明确不归，旧单目标 `{plan_id,ticket_id?,part_key?}` 仍兼容。本机和远端白名单都有，用户动作标识由接口生成，不能伪造强度；错误规划/任务/分件整体拒绝，不留半份修改。

用户纠正可以改锁定关系，记录 `attribution.changed`。尚未读的排队/held 收件改到新工作项，按目标现有叫停保留 held；已经读过的收件及原执行段不改，给真正读过它的 Bot 另留「这句改归到…」的纠正收件，新目标没有活段也可排队。多目标分别留收件；明确不归使未读收件 superseded，不回滚已做的事。纠正不解除叫停、不搬文件、不改旧轮的工作目录。

**持久原话也是多值**：同一份原话通过 `user_quote_filings` 关联全部目标，清空转录之后副目标仍能读到它，不只保留旧标量主目标。从这句话提取的需求出处随纠正移动；当前台账条目仍是单一作用域，按主目标重挂，不据此宣称一条要求已经自动扇出成几套独立审查义务。

<a id="group-lead"></a>
## 群负责人（Group lead）

2 级群里没点名的用户消息先给这件事在场的负责人，再给你已经确认的群负责人；这两者都没有时，沿用旧群的参与判断（仍是原有各 Bot 的判断，不宣称已改成一次判全体）。点名/`@everyone` 照常决定收件人，同事在同一规划上已开段时听进那一段，不因此改道。负责人被叫停也不换一个人偷偷继续。

近 **7 天**的交接记录只提出建议：数的是在执行段中真实发给另一个成员的点名交接（含全员点名），及从该群开出的 Bot↔Bot 私聊的第一条真实发言；普通闲聊、用户的点名、空私聊、后续对话不当交接数。只建议仍在场、未归档未删除的 Bot；证据为空或第一名并列就不建议。你确认才写入 `session_participants.is_lead`，Bot 没有任命工具；可重新指定在场 Bot，或用 `null` 清掉。

本机和远端白名单有 `GET /v1/sessions/:id/lead`、`PUT /v1/sessions/:id/lead {bot_id,confirmed:true}`；群会话显示确认/建议卡和选择入口。确认记录 `group_lead.confirmed`，不因为统计第一名变了自动换负责人。

<a id="mention"></a>
## 点名（Mention）

`@Bot` 指定 Bot（名册里有、但不在群里的仍按已有「拉入」加入后接收），`@everyone` 只指定群里除作者外的所有 Bot，不把群外的人拉进来；短名唯一对得上在场成员时照那位处理。未知名不叫醒谁，Bot 的 `send_message` 先退回一次供纠正，之后仍未知就在群里留系统提示。路径、网址、Markdown 链接目标中的 `@` 不算点名；紧贴 ASCII 字母、数字、`_`、`-` 或路径分隔符后的不算，斜杠连接的 `@A/@B` 仍是两位，中文和标点后面的照常识别。

2 级点名决定收件人，不决定结束旧轮：已有同规划段就听进它，不同规划另开或排队。你的群点名也如此；即时停止请用 Stop/叫停。0/1 级兼容仍可把用户群消息改道，携带旧轮写过的文件、最后调用和未读收件；Bot 的点名及回看尽量听进已有段。普通 Bot↔Bot 私聊及 `send_message` 的旧叫醒/结束语义在 0–2 级仍保留；3 级已切到显式 delegate 和普通私聊发言不叫醒，见[委派](behavior.md#delegation)。

<a id="turn"></a>
## 轮次（Turn）

2 级一段执行属于工作项，活状态包括 running/waiting_approval/waiting_ask；同 Bot × 规划只有一段，不是同 Bot 在整个群永远只一段。不同规划受工作名额限制（默认两个），桌面另计（见[工作项](behavior.md#work-item)）；无关的新请求先到桌面，不并给旧事。同规划新消息的阅读在工具边界之间，改变类用户收件使同一跳后面的未执行调用推迟，问题不推迟调用，长命令要等当前调用结束，立刻打断要叫停。

纯文字回复或 `end_turn` 能结束当前段；已有收件处置记录仍记照改、回答、不采纳（附理由）、推迟或未确认。结束不代表有 approved submission；3 级结束原因/义务核对已有域函数和引擎接入，具体已接入与缺口见[委派](behavior.md#delegation)，按持球者监督仍未实现。补全失败和中断分开；已有循环每 40 跳提醒是否卡住、160 跳收起工具仍保留，不把这些当新监督器。转录按时间交错、花费按调用记账。

旧级别群里用户点名/判断下场可走改道：旧段终止、从新消息开新段，带旧文件/调用/未读收件但不回滚过去副作用；Bot 同事消息和回看听进已有段。旧私聊的分叉与单群一 Bot 一轮是兼容行为，不是 2 级同规划唯一执行之外的承诺。

<a id="plan"></a>
## 规划（Plan）

**当前 2 级路径**：一件事可跨会话推进，一个会话可有多个非休眠规划，不能用「会话当前槽位」替消息猜归属。代码保留 `tasks`/`task_id` 历史名字；用户请求先按[归属](behavior.md#attribution)落到已有规划，拿不准开[桌面段](behavior.md#desk-segment)，引用原话或第一次获准的副作用才新开。另开规划不把还在做的旧规划搁置；本次没有「全部任务已通过 → 规划已交付/已验收」的新提交状态机，旧的 active/done/parked 与任务状态仍并存，done 导入成 delivered 也不代表已经有批准过的 submission。

休眠与叫停分开：休眠不改阶段、不解除叫停，不进默认候选、不自动叫回。清空主会话使之前的规划休眠；新开规划时，旧事只有同时两小时没用户活动、没近两小时执行、没有非 idle 的未关工作项、没有登记的 pending 作业才休眠；delivered 满 72 小时且无用户活动也会老化休眠。旧 done 规划迁移时超过 24 小时没用户原话的导入为 delivered + 休眠。这里对 pending 作业的检查只是兼容已存在表的条件，不宣称 P4d 轮询器已上线。明确引用、用户改归或继续能重新激活，但仍受叫停限制。

**以下为 0/1 级迁移兼容及已有规划显示的说明，不是 2 级消息归属算法；其中的单一当前槽位、消息先整理和换事搁置规则不适用于 2 级：**

一个会话里正在推进的一件事，由应用自己整理出来，不用你先定义。代码里沿用 `tasks` 表和 `task_id`（历史名，注释里叫 plan）。它有**要点**：类别、目标（现在到底要做什么）、验收（怎么算完成）、规则（你定过的口径、约束、改善意见）、流程与分工、进展（已完成 / 待做 / 卡住）、状态（进行中 / 已完成 / 搁置）；另记着开它的那条要求的原文（最初的要求）。要点由整理跳在你每条消息之后、以及规划静下来之后更新（静下来之后那次只记交接，见[整理跳](#organizer)），只是验收和规则只有你在流程图里写：整理跳不再写这两样，你的话里的要求记在[需求台账](#requirements-ledger)。每改一版留痕（哪条消息或哪一轮引起的，或是你改的），你也能在流程图里直接改。一个会话同时只有一个当前规划：整理跳判成换了一件事就新开一个、原来的搁置，判成回到以前那件就把它接回来，判成做完或搁置就空出来；没有时钟会替你切事。你叫停时它搁置，之后只有你说继续（或在流程图里改）才回到进行中。到了叫停这一级，是那条叫停扣着它（见叫停），只是催着停的话（「你没停」「还在进行」）由应用照实况回答，不经过整理跳（混着别的要求的照常归档），整理跳也不再按自己的理解搁置规划；这一级之前靠整理跳：催着停的话不会被当成继续，规划静下来后的整理也不会把它改回进行中。回看、批注叫醒的一轮在里面干活也不会：开一轮从不改规划的状态。每一轮的局面里都有它的要点、你在这件事里的原话（见[原话](#user-quote)）、需求台账里对它生效的要求（见[需求台账](#requirements-ledger)）、任务清单和本轮任务，交接到别的 Bot、别的会话、回看醒来、日程到点也一样，所以原始目标和你的要求不靠转录窗里还留不留着那一句。按类别找同类先例的做法已经删掉，局面和整理跳都不再读它。流程图头部写着上次变化是多久前、变的是什么（「上次变化 3 分钟前（任务 02《粗剪》：待验收）」，取这件事最新的一版要点、任务状态、检查的运行、轮次和需求台账的变动里最新的那个），休眠的规划标着「休眠」。规划有个名字：开它的那句话的前几个字，开了就不变，应用里和局面里是同一个。一个会话里常同时有好几件事，所以 Bot 读到的每一句都说得出是哪件事的：转录和听进的话里，属于另一件事或另一个任务的那一行，在说话人后面带着 `〔规划「…」· 任务 03〕`；局面里写出这件事的名字，在别的会话开的写明开在哪，此刻别的会话里也在做它的轮、这个 Bot 手上别的活轮都列出来，「经过」里在别的会话做的那一步标明在哪。第一轮在局面里标出来，是唯一还能先对齐要求再动手的那一轮。会话被清空历史或删除时，它的规划不再关掉，而是休眠：照样写上关闭时间，不认识休眠的旧版本读到的仍是关闭。休眠的规划没人去动：不再整理（已经发出去的那次整理回来也不落），也不叫回谁；清空或删除时，它排着的整理和到点再看一眼的那次当场取消，不会在清空了的会话里冒出来。它在这几种时候醒来：被放回它那个会话的当前位置（整理跳判成你的话回到了这件事、解除扣着它的叫停，或者旧版本把它接回来）；你的一句话或你对提问的回答归到它下面，不管是在哪个会话说的（这时它仍是关着的，除非这次归档也把它放回了当前位置）；你在流程图上改了它的要点或任务，改哪一处都算（只动检查不算）。Bot 在里面干活（回看、叫回、点名进来的轮）只挪关闭时间，不叫醒它。删除会话时，没人引用的规划照旧连同任务删掉；其余的规划休眠、关上，从此不属于任何会话，被那个群的叫停扣着的另有一条挂在它自己身上的叫停，流程图上改它能叫醒，但再也回不到哪个会话的当前位置。日程的常驻规划只关闭、不休眠，日程照常往里加任务。清空时，规划只要还有你没抹掉的原话、或者有挂在它或它的任务上的需求，就留着；两样都没有、转录里也没有别的轮和消息属于它，才像以前一样连同任务删掉。

<a id="ticket"></a>
## 任务（Ticket）

**2 级工作身份**：任务只缩小工作项在规划里的范围。`work_on` 可显式选任务或为新事建产出任务，应用校验它属于所选规划；不再用唤醒方的任务或「这个 Bot 恰好只有一个没收口任务」决定执行目录。Bot 发的消息用它自己的工作项归属。一件事不同任务仍受 I1b 约束。现有待做/进行中/待验收/已完成/搁置仍可由已有界面、观察推进和 settle 使用；「待验收」不是 P4e 的 submitted/approved，文件名补出分件也不等于分件审查通过。

**以下任务字段、产物和观察推进仍有保留；整理跳创建任务和按 worker 继承的部分只描述旧兼容路径：**

规划下一个有交付物的最小单位：序号、标题、说明与验收（要交出什么、怎么算完成；不写进展，也不写 Bot 给自己定的禁令）、状态（待做 / 进行中 / 待验收 / 已完成 / 搁置）、谁在做（整理跳开任务时按「流程与分工」先填，之后按观察到的更新；是记录，不是派工）、产物。整理跳和你改任务：整理跳按 id 引用已有任务、只写变了的字段（没写标题、状态或谁在做，就是不变），新任务用 new-N 开，不能删，只能改成已完成或搁置；你在流程图里改状态。应用自己也按看到的往前推一格，不调模型：归到这个任务的轮开始写文件、跑命令，待做变进行中；它交出了文件，变待验收；没人在做就记上这个 Bot。只往前，不会替谁标已完成或搁置。整理跳要等规划静下来才整理，这一步让流程图在几个 Bot 首尾相接地干活时也照实显示谁在做什么。每个任务在规划目录下有自己的文件夹 `NN-<标题>/`，被归到这个任务的轮次默认就在里面干活，没归到任务的轮次落规划目录。一个 Bot 被交接叫醒时，交来的任务是别人的、而它在这个规划里恰好只做一个没收口的任务，这一轮就落在它自己那个任务上，而不是跟着叫醒它的那一轮落在别人的任务里；交来的任务是它的、或者还没人做，就照交来的。产物按任务归属：消息带着 `ticket_id`，它引用的文件就是这个任务的产物，不搬文件。流程图旁边列出任务清单，点一条点亮它的卡片。

<a id="user-quote"></a>
## 原话（User quote）

**P4b 补充**：2 级消息的原话跟随全部归属，不仅是主目标（见[归属](behavior.md#attribution)）；`user_quote_filings` 把同一份原文关联到几件事，清空转录不丢副目标。下面关于「被轮次或整理跳归档」的说法只适用于旧路径；2 级归属来自确定性信号和桌面选择。台账条目的数值替代仍遵守 ADR 0042：只提议，用户确认才替换，不采用设计草稿里的自动数值覆盖。

你说过的话，按收到时的原样另存一份，和转录分开。存的是：你发的每句话（文件投递那个会话除外，那里没有 Bot）；你对 Bot 提问的回答（选中的选项和你自己写的话）；一批批注发出时你另外写的那句（只点了名、没写别的就没有）和每条批注本身；你在流程图上亲手写的内容——目标和任务说明里你改动的那几小句（留着没动的不算，那可能是整理跳写的）、新加的每条验收和规则（只拖动状态不算）。每条都在写下它的同一步落库：那句话没发出去，它也不存。一条最多 2000 码点，更长的留下开头和结尾，中间标出省了多少。它归在所属的规划和任务下：你的话落地之后才被归档（被它开出的那一轮，或被整理跳），原话跟着归档走，之后改归到别处也跟着改，旧版本写的归档也一样；批注归在它批的那次交付所在的规划和任务下；提问的回答归在提问的那件事下；流程图上写的归在那个规划（或任务）下，不属于哪个会话。

清空会话历史时，转录和轮次照删，原话都留着，只把指向那条消息的 id 置空；删除群时连「在哪个会话说的」也置空。两者都可以要求一并抹掉（清空历史或删除群的确认框里勾上「同时抹掉在这里说过的话」，不勾就不抹；请求里是 `erase_quotes`，本机和远端接口都认）：这个会话里说过的原话正文清空、标成已抹掉，行还在，站在这些话上的需求清掉文字、改成不再适用；流程图上写的不在任何会话里，不受影响。这个会话的规划怎么样见[规划](#plan)。

升级到这一版后第一次打开数据库时，转录里还在的你的话、回答和发出的批注各补存一次，归档照转录里的；之前清空掉的已经没了。之后每条随写随存，不再补；这期间共用数据目录的旧版本写下的话不会补进来。

一轮只要是在一件事里干活——群里、私聊里、Bot↔Bot 私聊里、回看醒来、日程到点，都一样——局面里就固定有一段「用户在这件事里的话」：归在这件事下、没抹掉的原话里最早 4 句和最新 6 句，原文照录（一句最多 400 码点，超出的截断加「…」），每句写明什么时候（本机时间，月-日 时:分）、在哪说的（群名、谁和谁的私聊、回答提问、批注，或在流程图写），中间省掉的写「中间还有 N 条」，不到 10 句就全列。它读的是原话，不是转录，所以会话清空了、Bot↔Bot 私聊里一句你的话都没有、离开转录窗四十句开外，Bot 读到的都一样。这件事的第一轮不列：那一轮的触发就是这句要求。被叫停扣着的一轮只读到叫停那一刻为止的：叫停之后你说的话、由它们记下的要求，解除以后才进它的局面，免得一轮不能动手的轮先读到一条新吩咐。

<a id="requirements-ledger"></a>
## 需求台账（Requirements ledger）

你对一件事提过的要求，一条一条记着，和规划的要点分开。每条都站在你的原话上：引文是原话里的一段（最多 300 码点），旁边是转述、类别、正反（要这样 / 不能这样）、作用于哪里——一个任务、这件事，或者这件事所在的会话（那个会话里以后的每件事都适用）——和你说过几次、每次是哪句原话。你给的数（时长、分辨率、画幅、帧率，连同「约」「以上」「以内」）由应用按固定规则从引文里读出来记在条目上，引文里只读得出一个数时才记。说的是画面里的某一刻、某一段或某个位置（「第 3 秒」「12 秒处」「前 3 秒」「logo 放在 3 秒」「字幕定在 5 秒」）、一个范围（「3-5 分钟」「一两分钟」）、多久内回复或做完（「5 分钟内回复我」「限你 3 分钟弄完」「给你 10 分钟」）、别的事要花多久（「等 5 分钟」「渲染要 20 分钟」「3 分钟前」「半小时左右能好吗」「预计 30 分钟出片」）、字数（「2k 字」）或你说不要的（「不要 4K」「不是 3 分钟」）的，不算数；数前面紧挨着「剪成」「改成」「控制在」这类词的，后面跟着什么都算（「剪成 90 秒发给我」是 90 秒），「压在 90 秒以内」「时长定在 90 秒」也算。比例要这句话里有「画幅」「比例」「屏」这类词才读，跟在「比分」后面的不读（「比分 2:1」）；单说「24 帧」是帧数，帧率要写成「帧率 N」「N fps」或「每秒 N 帧」；「90s 港风」「80s 复古」是年代。「不要超过 3 分钟」「不能少于 2 分钟」「至少要 2 分钟」按最多、最少读，「能不能改成 90 秒」「要不要 4K」是在问，不是说不要；没说比例时，竖屏、横屏也算画幅（横幅、竖幅常是标语，不算）；单写的「分」「m」只在紧跟着秒数（「1分30秒」「2m30s」）或跟在片长、时长后面时算分钟。

条目的状态有生效、待确认、被取代、不再适用、不是要求、旧规则（出处未核实）。只增不删：条目只会被新增、被再提一次。离开生效只有一条路：你自己操作。你更晚的一句话给同一个数换了新值（先说「约 2 分钟」，后来说「改成 3 分钟」）也一样：书记员只能提一条待确认的替代，指回旧的，旧条目照样生效，等你确认；模型给出的其他改动同样只生成待确认的替代。数据库守着两条：条目的引文必须是它出处那句原话里的一段（同样折叠后比），谁写的都一样，对不上或那句原话已被抹掉就写不进去；替代要站在比旧条目更晚的原话上才能把旧条目改成被取代（留给以后你确认替代的那条路）。删除只有你的彻底删除一种。

眼下写进来的有两种：书记员从你的话里记的（见[书记员](#scribe)），和兜底捕获。兜底捕获：书记员对一句话什么都没记下（没配模型、调用失败、答不成补丁、说没有要求，或者给的每一条都没通过核对），而这句话是在这件事交过东西之后说的（归在它下面的 Bot 的话带过文件，或者你说这句话时有任务在待验收、已完成；这句话的归档或它叫醒的轮随后把任务打回进行中，也照样算），又带着质量或否定的词（太假、不对、跳跃、穿帮、反了、太短、重做、不行、有问题、错乱……），应用就把这句原话整句（截到 300 码点）记成一条待确认的条目，归在这句话的任务下（没有就归这件事），不当门禁。

你在流程图上改规则或验收，就是在改台账：新加的一行记成这件事的一条生效条目，站在流程图替它存下的那句原话上（同样的话已经是对这件事整体生效的条目——这件事自己的、会话的或常设的；只管一个任务的不算——就算你又说了一次，已有的待确认条目或旧规则就当你确认了它，你设成不适用这件事的就又适用）；删掉的一行，对这件事生效、同样的话的条目都放下，不管最初是哪件事记下的：这件事自己的就不再适用，只是出处未核实的旧规则就记成不是要求；作用于整个会话或常设的，别的事还拿着这句话时（它的流程图上有这一行、你在那件事里说过它、它最初就是那件事记下的，或者是你自己点了「对这个会话都适用」「升为常设」；设成不适用的那件事不算），只对这件事「不适用」，别的事照旧（导入时同一个会话里几件事共用的那一条、你这一行只是又说了一次的会话条目，都是这样）；没有别的事拿着它，你删掉的就是它的最后一处，它和这件事自己的一样不再适用或记成不是要求，同一个会话里之后的事不会再继承它，也不会再问你它是不是你说的。每一步（新加、再说一次、确认、恢复、不再适用、不是要求、不适用这件事）都在工作记录里写明是你改的哪一版。之后你在话里改它（「机械臂改成右手」），和别的条目一样记成一条待确认的替代：流程图上写的条目没有类别，书记员给的改动对不对得上类别看不出来，就不丢。

作用于哪里：书记员点了某个任务的落到那个任务；说以后每件事都这样的落到这件事所在的会话；在视频的事里（交过视频文件、或调过视频工具），讲怎么做的工艺类要求（背景连贯、过门要有过渡、禁止多手与解剖异化、不用冻帧补时长、画风统一、色调一致）、片子看起来听起来怎样的取舍（色调、光影、打光、运镜、字幕样式、配音、音色、画风：「色调偏冷」「配音用男声」）以及同一系列不变的设定（左手、人设），也落到这件事所在的会话——只要它没点名某一镜、某一段（「C09 脚穿地」「前三镜背景跳跃」留在原处）——其余落到这件事；不是视频的事里，这些都留在这件事（报告里的「段落之间要有过渡」只管这一份）。只说「一致」「统一」「风格」「节奏」「字体」「画质」的不算工艺（「这次数据要和上个月一致」只管这一件），要连着说是什么一致才算（「画风统一」「色调一致」）；取舍也是这样，「色调偏冷」是这一部片子（或这个系列）的取舍，不是工艺。落到会话的条目，这个会话里新开的事从第一轮就适用，写明「继承自」哪件事；某一条不适合这件事，在它的流程图上点「不适用这件事」，只对这件事去掉，别的事照旧，点「恢复」再回来。设成不适用这件事的条目，你在这件事里又说了它的原话，书记员把它算成你又说了一次，它就又适用这件事，不另记一条。这件事自己的条目可以点「对这个会话都适用」扩大出去。同一类工艺要求（按书记员给的类别）你在同一个会话的两件以上视频的事里都提过（看你说它的话归在几件事下，只数这个会话里、做成了视频的事），应用在你说这句话的会话里出一张卡片「「背景连贯」这类要求你在 2 件事里都提过：「背景要连贯」。要不要以后每个视频都照这条？」，写出要升的条目的原话，附「升为常设」「不用」，每类只问一次；只算作用于这个会话或它的某件事的条目，某个任务的、别的会话的都不算，时长这类数、取舍（EP01 色调偏冷、EP02 色调要暖）、同一系列的设定（左手只是这个系列的）也不问。这一类的条目原话不一样时（说的可能是两回事，类别只是书记员贴的标签，按一下就会把它们一起升上去），不按类问，改成一条一条问：你刚又说了的那一条，它自己就在两件以上视频的事里说过，卡片只问它（「「背景要连贯」你在 2 件事里都说过。要不要以后每个视频都照这条？」），每条只问一次。「升为常设」只把此刻还符合这些条件的条目升上去；升为常设的条目对每一件视频的事都适用（没交过视频的事还读不到它）。

升级到这一版后第一次打开数据库时，每个规划要点里已有的规则和验收一次导入台账：你在流程图上亲手写的照样生效（有流程图存下的原话就站在上面）；在这件事你的原话里找得到的（同样折叠后比）生效，站在那句原话上；其余的——多半是整理跳写的——记成「旧规则（出处未核实）」，只作参考、不当门禁。视频的事里的工艺类、取舍和同一系列不变的设定导入到那个会话，其余（包括不是视频的事里的这些）留在原规划；同一个会话里几件事都有同一条的，只记一条（一件事里的一行和它继承的会话条目是同样的话，也算那一条）。之后不再导入。这件事第一次有你的话归进来时，它身上还有没问过的旧规则，应用就出一张卡片「这件事有 N 条台账之前的旧规则，没找到你说过它们的原话：……这些是你说的吗？」，附「都是」（全部改成生效）「逐条看」（打开流程图，每条有自己的按钮），每条只问一次。

Bot 在哪读到它：每一轮的局面里都有「用户要求」一段，列这件事适用的生效条目（设成不适用这件事的不列）：先按适用范围由近到远（这一轮的任务、这件事、别的任务、会话、常设），再按你说过的次数、最近说的时间排；说过两次以上的全部列出，其余最多 20 行、2000 码点，超出的写「还有 N 条」。每行是「R-31｜「前三镜背景严重跳跃」（转述：前三镜背景要连贯）｜用户已说 7 次（跨 3 个规划）｜适用：任务 01 Shot 01–03｜挂检查：时长 108–132 秒（待用户确认）」：编号、你的原话、转述、说过几次和在几件事里说过（一次的不写）、适用到哪（继承的写明继承自哪件事）、同一个数上按你的话加的检查（生效或待确认）。待你确认的替代和投诉原话单独一段「待用户确认的取代或建议（还没生效，不要当要求执行）」，出处未核实的旧规则单独一段「旧规则（出处未核实，只作参考）」，各最多 10 行。

流程图上「要点」里有一块「你的要求」，列同一张单子：这件事自己的、按来源的规划分组的继承条目、待你确认的、旧规则（出处未核实）、不适用这件事的。每条有编号、你的原话、转述、出处（你说的、你的回答、你的批注、你在流程图写的、旧规则、整句记下的投诉原话；还在转录里的点一下跳回那句话）、说过几次、适用到哪，和它此刻能按的按钮：待确认的和旧规则「确认」「不是要求」，继承来的「不适用这件事」，设成不适用的「恢复」，这件事自己的「不再适用」（在流程图规则、验收里写的那几行不给这个按钮，删掉那一行就是）和「对这个会话都适用」。本机接口是 `POST /v1/requirements/:id/action`，远端白名单里也有；已经变了状态的条目再按回 409。

清空会话不动台账，删群时作用于那个会话的条目只是不再记着会话；抹掉原话时，站在它上面的条目清掉文字、改成不再适用（见[原话](#user-quote)）。

<a id="scribe"></a>
## 书记员（Scribe）

你的一句话归到一件事之后（它开的轮都开了、要判断的都判完了），或者你回答了 Bot 的提问，应用在后台调一次默认端点的默认模型：无工具，答案最多 800 token，60 秒。它读的是你这句话（回答时连同那个问题）、在哪个会话说的、这件事的目标和任务清单、这件事已有的生效条目（这件事的、它的任务的、它所在会话的和常设的，最多 60 条，每条带编号和类别），给台账提一份补丁：新增哪些、哪些是你再说一次、哪些被你改了。没有删除，也不交整份列表，没提到的条目原样留着。它不挡任何一轮：你的话照常叫醒 Bot、开轮，它在旁边记；一句一句按顺序来，退出或更新时还没记的就不记了。它从不读 Bot 的话。问进度的话由应用自己回答，不经过它；引擎级别到了叫停这一级后，只是叫停或继续的话也不经过它，在这一级之前它们照常整理，也照常送到它这里。

补丁逐条核对：每一条的引文都要在你这句话里找得到（两边去掉空白、标点和符号，全半角折叠后比），记下的是你原话里的那一段；新增和待确认的替代至少要有 4 个字（同样折叠后数；整句不到 4 个字就要整句），一个字、两个字的引文说明不了要求，条目就只剩转述了，只说一个时长、分辨率、画幅或帧率的引文例外（「90 秒」「4K」「16:9」，长句里的「片长 2 分钟」也照收）；再提和改动只能指它看过、此刻仍生效的条目；新增的落到它点的那个任务（只点了一个时；这句话本来归在某个任务下、它没点也算），说以后每件事都这样的落到会话（视频的事里工艺类、取舍和系列设定也是，见[需求台账](#requirements-ledger)），其余落到这件事；同样的话已经是这里的一条生效条目，而且它管的不比新的窄，就算再提一次（你设成不适用这件事的也是，它随之又适用这件事）：某个任务的条目只对同一个任务的新增算，对整件事或整个会话的新增另记一条，不然那句话只挂在一个任务上，下一件事什么也继承不到；一句话最多新增 8 条。改动一律只记成待确认的替代，旧条目照样生效：给旧条目的那一项换了新数的（「改成 3 分钟」对「约 2 分钟」），不看类别；给回旧条目同一个数（「还是约 2 分钟吧」）只算再提一次；其余的，类别和旧条目相同才记，不同的整条丢掉；旧条目没有类别的（你在流程图上写的、导入的旧规则）看不出不同，照记。没通过的每一条都丢掉并在工作记录里写明原因，同一份补丁里的其他条照收。所以不管模型答什么，生效的条目一条也不会少。

没配默认模型、调用失败、答案截断或读不成补丁、说没有要求、或者一条都没落地时，这句话只走兜底捕获。每一次的原始答案都原样记进工作记录。花费记成「整理」这一类、用途是书记员，在花费视图里单列一行「书记员」（归「其他」），归这句话所在的会话，不归哪个 Bot。

<a id="organizer"></a>
## 整理跳（Organizer）

**版本边界**：`engine_level >= 2` 不调用 `organizeMessage`，也不靠 `resolveTurnTask` 的继承/兜底新建或 `ownOpenTicket` 决定新段归属。消息的确定性信号或 Bot 的桌面选择替代了这次开轮前猜测；没有信号不悄悄 openTask。级别 0/1 仍走这些旧路径，相关函数、消息模式提示词和运行记录没有物理删除。静下来 30 秒后的 settle 仍只记交接，P4c/P4e 替代其推进和交付判断之前不宣称整理员全部退场；规则和验收仍由原话/台账与用户确认守住（ADR 0042）。

**以下是仍保留的旧消息路径及 settle 细节；开轮前 message 模式仅适用于 0/1 级：**

替会话整理规划和任务的一次无工具短调用，跑在默认端点的默认模型上。两个时机：你的消息进会话之后、开轮之前，判这条消息是接着当前规划（continue）、换了一件事（new）、回到以前那件（resume），还是在说在场 Bot 正在别的会话推进的那件事（join：比如你在私聊里跟它说它在群里做的那件事；那件事开在别的会话时留在那里，这个会话的当前规划不变），更新要点和任务，并标出这条消息说的是哪个任务——消息盖上规划和任务后，它开的每一轮（点名、判断下场、分叉）都落在同一处；规划的活轮全部结束、静下来 30 秒之后再整理一次（你 Stop 掉的那一轮不引起这次整理：Stop 是要它停下，整理之后的叫回会让它接着做；同一个规划里前一轮结束后已经排着、还没开始的整理，和规划停下后等着到点再看一眼的那次，也随这次 Stop 取消，已经在跑的整理跑完也不再叫回谁，别的规划不受影响），把这几轮交出的东西归到任务上、更新任务状态、谁在做和进展。它看的是当前规划的要点和任务（每个任务附上落在它目录里、被引用过的文件）、上一版之后发生的事（谁说了什么、交出了什么、经过，以及这些轮真正跑过的命令和退出码）、这个会话之前推进过的规划、在场 Bot 正在别处推进的事（完整要点、任务、开在哪、谁在哪做、这个会话之前归到它的几句）和已有的类别标签；按类别找的同类先例已经删掉，它不再读。它还看这件事里你说过的每一句：上一版之后那些之外更早的话和你对提问的回答（同一句只算一次；太多时留最早几句和最近的，总长有上限），以及目标和任务说明是不是你在流程图里亲手写的（这些也算你的话，清理时不动）。每一行都标着是你说的、Bot 说的还是应用的提示，提问的回答算你的话。它不写验收和规则：提示词不要这两样，答案里写了也不落，新开的规划这两样是空的，已有的规划保持原样，也就是你在流程图上写的和之前的整理留下的；你的话里的要求由书记员记进需求台账（见[书记员](#scribe)）。Bot 说的决定不写进目标和任务说明，分三种放：它给自己定的暂停、冻结、不再重试、只做一部分，写进流程与分工并写明是谁定的，因此停着的写进卡住、写明等什么能解开；要你给东西（授权、密钥、确认花钱）才能往下做的，写进卡住、写明要你做什么；做法上的约束（不覆盖原文件、交付放哪个目录）写进流程与分工。你说继续推进、不要停下来，Bot 自己定的暂停和冻结不管写在流程与分工、进展还是任务说明里都撤掉，因此停着的挪回待做，但等你给东西的那种要你给了才撤，做法上的约束也不撤。只在你发消息那一次、看得到你说过的全部话时，它才把被 Bot 收窄的目标按你的话放回去。进展里的待做只写还没做的事，已经交出、只等你看的不算。任务说明写要交出什么，不写进展。规划静下来之后那次整理只记交接：交出了什么、任务到了哪一步、谁在做、进展和做法、做完没有，以及它提的检查；目标、类别和已有任务的标题、说明原样不动（空的说明可以补上），也不把规划搁置，答案里改了应用也退回，每退回一项写一行日志。这不看上一版之后你说没说过话：你的话在说的那一刻已经归档，要求也交给了书记员，静下来的这一次没有新依据。这次整理的调用期间规划被改过（你的话被归进来，或你自己改了），这次什么都不落。Bot 说「已完成」「测试通过」不算依据：标待验收要有这个任务交出的文件，标已完成还要有跑过的记录。几个人各做一块、合起来才能用时，另开一个「联调并给出启动方式」的任务。它判规划做完时还有待做或进行中的任务，规划就不算做完：这次的其它改动照收，规划仍是进行中（你在流程图里手动标完不受这个限制）。失败即不改：没配默认模型、端点拒绝、答得不成形、库拒绝这次改动，规划照旧，轮照开。判成回到以前那件或在说别处那件事，而读到答案时那件事已经不在可选的里面（比如它在别处的那一轮在这次调用期间结束了），也什么都不落，这条消息照原样留着：答案是照那件事写的，落到当前规划上会盖掉当前规划的要点，会话没有当前规划时照着它另开一个，就是一份没人要的副本。点的那件就是这个会话的当前规划时例外：那只是换了个说法的 continue，照 continue 落下。整理的这几秒里没有轮，但这条消息要叫醒的 Bot（私聊那一位；群里点到的，没点名就是在场的每一位）已经在它下面显示思考中，列表、顶栏里也是；整理完各自交给自己的轮或判断，中间不断档。花费单列一类「整理」，归决策路由，不归任何 Bot。

<a id="work-dir"></a>
## 工作目录（Work dir）

**2 级归属**：目录来自当前工作项的规划/任务，不继承唤醒方的任务，也不由整理跳盖章；未选归属的桌面不能有副作用。目录最多一次变化和继续的保护见[桌面段](behavior.md#desk-segment)。以下目录命名、保留文件和预览仍成立；「谁继承」、单一当前规划及先整理部分只描述 0/1 级旧路径。本次不把工作目录当沙箱，也不宣称已实施设计里所有跨任务写入限制。

一个规划的文件夹，在工作区的 `work/` 下，名字是目标（或开头那条要求）的前 12 码点 + 一小段 id，没有日期，也不带 `@`（换成 `-`，引用里面的文件时才不会被读成点名；旧的带日期或带 `@` 的目录不动）；它下面每个任务有自己的 `NN-<标题>/`，标题里的 `@` 同样换掉。一轮的工作目录是它所在的任务目录，没归到任务就是规划目录；壳默认在里面跑，文件工具的路径仍相对工作区根。谁继承：交接、点名、判断下场、Bot↔Bot 私聊、中断续跑和回看都用唤醒方那一轮的规划和任务，所以一件事跨 Bot、跨会话仍是同一处；你的消息由整理跳盖上规划和任务，它开的轮都落在那里。不按时钟切目录：一个会话的当前规划一直开着，直到整理跳判成换事、回到旧事、做完或搁置。日程有自己的常驻规划，每次到点新开一个任务。第一次真被用到才创建，只说话的轮次不留空壳。交付物不进来：你点名了路径就写在那儿，没点名的落本轮任务目录。两层都有保留子目录：`tool-results/` 是守护进程存的大工具结果（关闭够久后自动清掉），`scratch/` 是纯过程文件——都不会挂成产物；`map.md` 和 `ticket.md` 是应用的镜像文件，同样不算产物。删掉工作目录是你的事，应用只清 `tool-results/`。这件事在应用里按叫醒关系从上到下看经过，卡片上标着它干的是哪个任务，产物挂在交出它的那一轮上，点开走预览。

<a id="closing-check"></a>
## 收尾自检（Closing check）

**P4c 检查点**：下面旧的正则/执行记录自检仍被调用，3 级新增结束义务契约不等于已经删掉「随后」或交付前检查；`claimsVerification` 的保留和协作私聊覆盖需在最终接替时核对。本轮不声称 Bot↔Bot 私聊已受到同一整套收尾验证，也不把这个提醒算真正 implicit submission。当前结束事实与缺口见[委派](behavior.md#delegation)。

一轮要把交付物交给你之前的一次核对。时机不变：Bot 准备发出的消息引用了工作区文件，或者说自己「正在做」「结论随后」这类还没做完的事，目标会话里有你，这一轮属于一件事。从 2026-09-29 起（ADR 0037）它不再调模型，而是看三条确定的规则，任何一条不满足就把一段应用提示退回给 Bot：一、这件事有验收检查（ADR 0036）没过——文件类检查当场重新判一次，这一轮刚改好的文件不会因为旧结果被退回，按你的话加的检查当场用 ffprobe 再量一次，你还没确认或还没对上文件的不看；命令类检查看最近一次运行，这一轮已经把同一条命令跑成功的不算；最多列三条，提醒改交付物、不改检查，做不到就在收尾里说明原因；只对真的交付（引用了文件）的回复看这一条。二、说了稍后还有下文，却既没有在这里约回看、也没有点名交给谁——这一轮一结束就没人会接着做，要么现在做完，要么约一次回看，要么点名交出去。三、说已经跑过、测过、验证过，而这一轮一条命令都没跑（写明「未验证」的不算）。走 send_message 的，那次调用不执行，结果是这段提示；直接回复的，提示作为一行进回路。一轮只核一次，第二次不再拦；退回不算工具错误，复盘不把它当失败；没有模型调用，也就不记花费。发到没有你的 Bot↔Bot 私聊不核，没引用文件、也没说还在做的回复不核。原来用默认模型拿要点逐条对照交付物的那一步删掉了：黄金路径消融里关掉它不掉完成率、省下约四分之一的花费和时间，机器能判的验收交给验收检查去跑。
<a id="acceptance-check"></a>
## 验收检查（Acceptance check）

规划的要点里，验收是一句句你能检查的结果；验收检查是把其中能机器判定的那几条交给守护进程自己跑，不靠 Bot 自称、也不靠模型读 Bot 的收尾。四种：文件存在（且不是空的）、文件包含某段文字（可以反过来要求不包含）、文件匹配某个正则（同样可以反过来）、一条命令（期望的退出码，默认 0，可选期望的输出，比较前去掉行尾空白和末尾空行）。文件路径和命令没写目录时都相对工作区根，和文件树看到的一样；工作区外的路径和越界的命令写不进来，跑的时候再判一次，判到区外就记「越界」、不跑，从不替你批准。命令在自己的进程组里用 `/bin/sh` 跑，结束或超时（默认 120 秒，最长 600 秒）时整组杀掉，环境只带终端那份白名单（不带 `SSH_AUTH_SOCK`，也不带守护进程自己的变量）。每次运行记下结果（通过、没过、越界、出错）、一行说明（按应用的语言写）和输出的末尾一段；一条检查最多留最近 5 次。什么时候跑：规划静下来时先跑过期的（定义后还没跑过，或者之后这件事又有轮动过），整理跳整理完再跑它刚加的；你新建或改了一条就跑那一条；流程图上「跑检查」随时跑全部。每个规划同一时间只跑一次，命令检查整台 Mac 一次一条，一段静默最多跑 15 分钟。谁能写：你在流程图上加、改、删；改了整理跳加的那条，它就归你，整理跳不能再动；整理跳在答案里可以加、改、删它自己的（每次最多新加 3 条，一个规划最多 10 条），命令只能是这件事里某一轮在那个目录跑成功（退出码 0）过的、或你在归到这件事的消息里原话写过的，你删掉的不会再被它加回来；Bot 没有写检查的工具，只在局面块和 `map.md` 里看得到。检查挂在验收的那一句上，按文字对应：整理跳或你改写这一句时检查跟着走，这一句删掉了，检查就列在「对不上验收条目的检查」里，照跑照算。结果回到哪里：流程图每条验收后面挂着检查的结果，点开看说明、最近一次和输出；整理跳读得到每条检查的最近结果，有没过的（或定义后还没跑过的）就不能把规划标成做完，对应的任务也不能标完成，越界和出错不算依据，写进进展的卡住里；你手动把规划标完不受这个限制。规划回看开出的轮次准备发言时，应用比较这个 Bot 在同一会话、同一规划里最近 40 条回复。去掉格式后相同的回复静默结束；至少 12 个内容词的英文回复，只改冠词或「run longer / be longer」这类措辞、其余词序相同时，也算重复。数字、否定、问号、代码、链接目标、点名和文件路径保留比较；新增内容或新交出的文件照常发出。直接回复和 send_message 使用同一个判断，普通用户消息触发的回复照常发出，已有记录保留。规划静下来时，还有任务没收口或有检查没过，应用叫回一次，叫回的话里带着最多 3 条没过的检查和输出末尾，提醒修交付物而不是改检查；再叫之前要有进展（有任务交出或收口，或者有一条在上次叫回前就有的检查第一次通过），没有就发一次通知「这件事停下了」，会话里不留这条回顾；你最近一句话之后叫回的次数不超过任务数加检查数。每一轮的局面块里列着这件事的检查和结果。

衔接一致（`continuity`）是第五种，给几个 Bot 分头做、合起来才是一件交付的活：每个 Bot 只审自己那一块，接缝上的问题谁也看不见。各部分按顺序来自三处之一：一条列出各部分的命令（一行一个，最准）；一个通配路径（全部匹配按自然顺序排，C2 在 C10 前面；只有全是视频、又没给命令时，才当成反复重剪的成片，取最新的那个）；或一份文件切开——Markdown 和纯文本按一、二级标题切，HTML 按 h1、h2 切，视频按场景检测找剪切点（画面相近的镜头之间会漏判，实测 11 个交界只找到 6 个）。每条接缝取两边的证据：视频取前一镜尾帧和后一镜首帧、图片直接用两张图，并排拼成一张图存在规划目录的 `checks/<检查>/`（保留目录，不算产物），要能看图的模型；文字取前一部分末尾和后一部分开头各约 700 字，不需要看图。文字另有一次整体检查：每部分的标题、开头和里面带单位的数字、专有名词合成一份摘要，看同一个对象在所有部分里是不是同一种说法和口径。判的是默认端点的默认模型，提示里写着这条验收、规划的规则和一张通用清单：与规则一致；前后接得上（缺的过渡要点名）；同一对象前后一致（人物、产品和专有名词、术语、数字与单位、方位与方向）；风格一致（画面看画风、渲染、配色、角色设定，文字看语气、格式、编号）；重复或遗漏（看不出来就不要判）。图片和视频的接缝两侧几乎一样是好事，说明接得严丝合缝。它只答 JSON，读不出来重问一次。每条接缝和整体都没问题才算通过；不通过时说明写「N 处衔接里 K 处有问题：02-市场分析→03-渠道对比：……」，输出逐条列出（有对照图的带上路径），最后一行是整体结果。看图或读文字的调用记成花费里单独的一类「验收检查」。代码之间的衔接不用它，用一条联调或启动命令的检查。整理跳也可以提出这种检查，但各部分必须是这件事交出过的文件，或者清单命令这件事里真跑成功过。

应用还会按你说的数自己提议一种（你确认了才算数）：量视频的时长、分辨率、画幅或帧率，见[按你的话加的检查](#check-from-your-words)。

<a id="check-from-your-words"></a>
## 按你的话加的检查（Check from your words）

你对一件事说了时长、分辨率、画幅或帧率，应用就照你的话提议一条验收检查，量这件事最终交出的视频。你的话一归到这件事（它开的轮都开了），或者你回答了提问、在流程图上改了目标、验收、规则或任务说明，应用就按需求台账那套固定规则（见[需求台账](#requirements-ledger)）从这件事的原话里读数：不调模型，也不等书记员。流程图上改的只算你改动的那几小句（「剪一支约 60 秒的宣传片」后面加上「，加字幕」只算「加字幕」），整理跳写的、你只是留着没动的字不算你的话。读得很窄：读错只是多一张卡片，漏读只是少一张。时长要带着范围词（「约」「左右」「以上」「以内」「至少」「不超过」「最多」），或者数前面紧挨着「剪成」「做成」「改成」「控制在」这类词，或者同一小句里先说了「片长」「时长」；分辨率、画幅比例、竖屏横屏本身就算，比例还要这句话里有「画幅」「比例」「屏」这类词（「比分 2:1」不算），帧率要带「帧率」「fps」或「每秒 N 帧」（单说「24 帧」是帧数，「淡出 24 帧」不算）；「最长」「上限」「顶多」「别超」按不超过读，「最低」「最短」「下限」「打底」「起步」按至少读；「预算 2k」「报价 4k」「码率 8k」不是分辨率。一句话在问（带「吗」、问号、「能不能」「要不要」「怎么样」「你觉得」「试试」）、在假设（「如果」「会不会」「的话」）、在抱怨（质量或否定的词，含「短了」「有点短」「偏长」）、在说一版已经做出来的样子或中间版（「上一版」「这版」「这次」「第一版」「之前」「原来」「现在」「你交的」「只有」「才」「已经」「显示」「为什么」「怎么」「比要求的……」「粗剪」「完整版」，一小句只说「可以」「还行」，或数后面跟着「了」）、在说手上已有的文件（「我拍的是」「相机」「客户给的」「显示器」「ffprobe」），要另做一版（「横屏的也做一版」「竖版的也要」「抖音版 30 秒左右」「横屏版」），或者说的是一张图或界面（照片、海报、封面、壁纸、配图、动图、KV、界面），整句一个数也不读：「太长了，改成 2 分钟」「这版改成 90 秒」「能不能改成 90 秒？」都不读，要改就单独说一句（「片长改成 2 分钟」），或在流程图上确认。说的是作品的一部分的，哪一项都不读：它那一小句里点了某一镜、某一段、开头结尾、片头片尾、logo、字幕、口播、高潮、场景、空镜、每页每张（「开头控制在 5 秒以内」「logo 在 5 秒左右出现」「C09 做成竖屏」），或者前面的小句点了、它那一小句又没说「片长」「总长」「成片」这类说整部片子的词（「C09 这个镜头，时长 8 秒」；「加中英字幕，片长约 2 分钟」照读）；「这段」「那段」「采访」也算一部分；归在某个镜头任务下的话和批注也一样。说素材、参考片、配乐、歌的那一小句（「素材 20 分钟」「像苹果那支 90 秒的广告那样」），或者前面的小句说了这些、它那一小句又没说整部片子的，只读前面紧挨着「剪成」这类词的数（「把素材剪成 90 秒」）。「不要剪成 90 秒」「别压到 60 秒以下」这种前面带着不要的，不读；「帧率 24 改成 60」「分辨率从 4K 降到 1080」只读改成的那个数，改之前的、「24 或 30」这样二选一的都不读。说不要的（「不要 4K」「别做成 16:9」）、画面里的时刻和位置（「1 分钟左右切到产品」）、年代（「90s 港风」「90s 那种感觉」）、别的事要花多久（「2 小时以内搞出来」「这个任务大概 3 小时」），读数时就不读（见需求台账）。

读到的数分两种。说成目标的：同一小句里用「片长」「时长」「总长」「成片时长」「分辨率」「帧率」「画幅」「比例」这类词说它量的是成品的哪一项（「片长约 2 分钟」「画幅 9:16」「帧率 30」），或者前面紧挨着「剪成」「做成」「改成」「控制在」「压到」「砍到」（「剪成 90 秒发给我」「做成竖屏」），而且不在说素材、参考的上下文里。其余的（「约 90 秒」「不要超过 2 分钟」「1080p 就行」「要竖屏」「片子差不多 107 秒」）只在这一项还没有说成目标的数时出卡片。你的话从来不会自己变成门禁：读出来的数只出一张卡片「按你的话加检查：时长 108–132 秒？」，附「确认」「改」「不要」；卡片跟着你最后一次说成目标的数，一次都没有时跟着最后读到的数。你在另一句话里又说了同一个数（同一个数、同样的范围词；「约」和光说一个数算一样，「约 2 分钟」「2 分钟左右」「片长 120 秒」是同一个，「片长 115 秒」「片长改成 130 秒」不是；流程图上同一处改几次只算一句），卡片就再发一次，开头写「你已经说了 N 次」，免得看漏。只有你按「确认」（卡片上或流程图上），它才成为门禁。F-f 那次你两次说「片长约 2 分钟」：卡片出了两次，第二次写着「你已经说了 2 次」；107 秒的母带交了就量，结果写在流程图和 Bot 的局面里，但不拦；你按一次确认，它就拦下 107 秒的母带。「改」把「片长改成 」放进你的输入框，你说的数才是它的依据；「不要」删掉这条提议。你删掉或没选的数，还有你确认一条时之前说过的其他数，你那时说过的话都不再算（不出卡片、不计次数），之后再说才算；你最后说的正是你删掉的那个，就什么都不提，更早的数不会顶上来。生效的检查从不自己变：你后来把不一样的数说成目标，新数另出一张替换卡片（写着生效中是多少、你刚说的是多少，按钮是「用新的」「改」「留原来的」），旧的这条照样生效、照样拦，直到你选。选新的，旧的删掉；留原来的，新的那条删掉；又说回原来的数，替换卡片撤掉。没说成目标的数不出替换卡片。抱怨从不动检查：「上一版 107 秒太短了」「107 秒左右，短了」「你剪成 107 秒了，太短」都不读数。

怎么算：「约 2 分钟」「2 分钟左右」是 108–132 秒，「2 分钟以上」「不少于 2 分钟」只卡下限，「90 秒以内」「不要超过 90 秒」只卡上限，其余读到的（「改成 3 分钟」「片长 3 分钟」）也上下各放宽一成；分辨率按画面的短边算（1080p、1920×1080 都是 1080，4K 是 2160），帧率同样上下一成，画幅比例差 1% 以内算对，只说了竖屏（横屏）就是高大于宽（宽大于高）。每一项最多一条生效的，外加一条提议；一句话里同一项说了两个不一样的数，这句不算。

量的是这件事的最终成品：Bot 交出的文件（带在它归在这件事下、不是归在某个镜头任务或另一版任务（抖音版、竖版、预告……）下的话里、此刻还在的）里，文件名里有 MASTER 这个词（母带）的视频先于有 final 这个词（成片、终版）的，再其次是放在 `deliverables/` 下的视频，同一档里取最新的；只是名字先后只在同一类地方里比：放在 `deliverables/` 或这件事自己的目录（含任务目录）里的，先于放在别处的，不管名字。要整个词（`master_shot_03.mp4`、`EP01finale.mp4` 不算）；文件名里点了某一镜、另一版或格式、片头片尾、预览或代理的都不算（`C09_final.mp4`、`EP01_MASTER_9x16.mp4`、`EP01_30s_MASTER.mp4`、`EP01_douyin_MASTER.mp4`、`EP01_trailer_MASTER.mp4`、`intro_MASTER.mp4`、`logo_sting_final.mp4`、`EP01_MASTER_720p_preview.mp4`、`EP01_MASTER_proxy.mp4`、带「竖版」「片头」「镜头」的）；放在 footage/、raw/、ref/、素材/、参考/ 下的一律不算。新旧按第一次交出来的时间算，所以审片员拿上一版 `EP01_MASTER_v1.mp4` 来对比，检查也不会退回去量旧的。交了更新的就改量新的，上一个文件的结果不带过去。提议也会对上文件、当场量，结果写出来给你和 Bot 看：流程图上是「待确认 · 没过」，展开写着「未确认的检查：107.00 秒，你说的是时长约 2 分钟（待你确认）」，Bot 的局面块和 `map.md` 里也是这样一行；但它不拦任何交付、不叫回谁，整理跳照样能把规划标成做完，「检查 N/M 通过」里也不算它，这样读错了数、对错了文件，都拒收不了正常的交付（审查者要不要处理它，等交付和审查的阶段再定）。你确认之后，它当场用 ffprobe 再读一次（画面按播放时的方向算，手机竖拍、存成 1920×1080 再标了旋转 90° 的也算竖屏；读不出时长、画面大小或帧率算出错，没装 ffprobe 也算出错，都不当依据），之后和别的验收检查一样：规划静下来时跑，没过时整理跳不能把规划标成做完，应用带着它叫回做的 Bot，Bot 再把这个文件交给你时收尾自检当场再量一次。审查者放不放行，要等交付和审查（ADR 0040 P4e）才管得到。

卡片在这件事所在的会话里（你在的话）：每条提议一张，带三个按钮，你又说一次就再发一张写着次数的；你确认的检查第一次对上文件时一张，只带「删掉这条检查」（换成更新的一版只重新量，不另说，免得重剪几次就说几次）。你确认过的检查依据的那句原话被抹掉，它改回提议并出一张卡片告诉你，不会悄悄删掉；抹掉后来说的同一个数不影响它，那句话改归到别的事也不影响。提议站在的话被抹掉或改归别处，提议就去掉。按钮只能按一次，被后来的数撤掉的提议再按「确认」会被拒；卡片只给你看，不进 Bot 的转录。流程图上这些检查列在「按你的话加的检查」下面，挂在你那句话的说法（「时长约 2 分钟」）后面：提议能「确认」、能删、能重跑（对上文件之后）；生效的能删、能重跑；都不能编辑，本机接口改它会被拒（`derived_check`），确认走 `POST /v1/checks/:id/confirm`。一个规划最多 10 条检查的上限不算它们。清空或删除会话时连你说的话一起抹掉，站在那些话上的提议当场去掉，你确认过的改回提议。

检查表里它记为来源是你、种类是「文件存在」，另有几列写着它量什么、站在哪句原话上、怎么对上的文件、是提议还是生效：共用数据目录的旧版本把它当成一条检查那个文件在不在的检查，还没对上文件时是一条没写路径的检查，跑出来算出错，不拦东西。

<a id="pane"></a>
## 窗格（Pane）

桌面窗里的一块内容区。一块窗格是一组标签页；一个标签可以是一条会话（它的产物预览、流程图都跟着它；它自己的设置从这个标签里的对话右侧滑出、带一层只盖这块窗格的遮罩，不另占标签），也可以是一个终端（一个标签一条 shell 会话）、日程图、工作区或花费。窗里可以纵横任意分割出多块窗格，分隔条和交汇处都能拖；标签可以在自己的标签栏里拖动排序、在窗格之间拖、拖到边缘就地分割、按住 ⌥ 拖出来变成浮在上面的窗格。在窗格里任意位置右键，可以向上、下、左、右就地分出一块空窗格；里面本来有右键菜单的（消息、代码编辑器）和输入框仍是它们自己的，按住 ⌥ 右键是网页视图的原生菜单；浮动窗格不就地分，右键提供停靠回布局与关闭窗格。有别的窗格时，空窗格右上角可直接关闭（只剩一块平铺窗格时不显示：关掉它也只是再留一块空的，这时标签条上什么都没有，整条收起）；每块窗格的右键菜单也可关闭整块窗格及其标签，工作区和产物预览有未保存编辑时先确认。最后一块平铺窗格关闭后留下一块空窗格。**窗里分成多块窗格，那仍然是同一个窗口进程**，浮起来的也不是第二个系统窗口。同时只有一块是当前窗格——键盘在哪块就是哪块，在哪块里点一下或滚一下也换到哪块：Stop 打它那一轮，点通知先找已经开着那条会话的窗格。摆着不止一块时，当前那块四周描一圈强调色，一眼看得出是哪块；只有一块时不描。侧栏里点一条会话：只有一块窗格时，它替换这块窗格正看着的那条会话（终端、工作区这些不被顶掉，新会话在旁边开标签）；摆着不止一块时，已经开着它的那块切到前面，哪块都没开就在当前窗格里新开一个标签，不替换任何一块正看着的东西。会话设置同时只在一条会话上开着，在别处打开就把原来那处收起；日程图同时只有一块。每条会话只有一块产物预览、一块流程图：在这条会话里、它的预览文件树里或它的流程图上再打开别的文件、别的那件事，是那一块转过去，不另开一块。这两块的标签名是固定的，跟会话标题走：「<会话名>流程」「<会话名>的产物」，不跟打开的文件或这件事改。流程图标签换到后面再换回来，停在你离开时的地方：拖到哪、缩放多少、折起展开的轮、筛选和点亮的任务都照旧；在它的切换器里换一件事再换回来也一样；只有一条消息新要它去某张卡片时才会移开。会话窗格不再另画顶栏：头像（Bot 在干活、等你或出错时带状态点，空闲不带）和名字始终在标签上，顶栏的第二行成了标签的提示；鼠标移到标签上才出现 ⋯，里面是置顶、经过和设置，右键会话标签也在分割前面给出这几项。右键任何一个标签（会话标签的 ⋯ 里也有），可以关闭这个标签、同一块窗格里的其他标签、它右侧的标签或全部标签；全部关掉就和关掉最后一个标签一样，这块窗格跟着关掉，工作区和产物预览有未保存编辑时先确认。其他标签（终端、工作区、日程、花费、流程、产物）也始终在名字前带上各自的图标。窄屏（≤680px）和手机上没有窗格，仍然是一次一屏、一层层盖上去。

<a id="model"></a>
## 模型（Model）

某个端点认的一个补全名字。每个端点有自己的名单和默认，名单上的名字可带选路参考价、可选计费单价、支持的思考等级和擅长领域。选路参考价是应用挑模型时用的相对数；计费单价是 USD / 百万 token，输入和输出一起配，缓存输入可单配，留空沿用输入价。计费单价用于缺实报金额的花费估算；探测模型名单不会自动填单价。用户发消息开一轮时，应用只在 Bot 钉的端点（没钉端点就是默认端点）的名单里选模型和思考等级，不会因为设置里多了一个端点就把它的模型算进别的 Bot；Bot 钉了仍在名单上的名字则模型名受约束，钉的名字只在别的端点上时照钉的用。Bot 也可以钉思考等级（补全的 `reasoning_effort`）：档名以该模型名单为准（常见 none / low / medium / high，端点广告了还会有 xhigh、max 等）。探测 `/models` 时若对象带了思考档就自动写进该模型的 `thinking_levels`，设置里仍可手改。思考等级和模型一起钉，不单独存在：要么两个都不钉、模型和等级都由应用每条消息挑，要么钉一个模型并同时定下它的等级。钉模型时没给等级就落到该模型的默认档（应用对普通消息的偏好顺序）；换成不支持原档的模型会落到新模型的默认档；清掉模型一并清掉等级；没钉模型却给等级会被拒。你在 Bot 面板里点一下就能改，Bot 也能用工具改自己的。空钉不是「永远用端点默认模型」，而是应用可从该端点名单里挑；要用别的端点必须显式钉端点。谁来挑：每开一轮先由 agent 挑一次，它看这条消息、这个 Bot 的人设、候选名单、这个 Bot 最近的复盘结论（带当时那条消息和类别，对不上就当没看见）和最近干净做完的例子，答出模型、思考等级和一句理由；它自己固定跑在默认端点的默认模型上，答不出或答了不存在的东西就落回规则兜底，不让用户卡在选路上。用户后续说的每一句都原样留着（不按关键词筛），落在被引用的那一轮、`@` 的那个 Bot 最近的一轮，或会话里最近可见的一轮上；连着围绕同一件事的若干轮算一条纠正链。链结束时（换了话题或静默一段时间）复盘一次；没有后续发言，但这一轮是端点拒绝、回复不完整或工具错误不少于两次，也复盘一次。复盘看的是整段加上这一轮实际做了什么：这到底是模型不行、事情本身难、还是需求没说清，只有判成模型不行才留成这个 Bot 的经验，并说明该往更强 / 更轻 / 更快 / 更便宜哪个方向调。留下的是结论不是分数，没有权重、抵扣和封顶；被照做两次仍没有更干净的结论退出选路，记录还在。经验归 Bot 自己，删除 Bot 一并删掉。每轮选了什么、怎么结束、做了多少、收到哪些反馈都留有记录。用户不每轮自选。判断调用和轮次补全用同一个解析结果。

<a id="hold"></a>
## 叫停（Hold）

**P4b 续跑补充**：以下叫停范围、只有用户解除和回执约定仍有效。2 级解除后的段按 Bot × 规划唯一执行与工作名额接收：同规划听进已有段，不同规划开自己的段或排队；下文「群或 Bot↔Bot 私聊一个 Bot 同时只做一轮」仅描述 0/1 级兼容，不再把别的规划工作合进这一段。中断桌面的继续保护另见[桌面段](behavior.md#desk-segment)，本次不启用重启后自动监督续跑。

你叫的停落成的一条记录。**范围**：全部、某个 Bot（跟着它到它在的每个会话）、某个会话（连带以这个会话为主会话的规划，哪怕活在 Bot↔Bot 私聊里做——那条私聊里做的仍是这个群的事）、某件规划（连同它的任务）、某个任务、某个 Bot 在某件规划里的活、某一轮（覆盖这一轮约的回看）；另可带上建立时就定下的额外覆盖，比如这个 Bot 交出去的活所在的私聊，之后不再随着变。只有你能解除：用你的一句话，或一个按钮；别的调用方没有解除的入口，Bot 和整理跳都不行。记录从不删除：清空聊天、删群只把它指向的那句话置空，叫停本身还在；叫停点名的规划（叫停在这件规划、某个 Bot 在它里面的活、它的某个任务上，或额外覆盖里有它们，已解除的也算）清空聊天时也留着，不会让叫停指着一件已经没了的事。删群时，群上的叫停搁置着、群删后还留着的规划（别的会话里有它的轮次或消息）不再属于这个群，群上的叫停也就够不着它们，所以每件先各得一条自己的规划叫停（来源 `migration`），带着解除后怎么恢复；叫停之前就按旧办法搁置了的（状态和要点都是搁置）也一样，解除后回到进行中，和启动时接管旧搁置的做法相同；这件规划本来就有规划上的叫停的不用。

**建立时**：记下叫停的同一次写入里，它覆盖的在跑的轮都结束为 stopped；写入落库后，这一轮的补全、它的 MCP 调用（告诉服务器这次调用取消了）、它跑的命令的进程组（先让它们退出，3 秒后还在就强行结束）一起中止。每一轮做到了哪一步——写过的文件、最后几次调用——记在这条叫停上（`effect.stopped_turns`），同时记下同一件规划里它没覆盖、仍在做的别的 Bot 的轮（`working_beside`），以及结束之后它覆盖的还在跑的（`still_running`，除非出了错否则是空的）。你说的或按的叫停还连带被覆盖的 Bot 交出去、还没交回的活：由被覆盖的轮写的话开出来的别的 Bot 的轮——或者由这样的轮写的话再开出来的，往下最多三层——只要还在跑或还有待响的回看。每一个都作为额外覆盖记在那一轮上：覆盖那一轮本身、它约的回看和它的话会叫醒的人，不覆盖那个 Bot 自己的别的活；上游的一概不停。叫停放行开出的只读轮让它把回答说完。工作记录里记一条 `control.hold`。

**规划状态**：规划或会话上的叫停把它覆盖的进行中规划改成搁置，状态和要点里的状态一起改——流程图每次编辑都把要点里的状态原样送回，整理跳也在要点上改，只改一处就会被改回进行中。规划仍是会话的当前规划，只是停住了，不是被别的事挤开。已经被新规划挤下当前位置的（状态已是搁置、要点里仍是进行中）也一样把要点改成搁置，解除后回到被挤开的样子：要点里是进行中、状态仍是搁置，不当成回到进行中，免得不在当前位置的规划被叫回去干活。叫停期间整理跳或接回要它进行中，它仍是搁置，只记下解除后回到进行中；叫停期间被新开或接回的规划挤下当前位置的，解除后也回到被挤开的样子；在这个会话里新开的规划一开就是搁置；标已完成照样生效。叫停把要点改成搁置、解除时改回去，各算要点的一个版本：流程图拿着之前的版本再提交会被拒（`409 revision_conflict`），不会把刚叫的停送回去，也不会在解除后又叫一次停；这两个版本不算你写的，也不算整理，整理跳照样读叫停之前的话；修订历史里它们带 `cause: "hold"`。解除后回到原来的状态，空着的话也回到会话的当前位置；还有别的规划或会话上的叫停扣着它，就仍是搁置，由那一条记着解除后怎么恢复。Bot、任务、某一轮上的叫停不改规划状态，规划里别的 Bot 的活照常；全部上的也不改（否则要改遍每一件规划），规划详情的 `held_by` 列出覆盖整件事的叫停（规划上的、它所在会话上的、全部上的）。

**旧的改状态入口**：引擎级别到了叫停这一级之后，把规划状态改成搁置（`PATCH /v1/tasks/:id/spec`，旧客户端和手机的做法）就是在这件规划上叫停；改回进行中或标成已完成，解除这件规划上的叫停。会话或全部上的叫停还在时，改回进行中之后它仍是搁置（会话的）或状态照旧（全部的），`held_by` 说明是哪一条。算不算改状态，拿要点里的状态比：流程图显示并送回的是它，一次只改目标的编辑把它原样送回，不算叫停也不算解除；被挤开的规划状态列是搁置、要点里是进行中，按状态列比会把这样的编辑当成继续。在这一级之前，改成搁置就只是状态。

**回看**：被覆盖的待回看挂起，同时标作废，这样不认识叫停的旧版本也不会让它响；叫停期间新约的也一样挂起。解除后没有别的叫停覆盖它，就恢复待响，已经过了时间的随后补响一次。挂起期间会话被清空或删除、Bot 被删除，或者在有叫停之前约它的那一轮被 Stop，它就真作废，解除也不回来；0–2 级 Bot 在同一会话又约一次就以新的为准，旧的不再恢复；3 级只由同一精确工作项/去重键的新 timer 取代，不同工作或委派事件等待不因此丢掉。

**叫醒和工具**：叫停覆盖到的，什么都叫不醒——你的话（只开一段只读的轮，见下），别的 Bot 的话（点名它，或 Bot↔Bot 私聊里的每一句），它约的回看到点，它开的 Bot↔Bot 私聊静下来后的回报，规划静下来后的叫回，日程到点，中断后点「继续」，都不开轮；被叫停覆盖着的、正在跑的那一轮也不再听到新来的话：说的是叫停范围外的事的，在它旁边另开一轮，不打断它；你在别的会话里说、归到这件事的话也不转给它。被叫停的 Bot 自己说的话也叫不醒别人，它在 Bot↔Bot 私聊里的对方静下来时也不会把发起方叫回来，也不留到以后：解除后它在私聊里再做完一轮，私聊再静下来，就会叫回发起方。你在群里不点名说的话，被叫停的 Bot 不参与判断（不花那次判断调用）。每一次被挡下的叫醒都记进工作记录（`work_events` 里的 `wake.suppressed`），写明是什么叫醒（你的话、别的 Bot 的话、回看、规划叫回、日程、继续……）和是哪几条叫停。回看被挡下时挂起，解除后恢复；正在跑的一轮听到了、却没读就结束的话逐条看叫停：说的是被叫停的事的，每条记一次被挡下的叫醒，留在转录里等解除，其中最新的回看挂起，解除后再响；其余的照常在最新一条上再开一轮，只带上这些没被叫停的；开私聊的 Bot 被叫停时，私聊静下来后给它的回报也挂起，解除后再叫它回来；规划静下来后的叫回不留，等这件事下次有一轮结束、再静下来时再看；日程到点只记一次、不算已跑，解除后按最近一次补跑一回；「继续」返回 `409 held`，手机上也是这个错误码。被叫停覆盖着的轮次，有副作用的工具调用一律不执行，结果是 `held`：壳、写和删文件、发消息、约回看、向你提问、改人设、技能、记忆、日程、端点或 MCP 服务器、没有标只读的 MCP 工具；只读的照常（读文件、列目录、各类 `list_*`、`read_skill`、`end_turn`，以及服务器标了 `readOnlyHint` 的 MCP 工具，比如查一个视频作业）。等你批准的调用，你点允许时它已被叫停，也不执行。库本身再兜一层：turns 表上的触发器拒绝写入被叫停覆盖的活轮（不认识叫停的旧版本写的、没有 `mode` 的行一样拒绝——叫停优先于兼容），也拒绝把一轮活着的原地挪进覆盖范围、或改掉它的 `mode`。唯一放行的是你的一句话开的只读一轮（`mode = readonly`）：你对被叫停的 Bot 说话——在它的私聊里，或在群里点它的名——就在它原来的活旁边开这样一轮，不挂在任何规划上，只给它看不改东西的工具，开头一行写明你叫停了这件工作（带你的原话）、这一段只能回答。它的回复照常发出，不叫醒任何人；别的 Bot 这时点它的名，在它旁边另开一轮，不打断它。

**你的话**：你的一句话在进度询问之后先按控制句读一遍（见 CONTEXT 的控制句）。纯控制句由应用照办，不再去任何别处——不整理、不开轮、不调模型：
- 叫停：按话里的范围每个建一条叫停（来源 `user_text`，`source_message_id` 是这句话），应用在你说话的会话里回一条回执：不进 Bot 上下文的 `system` 行，带 `control: {kind: "receipt", verb: "stop", hold_ids, offer, scopes}` 供按钮用（撤销；扩大到所有 Bot；你同时说了「算了」时加「作废这件事」）。里面每一条都来自叫停的记录：停下的轮，各自的规划、会话和最后一步；挂起的回看；搁置的规划；这些规划里仍在做的别的 Bot；此刻在跑的。
- 继续：解除话里点到的叫停——对一个 Bot，是它自己的，扣住它全部的活或其中一部分的都算；对一件规划，是它上面的，以及某个 Bot 在它里面的活上的；在私聊里说，这两种还解除在这条私聊里用一句话建的其他叫停，别的 Bot 身上的除外；对群，是群上的，以及在群里用一句话建的每一条；对全部，是你建的每一条，启动时接管的不算。不越过话里的范围：在群里说「@X 继续」只解除 X 自己的，不解除群上的。被解除的叫停停下的每一轮，都在它原来的会话里带一条系统行重新开始：你的原话、它的规划和任务、写过的文件和最后几次调用；这一行只说发生了什么，不催它做什么。它是应用写给这个 Bot 的，和回看自己那一行一样只给它：只有它叫醒、或在那里被听到的那一轮读得到，流程图照样画出这一轮从被停下的那一轮接上；会话、手机、别的 Bot、整理跳、搜索、未读和会话列表的最后一条都看不到它，你看到的是回执。在你的私聊里，它在 Bot 这期间接手的别的活旁边另开一轮；在群里或 Bot↔Bot 私聊里，一个 Bot 同时只做一轮，由它在那里已有的那一轮听到这一行，不另开第二轮（回答你的只读轮不算）。Bot 已经在那里接着做了的不再开；还有别的叫停覆盖着的也不开，交给那一条（`held_over`，有不是 Stop 建的就交给那样的一条），那一条解除时再开。回执写明解除了什么、哪些重新开始、恢复了几个回看、哪些规划回到原状。什么都没叫停时，「继续」就是一句普通的话，照常交给 Bot。只剩它解除不了的叫停（全部上的；或你在群里点名一个 Bot 时，群上的，以及它这句会落到的那件规划上的）时，应用回一条状态行，给出「只让它继续」和「全部继续」两个按钮（`continue_only`、`continue_all`）；解除之后还剩这样的叫停时，回执也给这两个按钮。Stop 建的叫停跟着你关于那件事的下一句话走：只有它挡着、这句「继续」又落在那件事上时，「继续」就是一句关于这件事的普通的话，照常交给 Bot，像别的这种话一样解除它（见下）。对一个 Bot 说的「继续」（在它的私聊里，或在群里点它的名）也说到了它在别处被 Stop 的活，比如它在和别的 Bot 的私聊里做的那件事：你在那里说不上话，这条叫停就由这句解除。说到全部的「继续」（「所有 Bot 继续」「全都继续」）说到你在它之前按过的每一个 Stop，在哪里按的都算，哪怕别的都没叫停也一样被用掉，回执发在你说话的地方。「继续」这样、或因为解除了别的叫停而被用掉时，它说到的 Stop 叫停一起解除，它们停下的轮也带着同一条系统行重新开始——你的话只能这样到它那里。对一个 Bot 说的「继续」只说到这个 Bot 的 Stop：它这句会落到的那件规划上别的 Bot 的 Stop 不动，等你对它们那件事再说话。
- 「停了吗」「你没停」——以及规划的进度行接不住的、问被叫停 Bot 的进度询问——由应用回答：问到的范围上每一条叫停和当初那句话，以及其中此刻还在跑的（`control.kind` 为 `status`）。回答之前先把这些叫停下还在跑的停掉，记成违规（`effect.violations`，工作记录里的 `hold.violation`）；正常应当一条都没有。没有叫停时说「没停」，回答末尾给一个停下按钮；问能不能停（「能停么」「停下好吗」——没对 Bot 说「你」、没说「先」「一下」「请」，就是在问，不是在请它停）也这样回答、给这个按钮。关于一件规划的进度行，也照样列出这件规划和在里面干过活的 Bot 身上的叫停，之前做同样的核对。
- 带着控制词、还有别的内容的话照常投递，带上 `control: {kind: "possible_control", offer, scopes}` 供按钮用，其中什么都不执行。单说「算了 / 不做了 / 取消」也一样，按钮是停下或作废。

**卡片上的 Stop**：有了叫停之后，它是一条叫停——私聊和群里都能按，群里只停那一个 Bot 的这一轮，别的 Bot 照常（ADR 0016 的「群里不能停」由 ADR 0040 P2 推翻）——扣住这个 Bot 在这一轮的规划里的活（这一轮没有规划就只扣这一轮），来源 `user_button`，你的下一句话解除（`lift_on_next_user_message`）。这一轮照上面那样结束，它约的回看挂起而不作废，你在这一轮的会话里时回执也发在那里。你关于这件事的下一句话——归到这件规划，或落在它上面——在叫醒任何人之前解除它，Bot 从你这句往下，不另带说明重开：Stop 的意思是「不是这样」。不在它和你的私聊里说的（比如在群里），只算对它说的：点了它的名（回复它的话会自动带上）、@所有人，或在它在的群里谁都没点；只对别的 Bot 说的同一件事不解除它，它挂起的回看也照旧挂着，免得它没听到你一句话就被回看叫回这件事。只算按下 Stop 之后说的话：之前发出、按下时还在整理中的那句不算。单说「继续」也是这样一句话；对这个 Bot 说的「继续」，不在那件事所在的地方说也解除它，这时停下的轮带着说明重新开始（见上）。挂着按钮的像控制句的话，以及别的范围的叫停，都不会这样解除。

**按钮**：应用读过或写出的关于叫停的话（`control`）带的按钮，每条话只按一次：按过的记在 `control.acted`，之后这一行只说做了什么，再按（连按两下、手机重发的请求）什么都不做。应用自己写的这些行——回执、状态行、重启后的那一句，还有进度询问的进度行（`control.kind` 为 `status`，不带按钮，引擎级别不到叫停这一级时也这样）——在对话里显示成应用的话：头像处是 Deskfolk 标识，名字是「Deskfolk」加「应用」标签，不是它归在的那个 Bot 的头像和名字，读屏读作「来自 Deskfolk 应用的消息」；按钮照旧在下面。你的话上挂的按钮仍在你的话下面。
- 叫停的回执：「撤销」按按钮解除它的叫停，停下的活带说明重新开始，Stop 建的也一样——撤销就是当它没按过；叫停来自你的一句话时，这句话随后照常交给 Bot（整理、叫醒，像从没被读成叫停一样，不再按控制句或进度询问读）；这句话是在你和一个 Bot 的私聊里说的时，停在那里的活不另带说明重开，由这句话交给 Bot：私聊里你的话总会给它开一轮，再重开就是同时做两轮。在群里，这句话只叫醒它点到的（不点名、又没有谁还在做时，只换来各 Bot 的一次判断），所以停在那里的活照样带说明重开，这句话随后像你在群里说的任何一句那样交给 Bot。「扩大到所有 Bot」建一条全部上的叫停，回执发在同一个会话。「一起停下《…》」在叫停时还有别的 Bot 在做的那件规划上建一条规划叫停（`effect.working_beside` 里的规划）。「只停《…》」给回执里每条 Bot 上的叫停先建一条这个 Bot 在那件规划里的叫停（引用同一句话），再解除原来那条：它在别处被停下的活带说明重新开始，在那件规划里的交给新建的这条；应用另回一条回执，写明解除了什么、什么仍在叫停。每件规划各一个按钮，最多三个；「一起停下」也是。「作废这件事」把回执里生效的叫停记为作废（`action: cancel`）：它们照样扣着，解除就重开这件事；真正把一件事作废要等工作项。
- 状态行和「继续」的回执上的「只让 X 继续」：挡着的每条更大的叫停先拆成其他每个 Bot 各一条，引用建它的那句话——全部上的拆成每个 Bot 上的；规划上的拆成每个 Bot 在这件规划里的；会话上的拆成每个 Bot 在它搁置的规划和会话当前规划里的，外加其余 Bot 被它停下、不在这些规划里的每一轮上的叫停——然后连同 X 自己身上的叫停一起解除：X 的活带说明重新开始，别人的交给拆出来的那几条。「全部继续」把挡着的全部解除。两个按钮都回一条回执；回执的 `held_ids` 是这两个按钮针对的叫停。
- 你的话上的按钮：「停下」就是这句话要的叫停（来源 `user_button`，`source_message_id` 是这句话，回执引用它）；「作废」同样，记为作废；「继续」解除这句话会解除的叫停，解除不了时回一条状态行。状态行上的「停下」叫停问到的范围。

**停止菜单和列表**：会话里有 Bot 在做事时（私聊里是对面的 Bot 在任何地方做事，群里是有 Bot 在这个群里做事），Stop 或发送旁边有一个停止菜单：私聊里是「停下 X 的全部工作」「停下这件事」（它最新在做的那件规划，这个会话里的优先）和「停下所有 Bot」；群里是「停下这个群里的工作」、在这个群里做事的每个 Bot、「停下这件事」和「停下所有 Bot」；已被生效的叫停覆盖的项不列。流程图标题行有「停下这件事」「停下所有 Bot」。工具菜单有「全部停下」，已经全部叫停时换成「全部继续」（解除全部上的叫停）；菜单栏的「全部停下」建全部上的叫停，守护进程还没有叫停时退回停下最近有活动的私聊里的那一轮。菜单叫的停走 `POST /v1/holds`，带上菜单所在的会话，你在那个会话里时回执发在那里。守护进程拒绝的叫停或解除在按下的地方说「没做成，再试一次」；工具菜单的这句写在列表上方，到你再按一次、或全部上的叫停被别处建起或解除为止；连不上守护进程时这些按钮显示但按不了。生效中的、你建的叫停（启动时接管的旧搁置除外）列在会话列表上方：范围、时间，作废的标出来，各带「解除」（按按钮解除，见接口）。群上的叫停、私聊对面 Bot 上的叫停、Bot↔Bot 私聊里任一个 Bot 上的叫停，让那一行在没有别的状态时显示「已叫停」；全部上的只在上方列一次。流程图在标题下列出覆盖这件事的叫停——这件规划上的、某个 Bot 在它里面的、它所在会话上的、全部上的——各带「解除」。叫停建立或解除时，打开着的流程图重读规划，之后的编辑从叫停写出的那个版本起，不会被 409 拒；万一还是 409，它照旧重读。要点底部和修订历史把叫停写出的版本标为「叫停改的」（修订的 `cause: "hold"`，规划详情的 `revision_cause`）。这些都要守护进程到了叫停这一级：快照里有 `holds` 才出现。

**启动时**：引擎级别到了叫停这一级后，每次启动都核对一遍。在有叫停之前就被搁置的规划——状态和要点里的状态都是搁置，你或整理跳叫停时就是这样——接成一条来源为 legacy 的规划叫停，此后只有你能让它回到进行中；只是被新规划挤下当前位置的（要点里仍是进行中）不动。然后把叫停覆盖着、却没有搁置的规划和没有挂起的回看补上，记进 daemon.log。

**接口**：`GET /v1/holds`（默认只列生效中的，`?status=all` 连已解除的一起，新的在前）、`GET /v1/holds/:id`、`POST /v1/holds`（你从按钮或菜单叫停，记作 `user_button`；它覆盖的轮照上面那样当场结束）、`POST /v1/holds/:id/lift`（解除，它停下的轮像说「继续」一样重新开始，Stop 建的除外；已解除的原样返回）、`POST /v1/messages/:id/control`（上面的按钮：`{action, task_id?}`，`task_id` 给「一起停下」「只停」指明规划；返回 `{made, lifted}`；这句话没有按钮或不提供这个按钮时 422）；手机上同样可用。`POST /v1/holds` 可带 `session_id`：回执发到那个会话（你在里面时）。快照的 `holds` 是生效中的叫停，新的在前，到叫停这一级之前没有这个字段；叫停的 `plan_title` 是它点名的规划的标题。用 `PATCH /v1/tasks/:id/spec` 把规划改成搁置，也照样结束在里面跑的轮。`POST /v1/turns/stop` 就是上面的卡片 Stop。应用读过或写出的、关于你的叫停的话带着 `control`（`MessageControl`）。叫停的建立、解除和记下的效果都作为 `hold.upsert` 事件推给客户端。规划详情的 `held_by` 是读取那一刻的：全部上的叫停之类不改规划那一行，建立和解除时只推 `hold.upsert`，显示 `held_by` 的客户端收到它就重读规划。

<a id="terminal"></a>
## 终端（Terminal）

你自己在这台机器上开的一条 shell 会话，守护进程持有。和 Terminal.app 同权：cwd 默认落在工作区，但不关在工作区里，也不走批准——批准管的是 Bot 的危险动作，你不需要向自己申请。用来跑你自己的活，包括启动项目这类一直开着的进程。关窗不停。它在哪个目录，以 shell 自己报告的为准（zsh 开箱即用，每个提示符前报一次）：`cd` 之后标签名跟着变；从没报告过的，就是开的那个目录。退出或守护进程自己停掉时，里面的进程一起停，但它在哪个目录、屏幕上有什么会留下来，下次启动在那个目录重新开一个。结束会话才忘掉它。屏幕也在守护进程那里：接回时拿到的是它现在的样子，全屏程序也原样；程序问终端的问题只由它回答，窗格不答，所以几个窗格同时看一条会话也只答一次。shell 拿到的环境按 Terminal.app 那样配，但只放行一份白名单，守护进程自己的其他环境变量（包括密钥）不带进去。桌面和手机同时看一条会话时，它的行列按你最近在看、在敲的那一端来。配对过的设备同权，手机上看得见也敲得动。Bot 看不见、用不了，也不知道它存在。桌面上一个终端标签就是一条会话：新开一个终端标签就是新起一个 shell，标签里不再有一排会话可切。关掉标签只是从窗里拿走，进程照跑；没被任何标签摆出来的会话在「＋」和空窗格里可以「接回」。手机和窄屏上没有窗格，所有会话收在终端那一页里当它的标签。要停必须显式「结束会话」并确认。守护进程那份会话列表才是真的；同一个文件夹里开的几条按开的先后编号，桌面标签和手机上叫法一样。

<a id="interrupted"></a>
## 中断（Interrupted）

守护进程重启时，进行中的轮次都被标成中断，那一行写在这一轮所在的会话里。长活的轮多半在你不在的 Bot↔Bot 私聊里：2026-09-26 一件视频活被重启打断，中断只写在那条私聊里，停了 7.6 小时，直到你自己发现去点了继续。所以重启之后，引擎一起来、调度器走第一拍之前（停机期间到期的回看和日程不会抢在它前面叫醒 Bot），被打断的活每件各发一句，发在这件事所在、有你的会话：规划的轮发在规划所在的会话；你不在那里时，依次找这一轮所在的会话、这条 Bot↔Bot 私聊往上开出它的那个会话、你和这个 Bot 的私聊。同一件事、同一个地方的几轮（比如一件规划在两条 Bot↔Bot 私聊里各断了一轮）合成一句。这一句是应用写的系统行，不进 Bot 的上下文，显示成应用自己的话（见[叫停](#hold)的按钮）：
- **为什么重启**：这一次是开发版（`bun --watch` / `--hot` 跑的，或带 `REAL_BOT_DEV=1`），说「开发版守护进程重新启动了」，不管上一次怎么结束的：`--watch` 每次保存代码都先发 SIGTERM、不等进程退出就原地重启，收到 SIGTERM 的停机又先写下了「有意停下」，在那里这个标记分不清改代码和退出；不是开发版、上次是有意停下的（退出、更新、你让它重启，写了 `last_shutdown = clean`），说「守护进程停下后重新启动了」；其余是「守护进程意外退出后重新启动了」。
- **断在哪**：每一轮的 Bot、所在的任务（没有任务就是规划）、不在这个会话时它在哪、最后一步（执行记录里最后一条命令或 MCP 调用）。
- **接下来**：3 级及以下不会自己接着做；4 级起这一句写明[监督器](#supervisor)的续跑安排（有意停下立即续；意外退出稳定 1 分钟后续一次；开发版稳定 1 分钟、且前后 5 分钟内没有别的重启才续，否则等你；最后一步是结果不明的外部调用、或被叫停覆盖的不自己续），每一轮安排不同时逐个写明，自己续跑走的就是下面这个「继续」。点「继续」，这件事被打断的每一轮都照它自己那条中断行的「继续」接着做：新开一轮，触发条是那条中断行，同样受叫停管——叫停把这几轮全扣住时这次按下不算，解除后再按；只扣住其中几轮时，其余的照常接着做，按钮旁说接着做了几轮、还有几轮被叫停扣着，这一句不算按过，解除后再按接着做剩下的；已经接着做了的、Bot 已经在那里干活的、会话或 Bot 没了的跳过，都已经接着做了时按下就算按过，什么也不多做。点「不续」就先放着，中断行自己的「继续」回来。每句只按一次。
- **通知**：一件事一条（`interrupted`），这几轮各自中断行的通知作废；同一个会话里被这一句覆盖的中断行，在你按下按钮之前不再各带一个「继续」。

哪些轮算被重启打断：守护进程开始一次停掉所有轮时（退出、应用更新或远端重启时的强制排空、守护进程自己停掉），以及启动时收拾上一次留下的活轮时，把那一刻的活轮记下来；下次启动只取仍是中断、中断行还没被接着做的。只有紧接着的那次启动取：中间另有一次运行开过库却没取（没起来就挂了），或者中间跑过一个不认识这条记录的旧版应用、又开过轮，这条记录就过时了，只清掉，不拿这一次重启的原因去说那次早先的停机，那些轮的中断行和通知照旧。发这几句时出错只写一行 daemon.log，守护进程照常起来。卡住被清扫中断的轮不算；强制排空之后又取消的，取消时忘掉。每次启动在工作记录里记一条 `daemon.restart`（原因和被打断的轮），有被打断的再写一行 daemon.log。通知本身不看引擎级别；按原因自己续跑在 4 级（[监督器](#supervisor)），先查副作用记录，最后一步结果不明的不续，否则最后一步是送审或渲染时会付两遍钱。每一行都被接着做之后（不论是监督器还是你），这一句记为已继续、通知解决。「继续」「不续」走 `POST /v1/messages/:id/control`（`{action: "resume" | "leave"}`，手机上同样可用），这一句的 `control` 是 `{kind: "restart", cause, notes, offer, acted?}`，`notes` 是这几轮的中断行；只接着做了一部分时回答带 `partial: {continued, held}`。

<a id="completion"></a>
## 补全（Completion）

每一跳请求都带 `max_tokens`：取这个模型在端点名单里的 `max_output`，没填就是 32768，推理 token 也算在里面。没有上限时，2026-09-29 有三跳把同一句话写到了端点默认的 128,000 token（其中一跳写了 17 分钟，同一句 3,457 遍），被当成收尾发了出去；在 Bot↔Bot 私聊里还叫醒了对方，对方的下一跳又把整段读了一遍。32768 是看过花费记录定的：正常的一跳输出最多三万出头，超过 32768 的只有那三次复读，再低就会截断写大文件的正常跳。端点不认 `max_tokens`、在 400 里点名要 `max_completion_tokens` 的（OpenAI 的推理模型就是这样），马上换这个字段重发一次，这个模型之后都用它。模型能写的比这少的（DeepSeek 的 deepseek-chat 最多 8192，OpenAI 的 gpt-4o 最多 16384），端点会用 400 拒掉这个上限：报错里写了模型自己的上限，马上按那个数重发；没写，就不带上限重发；这个模型之后都这么发。没有上限时这些请求本来能过，所以这种拒绝不能让这一轮失败，而上限在设置里也改不了。提示词加上上限超过了模型的上下文（报错里写着「32768 in the completion」，或者点名上限、说的却是上下文长度，vLLM 就是这样）时，只有这一次不带上限重发，下一跳照样先带上限。

流式输出时，应用只看正文，不看工具参数、代码块和表格：在最近 6000 字符里按句切（句号、问号、感叹号、分号、省略号、换行，英文句点后面跟空格），每句只比字母和数字、不分大小写，数字照比（「镜头 11」和「镜头 12」是两句）。同一句（8 个字以上）连着出现第 5 次，或者最近至少 20 句里不同的句子不到两成，就当场掐断这次补全，记为复读，通常只要几秒。「连着」是说两次之间没有新句子，只隔着前面出现过的句子：复读的两遍之间只有复读本身；逐项的审片结论（每行一句「Shot 03：通过。画面稳定，无需返工。」）两遍之间隔着这一项自己的名字，不算复读。不同句子占比这一条不看句子长短，20 行一模一样的「- [x] 完成」、哪一行都没写是哪一项，照样算复读。写完的回复发出之前，再按同样的规则看一遍。

这几种补全算失败，不算回复：
- **复读**：见上。
- **拒答**：端点给的结束原因是 `content_filter` 或 Gemini 的 `SAFETY` 一类；或者整条回复不超过 300 字、没有工具调用，又是一句套话式的拒答（自称语言模型并说做不到，或者只有一句「I can't help with that」「抱歉，我无法协助处理这个请求」）。Bot 自己说明哪一步做不了、为什么，不算拒答。之前 Gemini 的拒答有两次被当成 Bot 的消息发了出去。
- **不完整**：没写完就关了连接（既没有结束原因，也没有 `[DONE]`；端点或中间的代理半路断开连接就是这样），结束原因说要调用工具、却没有一个完整的工具调用，或者工具调用的参数不是完整的 JSON。客户端先把同一个请求最多试三次，还是不完整才算失败。
- **超时**：一次请求从发出到流结束最多这么久：10 分钟和「`max_output` ÷ 这个模型实测的 p10 吞吐 × 1.5」里较大的那个。吞吐取名单里的 `stream_tps_p10`，没测过就是 10 分钟。等端点空位的时间、工具执行的时间、合盖睡着的时间都不算。

失败的补全什么都不发出、不进回路，也不叫醒谁。同一个模型带一句说明原因的提示再来一跳（复读的那句是：别复述，也别写收尾话，要做的事直接调用工具去做）；连着再失败，这一轮以失败结束，会话里留一行「这一轮没写完：……」，你在场时还有一条失败通知。中间只要有一跳正常，下一次失败就还能再来一次。连不上端点、端点忙、端点报错、流中途没了下文（连接还开着，却等不到下一段）这几种不在此列：客户端已经把同一个请求重发过，这一轮直接结束。没了下文要等满空闲时限（3 分钟）才知道，三次就是 9 分钟，再来一跳会再翻一倍；连接半路断开几秒就知道，所以算不完整，多来一跳也不贵。流中途没了下文或者断开时，前半截以前会当成回复发出、或者拿去执行里面的工具调用，现在一概不用。

结束原因不分大小写，经代理转来的 Gemini 原样结束原因也认：`STOP` 就是 `stop`，`max_tokens`、`MAX_TOKENS` 和 Mistral 的 `model_length` 都当作 `length`。空字符串不算结束原因：有的端点每个数据块都带一个 `""`，直到最后一块。客户端不认识的结束原因（比如 `eos`）说明模型自己写完了，这条流是完整的，不会当成半截流重发，回复照样按上面的规则判断。`error` 例外：OpenRouter 在它后面的模型半路出错时用它结束，前面到的只是半截，算不完整。结束原因到了之后流没了下文（端点没发用量和 `[DONE]`，也没关连接），等过空闲时限就当回复收下：模型已经写完，缺的只是端点最后那几个包。

写到输出上限被截断（结束原因是 `length`）、又没有复读的，接着写一跳：截下来的那部分不发出，但留在回路里让它接着写，提示它要做的事直接调用工具、长内容写进文件并分块写；截断发生在工具调用的参数里时，那次调用不执行，提示它分块写。接着写的那一跳又写到上限，这一轮以「写到输出上限」失败结束。

流式输出不再算作这一轮在推进：以前每来一段就刷新一次这一轮的动静，一跳写多久都不会被当成卡住。现在补全由自己的时间上限管，卡住清扫（20 分钟没有任何动静）只管补全之外的时候。

名单里的 `max_output` 和 `stream_tps_p10` 在设置里看不到；从设置再保存名单时，这两个值照旧保留，通过接口传 `null` 才会清掉。存着的名单里这两个值哪个不合法（比如 0 或者字符串），只忽略这一个值，模型照常留在名单里，用它的 Bot 也不受影响。

<a id="artifact"></a>
## 产物（Artifact）

一条消息里引用的工作区相对路径，或 `http`/`https` 链接。文件本体在工作区（或远端 URL）上。本轮写入的区内文件会自动出现在最终消息里。点开后在聊天右侧预览面板查看（图 / 音视频 / PDF / 文本 / 单文件 HTML / Word / Excel / PowerPoint）；其它种类（字幕、压缩包……）写明不支持预览：本机窗口给「用系统默认应用打开」，手机和浏览器里给下载按钮。远程打开的每个文件都能下载：手机在预览顶栏右端，宽屏在文件上方那排按钮里，流程图的文件卡片在卡片头部。远程打开、下载和发附件都不限文件大小；桌面端这条预览也可以拖成自己的一块窗格。面板左侧的树列的是**这件事**引用过的全部路径——不是只有这一条消息的，也不是工作目录里的全部文件，相关指的是被引用过；树以工作目录为根，这件事在目录之外引用的路径和它并列平铺，本条消息自己引用的那几个标出来，面板与聊天共用一栏、中间拖条改宽度；同一条消息多个路径或打开工作区时左侧是文件树，树和内容之间可拖。拖过的预览栏宽度和文件树宽度，退出后再开还在。文本用 Monaco + Shiki 编辑（行号、查找 / 替换走 ⌘F、匹配括号·标签·标题折叠、换行）；预览自己不再放查找、换行、复制、保存、关闭这些按钮。Markdown 和单文件 HTML 默认看渲染结果，内容顶部正中有一个浮动按钮，不随正文滚动，在预览和源码之间切换。PDF 用内置的 pdf.js 渲染（翻页、缩放、适合宽度 / 整页、页内查找），不走系统的 PDF 查看器。区内 UTF-8 文本可 Cmd+S / 保存写回同一路径；未保存切文件或关面板先确认。桌面端预览没有自己的标题栏，文件名和关闭都在工作台标签上；窄屏和手机留一条返回加文件名。文件树每一项右键是「在 Finder 中打开」和「用系统默认应用打开」，本机窗口才生效。树里的文件和文件夹（⌘ / Shift 多选的一起）可以直接拖到聊天框，停在框上时框会亮起，松开后在输入框上方排成附件，随下一条消息发出：挂的是工作区里的原路径，不上传、不复制进 `inbox/`，Bot 读到的是「附件：路径」，图片照常按像素交给模型；拖动时按 Esc 取消。文件投递那条会话、只读的会话和正在发送的聊天框不收；手机和触屏上不拖。交接时把路径写进给对方的那条消息，不另建种类。种类按扩展名在预览时推导。区内的产物可以批注（见「批注」）。

<a id="annotation"></a>
## 批注（Annotation）

你对某个产物的某一处写的一句意见。挂在一个工作区相对路径、一个锚点和交出这个产物的那条消息上。先是草稿，Bot 看不见；攒够一批一起发出，合成一条引用交付消息的回复，并 @ 交出它的 Bot。发出后是「待处理」，Bot 或你把它标成「已处理」；已处理的可以重新打开。一标成已处理就从文件上撤下——图上的框、代码页边的点、Markdown 里的标记、PDF 页上的框、HTML 的编号、时间轴上的标记——留在文件上的就是还没处理的；列表里照旧列着。预览栏的「显示已处理」勾上才画回来，只对这块预览有效；从列表点一条已处理的去定位，那一条在定位期间画出来，再点一下取消选中就撤下来；对话里点它的卡片只打开列表停在那一条，不画回文件上。文件改了、锚点对不上时标「原文已变」，状态不变；文件不在了标「文件不在了」。批注不是产物的快照：只记下当时的引文、位置和文件哈希，不保存旧文件（选区长过引文上限时，另记整段的长度和指纹，用来判断这一段还在不在、变没变）。挂到谁：从某条消息打开的预览，就挂到那条消息和交出它的 Bot；交付消息在你不在的 Bot↔Bot 私聊里时，这批发到你和交付 Bot 的私聊里，消息上记着来源。只批工作区内的文件，链接类产物不能批注。批注消息叫醒的每个 Bot 沿用它自己交出产物那一轮的工作目录（这批里它最近的一次交付），哪怕会话已经静默够久、那件事已经关了——改的是同一件交付物；这一轮只是在那个目录里干活，不把那件事重新打开，也不换掉会话的当前规划，那件事属于别的会话（Bot↔Bot 私聊交出的）时也一样，两边会话各自接着的事都不受影响。它就是一条普通的后续发言：落在交付那一轮上、进纠正链，不加权。一批最多 50 条，一条正文最多 2000 字。群里一批可以同时交给几个 Bot：上下文里每条批注都写明交给了哪个 Bot（交出那个产物的 Bot，删了就写「已删除的 Bot」），`list_annotations` 也带上；每个 Bot 只处理交给自己的，交给别的 Bot 的留给那个 Bot，可以提一句；交给已删除的 Bot 的没人接，归这批叫醒的 Bot 处理。Bot 能做的：逐条处理交给自己的，改了的用 `resolve_annotation` 标成已处理并写一句怎么改的（任何 Bot 都可以标——Bot 不是权限边界——记下是谁标的），用 `list_annotations` 查还没处理完的（路径和 `read_file` 一样解析，工作区外的路径直接报错），`read_file` 读到还有待处理批注的文件时会被提醒。Bot 不能做的：重新打开、删除、新建批注。清空历史、删会话时挂在这些消息上的批注一起删掉；删了文件不删批注。锚点种类：文本 / 代码行区间、Markdown 渲染态划词、图片框选、PDF 页内区域、HTML 元素、音视频时间点。

<a id="context-window"></a>
## 上下文窗（Context window）

一轮里模型实际看到的：人设、启用中的技能目录、系统指令、本轮 MCP、这个 Bot 的记忆、局面块（群里有在场成员、活轮、谁叫醒、用户最近一句；每一轮都有这件事的名字和规划要点（目标、流程与分工、进展）、你在这件事里的原话（最早 4 句和最新 6 句）、需求台账里适用的要求、验收检查、任务清单、本轮任务、已交出的文件、经过（在别的会话做的那步标明在哪）、自己待回看的那一次，规划开在别的会话时写明开在哪，还有此刻别的会话里做这件事的轮和这个 Bot 别的活轮，还没整理出要点时退回最初的要求，第一轮标「这是这件事的第一轮」；全部从库里已有的行读出，轮次本身不叫模型摘要）、最近一段转录（别人的行属于另一件事或另一个任务时，在说话人后面带 `〔规划「…」· 任务 NN〕`，Bot 自己的行不带，免得它学着写；含栅格附件的像素，只取最新的一份额度；带批注的用户消息在正文后面逐条展开每条批注的 id、交给哪个 Bot、路径、位置、引文或裁图和意见（页面和你写的文字折成一行或逐行缩进，冒充不了下一条），裁图和栅格附件花同一份额度、作为像素发给模型，额度用完的裁图只留批注的文字），以及本轮的工具回路。完整历史只存在库里，给你翻、给搜索，不整段塞进模型；判断调用用另一套更短的窗口，不含图。过大的工具结果先把完整 JSON 留在工作区，窗口里只放受限预览和 full_result_path；Bot 可继续用 shell 提取所需字段或解码文件，不把预览截断当作原始结果丢失。

<a id="spend"></a>
## 花费（Spend）

本机只增不减的调用账本。八类端点调用各记一行：轮次补全、判断、开轮前选路、纠正链复盘、复盘后的每一跳学习、输入建议、整理、验收检查。和别的调用共用一类的另记用途（`purpose`）：书记员记在「整理」一类下、用途是书记员，衔接一致检查送帧的那几次记在「验收检查」一类下、用途是看图判断（以后的反思也会记在「整理」下、单列一项）。选路和整理属于决策路由；复盘与学习跳合为反馈路由；判断单列，输入建议、验收检查、书记员和看图判断归其他；输入建议、整理、书记员和验收检查都不归任何 Bot。视图的类别明细里，一项用途单独成一行，「整理」只剩整理跳自己的调用；按类别或某一行筛选时也这样分，还没记过的用途不占一行。每行存实际模型、端点、思考等级及写入时的会话和 Bot 名称；删会话、清空历史、删 Bot 都保留，已删除对象用名称快照并标「已删除」，迁移时找不到模型的显示「未记录模型」。token 只用端点 `usage`，缺了显示「—」。供应商给出 `cost_in_usd_ticks` 时记实报；没有实报、输入与输出 token 齐全且配置了计费单价时算估算；估算跟着现在配置的单价走，设、改或清空某个模型的单价会重算它在该端点上所有没有实报的调用，从名单里去掉的模型保留原有估算。缓存输入使用缓存单价（留空沿用输入价，缓存 token 缺了当 0）；推理 token 已含在输出里，不重复加。实报与估算分开合计，覆盖不全会说明。应用里有独立花费视图：桌面一个窗格标签，窄屏和手机一个浮层，可按时间、模型、会话、Bot 及调用类别筛选、看趋势与逐次明细；明细可跳回触发消息。会话顶栏、列表行、设置和模型选择记录都不放花费数字。时间范围和维度只保存在本机。
