# 控制面：叫停、叫醒闸、控制句、回执和重启分类

[ADR 0040](0040-agent-kernel-the-job-owns-state.md) 的 P2 阶段。09-29 你在私聊里说「你手头的生成停一下」，这句话像普通要求一样过了整理跳，视频导演在另外两条 Bot↔Bot 私聊里的轮都没听到，一个接着重拼母带，一个把 Shot 11 送审；11:02 规划叫回又让它交了一个新镜头。停不住的原因在结构上：叫停只是规划上一个模型改得回去的「搁置」，开轮、叫醒和有副作用的工具调用都不看它。09-26 还有一件：重启打断了 Bot↔Bot 私聊里的长活，中断那一行只写在那条私聊里，你不在那里，活停了 7.6 小时没人知道。

本文记下 P2 怎么落地、和 ADR 0040 的出入，以及取代了什么：

- [ADR 0016](0016-group-one-live-turn-per-bot.md) 的「群仍无 Stop」：群里每个 Bot 正在写的回复都有 Stop，整个群也能从停止菜单或一句「停下」叫停。一人一轮、点名听进已有活轮不变。
- [ADR 0031](0031-heard-in-the-live-turn-and-plans-closed-on-evidence.md) 把「搁置」当成停下的做法：它写明群里没有 Stop、你说话改道是唯一的停法，叫停靠整理跳把规划标成搁置，规划对账只看规划是不是进行中。现在停下是一条只有你能解除的叫停记录；规划对账被叫停挡下时不改叫别人，只记一条挡下的叫醒。09-29 之后临时加在整理跳上的补丁（叫停句不重开搁置的规划、settle 不把搁置改回进行中、提示词里的叫停段）到了叫停这一级就不再用。

## 现在

**叫停是一行记录。** `holds` 表：范围（全部、Bot、会话、规划、任务、某个 Bot 在某件规划里的活、某一轮）、建立时定下的额外覆盖 `targets`、来源（你的话 `user_text`、按钮 `user_button`、启动时接管的旧搁置 `legacy`、删群时分出来的 `migration`）、做了什么 `effect`（只增不改）。只有你能解除（I7：`user_text` 必须指向一条你的话）；记录从不删除，清空聊天只把它指向的那句话置空。`held_scopes` 视图是「这个被叫停了吗」的唯一判据，store、叫醒闸和 turns 上的触发器都读它。库的地板随开始写叫停的那一级 `engine_level` 抬高，不随补列补表的迁移：空的 `holds` 表和新列旧版本读不错，读错的是开始往里写。启动时核对：状态和要点里的状态都是搁置的规划接成 `legacy` 叫停；只被新规划挤下当前位置的（要点里仍是进行中）不接，否则每件被挤开的规划都会冻住；叫停覆盖着却没搁置的规划、没挂起的回看补上，写进 daemon.log。

**规划状态照旧能读。** 规划或会话上的叫停把它覆盖的进行中规划改成搁置，状态列和要点里的状态一起改，原值记进 `effect.parked_plans`，解除时改回；只改一处，流程图的下一次编辑或整理跳会把它送回进行中。被挤开的规划原值记成 `aside`，解除后回到被挤开的样子，不回到进行中：对账会叫回任何状态列是进行中的规划，哪怕它不在当前位置。改和改回各算要点的一个版本（`cause = 'hold'`），拿旧版本提交的流程图得 409，整理跳的「上一版以来」跳过这两个版本。旧客户端和手机唯一的改状态入口是 `PATCH /v1/tasks/:id/spec`：改成搁置就是在这件规划上叫停，改回进行中或标成已完成解除这件规划上的叫停；算不算改状态拿要点里的状态比，因为流程图送回的是它。Bot、任务、某一轮和全部上的叫停不改规划状态，`held_by` 只列覆盖整件事的（全部、主会话、规划）。删群时，群上的叫停搁置着、群删后还留着的规划各得一条自己的 `migration` 规划叫停。

**所有叫醒和推进都过闸。** 三个开轮入口（普通开轮、「继续」按钮、日程）在准入之后先问 `mayWake`，挡下就记一条 `wake.suppressed`（工作记录 `work_events`：只追加，写明哪种叫醒和哪几条叫停）。叫醒方自己被叫停也算（`by`）：被叫停的 Bot 说的话叫不醒别人，委派方的回报在对方被叫停时不发。在跑的轮被叫停覆盖后不再听进新来的话，也不被改道；说的是叫停范围外的事的，在它旁边另开一轮。回看被挡下时挂起，解除后恢复；没读就结束的回看交还挂起；日程到点被挡下时不认领，解除后只补最近一次；规划叫回被挡下时不改叫别人：被叫停的 Bot 的任务可能正是别人等的上游。turns 上的 INSERT 和 UPDATE 触发器兜底（I2）：INSERT 只豁免「只读段、触发消息是你的话」，UPDATE 没有豁免，叫停在这一轮本身上时也拦；两个触发器每次开库都按这一版重建。工具闸（I3）在有副作用的调用前问 `mayAct`：放行的只有读文件、列目录、`list_*`、`read_skill`、`end_turn` 和标了 `readOnlyHint` 的 MCP 工具，被叫停的轮得结束得了；被拒的调用不发工具事件、不记执行记录、不算工具失败。`work_events` 按 ADR 0040 给工作记录定的整套列提前到这一阶段建，免得一张过渡表到 P6 再收。

**控制句由应用照办。** 你的一句话在进度询问之后、整理之前按固定词表读（`control-line.ts`，不调模型、不读库）。去掉控制短语和填充词之后剩下的不超过 2 个码点才执行；此外句子里有数字、画面类的词、「停顿」「停车」这类形近的词、时间词（「明天」「待会」）或否定词（「别再停了」「继续不了」）也不执行——光靠 2 个码点，「画面暂停」「停2秒」「继续这个风格」都会被当成控制。「不对」「没事」「等一下」这类开头的插话和后面分开读。问句只有请求式（「能先停一下吗」）算叫停，「怎么还在跑」「谁让你继续的」是在问，由应用照实况回答。不带 @ 的 Bot 名和 @ 一样算点名；私聊里 @X 就是 X；引用回复自动带上的 @ 是收话人，不算点名。带附件的话最多挂按钮，批注不按控制句读。带着控制词却还有别的内容的话照常交给 Bot，只挂按钮（`possible_control`）；控制句只来自你，Bot 没有叫停工具。

**叫停和回执。** 同一次写入里：每个范围一条叫停；被覆盖的 Bot 交出去、还没交回的活作为 `turn` 范围的额外覆盖记上（由它的轮写的话开出来的别的 Bot 的轮，往下最多三层，还在跑或还有待响的回看）——覆盖那一轮、它的回看和它的话会叫醒的人，不覆盖那个 Bot 自己的别的活，上游一概不停；它覆盖的活轮结束为 stopped，回看挂起而不作废，每一轮做到哪一步记进 `effect.stopped_turns`，同一件规划里没覆盖、仍在做的记进 `working_beside`。写入落库后再中止补全、发 MCP 取消、按进程组停命令。回执是应用写的 `system` 行，不进 Bot 上下文，界面上显示成应用的话（Deskfolk 标识和名字），不借它归在的那个 Bot 的头像和名字，每个字都来自 `effect` 和此刻的库，带 `messages.control` 供按钮用。「停了吗」「你没停」、以及问被叫停 Bot 的进度，每次都先把叫停下还在跑的停掉并记违规（`effect.violations`、工作记录 `hold.violation`），再按实况回答。`POST /v1/holds` 也当场结束它覆盖的轮。

**继续。** 解除话里点到的叫停，不越过话的范围：对一个 Bot，是它自己的（扣住它全部或一部分活的都算）；对一件规划，是它上面的和某个 Bot 在它里面的；对群，是群上的和在群里用一句话建的；对全部，是你建的每一条，`legacy`、`migration` 不算。在私聊里说，还解除在这条私聊里用一句话建的其他叫停，只在私聊，而且不碰别的 Bot 身上的。被解除的叫停停下的每一轮带一条说明重开（你的原话、它的规划、写过的文件、最后几步，不催它做什么）。说明是应用写给那个 Bot 的，像回看自己那一行（ADR 0028）只给被它叫醒、或在那里听到它的那一轮：`messages.bot_only` 标记它，列消息、别的 Bot 的转录、整理跳、搜索、未读、最后一条和事件流都用排除回看那一行的同一个条件把它排除（`notBotOnlyLine` / `isBotOnlyLine`，回看那一行仍认 `check_backs.message_id`），流程图照样从被停下的那一轮画到重开的那一轮；你看到的是回执。重开的地方：在和你的私聊里另开一轮，在群里或 Bot↔Bot 私聊里交给它在那里已有的那一轮听（`hearOrStart`），一个 Bot 在那里同时只做一轮。还被别的叫停覆盖的交给那一条（`held_over`，优先交给不是 Stop 建的），那一条解除时再开。什么都没叫停时「继续」是一句普通的话。只剩它解除不了的更大的叫停时，应用回一条状态行，给「只让 X 继续」「全部继续」。

**只读段。** 被叫停覆盖时你问它的话开一段 `mode = readonly` 的轮：不绑规划（绑上就会把问答写进规划的经过，还让被叫停的轮借它读到你的话），`mayAct` 按 mode 一律拒绝，回答不叫醒任何人，它不听进别的话，也不被改道。

**卡片上的 Stop。** 它是一条扣住这个 Bot 在这一轮的规划里的活的叫停（没有规划就只扣这一轮），私聊和群里都能按，回看挂起。你下一句对这个 Bot 说的、关于这件事的话在叫醒任何人之前解除它，Bot 从你这句往下，不另带说明：在它和你的私聊里说的都算，别处要点它的名、回复它或 @所有人，在它在的群里谁都不点也算；只对别的 Bot 说的不算；按下之前发出的不算。「继续」也是这样一句话。叫停在它和别的 Bot 的私聊里的那件事时，对它说的「继续」不管在哪说都解除它，停下的轮带说明重开；「所有 Bot 继续」算你之前按过的每一个 Stop；对一个 Bot 说的不动别的 Bot 的 Stop。按钮解除一条 Stop 建的叫停时不带说明重开。

**按钮。** 回执、状态行和标了按钮的话上的按钮每条只按一次（`control.acted`），再按什么都不做。「撤销」解除回执的叫停、停下的活重开，被读成叫停的那句话随后照常投递（`handleInboundMessage` 的 `ordinary`，不再读控制句）；这句话在你和那个 Bot 的私聊里说时，停在那里的那一轮不另开，由这句话交给它，群里照样重开。「只让 X 继续」先把挡着的更大的叫停拆成其他每个 Bot 各一条：全部的拆成每个 Bot 的，规划的拆成每个 Bot 在这件规划里的，会话的拆成每个 Bot 在它搁置的规划和当前规划里的，外加其余 Bot 被它停下、不在这些规划里的每一轮。「作废这件事」只把叫停记为作废（`action = cancel`），解除就重开：工作项之前没有作废的状态，标成已完成又会冒充交付。叫停相关的界面只在快照带 `holds`（到了叫停这一级）时出现。菜单栏原来那项 Stop 改成「全部停下」，守护进程还没有叫停时退回原来的做法。

**重启告诉你断在哪。** 为什么重启，看这一次怎么跑和上一次怎么结束：开发态（`bun --watch` / `--hot`，或 `REAL_BOT_DEV=1`）一律是 dev；否则上一次有意停下写了 `clean`（`settings.last_shutdown`）的是 clean，再否则是 crash。开发态不看这个标记，是因为 `bun --watch` 每次保存都先发 SIGTERM、不等进程退出就原地重启，而守护进程收到 SIGTERM 时的停机在第一次 await 之前就写下了 `clean`：在那里，标记分不清是改了代码还是你退出了。开发态下你有意退出也算 dev，宁可保守。被重启打断的活按「一件事、一个地方」各发一行：规划的轮发在规划所在、有你的会话；不在的话依次找这一轮所在的会话、这条 Bot↔Bot 私聊往上开出它的会话、你和这个 Bot 的私聊。这一行是应用写的 `system` 行，不进 Bot 上下文：为什么重启、每一轮停在哪一步、不会自己接着做，带「继续」「不续」（`control.kind = restart`）和一条通知（`interrupted`，semantic key `restart:<这一行>`）；这些轮自己那条中断行的通知作废，一件事只通知一次；同一个会话里被这一行覆盖的中断行，在你按下它的按钮之前不再各带一个「继续」。「继续」对每一轮照它自己的「继续」做，受叫停管：叫停把这件事的轮全扣住时这次按下不算（409），解除后再按；只扣住其中一部分时，其余照常接着做，回答说接着做了几轮、还有几轮被扣着（`partial`），这一句不算按过，解除后再按接着做剩下的；已经接着做了、Bot 已经在那里干活、会话或 Bot 没了的跳过，全都这样时按下就是按过、什么都不做。「不续」只是放着，中断行自己的「继续」回来。被打断的是哪些轮：守护进程开始一次停掉所有轮时（引擎的 `abortAll`、`close`，启动时恢复上一次留下的活轮）把当时的活轮记进设置 `_cut_by_shutdown`，连同被它的结束打断的那次运行（`Store.bootId`）和第一次记下的时刻，下次启动取一次、清掉，只留仍是中断、中断行还没被接着做的。只有紧接着的下一次启动认这条记录：每次开库把自己的 `bootId` 写进 `_last_run`，记录上的运行不是上一次的（中间有一次运行开过库、没来得及取就结束了），或者记下之后又有轮开出来（中间跑过一个不认识这条记录、也不写 `_last_run` 的旧版应用），就是过时的，只清掉，不拿这一次重启的原因去说很久以前的一次停机；那些轮自己的中断行和通知照旧。不用固定时限：你周五退出、周一再开，被打断的活仍该说。卡住的轮被清扫中断不算重启；强制排空后又取消的，取消时忘掉。每次启动记一条工作记录 `daemon.restart`（原因和被打断的轮），有被打断的再写一行 daemon.log。通知在引擎起来之后、调度器第一拍之前发，停机期间到期的回看和日程不会抢在它前面叫醒 Bot；发的时候出错只写一行 daemon.log，守护进程照常起来。这些都不看引擎级别：新的只是一行消息、两条设置和一条工作记录，旧版本读不错。

**整理跳的叫停补丁只留在叫停这一级之下。** 到了叫停这一级，整理跳的提示词不再有叫停段，叫停句不重开搁置的规划、settle 不把搁置改回进行中这两道拦截也不再用：控制句读得出、自己回答的话（纯叫停、继续、问状态）根本不经过整理跳，混着别的要求的照常归档，被叫停的规划由叫停扣着，而整理跳按自己的理解把规划标成搁置，就成了一条谁也没下、按钮列不出也解除不了的叫停。级别不到时（源码跑的守护进程旁边装着还不读版本闸的应用）叫停还不存在，这些补丁仍是唯一挡着叫停句把搁置的规划推回去的东西，照旧生效；它们和 `engine_level` 这个过渡开关一起在 P6 删掉。

## 和 ADR 0040 的出入

- **推迟到 P4 的四样。** 设计里叫停还要：把覆盖范围里排队的收件改成 held（收件表 `inbox_items` 是 P4a）；外部作业只跟踪、不叫醒（`external_jobs` 是 P4d；眼下 MCP 调用随中止收到取消通知，回执里没有作业可列）；上游等这些目标的等待改成 `waiting_on = held`（工作项和等待记录是 P4c）；执行段记 `end_reason = stopped_by_hold`（这一列和 I5 随 P4b 的 `work_item_id` 一起来；眼下是 `status = stopped` 加 `effect.stopped_turns` 加工作记录 `control.hold`，信息不丢）。
- **重启后自己续跑推迟到 P4c。** ADR 0040 让下次启动按 `last_shutdown` 决定怎么续跑，长活夹具的「正常退出后自己接着做」排在 P4c。按原因自己续要监督器和工作项，还要先查作业登记和重复副作用守卫，不然最后一步是送审或渲染时会付两遍钱，也要限制每小时次数；P2 只分类、告诉你、给按钮，原因记在工作记录里留给 P4c。
- **违规记成工作记录 `hold.violation`**，不是质量事件（质量事件表是 P5）。
- **额外覆盖是 `turn` 范围**，按轮的血缘算（触发消息 → 写它的那一轮），不是 Bot 或会话：委派是「别的 Bot 的那一轮」，那个 Bot 自己的活照常；把会话记进去还会连带搁置开在那条私聊里的规划。
- **「继续」的范围**比只解除这个 Bot 的 Bot 级和「Bot × 规划」级叫停宽：加上它的 `turn` 叫停，以及在这条私聊里用一句话建的；只解除最近一条的读法会让你说过两次停之后一句「继续」仍停着。
- **群的拆分有个缺口。** 「只让 X 继续」拆群上的叫停时，拆不出「其他 Bot × 这个群」，所以别的 Bot 之后在群里新开、不属于这些规划的轮不被扣住；要补得加一个范围取值（改 CHECK，C 类），留到 P6。
- **开发者可以替第二个条件担保。** ADR 0040 要等本机装好的应用也跟上含闸的版本，才把 `engine_level` 调上去。本机装的是 0.1.0-rc.11 这类还不读闸的版本时，源码跑的守护进程就一直停在 0 级，开发者天天用的那个数据目录里没有叫停。所以加了一个只在本机的放行：设置 `engine_gate_optin`（什么时候、经本机 API 还是脚本写的），由 `POST /v1/capabilities/raise { accept_older_app: true }` 或 `apps/daemon/scripts/engine-level.ts --accept-older-app` 写下。有它时，旧的或读不出版本的安装版不再挡住调级别：API 当场调，和启动时一样接管旧的搁置规划，连着的客户端重新取一次快照；脚本在守护进程没跑时只写下放行，下次启动调。用上放行的那一次写进 daemon.log。代价由开发者承担：那份旧应用在守护进程没跑时被打开，不会理会叫停。收回放行（`DELETE` 同一路径、`--clear`）不降级别：级别只往前，库在那一级写下的东西只能照那一级读。这个路由不在远端白名单里，手机碰不到。
- **S 基准（叫停到安静不超过 10 秒）没在真端点上跑**：它要付费端点和真数据目录；进程内的测试断言叫停是一次写入加中止。

## 取舍

- **叫停句按词表认，宁可漏也不误。** 漏认的叫停还有按钮和停止菜单兜底；误认会吞掉一句要求。结构上纯控制句剩不下 2 个码点，词表遇到新的误判就补。
- **回执不开模型轮。** 应用只写发生过的事，所以回执里不会出现「已停下」而实际还在跑。
- **Stop 不再作废被停轮约下的回看，改为挂起**：Stop 的意思是「不是这样」，你接着说话就解除，挂起的回看跟着回来；作废的话，解除后那些约好的回头看就没了。
- **重启一律等你按。** clean 的那一类（你退出了应用）本可立即续，但「clean」只说明是有意停下，不说明活已经排空：退出前正在跑的轮照样被打断。等 P4c 能核对最后一步的副作用、限制每小时次数，再按原因自己续。
- **被打断的轮记在设置里。** 只在一次停掉所有轮时记，恰好对上重启；按「上次启动以来中断的」算会把卡住后被清扫的轮也算成重启打断的。
- **补丁按级别留，不直接删。** 本机装的应用停在不读版本闸的旧版时，源码跑的守护进程一直在 0 级；这时删掉补丁，你叫停的规划又会被推回去，正是 09-29 那一出。

## 不做

- 不给 Bot 叫停或解除叫停的工具，也不让整理跳解除叫停。
- 不删叫停记录；清空聊天、删群都不删。
- 不在叫停前确认：回执上能撤销、扩大、缩小。
- 重启后不替你重交最后那次送审或渲染。
