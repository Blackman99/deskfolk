# 内置提示词你和 Bot 都能改：应用是一份工作方式模板 / Built-in prompts you and your Bots can edit: the app as a template of a way of working

Status: implemented 2026-10-06, at no engine level: a build that does not know the new tables never reads them and runs its own defaults. It narrows [ADR 0012](0012-judgement-system-prompt.md) (the judgement prompt holds no `{`, now checked on the filled text).

你说的是（2026-10-06）：「应用内置提示词支持 Bot 以及应用设置里更改……应用应当成为一个我作为开发者总结出来的工作方式模板，这些其实就是现在的内置提示词 + 应用层 UI 壳，使用者可以在应用内指挥 Bot 进行任何修改达到他们的工作预期。」在这之前，应用写给模型的每一段话——每一轮的系统指令、技能 / 记忆 / MCP 段的开头、工具说明、整理跳和读句这些应用自己的调用——都是代码里的中英常量，没有一处能改；有三处还靠对原文做 `.replace()` 打补丁（引擎级别、Windows 的 shell、叫停之后的整理跳），测试和演示带靠全文相等认出是哪一次调用。

You put it this way (2026-10-06): the app's built-in prompts should be editable by Bots and in the app's settings; the app should be a template of the way of working you, its developer, settled on — the built-in prompts plus the app's UI shell — and whoever uses it directs Bots in the app to change whatever they need. Until now every text the app sends a model — the System section of every turn, the notes that open the Skills, Memory and MCP sections, the tool descriptions, the organizer's and the line readings' own calls — was a constant in code, none of it editable; three were patched with `.replace()` on their own text (by engine level, for a Windows shell, for the organizer once holds exist), and tests and demo tapes told calls apart by their whole text.

## 决定 / Decisions

1. **模板 = 内置提示词 + 应用壳 / The template is the built-in prompts plus the app's shell.** 能改的是写给模型的话：每一轮的系统指令（`turn.system`）、技能 / 记忆 / MCP 段的开头（`turn.skills` / `turn.memory` / `turn.mcp`）、Claude Agent 的前言（`agent.preface`）、每个工具的说明（`tool.<名字>`），以及应用自己的调用（`call.*`：整理跳、四种读句、书记员、参与判断、输入建议、收窄的反思、完工复盘、三种衔接检查、照样片检查）。仍是代码、不能改的是应用壳：批准、叫停与 Stop、门禁、需求台账只收你的话、检查由应用自己跑，以及工具的参数、局面块和转录里应用写的行。提示词能让 Bot 换一种做法，但放宽不了任何一道由代码把守的规矩。/ What can change is what the app tells models: every turn's System section, the notes opening the Skills, Memory and MCP sections, the Claude Agent preface, each tool's description, and the app's own calls (organizer, four line readings, scribe, join judgement, composer suggestions, narrowed reflection, retrospective, three seams judges, the sample-standard judge). The shell stays code: approvals, holds and Stop, gates, a ledger that holds only your words, checks the app runs itself, and tool parameters, the situation block and the lines the app writes into transcripts. A prompt can change how Bots work; it cannot loosen a rule code enforces.

2. **槽位与默认 / Slots and their defaults.** 每段话在 `prompts/registry.ts` 登记成一个槽位：标题、说明、语言、代码要填的占位符。默认按引擎级别和 shell 渲染，和一直以来的拼法逐字相同（`prompts/registry.test.ts` 逐条核对）；你的版本替换的是渲染后的整段，不再对它打补丁。只有中文的那几段（整理跳、读句、书记员、参与判断、输入建议）不论应用用什么语言都用它。/ Each text is a slot in `prompts/registry.ts`: a title, a summary, its languages, the placeholders code fills. Defaults render per engine level and shell exactly as they always were (checked line by line in `prompts/registry.test.ts`); your version replaces that rendered text whole and is never patched. The Chinese-only calls are used whatever the app's language.

3. **应用自己的调用：输出格式锁住 / The app's own calls: the answer format is locked.** 代码要按固定格式读回答的那几段，拆成可改的说明和固定的格式：说明里在格式原来的位置有恰好一个 `{format}`，应用在那里填进格式；衔接检查和照样片检查另有 `{item}`（验收原文）和 `{rules}`（规划的规则），Claude Agent 前言有 `{workspace}` 和 `{cwd}`。占位符一遍填完，填进去的规则文字里即使写着 `{format}` 也只是字。参与判断和输入建议的回答从第一个 `{` 读起，所以它们填好之后不能有 `{`。/ The calls whose answers code reads keep their format fixed: the editable text holds exactly one `{format}` where the format always sat, and the app fills it in; the seams and standard judges also take `{item}` and `{rules}`, the Claude Agent preface `{workspace}` and `{cwd}`. Placeholders are filled in one pass, so a rule that says `{format}` stays words. Join judgement and composer answers are read from the first `{`, so those two may hold none once filled.

4. **修订与撤销 / Every change is kept and can be taken back.** 每次改动记一条修订：谁改的（你、经哪张批准卡放行的哪个 Bot、合并新默认的应用）、为什么、前后全文。撤销照 [ADR 0062](0062-retrospective-after-delivery.md) 的规矩：只撤最新的一次，而且只在提示词还是它写下的样子时；之后又改过就是新的，撤销被拒。任何一版都能「恢复这一版」，它会先和现在的默认合并。你在设置里同一次打开编辑器的连续自动保存合成一条。/ Each change is a revision: who (you, a Bot through which approval card, or the app merging a newer default), why, the text before and after. Undo follows ADR 0062: only the latest change, and only while the prompt still says what it wrote. Any version can be restored, merged onto today's default. Your saves in one sitting of the editor fold into one change.

5. **新的默认 / A newer default.** 应用升级带来新的默认时，开库（以及引擎级别抬高）时把它按行三方合并进你的版本：合得干净，就作为应用的一次改动写入，同样能撤销；合不上，你的版本照样生效，设置里标出「默认已更新 · 有冲突」，由你选「保留我的版本」或「换成新的默认」。`check:db` 在库的副本上先跑一遍，说出它会怎么做。/ When an update brings a newer default, it is merged into your version line by line at open (and when the engine level rises): a clean merge is written as the app's change, undoable; one that does not merge leaves yours in force and marks it, for you to keep yours or take the new default. `check:db` runs it on a copy first and says what it would do.

6. **Bot 提改动，你在批准卡上放行 / A Bot proposes; you let it through.** `list_prompts` / `read_prompt` 随时能用，叫停中也能读。`edit_prompt`（改法照 ADR 0062：替换恰好出现一次的原文、在它后面补、末尾追加）和 `reset_prompt` 先在当前文本上套一遍、校验，再出批准卡（种类 `prompt-edit`），卡上是逐处的改动对照和 Bot 写的理由。它不能设成 Always allow：每个 Bot 都读这段话，每一次都该由你放行。你放行时它在那一刻的文本上重新套一遍，等卡期间原文变了就退回让 Bot 重读，不硬改。修订记下是哪张卡放行的、卡在哪条消息上，卡上随后有「撤销这次修改」。/ Reading is free, even under a hold. An edit (ADR 0062's ways: replace a passage that occurs once, add after one, append) or a reset is applied to the current text and checked, then waits on an approval card (`prompt-edit`) showing each change and the Bot's reason. It is never Always-allowed: every Bot reads these. When you allow it, it is applied again to the text as it is then; one that no longer fits goes back to the Bot. The revision names the card and its message, and the card offers an Undo.

7. **读不懂的回答 / Answers that do not read.** 应用自己的调用回答来了却读不了（不是超时、端点出错或写到上限被截断）时，记一条 `prompt.parse_failed`，写明是哪段提示词、哪个修订。设置里每段旁边写着「自这次修改起读不懂 N 次」，没改过的写近 7 天的次数，好看出一次修改有没有把格式改坏。/ An answer to one of the app's own calls that came back and did not read (not a timeout, an endpoint error or one cut off at its cap) is recorded as `prompt.parse_failed` with the prompt and the revision it ran on. Settings show the count since your edit, or over the last 7 days on a default.

8. **东西放哪 / Where things belong.** 系统指令多了一段：每个 Bot 都该照做的写进内置提示词；只关于自己的做法写进自己的技能；学到的事实用 remember；你的要求留在需求台账里、以你的原话为准（[ADR 0042](0042-requirements-ledger.md)），不改写进任何提示词。/ The System section gains a paragraph: what every Bot should do goes into a built-in prompt; how one Bot works into its own skills; a fact into remember; your requirements stay in the ledger in your words (ADR 0042), never rewritten into a prompt.

9. **只在你开口时 / Only when you ask.** 没有后台定时调优：Bot 只在你要它分析、改进时提这类改动；想定期做，就设一个日程。/ No background tuning: a Bot proposes such changes only when you ask it to analyze or improve something; a routine does it periodically if you want.

10. **设置里的「提示词」 / The Prompts tab.** 按组列出（每一轮的系统指令 / Claude Agent / 工具说明 / 应用自己的调用），每条标着默认、谁改的、有没有冲突、读不懂几次；点开是编辑页：停手一秒自动保存，带着你看到的那次修订（别处改过就是 409，载入最新、你没保存的能复制走）；输出格式只读展示，能对比默认、看历史、撤销、恢复、恢复默认（先确认）。手机上同样能看能改。/ Listed by group, each with its state, who changed it, any conflict and unreadable answers; the editor saves a second after you stop, guarded by the revision you saw (a 409 loads the latest and lets you copy what you typed); the format is shown read-only; compare with the default, history, undo, restore, restore default after a confirm. The phone can do the same.

## 缺口 / Not done

- 局面块、回路里的提示（turn-pace、hop-limits、turn-inbox、收尾自检）、转录与控制文案、`INTERRUPT_FLAG`、结构标题和工具的参数说明还不能改。 / The situation block, in-loop notes, transcript and control lines, `INTERRUPT_FLAG`, structural headings and tool parameter descriptions are not editable yet.
- 没有按 Bot 或按会话的变体，没有 A/B；Bot 不能撤销或恢复修订，只有你能。 / No per-Bot or per-conversation variants, no A/B; only you undo or restore.
- 解析失败只有次数，没有分母；也还不能用你改过的提示词跑评估。 / Failure counts have no denominator; evaluations do not yet run on your edited prompts.

## 取舍 / Trade-offs

- **整段替换，不按段覆盖。** 你的版本是一整段；开发者后来改了默认，要靠开库合并接进来。按行合并在系统指令上和按段一样（每段一行），在复盘、反思这种按行写的提示词上更细。/ Whole-text versions: later default changes arrive only through the merge, which works line by line — per paragraph on the System section, finer on line-based prompts.
- **系统指令里点了代码写的名字**（「本轮触发」、规划 / 用户要求 / 已交出 / 经过、工具名）。改掉它们会悄悄对不上，没有守卫。/ The System section names things code writes; renaming them breaks the match silently.
- **合并干净不等于合并对了**：所以它是应用的一次可撤销改动，启动日志里也写明。/ A clean merge is not necessarily a right one: it is an undoable change, logged at boot.
- **每次改动都让端点的前缀缓存失效一次。** / Each change invalidates prefix caches once.
