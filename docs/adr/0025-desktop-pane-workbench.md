# 桌面主栏切成窗格

桌面端主栏从「一次只看一件事」换成一棵可任意纵横分割的窗格树：每块窗格一组标签页，标签可以是一条会话（连同它的预览、设置、流程图、模型选择记录）、一个终端、日程图或工作区。分隔条可拖；两条分隔条交汇的地方横纵两个方向都能拖。窄屏（≤680px）和手机不变，仍是一次一屏、一层层盖上去。

## 与 [ADR 0011](0011-session-first-three-pane.md) 的关系：补充，不取代

0011 在三种结构里选了会话优先三栏，并明确否决了「工作台轨道」。那次否决的是**拿轨道取代会话列表**——侧栏不再是名册。这次不动那件事：侧栏仍然是名册，窗格默认装的仍然是会话，会话窗格里仍然是转录加底栏输入，桌面默认布局也仍然是三栏，且可以一键重置回去。0011 锁的形状在每一块会话窗格**里面**原样成立；变的只是主栏可以被分开。

写成「取代 0011」会给人删掉会话优先外壳的许可，那正好是反的。

## 布局存本机，不进守护进程，也不进 URL

照仓库已有的惯例，没有例外：侧栏宽度、预览宽度、置顶会话全都在信使的 `localStorage` 里。布局按机器才说得通——27 寸上排好的四块窗格还原到笔记本上是错的，推给配对手机更没有意义。

URL 仍然只描述一个视图：当前窗格正看着哪条会话。布局树塞不进查询串，也不该塞——塞了就等于给「哪块窗格在前面」造了第二个真相来源。旧链接（`?o=trace&k=`、`?o=workspace&w=`、`?p=`）照常能开，落进当前窗格。

坏数据整份丢弃回默认布局，不做局部修补：半修好的布局是「工作台坏了但说不清哪里坏」的来源。

## 几条落在这上面的语义

- **Stop 打当前窗格那一轮。**「你正看着的那一轮」在四条会话同时可见时没有定义，所以换成键盘所在的那块窗格。注意**当前窗格不等于最上面那块**：一块浮在上面的终端不该把 Stop 从你正在打字的聊天上抢走。
- **已读跟着每块可见窗格各自计时。** 现有护栏（贴底、停留时长、窗口真的聚焦）本来就是每个转录实例各跑一份。理由是四条对话就在眼前时，只标一条已读会让另外三条继续顶着未读角标、继续发通知。代价写在这里：在线状态心跳一次只报一条会话，所以可见但不是当前的那条仍可能弹一次横幅；要根治得把心跳扩成一组会话 id，是协议加守护进程的改动，另开一票。
- **关标签不杀进程。** 终端标签上的 × 原本直接 `DELETE /v1/terminals/:id`，误点一下就把 `pnpm dev` 杀了。现在 × 只是从这块窗格拿走，结束会话是另一个带确认的动作。
- **会话设置和日程图同时只有一块。** 它们由信使独有一份的状态驱动（未保存草稿、哪个危险确认已就绪），第二块会显示第一块的编辑内容。再打开一次是把那一块挪过来，不是造一个对手。
- **每条会话一块预览、一块流程图。** 起初按「内容完全相同才复用」：点三个附件就是三块预览标签，从流程图卡片上开文件又是另一块，同一条会话的产物散在一排标签里。现在预览和流程图按会话绑定：会话里的附件和文件链接、预览自己的文件树、流程图卡片上的文件都落进这条会话的那一块预览；打开这条会话的另一件事，流程图那一块转过去；只说「打开流程图」不指定哪件事，就只是把它带到前面，不换它正看着的那件。不同会话各有各的。那块预览里有没保存的编辑时，先由它自己的保存 / 放弃 / 取消来问，答了才转过去——它是这条会话唯一的一块，没有「开在旁边」可选。规则落地前存下的布局可能有重复的，载入时只留离键盘最近的那块（当前窗格优先，再按阅读顺序），其余照关标签的方式关掉。

## N 条会话的历史是刻意串行取的

`EventSync` 的缓冲按连接计，`pause()` / `install()` 是全局的一对，两个并发的会话快照读会互相吃掉对方的帧。所以恢复一个四窗格布局是四次**串行**往返，每块窗格各自显示自己的加载态。这是被 `event-sync.ts` 逼出来的，不是疏忽。

## 一套内容，两个宿主

终端、工作区、流程图、模型选择记录各拆成 `XView`（只有内容，填满放它的地方）和 `XOverlay`（窄屏那套壳）。不许出现 `mode` / `phone` 这类 prop——那正是两个宿主开始长出不同行为的方式——并且由 `pane-content-drift.test.ts` 读源码强制执行，不靠自觉。

## 用窗格树而不是全局网格

规范化之后的树有一条性质：每个交汇点恰好有一条连续的分隔条穿过，垂直于它的那些只能抵住它。于是「交汇处两个方向都能拖」是结构上成立的。全局网格能表示四块矩形角对角相碰、没有任何连续分隔条穿过的交点，那里两个方向拖没有定义。

分支是 n 元不是二叉：三栏在二叉树里是 `Row(A, Row(B,C))`，拖 A|B 会让 C 跟着动。
