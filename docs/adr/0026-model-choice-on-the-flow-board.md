# 模型选择记录并入流程图

[ADR 0019](0019-agent-routing-and-review.md) 让每一轮的模型选择、用户后来的反馈和复盘都留下记录，信使里给它们开了单独一屏：会话顶栏的「模型选择记录」，倒序列出这个会话每一轮，可以搜、按结果 / Bot / 模型 / 类别筛。它和流程图说的是同一批轮次——流程图一张卡片是一轮，记录一行也是一轮，键都是 `turn_id`——却分在两个入口、两种排法里：在记录里看见一轮归咎了模型，要回到流程图才知道它在这件事的哪一步、是被谁叫醒、又叫醒了谁；在流程图上看见一轮中断了，要再开记录去找它用的是什么模型。

## 现在

**记录挂在卡片上。** 守护进程给 `/v1/tasks/:id/trace` 的每张 Bot 卡片带上这一轮的 `route`：记录本身、这条纠正链的复盘、以及链结束时记下的经验（复盘和经验只落在开链的那一轮上，链以那一轮命名）。你自己的卡片没有模型，`route` 为空；比模型选择更早的轮次也为空；更早的守护进程不带这个字段，信使当作没有。按这件事的轮次取，不按会话：一件事交接进了 Bot↔Bot 私聊，那边的选择也在同一张图上。

**卡片上一行，点开在卡片下面展开。** Bot 卡片底下写着模型、思考等级和消息类别，有模型反馈、复盘归咎模型、补全失败的各有记号，缩小看全局时记号仍是一眼能认的颜色。点这一行，理由、耗时和跳数、每条反馈（点一下跳回原话）、复盘结论和后效、记下的经验在卡片下面展开，一次只开一张——和卡片上的文件展开是同一种方式，板子照测量重新排。

**找问题是点亮，不是筛掉。** 工具条多两个开关：「有反馈」「归咎模型」，数字是这件事里有几张。打开一个，命中的卡片描边点亮，其余变暗，但都留在原位。原来的记录是一张表，筛掉无关行是对的；流程图的价值在形状，删掉卡片就看不出那一轮在哪一步、牵连了谁。原有的「只看还在进行的，和交出了产物的」仍是筛选，不变。

**没有单独的入口和页面。** 会话顶栏和手机的更多菜单里去掉「模型选择记录」，桌面的侧栏、窄屏的浮层、它的搜索和分面筛选、长列表窗口化都删掉。信使快照里不再存按会话拉的记录。本机接口 `/v1/sessions/:id/routes` 保留，[ADR 0019](0019-agent-routing-and-review.md) 说的「可经本机接口逐会话查看」仍然成立。

**流程图窗格自己保持最新。** 原来只有窄屏那块浮层会在这件事有新的轮次和消息时重读；桌面上的流程图窗格不会，于是一轮在眼前跑完，卡片上仍写着进行中。现在窗格登记它正看着的那件事（`runtime.watchTrace`），同一套事件也让它重读。

## 代价

- **不能再跨事情按会话看。** 一个会话里所有轮次用了什么模型、哪几轮挨了批评，原来一屏就能扫完；现在要在流程图的事情切换器里一件一件看。愿意付这个代价，是因为几乎每次追问模型都是在追问「这件事里这一步为什么这样」，而那正是流程图的问题。需要按会话、按 Bot 横着看时，本机接口仍在。
- **去掉了按模型、Bot、类别的筛选和全文搜索。** 一件事的卡片数通常是几张到几十张，点亮两类问题已经够找；真需要时再按同样的点亮方式加，不回到表格。
