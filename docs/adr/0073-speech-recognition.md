# 语音识别 / Speech recognition

Status: implemented 2026-10-09, at no engine level. Adds a speech endpoint beside the model endpoints of [ADR 0066](0066-anthropic-format-endpoints.md) and [ADR 0067](0067-local-model-servers.md); it is not one of them.

你说的是（2026-10-09）：「让应用支持语音识别，支持接入常见的端点以及自定义端点。」在这之前，输入框只能打字。手机上打长句费劲；电脑上有系统听写，但它不知道你在跟哪个 Bot 说话，也接不了你自己选的服务。

You put it this way (2026-10-09): make the app support speech recognition, with the common endpoints and custom ones. Until now the message box took typing only. Long lines are tiring to type on a phone; a computer has the system's dictation, but that is not a service you chose.

## 决定 / Decisions

1. **一个单独的语音端点，不是模型端点 / One speech endpoint of its own, not a model endpoint.** 语音转文字的服务没有模型名单、思考档、`/models`，也不该出现在 Bot 的模型选择里；Deepgram、ElevenLabs 这类只做语音的服务也接不进模型端点。所以设置 → 模型 里多一张「语音识别」卡：选服务、地址、模型、语言、密钥，存成 `settings` 的 `speech_*` 几行，密钥进钥匙串（`speech-api-key`，和端点的密钥在同一个条目里），读出来是 `Settings.speech`（不带密钥），随快照同步到手机。改它走 `PATCH /v1/speech`，不走 `/v1/settings`：请求回执续写密钥时按字段名从请求体里取，那里的字段是 `endpoint_api_key`，这里是 `api_key`。修订号和设置共用 `settings_rev`。密钥没写进钥匙串时，未完成的凭据里列出来，种类是 `speech`。Bot 没有改它的工具：只有你在设置里改。/ A speech-to-text service has no model list, thinking levels or `/models`, and does not belong in a Bot's model picker; speech-only services such as Deepgram and ElevenLabs could not be model endpoints anyway. So Settings → Models gains a Speech recognition card — service, address, model, language, key — kept as `speech_*` rows in `settings` with the key in the keychain (`speech-api-key`, in the same entry as the endpoints' keys), read back as `Settings.speech` without the key and synced to the phone with the snapshot. It changes through `PATCH /v1/speech`, not `/v1/settings`: a resumed request receipt reads a key back from the body by field name, which is `endpoint_api_key` there and `api_key` here. Its revision is the settings' `settings_rev`. A key the keychain did not take is listed among the unfinished credentials as kind `speech`. No Bot tool changes it: only you, in Settings.

2. **四种接口格式，六个预设加自定义（第五种和第七个预设见 8）/ Four wire formats, six presets and custom (a fifth and a seventh in 8).** `openai`：`POST …/audio/transcriptions`，multipart 的 `file` + `model`（+ `language`），Bearer 密钥，回 `{text}`——OpenAI、Groq、硅基流动，以及照抄它的 Mistral、本机的 Whisper 服务（speaches、faster-whisper-server、LocalAI）。`qwen_asr`：`POST …/chat/completions`，音频作 `input_audio` 的 data URI，语言放 `asr_options`，字在 `choices[0].message.content`——阿里云百炼的千问 ASR。`deepgram`：`POST …/listen?model=…&smart_format=true`，音频就是请求体，`Authorization: Token`，没选语言时 `detect_language=true`。`elevenlabs`：`POST …/speech-to-text`，multipart 的 `file` + `model_id`（+ `language_code`），`xi-api-key`。预设只是填好格式、地址和一个模型，都能改；「自定义」另能选格式。地址照模型端点的填法填到 `/v1`，路径由应用补；贴了整条路径的照用。本机或局域网的地址不要密钥（`isLocalEndpoint`，ADR 0067）。/ `openai`: multipart `file` + `model` (+ `language`) to `…/audio/transcriptions` with a Bearer key, `{text}` back — OpenAI, Groq, SiliconFlow, and those copying it: Mistral, local Whisper servers (speaches, faster-whisper-server, LocalAI). `qwen_asr`: `…/chat/completions` with the audio as an `input_audio` data URI and the language in `asr_options`, the text in `choices[0].message.content` — Qwen ASR on Alibaba Bailian. `deepgram`: the audio as the body of `…/listen?model=…&smart_format=true`, `Authorization: Token`, `detect_language=true` when no language is set. `elevenlabs`: multipart `file` + `model_id` (+ `language_code`) to `…/speech-to-text` with `xi-api-key`. A preset only fills in the format, address and a model, all editable; Custom also picks the format. The address goes up to `/v1` as for model endpoints and the app adds the path; a full path pasted in is used as is. An address on this computer or network needs no key (`isLocalEndpoint`, ADR 0067).

3. **录音原样发，经守护进程 / The recording goes as recorded, through the daemon.** 浏览器用自己的 `MediaRecorder` 录压缩音频（Chrome 是 webm/opus，WebKit 是 mp4），32 kbps；守护进程不转码，按 MIME 给文件取对的扩展名（OpenAI 按扩展名认格式）原样转给服务。`POST /v1/speech/transcribe` 收 `{audio: base64, mime}`，回 `{text}`，不存录音、不写消息、不留请求回执（`isNonReceiptPath`）：重发只是再转一次。密钥只在守护进程里，手机经中继一样能用。/ The browser's own `MediaRecorder` records compressed audio (webm/opus in Chrome, mp4 in WebKit) at 32 kbps; the daemon does not transcode, names the file with the right extension for its type (OpenAI tells the format by it) and passes it on as is. `POST /v1/speech/transcribe` takes `{audio: base64, mime}` and answers `{text}`, storing no audio, no message and no request receipt (`isNonReceiptPath`): a repeat only transcribes again. The key stays in the daemon, so the phone works the same over the relay.

4. **一次录音的上限 / How long one recording may be.** base64 最多 1,000,000 字（`SPEECH_AUDIO_BASE64_MAX`，和批注截图同一个界），整条请求才放得进中继一兆的逻辑消息；按 32 kbps 约四分钟。录音到 3 分钟，或已录的字节到界的九成（有的浏览器不照要的码率录），自己停下去转。不走中继的文件流：那条路只给发消息的附件用，会把文件暂存进附件目录、失败时还写回执。/ At most 1,000,000 base64 characters (`SPEECH_AUDIO_BASE64_MAX`, the bound an annotation's crop has), so the whole request fits the relay's one-megabyte logical message; about four minutes at 32 kbps. A recording stops by itself and is transcribed at 3 minutes, or once its bytes reach nine tenths of the bound (some browsers ignore the bit rate asked for). The relay's file streams are not used: they are for a message's attachments, stage files in the attachments folder and write a receipt on failure.

5. **字进输入框，你来发 / The text goes into the box; you send it.** 麦克风只在语音识别就绪（开着、有地址和模型、有密钥或是本机服务）时出现在输入框旁。点一下开始，输入框上方显示「正在听 0:07」和「不要这段录音」；再点一下停，转出的字插到开录时光标所在处（没有光标就接在末尾，拉丁文字之间补一个空格），录的时候切到别的会话，字进原来那个会话的草稿。不自动发送，不进转录：应用不替你说话（ADR 0070）。没听清、没权限、服务报错都在输入框上方说一句，服务自己的报错原话带上。/ The microphone shows beside the box only while speech recognition is ready (on, with an address and a model, and a key unless the service is local). Press it to start — "Listening 0:07" and "Discard this recording" show above the box — and press again to stop; the text goes in where the caret was when recording started (at the end when there was none, with a space between Latin words), and into the original conversation's draft if you switched away meanwhile. Nothing is sent by itself and nothing enters the transcript: the app does not speak for you (ADR 0070). Nothing heard, no permission, or a refusal from the service is said in a line above the box, with the service's own words.

6. **手机上的麦克风权限 / The microphone on the phone.** 中继发给托管页的 `Permissions-Policy` 原来是 `microphone=()`，页面根本拿不到麦克风；改成 `microphone=(self)`（`deploy/remote/Caddyfile`），只给这一个来源，嵌进来的框还是没有。已经在跑的中继要照改一次头再重载。浏览器第一次用时问你一次。/ The `Permissions-Policy` the relay sends with the hosted page was `microphone=()`, so the page could not reach the microphone at all; it is now `microphone=(self)` (`deploy/remote/Caddyfile`): this origin only, still none for framed content. A relay already running needs the same header changed and a reload. The browser asks you once, the first time.

7. **桌面上的麦克风权限 / The microphone on the desktop.** 窗口带 hardened runtime 签名，没有 `com.apple.security.device.audio-input` 授权就拿不到麦克风，系统也不会问；`Info.plist` 还得写明为什么要用（`NSMicrophoneUsageDescription`）。所以发行包加了 `Entitlements.plist`，`tauri dev` 用的 `Deskfolk Dev.app` 也带上同一份授权和说明。WebKit 那一层的授权由 wry 直接放行，系统第一次用时问你一次。/ The window is signed with the hardened runtime, which keeps the microphone shut without the `com.apple.security.device.audio-input` entitlement, and macOS does not even ask; `Info.plist` must also say why (`NSMicrophoneUsageDescription`). So the release bundle gains `Entitlements.plist`, and `tauri dev`'s `Deskfolk Dev.app` carries the same entitlement and words. WebKit's own permission is granted by wry; macOS asks you once, the first time.

8. **百炼 Token Plan：DashScope 原生接口，沿用端点的密钥 / Bailian's Token Plan: DashScope's own API, the endpoint's key.** 你说的是（2026-10-09）：「我用的是阿里云百炼 Token Plan 里的语音识别，应该用哪个端点」，以及「如果配置了内置的阿里云百炼 Token Plan，就提供快捷使用百炼里的」。Token Plan 套餐里的语音识别模型是 `qwen-audio-3.0-asr-flash`，它不走 OpenAI 兼容的 `chat/completions`（那里 400，回体只有 `{}`；`qwen3-asr-flash` 在 Token Plan 上 404），只认 DashScope 自己的 `POST {主机}/api/v1/services/aigc/multimodal-generation/generation`：音频作 `input_audio` 的 data URI，`parameters` 里必须有 `format`（容器名：webm、ogg、mp4、wav……）和 `sample_rate`，缺了也是 400 `{}`；字在 `output.text`。于是多了第五种格式 `dashscope` 和预设「阿里云百炼 · Token Plan」（地址是主机本身，填 `…/compatible-mode/v1` 也会剥掉再拼）。语言参数不发：它不报错，但填 `en` 照样出中文。另外，语音设置可以不存自己的密钥，而是记一个端点（`speech_key_provider_id`），每次转写时读那个端点的密钥：内置的千问连接器（ADR 0072）接过的百炼端点，卡片上直接提示「用它识别语音」，一按就填好这个套餐的地址和模型并沿用它的密钥——Token Plan 用上面的原生接口，按量付费用它那个 compatible-mode 地址加 `qwen3-asr-flash`。端点换了密钥语音跟着换，端点删了就不再沿用；在语音卡里填了自己的密钥就改用自己的。/ You put it this way (2026-10-09): which endpoint to use for speech on Bailian's Token Plan, and, with the built-in Bailian Token Plan set up, offer a shortcut to Bailian's. Token Plan's speech model is `qwen-audio-3.0-asr-flash`, which does not take OpenAI-compatible `chat/completions` (a 400 whose body is `{}`; `qwen3-asr-flash` is a 404 there) but only DashScope's own `POST {host}/api/v1/services/aigc/multimodal-generation/generation`: the audio as an `input_audio` data URI, and `parameters` must carry `format` (the container: webm, ogg, mp4, wav…) and `sample_rate`, or it is the same 400 `{}`; the text is in `output.text`. Hence a fifth format, `dashscope`, and a preset "Alibaba Bailian · Token Plan" (the address is the host; a `…/compatible-mode/v1` given is cut back). No language is sent: it is accepted and ignored (`en` still came back Chinese). And speech may take a model endpoint's key instead of its own (`speech_key_provider_id`), read at each call: a Bailian endpoint the built-in Qwen connector (ADR 0072) added is offered on the card — "Use it for speech" fills in that plan's address and model and takes its key: DashScope's own API for Token Plan, the endpoint's compatible-mode address with `qwen3-asr-flash` for pay-as-you-go. A new key on the endpoint is the one used next; a deleted endpoint lends nothing; a key typed into the speech card is used from then on.

## 实测 / Measured

2026-10-09，你的 Token Plan 密钥（北京）：`say` 合成的 5 秒中文，原生接口 0.7 秒内回「你好，这是一段语音识别测试。今天是10月9号。」；ffmpeg 做的 webm/opus、ogg/opus、mp4/AAC、m4a 照收，48 kHz 的 webm 报 `sample_rate: "16000"` 也一样；去掉 `parameters` 回 400 `{}`；去掉 data URI 的前缀回 500。按量付费的千问 ASR 没有可用的密钥，只用替身请求测过；套餐条款写明 Token Plan 个人版只用于编程和智能体工具里的交互，语音输入是你在应用里当场按的。/ On 2026-10-09 with your Token Plan key (Beijing): 5 s of `say`-made Chinese came back within 0.7 s as 「你好，这是一段语音识别测试。今天是10月9号。」 through the native API; ffmpeg-made webm/opus, ogg/opus, mp4/AAC and m4a were all taken, a 48 kHz webm declared as `sample_rate: "16000"` the same; without `parameters`, 400 `{}`; without the data URI prefix, 500. Pay-as-you-go Qwen ASR had no working key and is tested against a stand-in only. The plan's terms keep Token Plan (personal) to interactive use inside coding and agent tools; voice input is pressed by you, in the app, as you go.

## 没做的 / Not done

- 边说边出字（流式识别）、按住说话、快捷键、听写的文字直接发出：先看一次一段够不够用。/ Text appearing while you speak (streaming recognition), push-to-talk, a shortcut, sending the text right away: first see whether one recording at a time is enough.
- 系统自带的识别（浏览器的 Web Speech、macOS 的 SFSpeechRecognizer）：前者在 WKWebView 里不可靠、在安卓 Chrome 上发给谷歌，后者要原生插件；都不是你选的服务。/ The platform's own recognition (the browser's Web Speech, macOS's SFSpeechRecognizer): the first is unreliable in WKWebView and goes to Google on Android Chrome, the second needs a native plugin; neither is a service you chose.
- Azure OpenAI 那种按部署名和 `api-version` 拼的地址：现在只能用自定义 + 完整地址凑，密钥头不同则不行。/ Azure OpenAI's addresses built from a deployment name and `api-version`: only reachable as Custom with a full address, and not where its key header differs.
- 让 Bot 设置语音端点的工具。/ A Bot tool for setting the speech endpoint up.
