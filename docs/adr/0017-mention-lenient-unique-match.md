# 点名写错先按唯一可辨的在场成员处理，再拒绝一次，最后留痕

群里 Bot 互相点名靠正文里的 `@名字`，解析一直只认与名册逐字相同的名字。实际转录里出现过导演把「分镜师」写成 `@分镜`：解析对不上，交接无声无息地丢掉，群卡了七分钟直到用户手动纠正。根因不是解析器截断了名字，而是模型凭记忆写名——系统提示只给它自己的人设，`@Name` 的说明不带任何具体名字，在场但最近四十条里没发过言的成员，其准确写法在提示词里根本不存在；「分镜」又是「分镜师」最自然的缩写。因此决策分三层。第一层把名字放进模型眼前：群轮的局面块第一行逐字列出除自己以外的在场成员（`@选题策划、@分镜师、…`），系统提示与 `send_message` 说明要求点名逐字复制、不缩写不省后缀。第二层让解析容错但不猜：精确匹配失败后，取 `@` 后到空白或中英文标点为止的词，若它是**且仅是**一位在场成员名字的前缀或后缀（忽略大小写，至少两个码点），就按那位成员处理，并把「写的什么、当成了谁」记在解析结果里；有歧义或只有一个字一律不认。候选只限在场成员而不是整本名册——精确写名可以把名册里不在场的人拉进群，猜名不该有这种副作用。不做编辑距离之类的模糊匹配：误叫醒一个人比叫不到人更糟，而且不可解释。

第三层是让对不上的 @ 不再静默。`send_message` 在群里遇到对不上的名字时先返回 `unknown_mention`，附上在场成员的完整名字，让模型在同一轮里改正重发；同一个词第二次仍对不上就放行，避免模型固执时无限重试烧钱。发出后（以及模型不经工具、直接以正文回复的路径）由参与处理在群里插一条系统消息「@xx 没有匹配到群成员。在场：…。点名请逐字写全名」，用户当场看见，后续轮次的转录里也有。正文本身不改写：那是模型的原话，静默替换会让转录与模型看到的不一致；信使按同一套规则渲染，缩写能唯一对上时显示成那位成员的完整芯片，对不上时用虚线下划线弱提示。「一人一轮」（ADR 0016）不受影响：被容错解析叫到的成员若已有活轮，同样听进那一轮。
