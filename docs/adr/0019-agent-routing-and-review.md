# 选模型和评判选得对不对，都交给 agent

此前两件事都是机械的。**认反馈**靠一串正则（`isCritiqueMessage`：「换个模型」「太慢」「幻觉」…），**罚多少**是固定权重（命中即负 1，权重 10，正向按 0.25 抵扣，封顶 3）。两头都错：

- 用户真实的不满是「这里不对」→「还是不行」→「算了我自己改」，连着几轮，一个关键词都不命中；而「@导演 你 @ 的分镜不对，群里它叫分镜师」这种点名纠正反倒命中了。本机库里就有这条：它让九个 Bot 各挨一分，`grok-4.6` 在 `general/low` 上得分 −8，从此再没被选中过。
- 被罚的组合拿不到正分（不会被选中就没有干净完成），只能等别的候选也被罚到更低才翻身。ADR 0018 把这条记为「不做探索」，现在它变成了实际故障。
- 罚的方向也丢了。「太慢」和「太浅」指向完全相反的下一次选择，落到经验里都只是一个负数。

整个应用是 agent 优先，这两处不该例外。

## 现在

**一、每开一轮，先由 agent 挑模型和思考等级。**

开轮前发一次**选路调用**：短、无工具、结构化返回。它看到这条触发消息、这个 Bot 的人设、候选名单（名字、支持的思考等级、价格、擅长领域），以及这个 Bot 最近的复盘结论，然后答：

```
model:          候选之一
thinking_level: 该模型支持的一档
reason:         一句话
```

不缓存、不按类别归并——每条消息都可能难易不同，这正是交给 agent 的理由。代价是用户等回复时多一个来回，所以这一跳必须短：只发这条消息和一张表，不带历史转录，输出三个字段。

选路调用自己不能再被路由（否则递归），它固定打到**默认端点的默认模型**——这也是「全局默认模型」现在唯一的职责。

返回不可信时不追问：模型名不在候选里、档位该模型不支持、超时或端点出错，一律落回冷启动规则（见三）并照常开轮，不让用户卡在选路上。Bot 自己钉死了模型和思考等级时跳过这一跳。

**二、评判交给复盘，一条纠正链只跑一次。**

一轮结束不立刻记账。用户还围着同一件事跟进时，这条**纠正链**在长；等它结束——用户换了话题、开了新轮次，或静默超过一段时间——才发一次复盘调用。它看到的是整段而不是一句：触发消息、选了什么模型和思考等级、Bot 的回复、之后用户说的每一句、这一轮怎么结束。

返回结构化结论：

```
fault:      model | task | prompt | none
direction:  stronger | lighter | faster | cheaper | same
rounds:     用户为这件事纠正了几轮
confidence: 0–1
reason:     一句话
```

只有 `fault: model` 留成这个 Bot 的经验。`prompt`（指令没说清、点名写错、需求本来就没讲明白）和 `task`（事情本身难、中途改了需求）一律不留——今天那条点名纠正属于 `prompt`。

留下来的是**结论本身**，不是分数：哪条消息、选了什么、判成什么错、该往哪个方向调、几轮才罢休。下一次选路调用把这个 Bot 最近的若干条结论原样读进去，由它自己权衡，不再有权重、抵扣和封顶。

**三、规则降级成兜底。**

擅长领域、价格、档位轻重仍然在，但只在选路调用不可用时兜底：没配默认端点、调用超时、返回不合法。它不再是主路径，也不再有「惩罚」这个概念——`route_learned` 那张按权重加减的表停用，升级时清掉（它现在装的是错判留下的分数）。

## 取舍

- **每条消息问 vs 缓存成策略**：选了每条消息问。缓存成「消息类别 → 模型」的策略表能把额外延迟降到零，但那又把判断压回了分类器，认不出「这一条特别难」。既然是 agent 优先，就让 agent 每次都看真正的那条消息；代价是每轮多一个来回，用最短的提示和最小的输出把它压到最低。
- **选路失败就走规则，不重试**：用户在等回复，不能为了选得更好而卡住。
- **纠正链的边界靠启发式**：换话题（由同一次选路调用顺带判）、静默超时。判错了最坏的后果是复盘看到的上下文多一点或少一点，不会误伤——`fault` 判定本身还在 agent 手里。
- **静默定时器只在内存里**：守护进程停掉，那条链的复盘就悬着。所以启动时扫一遍：已经安静下来、但还没复盘的链补上，只看最近一天内的，一次最多 20 条。再老的既不再被新轮次接上，也不值得为它付一次补全。
- **复盘也要花钱**：一条纠正链一次调用，比每轮一次省，也比每条消息一次省得多。用轻模型跑。
- **复盘可能判错**：`confidence` 低于阈值的结论不留。留下的结论进模型选择记录，你能看见选路凭什么这么选、复盘又凭什么这么判。

## 不做

- 不做跨 Bot 汇总先验：结论仍归 Bot 自己，删 Bot 一并删掉。
- 不做时间衰减：选路调用只读最近若干条结论，旧的自然滚出窗口，不需要给它们算折旧。
- 不让复盘改人设、技能或端点：它只写自己的结论表。
- 不给选路调用工具，也不让它读历史转录：它只看这一条消息、候选名单和最近的结论。
