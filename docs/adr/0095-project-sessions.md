# 项目会话：按目录和 Agent 直接聊，也能接着终端里的会话 / Project sessions: talk to an agent in a directory, or carry a terminal session on

Status: implemented 2026-10-20. Builds on [ADR 0061](0061-claude-agent-runner.md) (Claude Agent) and [ADR 0092](0092-permission-modes.md) (permission modes). A third kind of conversation beside groups and directs; it has no Bot, and none of the Bot machinery of [ADR 0040](0040-agent-kernel-the-job-owns-state.md) and later runs in it.

2026-10-20 你问能不能把 Agent 的对话接入应用。第一版把导入的会话做成一个新的 Claude Agent Bot；你看过后说：导入的 Agent 会话不该再是 Bot，要和 Claude、Codex 自己的桌面端一样，是一个基于项目目录的会话。追问时你选了：也能在应用里直接新开（选目录和 Agent）；应用只管权限和停止；侧栏按项目分组；先做 Claude Code。

On 2026-10-20 you asked whether an agent's conversation could be brought into the app. A first version made an imported session a new Claude Agent Bot; having seen it, you said an imported agent session should not be a Bot but, as in Claude's and Codex's own desktop apps, a session based on a project directory. Asked further, you chose: such sessions can also be started in the app (pick a directory and an agent); the app keeps only permissions and Stop; the sidebar groups them by project; Claude Code first.

查下来：Agent SDK 有 `resume` 和 `forkSession`。实测（Claude Code 2.1.304、SDK 0.3.289）：在另一个目录 `resume` 一个会话照样找得到；`resume` 加 `forkSession: true` 开出新分支、原会话一条不变；之后再 `resume` 那个分支，上下文一直在。应用里的轮次、批准卡、Stop 和花费都挂在 Bot 上（`turns.bot_id` 不能为空）；直接查 `bots` 表的地方有 58 处，做一个「藏起来的 Bot」迟早从哪里漏出来。

What was there: the Agent SDK has `resume` and `forkSession`. Tried on Claude Code 2.1.304 with SDK 0.3.289: a session resumes from another directory; `resume` with `forkSession: true` starts a new branch and leaves the original untouched; resuming that branch afterwards keeps the whole context. The app's turns, approval cards, Stop and spend all hang on a Bot (`turns.bot_id` is not null), and 58 places query the `bots` table directly, so a "hidden Bot" would leak out somewhere sooner or later.

## 决定 / Decisions

1. **项目会话是第三种会话 / A project session is a third kind of conversation.** `sessions.kind` 多一种 `project`，带目录、Agent（现在只有 `claude_code`）、Claude 账号目录、Agent 自己的会话 id，导入的还记着来源会话。它没有 Bot：参与者只有你，Agent 的话记成作者 `agent` 的行。名字是导入会话的标题，新开的取你的第一句。 / `sessions.kind` gains `project`, with a directory, an agent (only `claude_code` for now), the Claude account directory, the agent's own session id, and for an import the session it came from. It has no Bot: you are its only participant, and the agent's words are lines by the author `agent`. Its name is the imported session's title, or your first line for a new one.

2. **新开或导入 / Started or imported.** 新开：选一个目录（窗口里用系统的文件夹选择，也能直接填路径；Claude Code 会话出现过的目录列在前面），第一轮在那个目录里起 Claude Code，`init` 给的会话 id 记下，之后每一轮 `resume` 它。导入：列出你在终端里开过的 Claude Code 会话（每个账号目录下的 `projects/*/*.jsonl`，最近改过的在前；SDK 起的会话，包括应用自己开出的，和子代理都不列），选一个就开一个项目会话，目录是原会话的目录；你说过的话和 Claude 的正文按原时间补进来（走原会话结束时的那条链，跨过压缩边界；工具调用不逐条导入，最下面一条系统行写来源和省掉了几次），第一轮 `resume 来源 + forkSession`，原会话不变。应用里新开的会话由 SDK 起，终端的 `/resume` 不列它们，这是 SDK 的规矩。 / Started: pick a directory (the system folder picker in the window, or a typed path; directories your Claude Code sessions ran in are offered first); the first run starts Claude Code there and records the session id `init` gives, and every later run resumes it. Imported: your terminal Claude Code sessions are listed (`projects/*/*.jsonl` under each account directory, the most recently changed first; sessions the SDK started, the app's own among them, and subagents are left out); picking one opens a project session in that session's directory. What you said and Claude's text land at their own times (along the chain the session ended on, across compactions; tool calls are not imported one by one, a system line at the bottom says where it came from and how many it left out), and the first run resumes the source with `forkSession`, the original left as it was. Sessions started in the app are started by the SDK, so the terminal's `/resume` does not list them; that is the SDK's rule.

3. **应用只管权限和停止 / The app keeps only permissions and Stop.** 每个工具过 `decideAgentCall`，按应用的权限模式（项目会话没有自己的模式）：自动和全部允许下直接跑，改动先问下出一张批准卡（允许 / 拒绝），只读下拒绝；Claude Code 自己的凭据照样碰不到。Stop 结束这一轮和它起的所有进程。工作、规划、流程图、整理跳、读句、收尾契约、交付审查、监督器、回看、叫停这些都不进项目会话：你的话不经过 `handleInboundMessage`，打「停下」只是一句话，停要按 Stop。 / Every tool goes through `decideAgentCall` under the app's permission mode (a project session has none of its own): auto and allow all run it, ask first puts up an approval card (allow or deny), read-only refuses it; Claude Code's own credentials stay off limits. Stop ends the run and every process it started. Jobs, plans, the flow, the organizer, line readings, the end contract, deliveries and reviews, the supervisor, check-backs and holds stay out: your lines never go through `handleInboundMessage`, and typing 「停下」 is just a line — Stop is the button.

4. **像在终端里一样 / As in the terminal.** Claude Code 读你的用户、项目和本地设置与 CLAUDE.md（`settingSources` 三项都开），系统提示是它自己的，应用不加人设和工具；对话只发你的新话，历史它自己记着。权限仍由应用的 PreToolUse 钩子说了算：它的回答在设置里的放行规则之前。设置里的 MCP 工具和应用没列的工具照旧被拒（以后的事）。`AskUserQuestion` 不开：应用这里没有它的界面。一轮在跑时你再说话，那句话直接送进这一轮，Claude Code 在下一步读到。 / Claude Code reads your user, project and local settings and CLAUDE.md (all three `settingSources`), with its own system prompt and no persona or tools from the app; only your new line is sent, it keeps the history itself. The app's PreToolUse hook still decides permissions; its answer comes before any allow rule in the settings. MCP tools from settings and tools the app does not list are still refused (later work). `AskUserQuestion` is off: the app has no interface for it here. A line you send while a run is going goes into that run, read at Claude Code's next step.

5. **一轮是一条 agent_runs / A run is an `agent_runs` row.** 不动 `turns`：项目会话的每一轮记在 `agent_runs`（状态、等你批准的那一项、正在做什么、出错原因），经 `agent_run.upsert` 事件推给界面；重启时还在跑的记作中断。不记进花费表、不算进每日上限：用量算在它的 Claude 账号上，用量挂件里照样看得到。 / `turns` is left alone: each run of a project session is an `agent_runs` row (status, the approval waiting on you, what it is doing, why it failed), pushed to the interface as `agent_run.upsert`; a run still going at a restart is marked interrupted. Nothing goes into the spend ledger or counts toward the daily cap: the usage is the Claude account's, shown in the usage widget as before.

6. **侧栏按项目分组 / The sidebar groups them by project.** 「项目」一段在「你 ↔ Bot」下面：每个目录一行（目录名，悬停看完整路径），展开是它下面的会话，最近的在前，每个会话前面是它的 agent 的标志：同一个目录可以有不同 agent 的会话；段头的「+」分两项：在文件夹中新开（窗口里直接用系统的文件夹选择），或导入终端会话；每个目录行有自己的「+」，在那个目录直接新开。两个面板都先选 agent，再按目录列出。手机上一样，经同样的路由。 / A 项目 section below 你 ↔ Bot: one row per directory (its name, the full path on hover), unfolding to its sessions, newest first, each led by its agent's mark: one directory can hold sessions of different agents; the section's "+" offers two things, a new session in a folder (the system folder dialog in the window) or a terminal session to import, and each directory row has its own "+" that starts a session right there. Both sheets pick the agent first, then list directories. The phone has the same, through the same routes.

7. **任务地图读得到它在哪干活 / The task map can see where it works.** 2026-10-20 另一个会话做任务地图的原型（地点是目录，角色是 Agent 和子代理，能回放也能实时看），要了两样东西。实时：每个工具调用开始和结束各发一个 `ToolFrame`，`turn_id` 是这一轮的 id，`agent_run` 里有会话、子代理 id（主线为空）、地点、做这一步的模型和时间，结束时还有成没成；不落库。模型按调用 id 从请求它的那条消息上取（子代理的也一样），取不到用这个 Agent 上次的模型，再取不到用这一轮开始时的模型，都没有就是 null。没有另起一种帧，因为没更新的窗口和手机把不认识的帧当成坏掉的事件流、会断开连接，`ToolFrame` 它们当成一个看不见的轮的工具。回放：`GET /v1/project-sessions/:id/replay` 读 Agent 自己的会话文件和它旁边的 `subagents/`，导入的会话连来源文件一起读，返回每个工具调用（时间、主线或子代理、工具、地点、做它的模型、成没成、耗时、Claude Code 记下的放行决定）、子代理（说明、类型、模型、头尾时间）和你说的话（含你回答它的提问）。只算 `assistant` 记录里的调用，同一个 id 只算一次。命令、文件内容和结果都不带出来。地点是项目里的相对路径、项目外的绝对路径（`~/.claude*` 和你列的账号目录单列为 Claude Code 自己的文件），或者测试/类型检查、git；shell 命令按它提到的路径投票，同一目录的文件算一票，平票取靠后的，`claude-code/tool-place.ts`。 / On 2026-10-20 another session prototyping a task map (places are folders, characters are the agent and its subagents, replayed or live) asked for two things. Live: each tool call sends a `ToolFrame` as it starts and as it ends, `turn_id` the run's id, `agent_run` carrying the session, the subagent (null for the agent itself), the place, the model making the step and the time, and on the end whether it went through; nothing is stored. The model is taken by the call's id from the message that asked for it (a subagent's too), else that agent's last known model, else the run's from its start, else null. No new kind of frame: a window or phone older than this reads a frame it does not know as a broken event stream and drops the link, while a `ToolFrame` it takes for a tool of a turn it does not show. Replay: `GET /v1/project-sessions/:id/replay` reads the agent's own session file and the `subagents/` beside it, an imported session's source file too, and returns each tool call (time, the agent or a subagent, tool, place, the model that made it, whether it went through, how long, the permission decision Claude Code wrote down), each subagent (description, type, model, first and last step) and what you said (your answers to its questions included). Only calls in `assistant` entries count, each id once. Commands, file contents and results are not carried on. A place is a path relative to the project, an absolute path outside it (`~/.claude*` and the account directories you listed apart, as Claude Code's own files), a test or type check, or git; a shell command goes where most of the paths it names are, a folder's files counting together, the later on a tie (`claude-code/tool-place.ts`).

8. **放行决定在会话文件里 / The permission decision is in the session file.** 实测（Claude Code 2.1.304，权限模式「改动先问」）：应用的 PreToolUse 钩子做的决定，Claude Code 都写进会话文件，挂在带结果的那条记录的 `permissionDecision` 上，回放照原样给出。钩子直接放行 `{decision: accept, source: hook, reasonType: hook}`；钩子拒绝（比如读 `~/.claude.json`）`{reject, hook, hook}`；先问再在卡上允许 `{accept, user_temporary}`；在卡上拒绝 `{reject, user_reject}`，结果是错误。设置里的规则放行是 `{accept, config, rule}`。所以项目会话里 `user_temporary` 是你在卡上按了允许；在终端里同一个值多半是你回答了 AskUserQuestion。导入的会话：第一轮开出的分支把来源会话的工具调用连同原来的 id 一起抄了过去，所以回放按 id 去重，不会重复。 / Tried on Claude Code 2.1.304 under ask first: every decision of the app's PreToolUse hook is written to the session file, as `permissionDecision` on the entry carrying the result, and the replay gives it as written. A hook allowing a call: `{decision: accept, source: hook, reasonType: hook}`; a hook refusing one (reading `~/.claude.json`): `{reject, hook, hook}`; asked and allowed on the card: `{accept, user_temporary}`; denied on the card: `{reject, user_reject}`, its result an error. An allow rule in settings: `{accept, config, rule}`. In a project session, then, `user_temporary` is you pressing Allow on a card; in a terminal the same value is mostly you answering AskUserQuestion. An imported session: the branch its first run opens copies the source's tool calls with their ids, so the replay, counting each id once, shows none twice.

9. **模型和思考等级可以选 / You can pick the model and the thinking level.** 2026-10-21 你要在接着的会话里也能换模型，随后又要能设思考等级，这把决定 3 放宽了两项。每个项目会话记一个模型（`sessions.project_model`）：空着照你的 Claude Code 设置；选了，每一轮把它作为 `model` 交给 Claude Code。可选的是 Claude Code 的别名 sonnet、opus、haiku、fable，别处设的完整 id 也留作一项。思考等级同样记一个（`sessions.project_effort`）：空着照你的设置，选了每一轮作为 `effort` 交给 Claude Code，可选低、中、高、极高、最大（`CLAUDE_EFFORTS`）；模型不支持的等级由 Claude Code 自己降下来。两个都在输入框底部选，从下一步起生效：正在跑的那一轮经 SDK 的 `setModel` 和 `applyFlagSettings({effortLevel})` 当场换，之后的每一轮开跑时带上。手机经同一条路由 `PATCH /v1/project-sessions/:id {model?, effort?}`，只改带了的那一项。 / On 2026-10-21 you asked to be able to change the model in a carried-on session too, then to set the thinking level, which widens decision 3 by two things. Each project session keeps a model (`sessions.project_model`): empty follows your Claude Code settings; set, every run hands it to Claude Code as `model`. The choices are Claude Code's aliases sonnet, opus, haiku and fable, plus a full id set elsewhere. The thinking level is kept the same way (`sessions.project_effort`): empty follows your settings; set, every run hands it to Claude Code as `effort`, one of low, medium, high, extra high and max (`CLAUDE_EFFORTS`), and Claude Code lowers one its model does not take. Both are picked at the bottom of the composer and take effect from the next step: a run going now switches through the SDK's `setModel` and `applyFlagSettings({effortLevel})`, and every later run starts with them. The phone uses the same route, `PATCH /v1/project-sessions/:id {model?, effort?}`, which changes only what it carries.

10. **它提到的文件点得开 / The files it names open.** 2026-10-21 你说 agent 会话里提到的文件都打不开。查下来是两处：项目会话的聊天视图没接文件链接的点击，点了什么也不发生；接上了也不行，因为链接的路径按应用的工作区找，而 Claude Code 写的路径相对它干活的地方，也就是项目目录或目录里的某个仓库（那次是 `~/trustin` 下的 `steez/`、`web-admin/`、`web-app-v2/`，它写的是 `comm/defs.go`、`src/lib/adminApi.ts`、`server.go`）。现在点开前先问守护进程 `GET /v1/project-sessions/:id/locate?path=`：绝对路径或 `~/` 照写；项目目录下有就用它；否则在项目目录里一层层找路径以它结尾的文件或文件夹（按整段比，不进点开头的文件夹、`node_modules` 和符号链接的文件夹，最多两万项），取最浅的；最浅的有几个就算没找到，并列出它们。界面把找到的绝对路径交给原来的预览（[ADR 0090](0090-the-workspace-bounds-bots-not-you.md) 起绝对路径哪里都打得开）；没找到或有几个时弹提示，不开预览。链接怎么认没有改：`feat/x` 这类带 `/` 的分支名照旧画成链接，点了说没找到。 / On 2026-10-21 you said none of the files an agent session names would open. There were two causes: the project session's chat view never wired the file links' click, so pressing one did nothing; and wired, it would still fail, since a link's path is looked for in the app's workspace while Claude Code writes paths relative to where it was working, the project directory or a repository inside it (that time `steez/`, `web-admin/` and `web-app-v2/` under `~/trustin`, written as `comm/defs.go`, `src/lib/adminApi.ts`, `server.go`). Before opening, the window now asks the daemon `GET /v1/project-sessions/:id/locate?path=`: absolute or from `~/`, as written; there under the project directory, that; else, level by level under the project directory, the file or folder whose path ends in the cited one (whole names; hidden folders, `node_modules` and symlinked folders not looked in; at most 20,000 entries), the shallowest; several at that depth count as none found and are listed. The window hands the absolute path to the preview as before (absolute paths open anywhere since [ADR 0090](0090-the-workspace-bounds-bots-not-you.md)); with none or several, a toast says so and nothing opens. How links are recognised is unchanged: a branch name like `feat/x` still shows as a link, and pressing it says it was not found.

## 取舍 / Trade-offs

- **记忆在应用外 / Memory outside the app.** 项目会话记得什么在 Claude Code 自己的会话文件里，库里的消息只是给你看的。文件被删，下一轮找不到会话就失败，说明原因。 / What a project session remembers lives in Claude Code's own session file; the store's lines are for you to read. If the file is deleted, the next run fails saying it cannot find the session.
- **少了 Bot 的那些 / Without what a Bot has.** 没有交付、审查、流程图和整理；要这些就建 Bot。项目会话也不能被拉进群、被 `@`。 / No deliveries, reviews, flow or organizing; for those, make a Bot. A project session cannot join a group or be `@`-mentioned.
- **只有 Claude Code / Claude Code only.** Codex 的 app-server 有 `thread/resume`，ACP 有 `session/load`（Agent 声明了才有）；`agent` 列为它们留着。本机上 `~/.codex/sessions` 不存在，Codex 的会话要先确认存在哪。 / Codex's app-server has `thread/resume`, ACP has `session/load` (when declared); the `agent` column leaves room for them. `~/.codex/sessions` does not exist on this machine, so where Codex keeps sessions needs checking first.
- **回放靠会话文件 / The replay rests on the session files.** 文件被删就没有回放，和记忆在应用外是同一个取舍；实时的工具帧不落库，错过就只能等回放。 / With the files deleted there is no replay, the same trade as the memory living outside the app; the live tool frames are not stored, so one missed waits for the replay.
- **旧版本的窗口和手机 / Older windows and phones.** 没更新的客户端不认识 `project`，会把这些会话当成「你 ↔ Bot」列出来、没有名字，直到更新。 / A client from before this does not know `project` and lists these sessions under 你 ↔ Bot with no name until it is updated.
- **权限模式只有应用的 / Only the app's permission mode.** 按会话或按项目另选模式以后再说。 / A mode per session or per project is later work.

## 实现 / Implementation

守护进程：`claude-code/sessions.ts`（扫描、读链）、`store/project-sessions.ts`（重建 `sessions` 放进 `project`、新开、导入、消息、`agent_runs`）、`project-runner.ts`（起 Claude Code、权限、批准、Stop、工具帧）、`claude-code/tool-place.ts`（地点）、`claude-code/replay.ts`（回放）、`project-paths.ts`（找它提到的路径）；路由 `GET /v1/runtime/claude-code/sessions`、`POST /v1/project-sessions`、`GET /v1/project-sessions/:id/run`、`GET /v1/project-sessions/:id/replay`、`GET /v1/project-sessions/:id/locate`（它提到的路径在哪）、`PATCH /v1/project-sessions/:id`（模型、思考等级）、`POST /v1/agent-runs/:id/(approve|deny|stop)`，你在项目会话里的话走原来的 `POST /v1/sessions/:id/messages`，只是交给 `project-runner`；手机经同样的路由（`remote/routes.ts`）。界面：侧栏「项目」一段、新开或导入的面板、项目会话的聊天视图。
