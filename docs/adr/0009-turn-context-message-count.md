# 轮次上下文按条数和码点裁，不估 token

## 2026-09-16：保留过大工具结果

8,000 码点的工具结果预算保持不变，但裁剪之前先把完整 JSON 保存到工作区。模型拿到 `full_result_path` 与受限预览，可通过既有 shell 解析、筛选字段和解码内嵌二进制；不能因大图片占满预览而丢失末尾链接，不能把大错误包装成成功。保存路径须通过工作区边界检查，文件独占创建；保存失败明确反馈，不能假称完整内容仍可读。

这不是自动摘要或历史回放：文件只保存本次工具返回，后续仍按需读取。本轮主动排障规则要求 Bot 先检查完整结果与可用替代方法，遵守批准、拒绝、Stop 及副作用约束，再决定是否真正需要用户介入。

## 原始决策

v1 只有一个未知模型的兼容端点，本机没有可靠分词器；用 token 或窗口百分比裁，会和 [花费只透传端点 usage，判断单独记账](0006-spend-passthrough-usage.md) 一样估不准。轮次窗因此按主转录条数和 Unicode 码点从头截，常数写死。人设、系统指令和完整 `tools` 数组永不丢——默默摘 MCP 会让模型幻觉调用，摘人设会让 Bot 不再是那个队友；塞不下让端点报错。历史轮次的 tool 回路不回放：文件正文一旦进下一轮的窗就会把黄金路径撑爆，模型只看见当时落到转录里的 bot 正文。「上次断了」跟 Bot 不跟人设，且只在端点真正返回过 `choices` 之后才烧掉，以免超时或未发出的请求把唯一一次通知吞掉。
