# 界面也是你的：Bot 照你说的改外观和用法 / The interface is yours too: Bots change how it looks and works when you ask

Status: implemented 2026-11-04. Supersedes in part [ADR 0014](0014-bot-catalog-tools.md)'s line that language and appearance are not the Bot's, and clarifies [ADR 0064](0064-built-in-prompts-you-and-your-bots-can-edit.md) decision 1 (the app's shell). Moves focus mode and where windows open ([ADR 0074](0074-where-windows-open.md)) from each window's storage into the daemon; [ADR 0025](0025-desktop-pane-workbench.md)'s rule that layout stays on the machine still holds for the layout and the widths.

2026-11-04 你说：「让用户支持完整的 UI，UX 自定义机制，可以直接通过应用内的 Bot 对话进行」。到这一天，应用的样子只有主题和语言两项存在守护进程里；专注模式、窗口从哪打开、侧栏宽度这些都在各个窗口自己的存储里，守护进程看不到，Bot 也就够不着。令牌集中在 `tokens.css`（约 260 个），组件里六千多处用它们，所以改令牌就能换掉几乎所有颜色、圆角、阴影和字体；但没有注入你自己样式的地方，界面上的字改不了，ADR 0014 还写着「语言和外观是你个人的偏好，不归 Bot」。ADR 0064 定下应用是一份工作方式模板，「内置提示词 + 应用层 UI 壳」，那时只做了提示词。

On 2026-11-04 you asked for full UI and UX customisation, done by talking to a Bot in the app. Until then only the theme and the language lived in the daemon; focus mode, where windows open and the sidebar's width were in each window's own storage, out of the daemon's sight and so out of a Bot's reach. Design tokens sit in `tokens.css` (about 260), used in over six thousand places, so changing a token changes nearly every colour, corner, shadow and font; but there was nowhere to put a stylesheet of your own, the words on screen could not change, and ADR 0014 said language and appearance were your personal preference and not the Bot's. ADR 0064 made the app a template of a way of working — the built-in prompts plus the app's shell — and did the prompts.

## 决定 / Decisions

1. **一份界面方案，叠在应用自己的上面 / One interface profile, laid over the app's own.** 方案有四部分：令牌（`tokens.css` 里有的任何 `--x`，浅色、深色分开设或一起设）、用法（一份固定清单，见决定 4）、自定义 CSS（最多 64 KB）、改过的字（按语言、按位置的键）。默认值仍是代码，方案只覆盖；`enabled` 关掉就回到应用自己的样子，用法照旧。主题和语言还存在设置里，但同一个工具改它们，也记进同一条修订。所有窗口和配对的手机读同一份；CSS 要分设备，就用根上的 `data-surface="desktop|tablet|phone"`。拖出来的宽度和布局照旧只存本机（ADR 0025）。 / Four parts: tokens (any `--x` in `tokens.css`, for the light look, the dark one or both), behaviour (a fixed list, decision 4), a stylesheet of your own (up to 64 KB), and changed words (by language and by where they sit). The defaults stay code; the profile only overrides, and switched off (`enabled`) the app looks as it ships while behaviour holds. Theme and language still live in Settings, but the same tool changes them and the same revision records them. Every window and a paired phone read one profile; a stylesheet that should differ by device keys off the root's `data-surface`. Dragged widths and the layout stay on the machine (ADR 0025).

2. **底线由代码把守 / The floor is kept by code.** 能让你掌控局面的东西不能被盖住：停止按钮、等你的卡片上的按钮、提问卡、去设置的入口、「暂停自定义界面」和撤销界面修改。它们都标着 `data-floor`。每个窗口套用方案之后、以及它们出现的时候查一遍：显示着、祖先累乘的不透明度够、够大、能点、字不透明、中点没被别的盖住。只有方案造成的才算：关掉方案的样式再查一次，那时没问题的才记。不过关的窗口就停掉令牌层和 CSS 层（用法和字照旧），弹一次提示，回报给 Bot。另有两条 CSS 拦不住的回路：地址里加 `?ui=default`，和 ⌥⇧⌘U（Windows、Linux 是 Ctrl+Alt+Shift+U），后者在捕获阶段由页面自己的键盘处理接住，样式管不到它。 / What keeps you in charge cannot be hidden: Stop, the buttons of a card waiting on you, a question card, the way to Settings, pausing the custom interface and undoing a change, each marked `data-floor`. Every window checks them after applying the profile and whenever one appears: shown, solid enough through its ancestors, big enough, taking clicks, its words visible, not covered at its middle. Only what the profile causes counts — checked again with the profile's sheet off, and only what then passes is recorded. A window that fails drops the token and CSS layers (behaviour and words stay), says so once, and reports it for the Bot. Two ways back no stylesheet can take: `?ui=default` in the address, and ⌥⇧⌘U (Ctrl+Alt+Shift+U elsewhere), caught by the page's own key handling before anything else.

3. **Bot 看不见屏幕，窗口替它看 / A Bot cannot see the screen, so the windows look for it.** 桌面窗口每次连上报一次目录：令牌和它们在两种外观下的默认值（从这个窗口加载的样式表里读），应用全部的字和它们的键，应用的版本。每次套用之后报一次回报：眼下一个元素都没选中的选择器、浏览器读不了丢掉的规则、作为颜色读不了的令牌值、被盖住的底线。这两样守护进程只放在内存里，不进库。`[data-ui="…"]` 是二十多个主要区域的稳定钩子，清单在协议包的 `UI_HOOKS`，一条源码测试核对每个都还在，改名会让测试失败，而不是让你的样式悄悄落空。每条修订记下当时的应用版本。 / A desktop window reports a catalog each time it connects — every token with its defaults in both looks, read off the sheets it loaded, all of the app's words with their keys, the app's build — and after each apply a report: selectors matching nothing there just then, rules the browser dropped, token values a colour would not take, floors hidden. The daemon keeps both in memory only. `[data-ui="…"]` marks some twenty-five main parts as stable hooks, listed in the protocol's `UI_HOOKS`; a source test checks each is still there, so a rename fails a test rather than your stylesheet. Every revision records the build it was made against.

4. **用法从固定清单里选 / Behaviour comes from a fixed list.** 专注模式；每种窗口在桌面上从哪打开（只在桌面上）；回车发送还是 ⌘/Ctrl+回车 发送；消息时间按 24 小时或 12 小时；动效跟随系统还是一直减弱。加一项是代码的事：它要有地方读、要能测。专注模式和窗口打开位置原来存在各窗口里，现在进方案：第一个连上的窗口把它自己的选择带进去一次（记成你的一次修改，理由写明是带过来的），之后各窗口都跟方案；守护进程比这旧时还用本机的。 / Focus mode; where each kind of window opens (desktop only); Enter or ⌘/Ctrl+Enter to send; message times in 24- or 12-hour form; motion as the system says or always reduced. Adding one is code's to do: it needs a place that reads it and a test. Focus mode and where windows open move from each window into the profile: the first window to connect carries its own choice in once (recorded as a change of yours, with a reason saying so), and every window follows the profile after; with an older daemon a window keeps its own.

5. **修订与撤销 / Every change is kept and can be taken back.** 每次修改一条修订：谁改的（你，或你让哪个 Bot、经哪张卡改的）、为什么、修改前后的整份记录（连同主题和语言）、当时的应用版本。撤销照 [ADR 0062](0062-retrospective-after-delivery.md)：只撤最新的一次，而且只在界面还是它写下的样子时；任何一版都能恢复。你在设置里同一次打开的连续保存合成一条；改回这一次开始前的样子另记一条，之后再改又是新的（2026-10-07 那条规矩）。Bot 也能恢复某一版，那是一次新的修改。 / Each change is a revision: who (you, or which Bot you asked, through which card), why, the whole record before and after (theme and language included), and the build. Undo follows ADR 0062: only the latest change, and only while the interface still says what it wrote; any revision can be restored. Your saves in one sitting of Settings fold into one; typing it back to how the sitting began is a revision of its own, and what follows starts another (2026-10-07's rule). A Bot may restore a revision too, which is a new change.

6. **是「改」，不是「改配置」 / A change, not a change to the app's setup.** `edit_interface` 碰不到任何工具、端点、提示词或规矩，底线由代码查，每一次都能撤销，所以按权限模式（[ADR 0092](0092-permission-modes.md)）算「改」：自动和全部允许下立刻生效，「颜色再深一点」能一来一回地调；改动先问时出 `ui-edit` 卡，卡上逐项列出改动和理由，能在这个窗口先试看，放行时在当时的界面上再套一遍，套不上就退回 Bot；只读时拒绝。卡上「以后都直接干」把这个 Bot 移到自动，不是全部允许。`describe_interface` 随时能读，叫停中也能。两个工具单成一组「界面」，任何引擎都带着。 / `edit_interface` reaches no tool, endpoint, prompt or rule, the floor is checked by code and every change can be undone, so under the permission modes it is a change: under auto and allow all it applies at once, so "a bit darker" can go back and forth; under ask first it waits on a `ui-edit` card that lists each change and the reason, can be tried in this window first, and is applied again on the interface as it is when you allow it, going back to the Bot if it no longer fits; read-only refuses it. "Allow from now on" on that card moves the Bot to auto, not allow all. `describe_interface` reads freely, under a hold too. The two make a tool group of their own, `interface`, which every engine carries.

7. **只在你开口时改，对话里不多一行 / Only when you ask, and no line of the app's own.** 工具说明要 Bot 只在你要的时候改；没有规则或词表去拦（2026-10-03 起的规矩），修订记录说明是谁、为什么。应用不在对话里写字（[ADR 0070](0070-the-app-stays-out-of-the-conversation.md)）：自动模式下，做出改动的那一轮，Bot 自己的回复下面挂一个「界面已改 · 撤销」小标，和交付文件挂在回复上一样；每个窗口右上角提示一次「某某改了界面」。改动先问时，卡片本身就是那张需要你的卡。在私聊里让 Bot 改界面，归属照 [ADR 0057](0057-the-job-a-line-is-about-is-read.md) 由模型读，读成当场做完就不开事。 / The tool's description has the Bot change it only when you ask; no rule or word list stands in the way (the rule since 2026-10-03), and the revision says who and why. The app writes nothing in the conversation (ADR 0070): under auto, the reply of the turn that made the change carries a quiet "Interface changed · Undo" chip, as a reply carries the files it handed in; each window says once, in its corner, who changed it. Under ask first, the card is the one card that needs you. Asked in a direct, the line's job is read by a model as ADR 0057 says, and read as done in place it opens none.

8. **安全 / Safety.** 样式作为文本放进最后一个 `<style>`，不经过任何标记解析；不能 `@import`，`url()` 只收内联的 `data:image/…`，不能有 `</style>`、`expression()`、`behavior`、`-moz-binding`、`javascript:`。令牌的值不超过 200 字，不能有 `; { } < >`、`url()`、`!important`。两边的 CSP 本来就不让加载外面的东西；手机上不收 `data:` 字体，所以字体只能是系统里有的。改过的字只在应用本来有字的键上生效，原文的 `{占位符}` 一个不能少、也不能多，渲染时照普通文本转义。 / The stylesheet goes into the last `<style>` as text, never through a markup parser; no `@import`, `url()` only for an inline `data:image/…`, no `</style>`, `expression()`, `behavior`, `-moz-binding` or `javascript:`. A token's value is at most 200 characters with no `; { } < >`, `url()` or `!important`. Both pages' CSP already refuse anything from elsewhere, and the phone's takes no `data:` font, so fonts are the system's. A changed word takes only where the app has plain words at that key, with every `{placeholder}` the original had and no other, and renders as text.

9. **设置 › 界面 / Settings › Interface.** 能看、能改、能撤销：开关、用法、令牌（带色块）、自定义 CSS（停手一秒自动保存，带着你看到的那次修订，别处改过就是 409）和可用的钩子、改过的字、修改记录（撤销、恢复这一版）、各种窗口的回报、全部恢复默认。这个窗口暂时用默认界面时写明原因和怎么恢复。手机上同样能用。 / See, change and undo: the switch, behaviour, tokens with swatches, the stylesheet (saved a second after you stop, guarded by the revision you saw; a change elsewhere is a 409) with the hooks it can use, the changed words, the history (undo, restore), each kind of window's report, put everything back. A window showing the default for now says why and how to bring yours back. The phone has it too.

## 后果 / Consequences

- **类名会变，钩子不会 / Class names change; hooks do not.** 写在类名上的样式，应用更新后可能对不上；回报会说哪些选择器不再选中东西。钩子之外的部分不做保证。 / A stylesheet written against class names may stop matching after an update; the report says which selectors no longer match. Nothing beyond the hooks is promised.
- **有几处够不着 / A few places are out of reach.** Monaco、Shiki、PDF、Office 预览只认浅色和深色，自定义配色到不了它们；少数组件自己重定义了令牌（侧栏玻璃下的 `--muted`、`--selection`），根上的覆盖盖不到，要靠 CSS。 / Monaco, Shiki and the PDF and Office previews know only light and dark, so a palette of yours does not reach them; a few components define tokens of their own (`--muted` under the sidebar's glass, `--selection`), which a root override does not reach and only a stylesheet does.
- **字号和间距不是令牌 / Font sizes and spacing are not tokens.** 一千多处写死的字号和间距不随令牌变；整体放大缩小要等桌面窗口的原生缩放做完、在真窗口里核过拖动、编辑器和红绿灯的位置之后再加，现在不在清单里。密度由自定义 CSS 做。 / Over a thousand literal font sizes and paddings do not follow any token. A whole-window scale waits for the desktop window's native zoom, checked in a real window for drags, the editors and the traffic lights; it is not on the list yet. Density is a stylesheet's to do.
- **降级会丢 / A downgrade drops it.** 旧版本不认识这两张表，窗口显示应用自己的样子；专注模式和窗口打开位置回到各窗口自己存的那份。 / An older build knows neither table and shows the app as it ships; focus mode and where windows open fall back to each window's own.
- **没做 / Not done.** 快捷键重绑（匹配散在八处，还有原生菜单的加速键，要先收成一张表）、整体缩放、间距令牌、Bot 写的 HTML 小部件和面板、按会话或按 Bot 的界面、给 Bot 看窗口截图。 / Rebinding shortcuts (their matching is spread over eight places plus the native menu's accelerators, which want one table first), a whole-window scale, spacing tokens, Bot-written HTML widgets and panels, an interface per conversation or per Bot, and showing a Bot a picture of the window.

## 取舍 / Trade-offs

- **改界面不出卡。** 自动模式下 Bot 改完就生效，比提示词宽：提示词每个 Bot 每一步都读，界面只有你看得见。代价是一句话说错，界面就先变了；撤销就在回复下面。要每次都问，就把那个 Bot 设成「改动先问」。 / **No card for a change of look.** Under auto a Bot's change applies at once, wider than for a prompt: every Bot reads a prompt at every step, and only you see the interface. A misread line changes it first; the undo is right under the reply. To be asked every time, set that Bot to ask first.
- **一份方案，不按设备。** 手机和桌面看同一份，分开写靠 `data-surface`。两份方案会让「我改了怎么手机上没变」成为常态。 / **One profile, not one per device.** Phone and desktop read the same one, split by `data-surface` where needed; two profiles would make "I changed it, why didn't the phone?" the usual case.
- **底线查不到对比度。** 文字和背景同色、或用伪元素在按钮上画东西，查不出来；能查的是看得见、点得到、没被盖住。其余靠两条回路和撤销。 / **The floor does not check contrast.** Text the colour of its background, or something drawn over a button with a pseudo-element, gets past it; what it checks is shown, clickable and uncovered. The two ways back and undo cover the rest.

## 实现 / Implementation

- 协议：`packages/protocol/src/interface.ts`（类型、`UI_HOOKS`、`UI_FLOORS`、清单、`applyInterfacePatch` 和校验，两端共用）；`interface.changed` 事件，快照里的 `interface`。 / Protocol: `interface.ts` (types, hooks, floors, the list, `applyInterfacePatch` and its checks, shared by both ends); the `interface.changed` event and the snapshot's `interface`.
- 守护进程：`store/interface.ts`（两张表 `interface_profile`、`interface_revisions`，修订、合并、撤销、恢复，窗口的目录和回报放在内存），`local-api/routes/interface.ts`，`collab-tools/interface.ts` 和 `prompts/tools/interface.ts`（`describe_interface`、`edit_interface`）；手机的路由表放行同样的读写，窗口回报不带请求回执。 / Daemon: the store module with its two tables, the routes, the two tools; the phone's route list allows the same, and a window's report carries no receipt.
- 信使：`src/lib/interface/`（`apply.ts` 套用，`floor.ts` 底线，`report.ts` 回报，`catalog.ts` 目录，`controller.svelte.ts` 每个窗口一个，`behaviour.svelte.ts` 给读用法的地方），`copy.ts` 的 `copyFor(locale, overrides)`，设置 › 界面，`ui-edit` 卡，回复下的撤销小标。 / Messenger: the `interface/` module, `copyFor` with your words, Settings › Interface, the `ui-edit` card and the chip under a reply.
