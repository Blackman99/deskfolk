# 整理模型 / The organizing model

Status: implemented 2026-10-10, at every engine level; extended the same day by [ADR 0077](0077-built-in-models.md), which gives every built-in call (these three each) a model of its own, a Claude model of yours included. Builds on [ADR 0055](0055-lines-read-by-a-model.md), which gave reading lines a model of its own; [ADR 0042](0042-requirements-ledger.md), where the organizer and the scribe keep the plan and the ledger; [ADR 0060](0060-large-jobs-sample-first.md), where the sample check is a gate; and [ADR 0066](0066-anthropic-format-endpoints.md), whose endpoints it can run on. A Claude model of yours (ADR 0061) is left for later.

## 背景 / Context

你说的是（2026-10-10）：「整理这些数据的模型要可以指定，这里要用强模型才可以。」

在这之前，只有读句（ADR 0055）能单独选模型。整理跳、书记员，以及照样片和衔接一致两种检查里请模型对照的那几次，都跑在默认端点的默认模型上；默认模型是为 Bot 干活、为快选的，往往不是强的那个。这次触发它的是 IG MV 那件事：它的进展是 grok-4.7-build-fast 写的，一个为快选的模型。整理是把整份规划读进去、再整份写回来，写错了的进展、要点和任务状态会被每个 Bot 当成事实读到，所以这是最该用强模型的地方，却是最没法单独选的一处。

You said (2026-10-10): the model that organizes this data has to be choosable, and it has to be a strong one.

Until now only reading lines (ADR 0055) had a model of its own. The organizer, the scribe, and the calls in the sample and seams checks that have a model compare all ran on the default endpoint's default model, which is picked for Bots to work on and for speed, and is often not the strong one. What set it off was the IG MV job: its progress was written by grok-4.7-build-fast, a model picked for speed. Organizing reads the whole plan and writes the whole plan back, and a wrong progress line, requirement or ticket state is read as fact by every Bot, so it is where a strong model matters most and where it could least be chosen.

## 决定 / Decisions

1. **一个设置，端点上的模型 / One setting, an endpoint's model.** `Settings.organizer_model` 是 `{ provider_id, model }` 或 null，和读句的 `reader_model` 一个形状，存成 `organizer_provider_id` 和 `organizer_model` 两个设置项。null 跟默认端点的默认模型走（也是没设时的样子，一切和以前一样）；端点删掉、或端点名单不再列这个模型时读成 null，名单上又有了就又是你选的。只收端点上的模型：别的端点 404，名单上没有的模型 422，Claude 模型那一种形状 422。这一版不做 Claude Code：它每次要起一个 `claude`，而整理一次要读整份规划、写整份规划，花的是你的套餐额度，这该由你按用量定，不在这里先替你定。/ The same shape as `reader_model`, stored as two settings. Null follows the default endpoint's default model, which is also how it is before it is set; it reads as null while its endpoint is gone or no longer lists the model, and is your choice again once it is listed. Only an endpoint's model is accepted: another endpoint is 404, a model the list lacks is 422, and the Claude shape is 422. The Claude Code runner is not in this round: it starts a `claude` for each call, and one settle reads and writes a whole plan on your plan's allowance, which is yours to meter, not for this to decide first.

2. **谁用它 / Who uses it.** 整理跳（整理一句话、整理一个规划）、书记员、照样片的判定、衔接一致的判定。四处的目标由一处解出来（`engine/organizer-target.ts`）：选了且能用就是它，否则就是默认端点的默认模型，和以前一样。花费的类别和用途一个不改（整理、书记员、验收检查、看图）。/ The organizer (a line, a plan), the scribe, the sample judge and the seams judge. One place resolves the target (`engine/organizer-target.ts`): the chosen model when it is chosen and usable, else the default endpoint's default model, as before. Spend kinds and purposes are unchanged.

3. **思考档 / Thinking level.** 选了整理模型之后，调用才指定思考档；没选时一个字不变（不指定，端点爱怎么想怎么想）。整理跳和两种判定取 `high`：模型没列 `high` 就取它列出的、不超过 `high` 的最高一档，只列了更高的就取其中最轻的，不取 `xhigh`、`max`（答案和思考共用一个输出上限）。书记员取 `low`，没列就取 `none` 以上最轻的一档，它每句话都跑、没有哪一轮在等它。目录里没列任何一档的模型不发思考档。/ A thinking level is named only for a chosen model; with none chosen nothing changes (none named, the endpoint thinks as it likes). The organizer and both judges take `high`: when the model does not list it, the highest it lists up to `high`, and when it lists only higher ones the lightest of those, never `xhigh` or `max` while `high` is there (the answer shares one output cap with the thinking). The scribe takes `low`, else the lightest above `none`: it runs on every line and no turn waits for it. A model whose catalog lists no level is sent none.

4. **看图的判定 / The calls that send pictures.** 两个判定有时发图（样片的帧、接缝的前后两张），有时只发文字。发图的那一次，选的模型必须在模型属性里标了「能看图」（`input_image: true`）；没标（不知道）或标了看不了，这一次改用默认模型，不报错、不停下。只发文字的判定（文字接缝、整体摘要、文字样片）不受这条限制，用整理模型。不知道算不能：别处把「不知道」当成能，是因为错了只是一轮要换模型；这里错了是一个门禁判不出来。/ The judges send pictures at times (the sample's frames, the two sides of a seam) and words at others. A call that sends pictures runs on the chosen model only when its attributes mark it as taking pictures (`input_image: true`); unmarked (not known) or marked as not, that one call uses the default model, with no error and no stop. A judge that sends only words (a text seam, the whole-set digest, a text sample) is not held to it and uses the organizing model. Unknown counts as unable: elsewhere unknown counts as able, because a wrong guess costs one turn on another model; here it would be a gate that cannot judge.

5. **设置里 / In Settings.** 设置 → 模型里多一页「整理模型」，排在「读句用的模型」后面：一个下拉，「跟随默认模型（X）」加每个端点的每个模型，不列 Claude 一组；页上的说明写明这里要用强模型，在 opus 上一次整理大约输入 20k、输出 6k token，以及看图判定的退回。读句和整理模型共用一张卡片组件（`SideModelCard.svelte`），标题、跟随默认的文案、存哪个设置项、要不要列 Claude 模型是它的参数。手机的列表上这一行写着现在选的是哪个模型。Bot 的 `update_model_settings` 和 `list_endpoints` 也带 `organizer_model`（只收端点上的模型），和读句一样直接执行；手机的设置补丁也放行它。/ A page, Organizing model, after the reading model: one select, "Follow the default model (X)" plus every model of every endpoint, with no Claude group; the page says to use a strong one, about 20k tokens in and 6k out per settle on Opus, and what the picture checks fall back to. The two settings share one card component, with the title, the follow-the-default wording, the setting it saves and whether Claude models are offered as its parameters. On a phone the list row names the choice. A Bot's `update_model_settings` and `list_endpoints` carry `organizer_model` too (an endpoint's model only), running at once like the reading model; the phone's settings patch lets it through.

## 后果 / Consequences

- **花费 / Cost.** 选一个强模型，整理一次是实打实的一笔：opus 上约输入 20k、输出 6k token，比一次读句或书记员大得多；每个规划静下来 30 秒后还要整理一次，每句话还有书记员。花费视图仍按原来的类别和用途记，所以看得到整理跳和书记员各花了多少，也看得出判定里看图的那一部分。选了才花，不选一个字不变。/ A strong model makes one settle a real cost, about 20k tokens in and 6k out on Opus, far more than a reading or a scribe note; each plan settles again after 30 quiet seconds, and every line has its scribe. The spend view books it under the same kinds and purposes as before, so you can see what the organizer and the scribe each cost and the picture part of the judges. It costs only when chosen; unchosen, nothing changes.
- **输出上限 / Output cap.** 思考算在输出上限里。整理一次的上限从 4096 提到 16384 token：`high` 的思考加上写回整份规划，4096 在会思考的模型上留不下多少给答案；这是上限，不是用量，用不到不花。书记员 800、两个判定各 1024 不变：上限不到 2048 时，Anthropic 格式只带 effort、不开思考，答案不会被思考挤掉。/ The thinking counts inside the output cap. A settle's cap goes from 4096 to 16384 tokens: `high` thinking plus the whole plan written back left a thinking model little room for the answer at 4096; it is a ceiling, not a spend. The scribe's 800 and each judge's 1024 stay: under a 2048 cap the Anthropic format sends the effort alone and no thinking, so the answer is not crowded out.
- **看图退回 / Picture fallback.** 选的整理模型没标「能看图」时，看图的判定悄悄用默认模型，设置页的说明里写了这一点；没有另一个警告。模型属性里把它标上「能看图」就生效。/ A chosen model not marked as taking pictures leaves the picture judges on the default model, which the page's intro says; there is no separate warning. Marking it "takes pictures" in its attributes turns it on.
- **没做的 / Not done.** Claude Code 的 Claude 模型来整理（上面第 1 条）；按用途分别选（整理跳一个、书记员一个、判定一个）：先看一个设置够不是；其它后台调用（完工复盘、选路、收尾核对、输入建议）仍跟默认模型走。/ A Claude model through Claude Code for organizing (decision 1); a separate choice per use (organizer, scribe, judges), to see first whether one setting is enough; the other background calls (retrospectives, routing, closing checks, input suggestions) still follow the default model.
