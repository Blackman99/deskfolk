# 内置连接器 / Built-in connectors

Status: implemented 2026-10-09, at no engine level. It amends the CONTEXT entry on the model endpoint and [ADR 0066](0066-anthropic-format-endpoints.md) (Anthropic's own address had not been tested).

你说的是（2026-10-09）：「我用 Anthropic 官方的配置，获取不到模型」，接着是「正好把小米，千问，Anthropic 官方都做系统内置连接器，只要配置 key 即可，记得卡片加上对应的 LOGO」。获取不到模型的原因：你的 key 是 `sk-ant-usr-` 开头的个人 key，没限定到某个工作区，Anthropic 要求这种 key 的每个请求都带 `anthropic-workspace-id`，否则一律 400；应用没地方填它，报错又在第 150 个字处截断，正好截掉了「加上这个头，或者换一把限定了工作区的 key」。这把 key 也列不出工作区（403 `permission_error`），所以应用没法替你查到 ID。之后你把工作区 ID 填进了密钥栏，存下来盖掉了原来的 key，从那以后每个请求都按无效 key 被拒。小米和百炼的问题是另一种：同一家按套餐和地区分好几个地址，每个地址只认自己那套 key，填错地址就是 401，而地址得自己去控制台抄。

You put it this way (2026-10-09): "with Anthropic's own settings I can't fetch the models", then "make Xiaomi, Qwen and Anthropic built-in connectors that only need a key, and put each one's logo on its card". The models could not be fetched because the key was a personal one (`sk-ant-usr-…`) not scoped to a workspace: Anthropic refuses every request with such a key (400) unless it names one in `anthropic-workspace-id`. The app had nowhere to put it, and the error was cut at 150 characters — just before "Add the header, or use an API key that is scoped to a workspace." The key cannot list workspaces either (403 `permission_error`), so the app cannot look the ID up. The workspace ID was then typed into the key field and saved over the key, and every request after that failed as an invalid key. Xiaomi's and Bailian's trouble is different: one vendor serves several addresses, by plan and region, each taking only its own keys — the wrong one is a 401 — and the address had to be copied from the vendor's console.

## 决定 / Decisions

1. **连接器是一组已知地址，不是存下来的一种端点 / A connector is a set of known addresses, not a kind of endpoint stored.** 协议包里的 `CONNECTORS` 列出三家（`anthropic`、`xiaomi`、`qwen`），各自的格式和套餐地址；一个端点是不是某家的，看它的 base URL 是不是那家的某个套餐（`connectorFor`：大小写、末尾斜杠、Anthropic 格式末尾的 `/v1` 不算差别，格式要一致）。库里不多一列：已有的端点（你的「小米」「阿里百炼」「My Anthropic」）一打开就是对应的连接器，带上 LOGO；手填同一个地址的也一样。名称仍是你起的。/ `CONNECTORS` in the protocol package lists the three (`anthropic`, `xiaomi`, `qwen`), each with its format and plan addresses; an endpoint is a connector's when its base URL is one of that connector's plans (`connectorFor`: case, trailing slashes and, in Anthropic's format, a trailing `/v1` make no difference; the format must match). No column is added: existing endpoints (your "小米", "阿里百炼", "My Anthropic") open as their connector, logo and all, and an address typed in by hand does too. The name stays yours.

2. **套餐由 key 找出来 / The plan is found from the key.** 添加端点先出四块：三家和「自定义」。选了一家，表单只有名称和密钥（Anthropic 多一栏工作区 ID）；填好 key，应用拿它依次问各套餐的模型名单，401 就问下一个，第一个认的就用它的地址和名单；别的拒绝（要工作区的 400、5xx、连不上）说的是请求而不是 key 是谁的，就停在那里照实说。一个一个问而不是同时问：同一把 key 不必同时出现在几个地址的日志里。没有哪个套餐认之前地址是空的，自动保存什么也不建。套餐也能手动选，手选只问选的那一个。改已有端点的 key 会重找一遍，先问它现在的套餐。/ Adding an endpoint starts on four tiles: the three and Custom. A connector's form has the name and the key (Anthropic adds a workspace ID); once the key is in, the app asks each plan's model list in turn, moves on at a 401, and keeps the address and list of the first that takes it. Any other refusal (a 400 asking for a workspace, a 5xx, no connection) is about the request rather than whose key it is, so the search stops there and says so. One at a time rather than all at once, so one key is not in several vendors' logs at once. The address stays empty until a plan takes the key, so the autosave creates nothing. A plan can also be picked by hand, which asks only that one. A new key on an existing endpoint searches again, its current plan first.

   套餐清单只收官方文档写了、或者实测地址存在的：小米 Token Plan 中国 / 新加坡 / 欧洲（`token-plan-{cn,sgp,ams}.xiaomimimo.com/v1`）和按量付费（`api.xiaomimimo.com/v1`）；百炼 Token Plan（北京，`token-plan.cn-beijing.maas.aliyuncs.com/compatible-mode/v1`）和按量付费北京 / 国际（`dashscope{,-intl}.aliyuncs.com/compatible-mode/v1`）；Anthropic 只有 `api.anthropic.com`。百炼 Coding Plan 不收：它的模型名单不验 key（假 key 也 200），没法用来认；它的条款也只许编码工具用。百炼新加坡的 Token Plan 地址只在一份 CDN 配置示例里出现过，不算文档。/ Only addresses documented by the vendor, or found to exist, are listed: Xiaomi's Token Plan for China, Singapore and Europe (`token-plan-{cn,sgp,ams}.xiaomimimo.com/v1`) and pay-as-you-go (`api.xiaomimimo.com/v1`); Bailian's Token Plan (Beijing, `token-plan.cn-beijing.maas.aliyuncs.com/compatible-mode/v1`) and pay-as-you-go Beijing and international (`dashscope{,-intl}.aliyuncs.com/compatible-mode/v1`); Anthropic's `api.anthropic.com` alone. Bailian's Coding Plan is left out: its model list does not check the key (a made-up one gets a 200), so it cannot be told apart that way, and its terms keep it to coding tools. A Singapore Token Plan address for Bailian appears only in a CDN configuration example, which is not documentation.

3. **Anthropic 工作区 ID / An Anthropic workspace ID.** `providers.workspace_id`（可空，`wrkspc_` 加字母数字），有就随这个端点的每个请求发 `anthropic-workspace-id`：轮次补全、判断、读句、整理、测速和探模型名单都发，类型上是必填的 `workspaceId: string | null`，漏传过不了类型检查。只有 Anthropic 自己的地址显示这一栏；别的 Anthropic 兼容地址用不上它。Bot 的 `add_endpoint` / `update_endpoint` 也能带：改它和改 URL、格式一样要批准，默认端点的改不了。密钥栏里填的是 `wrkspc_…` 时，表单当场说它该填到哪一栏，也不拿它去试；工作区栏格式不对也当场说。/ `providers.workspace_id` (nullable, `wrkspc_` and letters and digits), sent as `anthropic-workspace-id` with every request on that endpoint: turn completions, judgements, readings, the organizer, the speed test and the model-list probe. The type is a required `workspaceId: string | null`, so a path that drops it does not compile. Only Anthropic's own address shows the field; other Anthropic-compatible addresses have no use for it. Bots' `add_endpoint` / `update_endpoint` take it too: changing it needs approval like a URL or format change, and the default endpoint's cannot be changed. A `wrkspc_…` typed into the key field is pointed to its own field on the spot and never tried; a malformed workspace field says so as it is typed.

4. **拒绝的原话 / What a refusal says.** 拉模型名单被拒时，横幅里是对方 JSON 错误里的 `message`（最多 400 字），不是响应体的前 150 字；不是 JSON 的才截前 150 字。/ A refused model-list request shows the `message` of the vendor's JSON error (up to 400 characters) rather than the first 150 characters of the body; a body that is not JSON is cut at 150 as before.

5. **LOGO / The logos.** 端点卡片、添加时的四块、编辑页标题和首次向导的预设上，三家各用自己的 LOGO，放在自己品牌色的底上（Anthropic 象牙底、小米橙底、千问白底），浅色深色主题一个样：LOGO 不跟主题。字形取自 lobe-icons（MIT），商标归各家，见 THIRD_PARTY_NOTICES。卡片上地址后面多一个套餐标签（只有一个套餐的不标）。/ The endpoint card, the four tiles, the editor's heading and the first-run wizard's presets show each vendor's logo on its brand's own tile (ivory for Anthropic, orange for Xiaomi, white for Qwen), the same in both themes: a logo is not themed. The glyphs come from lobe-icons (MIT); the trademarks are their owners' (see THIRD_PARTY_NOTICES). The card adds the plan beside the address (not for a single-plan connector).

6. **首次向导 / The first-run wizard.** 预设里多了小米 MiMo 和千问；选了先填第一个套餐的地址，拉模型名单时按上面的办法找套餐，找到就换成那个地址。Anthropic 预设多一栏工作区 ID。向导仍然显示地址和格式：它一直是可以改地址的那种表单。/ The presets gain Xiaomi MiMo and Qwen; picking one fills in the first plan's address, and fetching the list searches the plans as above, switching to the address found. The Anthropic preset gains the workspace ID. The wizard still shows the address and format: it has always been a form where the address can be edited.

## 实测 / Measured

2026-10-09，一个独立的运行时（全新的数据目录、端口 17991，key 只在内存里）加 worktree 的 Vite，Playwright WebKit：

- 小米：你的 `tp-` key 只在 `token-plan-cn` 上 200（8 个模型），新加坡、欧洲和按量付费都 401。向导里选「小米 MiMo」、贴 key，第一个套餐就认了，下一步列出 8 个模型，保存后建出的端点在 `token-plan-cn`。
- 百炼：你的 `sk-sp-` key 在 Token Plan 上 200（16 个模型），按量付费北京和国际 401；Coding Plan 也 200，但随便一把假 key 同样 200。设置里「添加端点」→「千问」→ 贴 key，建出的端点在 Token Plan，16 个模型。
- Anthropic：这把个人 key 不带工作区时，`/v1/models` 回 400「This API key is not scoped to a workspace, so this request must include the anthropic-workspace-id header with the ID of the workspace to use. Add the header, or use an API key that is scoped to a workspace.」，`x-api-key` 和 Bearer 一样；`/v1/organizations/workspaces` 回 403。之后钥匙串里这一项变成了工作区 ID，两种发法都是 401「invalid x-api-key」/「Invalid bearer token」，表单如实说 Anthropic 不认这把 key。
- 卡片：宽屏和 iPhone 13 宽度下，两张卡片都换成了 LOGO，地址太长时自己省略，套餐标签不被挤掉；选四块的那一页在手机上是单列。页面没有报错。

On 2026-10-09, with an isolated runtime (a fresh data folder, port 17991, keys only in memory), the worktree's Vite and Playwright WebKit:

- Xiaomi: your `tp-` key gets a 200 only from `token-plan-cn` (8 models); Singapore, Europe and pay-as-you-go are 401. In the wizard, picking Xiaomi MiMo and pasting the key: the first plan took it, the next step listed the 8 models, and the endpoint saved is on `token-plan-cn`.
- Bailian: your `sk-sp-` key gets a 200 from the Token Plan (16 models) and 401 from pay-as-you-go Beijing and international; the Coding Plan answers 200 too, but so it does for any made-up key. In Settings, Add endpoint → Qwen → paste the key: the endpoint is created on the Token Plan with 16 models.
- Anthropic: without a workspace, this personal key's `/v1/models` is a 400, "This API key is not scoped to a workspace, so this request must include the anthropic-workspace-id header with the ID of the workspace to use. Add the header, or use an API key that is scoped to a workspace.", sent either way; `/v1/organizations/workspaces` is a 403. Once the Keychain held the workspace ID in its place, both ways were 401 ("invalid x-api-key" / "Invalid bearer token"), and the form said "Anthropic does not take this key".
- Cards: at desktop width and at iPhone 13 width both cards show the logo, a long address truncates itself and the plan label stays whole; the four-tile page is one column on a phone. No page errors.

## 没测的 / Not tested

- Anthropic 带上工作区 ID 的真实请求：测的时候那把 key 已经被工作区 ID 盖掉了，要你重新填上。/ A real Anthropic request with a workspace ID: by then the key had been overwritten by the workspace ID; it needs the key entered again.
- 小米按量付费、新加坡和欧洲的 key，百炼按量付费的 key：这台机器上没有。/ Xiaomi pay-as-you-go, Singapore and Europe keys, and Bailian pay-as-you-go keys: there are none on this machine.

## 没做的 / Not done

- 替你列出工作区：个人 key 调不了组织接口（403）。/ Listing the workspaces for you: a personal key cannot call the organization API (403).
- 更多厂商（DeepSeek、Kimi、智谱……）：加一家就是在 `CONNECTORS` 里加一行、在文案里加名字和套餐名、配一个 LOGO。/ More vendors (DeepSeek, Kimi, Zhipu…): one more is a row in `CONNECTORS`, its name and plan labels in the copy, and a logo.
- 按 key 的前缀猜套餐：前缀没有文档，挨个问一遍也就一两秒。/ Guessing the plan from the key's prefix: prefixes are not documented, and asking each plan takes a second or two.
