# 批注是带锚点的引用回复

产物交出来之后，你能给的反馈只有一句追问，指不到「这一段」「这个角落」「第三页那张图」。Bot 拿到的是整份产物加一句话，先得猜你说的是哪里。

## 现在

**批注是带锚点的引用回复，不是新的消息种类。** 一条批注挂在一个工作区相对路径、一个锚点（行区间 / 图片框 / PDF 页内区域 / HTML 元素 / 时间点）和交出这个产物的那条消息上。发出去时合成一条 `kind = user` 的消息：`parent_id` 指到交付消息的根，正文前面补上交付 Bot 的 `@名字`，再接你的总话。开轮、点名、参与规则照旧，复盘也照旧——它就是交付那一轮的一条后续发言，进纠正链，不加权。

**草稿存库，攒一批再发。** 草稿以守护进程为准（`annotations` 表 + `annotation.upsert` / `annotation.removed` 事件），窗口崩了或换到手机上都还在，Bot 看不见。`POST /v1/annotations/send` 在一个事务里建消息、把这批草稿转成「待处理」；一批里有不属于这个会话的、已经发出的，或超过 50 条，整批拒绝。

**有状态，不存旧版本。** 待处理 / 已处理由 Bot（`resolve_annotation`，必须写一句怎么改的）或你切换；已处理的可以重新打开。库里只记当时的引文、位置和文件哈希，陈旧与否每次现算：文本按「引文 + 前后缀」重新定位，定位到了显示新的行区间，定位不到标「原文已变」；其它种类哈希变了就标「文件已变」。不做快照副本、不做 diff 视图。

**Bot↔Bot 私聊里的产物，批注改发到你的私聊。** 你不是那条私聊的参与者，发不进去。这批落到你和交付 Bot 的 1:1 私聊里（没有就建一条），消息没有 `parent_id`，改记 `annotation_source_message_id`，信使据此画出跳回原消息的链接。

**叫醒的那一轮沿用交付那一轮的工作目录。** `resolveTurnTask` 接受一个显式指定的 task：批注消息叫醒的轮次取交付那一轮的 task，哪怕会话已经静默超过六小时、那件事已经关了——关了就重新打开，这个会话里当前开着的那件按现有规则关掉。改的是同一件交付物，就在同一个文件夹里改。

## 不做

- 不保存旧版本、不做 diff 视图（术语表「产物」里 Avoid 快照副本这一条不变）。
- Bot 不给你批注，Bot 之间不互相批注：批注只从你这里发出。
- 批注不进模型选择记录、不当模型反馈：到底是谁的错仍由复盘判断。
- 链接类产物不能批注。
- 每条批注不单独叫醒一次：一批一条消息，一次叫醒。
