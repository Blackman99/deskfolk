# 项目会话里的计划模式和斜杠命令 / Plan mode and slash commands in project sessions

Status: implemented 2026-10-22. Builds on [ADR 0095](0095-project-sessions.md) (project sessions) and [ADR 0092](0092-permission-modes.md) (permission modes).

2026-10-22 你问应用里的 Claude Agent 能不能支持 CLI 的一些功能，比如命令和 plan mode；看过现状后说「做一下」。项目会话本来就是照终端的样子做的（ADR 0095 决定 4），这两样放在项目会话里；Bot 那一路的提示词、工具和规划由应用接管，不放。

On 2026-10-22 you asked whether the Claude Agent in the app could support some of the CLI's features, such as commands and plan mode; having seen where things stood, you said "do it". A project session is already made to be like the terminal (ADR 0095, decision 4), so both go there; a Bot's prompt, tools and planning are the app's, and they stay out of it.

查下来（Claude Code 2.1.307、SDK 0.3.289，选项和项目会话的一样）：

- **斜杠命令**：一句以 `/` 开头的话原样交给 Claude Code 就会执行。`/context` 在本地回一张用量表，不花 token；`/compact` 压缩上下文，结果是空的；`/clear` 开一个新的会话 id，结果也是空的；手打的 skill（`/simplify`）不用 `Skill` 工具也会展开。`/config`、`/mcp`、`/agents`、`/usage`、`/model` 都回一段文字，不会卡住。不带提示词起一次会话问 `supportedCommands()`，大约 1.5 秒，不花用量，列出 74 条：Claude Code 自己的，加上账号里的 skill 和插件命令。`init` 另把 `doctor`、`color`、`focus`、`reload-plugins` 标成只在终端里用。
- **计划模式**：以 `permissionMode: "plan"` 起跑，或者跑到一半 `setPermissionMode("plan")`（下一步生效，`status` 消息报出新模式）。Claude Code 把计划写进账号配置目录下的 `plans/<名字>.md`，再调 `ExitPlanMode`。钩子和 `canUseTool` 收到的输入里有 `plan`（计划全文）和 `planFilePath`，SDK 的类型里没写这两项。批准时回 `updatedPermissions: [{type: "setMode", mode: "default", destination: "session"}]`，Claude Code 就离开计划模式接着干。计划模式本身挡不住命令：你的设置里有 `Bash(*)` 这类放行规则时，钩子不表态，计划模式里的 `touch` 照样跑了。应用的钩子一放行，设置里的规则和计划模式就都管不着了。而应用现在把计划文件当 Claude Code 的凭据拦着，计划写不进去。

What was there (Claude Code 2.1.307, SDK 0.3.289, with a project session's options):

- **Slash commands**: a line starting with `/`, handed to Claude Code as it is, runs. `/context` answers a usage table locally and spends no tokens; `/compact` compacts the context and answers nothing; `/clear` starts a new session id and answers nothing either; a typed skill (`/simplify`) expands without the `Skill` tool. `/config`, `/mcp`, `/agents`, `/usage` and `/model` each answer a line of text and do not hang. A session started without a prompt answers `supportedCommands()` in about 1.5 s, spending nothing, with 74 rows: Claude Code's own plus the account's skills and plugin commands. `init` also marks `doctor`, `color`, `focus` and `reload-plugins` as the terminal's own.
- **Plan mode**: a run starts in it with `permissionMode: "plan"`, or switches mid-run with `setPermissionMode("plan")` (from its next step; a `status` message names the new mode). Claude Code writes its plan to `plans/<name>.md` under the account's config directory, then calls `ExitPlanMode`. The input the hook and `canUseTool` get carries `plan` (the whole plan) and `planFilePath`, though the SDK's types do not list them. Answering with `updatedPermissions: [{type: "setMode", mode: "default", destination: "session"}]` takes Claude Code out of plan mode and on to the work. Plan mode stops no command by itself: with an allow rule such as `Bash(*)` in your settings and the hook saying nothing, a `touch` ran in plan mode. Once the app's hook allows a call, neither the settings' rules nor plan mode have a say. And the app kept the plan file off limits as Claude Code's credentials, so no plan could be written.

## 决定 / Decisions

1. **计划模式是会话自己的开关 / Plan mode is the session's own switch.** `sessions.project_mode` 是 `plan` 或空，`PATCH /v1/project-sessions/:id` 带 `mode` 改它。开着时这个会话的每一轮都以计划模式起跑；跑到一半切换，下一步生效。输入框里有「计划」开关，Shift+Tab 也能切，和终端一样。计划被批准后开关自动关上。不提供 `EnterPlanMode`：只有你能打开计划模式，开关上看到的就是它的状态。 / `sessions.project_mode` is `plan` or null, changed by `mode` on `PATCH /v1/project-sessions/:id`. While it is on, every run of the session starts in plan mode; switched mid-run, it takes effect from the next step. The composer has a Plan switch, and Shift+Tab flips it as in the terminal. An approved plan turns it off. `EnterPlanMode` is not offered: only you turn plan mode on, so the switch shows what it is.

2. **计划模式下只改计划 / In plan mode only the plan changes.** 规则在 `decideAgentCall` 里（`plan: { on, dirs }`）。原则：打开计划模式只会更严，应用的权限模式本来要问或要拒的调用，计划模式下不会放过。 / The rules are in `decideAgentCall` (`plan: { on, dirs }`). The principle: turning plan mode on only tightens; a call the app's permission mode would ask about or refuse is never let through by it.
   - 写文件：计划文件夹（账号配置目录下的 `plans/`）里直接写，每种权限模式都是，只读也是：那是 Claude Code 自己的草稿，和待办清单一样，不在项目里。别处的写一律拒绝，告诉它先用 `ExitPlanMode` 交计划。 / Writes: into the plans folder (`plans/` under the account's config directory) they run, in every permission mode, read-only too: it is Claude Code's own draft, like its to-do list, outside the project. Anywhere else they are refused, telling it to present the plan with `ExitPlanMode` first.
   - 命令：和计划模式关着时一样，按应用的权限模式走：自动、全部允许下直接跑，改动先问下出批准卡，只读下拒绝。让命令只看不动的是 Claude Code 自己的计划模式（它的指示里写着计划期间不做任何改动）；哪些命令只是看看，应用猜不准，就不替它挡。起初这里是每条命令都先问，见文末的补记。 / Commands: by the app's permission mode, as with plan mode off: they run under auto and allow all, get an approval card under ask first, and are refused under read-only. What keeps them to looking is Claude Code's own plan mode, whose instructions say nothing changes while it plans; which commands only look is not the app's to guess, so it does not stand in for that. At first every command asked here; see the addendum at the end.
   - 读、搜索、待办清单和子代理照常。Claude Code 自己来问（没经过应用的卡）时，计划模式下拒绝。 / Reads, searches, the to-do list and subagents go on as usual. Claude Code asking on its own (not through the app's card) is refused in plan mode.
   - 计划文件夹和记忆文件夹（ADR 0095 决定 13）一样对文件工具开放：随时可读，批准后它会回头看计划；计划模式关着时写按权限模式；命令仍然进不去。 / The plans folder opens to the file tools as the memory folder does (ADR 0095, decision 13): reads always run, since after approval it looks back at the plan; with plan mode off, writes go by the permission mode; commands still cannot reach it.

3. **计划是一张自己的卡 / The plan is a card of its own.** `ExitPlanMode` 在每种权限模式下都出卡：`approval` 的 `kind_key` 是 `plan`（`PLAN_APPROVAL_KIND`），`summary` 是计划的 markdown，`target` 是计划文件。卡上按 markdown 画出计划，长了在卡里滚动，下面是「批准，开始做」和「接着改」。批准：Claude Code 离开计划模式接着干，会话的开关关上，之后按应用的权限模式走。接着改：告诉它你还没批准、要接着改，它留在计划模式。卡等着时你发的话不算批准，算要改的地方：卡按「要改」回答，这句话照常送进这一轮。旧版本的窗口和手机把它当普通的批准卡（计划原文加允许、拒绝），照样能答。 / `ExitPlanMode` puts up a card in every permission mode: the approval's `kind_key` is `plan` (`PLAN_APPROVAL_KIND`), its `summary` the plan as markdown, its `target` the plan file. The card draws the plan as markdown, scrolling inside the card when long, with Approve and start and Keep planning under it. Approved, Claude Code leaves plan mode and gets to work, the session's switch turns off, and from then on the app's permission mode decides. Keep planning tells it the plan is not approved and stays in plan mode. A line you send while the card waits is not an approval but what to change: the card is answered as such, and the line goes into the run as any other. A window or phone from before this reads the card as an ordinary approval (the plan as text, Allow and Deny) and can still answer it.

4. **打 `/` 列出命令 / Typing `/` lists the commands.** `GET /v1/project-sessions/:id/commands`：daemon 按这个会话的账号、在它的目录里不带提示词起一次 Claude Code，读你的设置（带出 skill、插件和项目自己的命令），问 `supportedCommands`，按账号和目录记 10 分钟。不列的：终端专用的（`doctor`、`color`、`focus`、`reload-plugins`），应用自己有控件的（`model`、`effort` 在输入框的选择器里，`rename` 在侧栏），`__` 开头的内部命令。一句话以 `/` 开头、光标还在第一个词里时，输入框上面弹出列表：名字或别名开头对得上的在前，名字里含有的在后；↑↓ 选，Tab 补全，Enter 直接执行，Esc 关上，点一行补全。没列出的命令照样能直接打、发出去。 / `GET /v1/project-sessions/:id/commands`: the daemon starts Claude Code once without a prompt, under the session's account and in its directory, reading your settings (which bring the skills, the plugins and the project's own commands), asks `supportedCommands`, and keeps the answer per account and directory for 10 minutes. Left out: the terminal's own (`doctor`, `color`, `focus`, `reload-plugins`), the ones the app has its own control for (`model` and `effort` in the composer's picker, `rename` in the sidebar), and internal ones starting with `__`. When a line starts with `/` and the caret is still in its first word, a list opens above the composer: names or aliases that start with what you typed first, names that contain it after; ↑↓ move, Tab fills in, Enter runs it, Esc closes, a click fills in. A command not listed can still be typed and sent.

5. **没话说的命令也有一行 / A command that answers nothing still says it ran.** `/compact`、`/clear` 这类结果为空的命令，会话里加一行系统行（「已执行 /compact：…」）。`/compact` 进行中，工作行写「正在压缩上下文」。`/clear` 让 Claude Code 开一个新会话，应用跟着记下新的会话 id（`init` 每次都记），之后的轮次接着新的；这里的记录不删，任务地图只回放新的那段。命令不给会话起名：新会话的名字取第一句不是命令的话。 / A command answering nothing, such as `/compact` or `/clear`, gets a system line in the session ("Ran /compact: …"). While `/compact` works, the working line says Compacting the conversation. `/clear` makes Claude Code start a new session; the app records the new session id (it records one on every `init`) and later runs carry that one on; the lines here stay, and the task map replays only the new part. A command names no session: a new one is named by the first line that is not a command.

## 取舍 / Trade-offs

- **列命令会跑你的 SessionStart 钩子 / Listing the commands runs your SessionStart hooks.** 问列表的那次启动读你的设置，设置里的 SessionStart 钩子会在项目目录里跑一次，每一轮开跑时本来也会跑。MCP 服务不起（`strictMcpConfig`）。 / The start that asks for the list reads your settings, so a SessionStart hook in them runs once in the project directory, as it does at the start of every run anyway. MCP servers are not started (`strictMcpConfig`).
- **计划期间的命令只凭 Claude Code 自觉 / While it plans, commands rest on Claude Code's word.** 在「自动」「全部允许」下，命令里夹着的写（`rm`、`sed -i`、重定向、`git commit`）计划期间也会真的执行：应用只拦文件工具的写。想每条命令都过目，用「改动先问」。 / Under auto and allow all, a write inside a command (`rm`, `sed -i`, a redirect, `git commit`) runs while it plans too: the app holds back only the file tools' writes. To see every command first, use ask first.
- **计划文件夹按默认位置找 / The plans folder is the default one.** 用 `plansDirectory` 设到别处的计划写不进去：应用不读设置。 / Plans set elsewhere with `plansDirectory` cannot be written: the app reads no settings.
- **`AskUserQuestion` 和 `Skill` 工具仍然不开 / `AskUserQuestion` and the `Skill` tool stay off.** 计划模式里 Claude Code 常用 `AskUserQuestion` 问清需求，现在只能在回复里问；手打 `/skill` 能用，Claude Code 自己调不了 skill。 / In plan mode Claude Code often asks with `AskUserQuestion`; here it asks in its reply. A typed `/skill` works; Claude Code cannot call a skill itself.
- **手打 `/model` 只管这一轮 / A typed `/model` lasts the run.** 菜单里不列，打了照样发给 Claude Code：它换这一轮的模型，输入框的选择器不知道，下一轮照选择器的来。`/effort` 也一样。 / Not listed, but typed it still goes to Claude Code: it switches this run's model behind the picker's back, and the next run goes by the picker. `/effort` likewise.

## 实现 / Implementation

守护进程：`claude-code/policy.ts`（`plan`、`planApproval`）、`claude-code/memory-dir.ts` 的 `claudePlanDirs`、`project-runner.ts`（起跑模式、`ExitPlanMode` 和计划卡的三种回答、`setPermissionMode`、命令的系统行和压缩中的工作行）、`claude-code/commands.ts`（问命令列表）、`store/project-sessions.ts`（`project_mode`）；路由 `GET /v1/project-sessions/:id/commands` 和 `PATCH /v1/project-sessions/:id` 的 `mode`，手机经同样的路由（`remote/routes.ts`）。信使：`chat/ProjectChat.svelte`（开关、Shift+Tab、菜单的按键）、`chat/ProjectPlanCard.svelte`、`chat/ProjectCommandMenu.svelte`、`chat/project-commands.svelte.ts`（取列表、匹配、补全）。

Daemon: `claude-code/policy.ts` (`plan`, `planApproval`), `claudePlanDirs` in `claude-code/memory-dir.ts`, `project-runner.ts` (the mode a run starts in, `ExitPlanMode` and the plan card's three answers, `setPermissionMode`, a command's system line and the compacting working line), `claude-code/commands.ts` (asking for the list), `store/project-sessions.ts` (`project_mode`); routes `GET /v1/project-sessions/:id/commands` and `mode` on `PATCH /v1/project-sessions/:id`, the phone through the same ones (`remote/routes.ts`). Messenger: `chat/ProjectChat.svelte` (the switch, Shift+Tab, the menu's keys), `chat/ProjectPlanCard.svelte`, `chat/ProjectCommandMenu.svelte`, `chat/project-commands.svelte.ts` (the list, matching, filling in).

2026-10-22 补 / Addendum：起初计划模式下每条命令都先问，自动、全部允许下也一样，打算等有了靠得住的只读命令判断再放宽。头一次真用就出了 11 张卡：一轮计划里主线 4 条命令、两个子代理 7 条，全是 `ls`、`wc -l`、`git log`、`curl` 这类查看。你在「认得出的只读命令直接跑」和「按权限模式走」之间选了后者，接受计划期间命令里的写只靠 Claude Code 的计划模式拦着。决定 2 的命令一条和取舍里对应的一条按此改写。 / At first every command asked in plan mode, under auto and allow all too, meant to loosen once a dependable read-only check existed. Its first real use put up 11 cards: one planning run's 4 commands plus 7 from two subagents, all of them looking (`ls`, `wc -l`, `git log`, `curl`). Offered "run the commands known to only look" or "go by the permission mode", you chose the latter, accepting that while it plans a write inside a command is held back only by Claude Code's plan mode. Decision 2's rule for commands and the matching trade-off were rewritten to suit.
