# Bot 读到的每句都标明是哪件事，你在别处说到的事转给正在做它的轮

部分被 [ADR 0040](0040-agent-kernel-the-job-owns-state.md) 的 P1 取代（2026-09-30）：解析或应用时对不上候选集的 resume、join 不再当 continue，这次什么都不落，消息照原样留着；点的正是会话当前规划的（它从不在候选集里）仍当 continue 落下。答案是照那件事写的：当 continue 会把它的要点写到当前规划上，会话没有当前规划时还会照着它新开一个副本（2026-09-29，要并入的那件事在调用期间结束了）。

[ADR 0030](0030-plans-tickets-and-organizer.md) 让一件事跟着工作跨 Bot、跨会话走：交接、点名、Bot↔Bot 私聊都继承唤醒方那一轮的规划。[ADR 0031](0031-heard-in-the-live-turn-and-plans-closed-on-evidence.md) 让队友的话听进活轮。有两处没管到：

- **只有局面块说是哪件事。** 局面块也只说本轮自己那件。一个群里常同时有好几件事，一个私聊里既有你跟它随口说的，也有它在群里那件事的交接，可转录的每一行、「有人找你」的那一行、改道带过去的那一行、回看都不说自己属于哪件事。其实 `messages.task_id` / `ticket_id` 早就盖好了，只是没画给模型看，Bot 只能靠猜。
- **你在别处说的话进不了那件事。** bot1、bot2 在群里（或它们的 Bot↔Bot 私聊里）推进一件事，你在私聊里跟 bot1 说「标题别太长」，会出三件事：
  - 整理跳只在私聊自己的规划里挑，这句就被归成私聊里的一件新事。
  - 私聊里开的那一轮看不到群里那件事的局面，连自己在群里还有一轮在跑都不知道。
  - 群里正在做这件事的轮，收件箱只收同一会话里 Bot 的话，所以听不到这句。

## 现在

**每句都带是哪件事。**
- `planTagger` 按读它的那一轮算标注：
  - 别人的一行属于另一件事时，在说话人后面写 `〔规划「标题」· 任务 03〕`。
  - 同一件事的另一个任务写 `〔任务 03〕`。
  - 本轮自己的任务、或没归类的行，不写。
- 标题用 `tasks.title`，开规划后不再改，和信使里显示的是同一个名字；标注里截到 20 码点。
- Bot 自己的行（assistant）不加标注：模型会照着自己说过的话的格式往下写。系统说明也明写这是应用加的，不要写进自己的消息。

**收件箱和改道同样带标注。**
- 听进的每一项在放进收件箱时，按接收那一轮的规划 / 任务算好 `tag`，回看用它自带的 `lands`。
- 从别的会话来的项另带 `where`，渲染成 `【user，在你和用户的私聊里】〔规划「…」〕正文`。
- 改道时，旧轮和新轮不是同一件事的话，`redirectCarryNote` 会多一句「它在做的是〔规划「…」· 任务 02〕」。这一句要在 `createTurn` 之后才渲染，因为那时才知道新轮落在哪。

**局面块写清这件事在哪、谁在做。**
- 规划行带名字：`规划「标题」：目标`，最初的要求和第一轮那两行也带。
- 规划开在别的会话时，写「这件事是在群「X」里开的」。
- 列出此刻在别的会话里做这件事的轮，自己在别处的那一轮写成「你」；再列出这个 Bot 手上别的活轮（别的规划，最多 3 条）。
- 「经过」里在别的会话做的那一步，标明在哪。
- 会话的说法由 `sessionLabel` 从读它的那个 Bot 的位置说：`群「名」`、`你和用户的私聊`、`用户和X的私聊`、`你和X的私聊`、`X和Y的私聊`。

**整理跳可以把一句归到在场 Bot 正在别处推进的事。**
- 候选集是 `elsewherePlans(sessionId)`，最多 3 件。条件：没做完、不是日程、不是本会话的当前规划；并且在场的某个 Bot 满足下面任一条：
  - 在别的会话里有这件事的活轮；
  - 在这件事进行中时，是它某个没收口任务的 worker。
- message 模式的载荷多了 `elsewhere_plans`，每项含：
  - 完整 spec 和任务清单；
  - `home`（开在哪）；
  - `working`（此刻谁在哪做它）；
  - `said_here`（本会话里之前归到它的最后 3 句），让「还有，别用表格」这种接着说的话也对得上。
- 同一件事不在 `recent_plans` 里重复出现。
- 新增决定 `join` + `join_plan_id`。`plan` 在那件事的 spec 上改，`tickets` 和 `message_ticket` 引用那件事的任务。
- `current_plan` 为 null 时可以选 new 或 join。
- 解析和应用都用候选集核一遍 id，对不上的当 continue。
- join 不动别的会话：那件事开在别的会话时留在那里（`reopenTask` 跨会话分支只动 `closed_at`），这个会话的当前规划照旧。它若是这个会话自己换事时搁下、却仍有人在别处做的那件，就像 resume 一样接回来，重新当这个会话的当前规划。之后的 settle 和对账仍按那件事自己的会话跑；这边盖了章的消息会按 `task_id` 进到 settle 里。

**你说到的事，转给正在做它的轮。**
- `turn-engine` 整理完后，重新读一次这条消息，再交给参与路由。这也修掉了一个旧问题：以前判断拿的是整理前的对象，看到的是会话当前那件，不是这句被归到的那件。
- 消息盖了规划时，`hearAcross` 把它放进这件事在**别的会话**里每个本进程在跑的活轮的收件箱，不管是哪个 Bot。它带着 `tag`、`where` 和附件路径，标上 `elsewhere`。同一会话的活轮不重复放，它们在转录里本来就看得到。
- 这一步在开轮之前做。新开那一轮的局面里写「触发这一轮的那句已经转给了你、bot2」，只列这句进来时已经在跑的那些轮（按轮和消息的时间比），后来才开的轮没收到，不算。自己也在其中时，局面还会加一句「你在那边的那一轮也收到了，要动手的由它接着做；这里回应用户就好，不要重复做同样的改动」。
- 判断载荷的 `plan` 多了 `live_elsewhere` 和 `you_heard_elsewhere`，提示词让判断只在用户需要当面答复时为此下场。
- 带 `elsewhere` 的项在那一轮读到之前就收尾的话，不补开轮（`reopenForUnheard` 跳过它们）：这句已经在你说话的那边有人回应，那件事的规则也已经被整理跳改过。

## 取舍

- **你的话只转给同一件事的活轮，而且是全部。** 选「这件事的活轮都收到」，而不是「只给你私聊的那个 Bot」：你说「标题别太长」时，写标题的未必是你正在私聊的那一位。听进不打断，代价只是对方下一跳多读一行。
- **你说话那边照常开一轮。** 群里那一轮要回你，只能 `send_message` 到你的私聊，而成功发送就会结束它手上的那一轮。所以回你的是私聊那一轮，动手的是群里那一轮；局面里那一句提醒私聊那一轮别重复动手。
- **不补开。** 在群里开一轮、触发它的消息却在私聊里，流程图和转录窗都对不上号；这句又已经有人回，规则也改了。
- **标注按读它的轮算，不写死在消息上。** 同一行对 A 轮是另一件事，对 B 轮就是自己这件；写死的话，每一行都得带标注，反而更吵。
- **只有 join 能跨会话。** resume 仍只认本会话最近的规划。它只看得到别的规划的 goal，却会整份改写 spec；join 给了完整 spec，才敢让它改。

## 不做

- 不修 resume 盲改 spec 的老问题：它只拿到 goal 就覆盖整份要点，和这次无关，另开。
- 整理跳没跑出结果（没配默认模型、失败、答不成形）时不转发：消息没有盖章，就不知道是哪件事。
- 不转发 Bot 的话：Bot 之间的交接本来就走点名、Bot↔Bot 私聊和听进。
