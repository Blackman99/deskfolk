# 还没读到的话：撤回和直接插入 / A line no Bot has read yet: take it back, or have it read now

Status: implemented 2026-10-08, at every engine level with work items. The daemon says so in its snapshot (`queuedLineActions`); a window or phone on an older daemon offers neither and shows no row. Builds on [ADR 0040](0040-agent-kernel-the-job-owns-state.md) P4a (a working Bot's inbox), [ADR 0061](0061-claude-agent-runner.md) (Bots run by Claude Code) and [ADR 0063](0063-edit-a-line-and-lines-in-order.md) (changing a line, lines in order).

2026-10-08，你要排队中的消息能撤销、能直接插入。Bot 干活时你发的一句进它这一轮的收件箱，在它下一步读到：应用自己跑的 Bot 是下一跳（一次模型调用加它的工具调用），Claude Code 跑的 Bot 是它手上这一批工具调用跑完之后。你的 Bot 都是 Claude Code 跑的：那天视频导演在一次长渲染里分别到第 39、45、61 步才读到你中途的三句话。这期间什么都不显示这句在等（ADR 0063 的缺口），也收不回来；想让它早点读，只能叫停。查了数据库：从来没有出过「排在第 N 位」的提示，你说的排队就是干活中的 Bot 的收件箱。另外查出一个毛病：这三句每一句读过之后，那一段结束时还会为它再开一轮，什么新东西都没有。

On 2026-10-08 you asked for queued lines to be undoable and insertable. A line you send while a Bot works goes into that turn's inbox and is read at its next step: for a Bot on the app's own loop the next hop (one model call and its tool calls), for a Bot run by Claude Code the end of the batch of tool calls it is running. Your Bots all run on Claude Code: that day 视频导演 read three lines sent during a long render only at steps 39, 45 and 61. Meanwhile nothing showed the line as waiting (a gap ADR 0063 left), nothing took it back, and nothing but Stop made it read sooner. The database had no "Queued, at position N" notice ever: the queue you meant is the working Bot's inbox. It also showed a fault: each of those three lines, read already, opened one more turn when the segment ended, which found nothing new.

## 决定 / Decisions

1. **画出它在等 / Where it waits is drawn.** 你的一句话还没有任何 Bot 读到——它在收件箱里排着（`queued`）或被叫停扣着（`held`）——气泡下面就有一行：Bot 正在干活时「排队中 · 它下一步读到」，等它下一轮或空出手时「排队中 · 轮到时读到」，叫停扣着时「叫停中 · 解除后读到」。读到了这一行就没了。 / Under a line of yours no Bot has read yet — queued in an inbox or held by a stop — one row says where it waits: "Queued · read at its next step" while its Bot works, "Queued · read when its turn comes" while it waits for that Bot's next turn or a free slot, "Held by a stop · read once it lifts". Once read, the row goes.

2. **撤回 / Take back.** `POST /v1/messages/:id/withdraw`。能撤回的只有能改的那种话（ADR 0063 #2：你写的普通话，可写的会话里），还没开出过轮，而且它在每个收件箱里的副本都还在排着或被扣着。撤回时，每个副本记成 `withdrawn`；这句标上 `withdrawn_at`，从此不进任何 Bot 读的转录（`hidden_from_bots`），后来的话读句时也看不到它；它的原话抹掉，台账里站在这些原话上的条目随之作废（和你要求抹掉原话时一样）；只为它排着的工作退回空闲，不再占队里的位置。转录里这句变成「你撤回了这句话 · 重新编辑」：输入框空着时字直接放回去（引用回复也带回），「重新编辑」把字接在已经打的后面。撤回的话不能再改、改归属或新开一件事——要说就重新发。已经有 Bot 读到（409 `already_read`）、没在等任何 Bot（409 `not_queued`）、不是你能改的话（422 `not_withdrawable`）都拒绝。和别的写入一样带回执去重，手机上也有。 / Only a line that could be changed (ADR 0063 #2: a plain line of yours, where you can write), that opened no turn, and whose every copy is still queued or held. Each copy becomes `withdrawn`; the line gets `withdrawn_at` and is kept out of every transcript a Bot reads (`hidden_from_bots`), and of a later line's reading; its words kept as yours are erased, and the ledger entries standing on them waived, as erasing does; work queued for it alone goes idle and leaves the queue. The transcript shows "You took this line back · Edit again": its words go back into an empty box (with the line it quoted), and Edit again adds them after what is typed. A line taken back is not changed, refiled or opened as a job: send it again. Refused when a Bot has read it (409 `already_read`), when it waits for no Bot (409 `not_queued`), and for anything not changeable (422 `not_withdrawable`). Receipted like any write; on the phone too.

3. **直接插入 / Insert now.** `POST /v1/messages/:id/insert`，返回 `{ message, inserted }`。只对排着的话（被叫停扣着的由叫停说了算）。这句在等的、本进程在跑的每一轮——在干活（不是等你批准或回答），也不是叫停下的只读答复——都被打断一下：
   - **Claude Code 跑的 Bot**：应用让 Claude Code 中断（`interrupt()`），和在 Claude Code 里按 Esc 一样，正在跑的命令停掉；中断生效后，这一轮在等的所有话按顺序作为它下一条读到的消息送进去，带一个 uuid。消息开头说明「刚才那一步是为这个停下的，不是用户拒绝了它；正在跑的命令没跑完，还需要的话重跑」——它刚看到的是「用户不想继续这次调用」。被打断那一步自己的结束（`aborted_tools` / `aborted_streaming`）既不是回复也不是失败，被吃掉；带着那个 uuid 的结果才是回答。被切断的调用由应用收尾：效果记录的结果记成未知（`cut_for_line`），命令卡上那条记成停下了，执行帧退出。Claude Code 空着时（应用正在核对它的回复）没有可打断的，不中断。
   - **应用自己跑的 Bot**：正在进行的那次模型调用被切断（它自己的 `cut` 信号；整轮的信号还是同一个对象），已经吐出的半截不要；这一跳还没跑的工具调用推迟，和中途收到改动一样；已经在跑的命令跑完。下一跳一开始就读到。
   `inserted` 是打断了几轮；0 时这句下面说「这会儿没有能打断的一步，它下一步就读到」。同一刻有叫停落下时叫停说了算：这一轮照停，这句没送进去，被扣着等解除。

   `POST /v1/messages/:id/insert`, answering `{ message, inserted }`. Only for a queued line (a stop decides about a held one). Every turn of this process the line waits in, at work (not waiting on your approval or answer) and not a read-only answer under a stop, is cut short:
   - **A Bot run by Claude Code**: the app interrupts Claude Code (`interrupt()`), as Esc does in Claude Code, and a command it runs stops; once the interrupt went through, every line waiting for the turn goes in, in order, as the next message it reads, under a uuid. The message opens by saying the step was stopped for these lines and not refused by the user, and that a command cut short did not finish and may need running again — what it just saw was "the user doesn't want to proceed with this tool use". The cut step's own end (`aborted_tools` / `aborted_streaming`) is neither a reply nor a failure and is consumed; the result carrying the uuid is the answer. The calls it cut are closed by the app: the effect's outcome unknown (`cut_for_line`), the command on the turn's card as stopped, the frame exited. An idle Claude Code (the app settling its reply) has nothing to cut and is not interrupted.
   - **A Bot on the app's own loop**: the completion in flight is cut (its own `cut` signal; the turn's signal stays the one object every hop and tool call carries) and what it had streamed is dropped; the calls of the hop still waiting are postponed, as for a change arriving mid-step; a command already running finishes. The next hop opens by reading the lines.
   `inserted` is how many turns were cut; at 0 the line says "No step to cut right now; it reads this at its next step". A stop landing in the same moment decides: the turn stops as it would, the line does not go in, and it is held for the lift.

4. **读过的话不再多开一轮 / A line read is not read again.** Claude Code 跑的一轮在一批调用后读到的话，原来留在这一轮内存里的待读列表上，段结束时被当成没读过、为它再开一轮。现在读到就从列表上拿掉；段结束时只为收件箱里还在排着或被扣着的行开轮，撤回的也不开。 / A line a Claude Code turn read after a batch of calls stayed on the turn's in-memory list of unread lines, so the end of the segment took it for unread and opened another turn on it. It now leaves the list once read, and the segment's end opens a turn only for rows still queued or held in the inbox — never for one taken back.

2026-10-09 补记 / addendum：被你按的停止扣着的那句也能「直接插入」——停止随之解除，Bot 马上开一轮读它，`inserted` 是读它的 Bot 数；要你自己解除的叫停扣着时照旧 409 `held`（[ADR 0063](0063-edit-a-line-and-lines-in-order.md) #7）。同一天 [ADR 0071](0071-a-stop-is-only-stop-for-now.md) 起你的叫停都不再要你亲手解除：覆盖多个 Bot 的只放开这句的 Bot；409 只剩应用自己的保持（搁置的旧规划），这句下面说「这件事搁置着：到它的流程图上让它继续」。 / A line a Stop of yours holds can be inserted too: the Stop lifts and the Bot opens a turn on it, `inserted` counting the Bots that read it; under a stop that stays until you lift it the answer is still 409 `held`, said under the line (ADR 0063 #7). From ADR 0071 the same day no stop of yours waits to be lifted — one over more Bots releases that line's Bot — and 409 is left for the app's own holds (old parked plans).

## 为什么用 interrupt，不用 `priority: 'now'` / Why interrupt, not `priority: 'now'`

Agent SDK 的用户消息可以带 `priority: 'now'`。2026-10-08 实测（SDK 0.3.289，本机 Claude Code）：后台任务关着时——应用就是这样跑 Claude Code 的——`now` 会等正在跑的前台命令跑完再打断，和一批调用结束时读到没有区别；`interrupt()` 立刻停掉命令（工具结果是「用户不想继续这次调用」），会话不断，接着处理下一条消息。

An Agent SDK user message can carry `priority: 'now'`. Measured on 2026-10-08 (SDK 0.3.289, this Mac's Claude Code): with background tasks off — as the app runs Claude Code — `now` waits for the running foreground command to finish before it cuts, which is no sooner than the end of the batch; `interrupt()` stops the command at once (its tool result says the user did not want to proceed) and the session goes on with the next message.

## 取舍 / Trade-offs

- **直接插入会丢掉进行中的活。** Claude Code 跑的 Bot 正在跑的命令停掉，半截渲染白跑；你按它就是为了这个，消息里提醒 Bot 被打断的要重跑就重跑。应用自己跑的 Bot 只切模型调用，命令照跑完——两种 Bot 的按钮提示写明各自会打断什么。 / Insert now loses work in flight: a command a Claude Code Bot runs stops, and a half-done render is wasted — that is what you press it for, and the message tells the Bot to run again what was cut. On the app's own loop only the model call is cut and a command finishes; each Bot's button says which.
- **撤回抹掉原话，由它来的台账条目作废**；由这句里的数自动生成、还在生效的检查不自动退，要退在流程图上退（和 ADR 0063 删掉的字一样）。 / Taking back erases the words and waives the ledger entries made from them; a check derived from a number in the line and already in force stays until you retire it on the board, as for words deleted by a change (ADR 0063).
- **被切断的那次模型调用的花费**：应用自己跑的 Bot 切断时流里还没有用量，这一次不记；Claude Code 自己报的照记。 / The cut completion's spend: on the app's own loop a stream cut short has reported no usage and nothing is recorded; Claude Code's own report is recorded as ever.

## 缺口 / Not done

- **还在读的那句撤不回**：应用读完、归好、送进收件箱之前没有这一行（ADR 0063 「上一条还在路上」的缺口还在）。 / A line still being read cannot be taken back: it has no row until it is read, filed and in an inbox (ADR 0063's "on its way" gap stands).
- **直接插入只打断本进程在跑的轮**：守护进程重启后接着跑的轮照样能打断；别处在跑的不能。 / Insert now cuts only turns this process runs; a turn picked up after a restart is one of them, a turn run elsewhere is not.
- **转录窗里瞥见过的不收回**：撤回前某一跳的转录窗里已经出现过这句，那一跳读过就是读过。 / A hop that glimpsed the line in its transcript window before it was taken back has seen it.
