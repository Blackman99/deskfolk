## 决定 / Decisions

1. **项目会话的 Agent 可以是 Grok / A project session's agent can be Grok.** `PROJECT_AGENTS` 最后多了 `grok`（和 Bot 的 runner 同一个键），九项 caps 全是有：计划模式、命令、账号、可导入、分支、回放、任务、单独停一个任务、先问。 / `PROJECT_AGENTS` gains `grok` last (the Bots' runner key), with all nine caps on: plan, commands, accounts, importable, branches, replay, tasks, stopsTask, asksFirst.

2. **像在 Grok 自己的终端里 / As in its terminal.** 每一轮在目录里起一个 `grok agent --no-leader stdio`（按 Bot 的 Grok 那样找，会话的账号就是它的 `GROK_HOME`）；客户端不提供文件系统和终端，Grok 用自己的工具；不加指令、不给应用的工具、不加 MCP、不改沙箱，你的设置、AGENTS.md、skill 和 MCP 照常。第一轮 `session/new`，之后每一轮 `session/resume`，从不 `session/close`。`initialize` 里没有 `pre_tool_use` 钩子或不能 resume 的 Grok 不启动，写一行请你 `grok update`。模型和思考等级走 `session/set_config_option`（`model`、`reasoning_effort`），一轮进行中改了立刻发；那个模型没有的等级（grok-4.5 没有 xhigh）就不设。 / Each run starts `grok agent --no-leader stdio` in the directory (found as a Bot's is, the session's account as its `GROK_HOME`), offering no file system and no terminal, so Grok uses its own tools; no instructions, none of the app's tools, no MCP server, no sandbox change: your settings, AGENTS.md, skills and MCP servers apply. The first run calls `session/new`, later runs `session/resume`, never `session/close`. A Grok whose `initialize` names no `pre_tool_use` hook or no resume is not started, with a line asking for `grok update`. Model and thinking level go by `session/set_config_option` (`model`, `reasoning_effort`), at once during a run; a level the model lacks (grok-4.5 has no xhigh) is left alone.

3. **权限：应用的钩子在每个调用之前 / Permissions: the app's hook before every call.** 每个会话（新开、接续、分支出来的）都登记 `pre_tool_use` 钩子，超时 600 秒。钩子按应用的规则（`decideAction`，项目目录为工作区）判每个调用，子代理的也一样：允许就 continue，拒绝就 deny 并说理由，先问下出批准卡、等你答。卡最多挂约 590 秒：到时还没答，回 deny，理由是「这一步在等用户批准，还没批；收到批准的消息之前不要再试」，卡不撤、这一轮不结束；你之后批准了，应用按这个调用的种类和它点名的命令或路径记一次批准，并发一句「你刚才要做、被告知在等批准的……，用户现在批准了」，Grok 再试时直接放行。凭据照旧碰不到；Grok 自己的文件夹（这个会话的目录、skills、agents、plugins、`memory-v2`、`bundled`、后台任务 skill 的脚本目录）按权限模式开放，`auth.json`、`config.toml` 和别的会话的目录照旧关着。替 Grok 定后续安排的工具（调度、workflow、loop、goal）一律拒绝，理由是这一轮结束进程就退出。应用认不出的工具（MCP 服务器的、Grok 新加的）可能改任何东西，按改动走：先问下出一张「tool」卡，只读和计划模式下拒绝；调用 skill 不算（skill 接着做的事照样一步步过钩子）。Grok 若按它的设置发 `session/request_permission`，同样照规则答，只用 allow-once / reject-once，从不选会存进它授权里的 always 选项。 / Every session (new, resumed, branched) registers the `pre_tool_use` hook with a 600 s timeout. The hook decides each call, a subagent's too, by the app's rules (`decideAction`, the project directory as the workspace): allowed it continues, refused it is denied with the reason, under ask first a card waits on you. A card is held about 590 s: unanswered by then, Grok is told the step waits for the user's approval and not to try again until told, the card stays and the run stays open; approving it later records a one-time approval for that kind of call and the command or paths it names, and tells Grok it is approved, so its next try goes through. Credentials stay shut; Grok's own folders (the session's own, skills, agents, plugins, `memory-v2`, `bundled`, the background-task skill's scripts) are open by the permission mode, while `auth.json`, `config.toml` and other sessions stay shut. Tools that would schedule work past the reply (the scheduler, workflow, loop, goal) are refused, since a run's Grok ends with the run. A tool the app cannot tell (an MCP server's, one Grok added) may change anything, so it goes as a change: a "tool" card under ask first, refused under read-only and in plan mode; invoking a skill is not one (what the skill then does comes through the hook step by step). A `session/request_permission` Grok sends by its own settings is answered by the same rules, allow-once or reject-once only, never an "always" option that would land in its grants.

4. **计划模式 / Plan mode.** 输入框的计划开关和 Shift+Tab 对 Grok 也有；每个提示词带 `_meta.mode`（`plan` 或 `agent`），不靠 Grok 记着的状态；一轮进行中切换就发 `_x.ai/toggle_plan_mode`，当场生效。计划开着时钩子另外拒绝 `plan.md` 以外的任何改动，包括会写东西的命令和子代理的调用（Grok 自己的计划闸门只管它的改文件工具，子代理也不在里面）。`_x.ai/exit_plan_mode` 是计划卡（和 Claude Code 的同一张）：批准就回 approved、关掉会话的计划模式，Grok 在同一轮接着做；不批准就回 cancelled、让它接着完善；它等着时你发的话作为 feedback 交回去。Grok 自己进出计划模式时，会话的开关跟着变。 / The composer's Plan switch and Shift+Tab work for Grok; every prompt says its mode (`_meta.mode`, `plan` or `agent`), never relying on Grok's own state; a switch during a prompt sends `_x.ai/toggle_plan_mode`, which takes at once. While planning the hook also refuses any change outside `plan.md`, commands that write and a subagent's calls included (Grok's own gate covers its edit tools only). `_x.ai/exit_plan_mode` is the plan card (Claude Code's): approving answers approved and turns plan mode off, and Grok goes on in the same turn; not approving answers cancelled and it keeps planning; a line you send while it waits goes back as the feedback. When Grok enters or leaves plan mode by itself, the session's switch follows.

5. **问题卡 / Question cards.** `_x.ai/ask_user_question` 的每个问题是对话里一张问题卡，答完才接着做；答案按问题原文对上，你自己写的话跟在选项后面。MCP 服务器的表单（`elicitation/create`）也成问题卡。 / Each question of `_x.ai/ask_user_question` is a card in the conversation that Grok waits on; answers go back by the question's own words, your words after the options picked. An MCP server's form (`elicitation/create`) is cards too.

6. **后台和子代理 / Background and subagents.** 后台命令和监视是 shell / monitor 任务，子代理是 subagent 任务（带描述、类型、工具数和 token），运行保持打开、读作空闲，你说的话立刻答。每一件都能单独停（`_x.ai/task/kill`、`_x.ai/subagent/cancel`），Stop 结束全部。一件结束后 Grok 自己开的那一轮，它说的话在那一轮结束时贴出。命令的输出结束后存成临时文件供任务列表看；子代理打开看的是它的会话（`_x.ai/session/updates`）：派它的那句话、它的模型、每一步。 / Background commands and monitors are shell / monitor tasks, subagents subagent tasks (description, type, tool count, tokens); the run stays open and reads idle, and a line you send is answered at once. Each can be ended alone (`_x.ai/task/kill`, `_x.ai/subagent/cancel`); Stop ends them all. What Grok says in a turn it takes by itself after one ends is posted when that turn ends. A command's output is kept in a temporary file for the tasks list; a subagent opens onto its own session (`_x.ai/session/updates`): what it was asked, its model, each step.

7. **`/` 命令 / The `/` list.** 这个目录里一次运行听到的 `available_commands_update`，没有就问一个不开会话的 Grok（`initialize` 的 `availableCommands`）；记十分钟。`always-approve` 不列（能不问就做什么由应用的权限模式定），`loop`、`goal`、`workflow` 不列（它们让 Grok 回复之后按自己的安排接着做，而项目会话里 Grok 随这一轮结束）；你打了这些，写一行说明，不发。`/compact` 照原样发出，没回话就写「已执行 /compact：Grok 把之前的对话压成了摘要」。 / What a run in the directory heard (`available_commands_update`), else asked of a Grok that opens no session (`initialize`'s `availableCommands`); kept ten minutes. Not listed: `always-approve` (the app's permission mode decides) and `loop`, `goal`, `workflow` (they keep Grok working after its reply, and a project session's Grok ends with its run); typed, a line says why and nothing is sent. `/compact` goes as written; with no reply the line says the conversation was compacted.

8. **你的话、回复、失败和 Stop / Your line, the reply, failure and Stop.** 图片作为 image 块，别的文件写成「附件：」加路径，批注写全；ACP 没有 steer，进行中发的话跟下一个提示词走。它说的话就是回复，被工具调用隔开的几段之间空一行。没登录写「Grok 还没登录：在终端里运行 grok login」（非默认账号带上 `GROK_HOME=`）。Stop 发 `session/cancel`（连子代理一起），再结束进程；不 rewind，它已经说的话留成它的一行。 / Pictures go as image blocks, other files as "Attached:" with the path, annotations spelled out; ACP has no steer, so a line sent during a prompt goes with the next. Its words are the reply, the stretches a tool call separates set apart as paragraphs. Signed out, the line says to run `grok login` (with `GROK_HOME=` for an account other than the default). Stop sends `session/cancel` (subagents with it) and ends the process; nothing is rewound, and what it had said stays as its line.

9. **花费 / Spend.** 每个 `turn_completed`（你的、它自己开的、子代理的）记一行，供应商「Grok」，模型取它用量里写的；`costUsdTicks` 是报告的价钱，计入每日上限；没报价钱的那一轮按内置价目表估算（`agent-prices.ts`：grok-4.7、4.6 每百万 token 2 / 0.5 / 6 美元，4.5 是 2 / 0.3 / 6，Grok Build 专用的 grok-4.7-build-fast 是 4 / 1 / 12；用量里的 `grok-4.7-build` 按 grok-4.7 算）。 / Each `turn_completed` (yours, its own, a subagent's) is a row under "Grok", the model its usage names; `costUsdTicks` is recorded as reported and counts toward the daily cap; a turn without a price is estimated from the built-in table (`agent-prices.ts`: grok-4.7 and 4.6 at $2 / $0.5 / $6 per million, 4.5 at $2 / $0.3 / $6, the Grok Build-only grok-4.7-build-fast at $4 / $1 / $12; the usage's `grok-4.7-build` counts as grok-4.7).

10. **接着终端里的 Grok 会话 / Carrying on a terminal Grok session.** 导入面板和首启向导列出你每个 Grok 账号的会话（`session/list`），去掉应用自己的（应用持有的、工作区里的、`deskfolk-call-*` 文件夹里的，和 agy 同一套）；读的是它存下的更新，你的话和它的回答落在它们真实的时间，工具调用只数；没有标题的（`grok -p` 开的）用你的第一句话当名字。接着时第一轮先 `_x.ai/session/fork` 出一个新会话（`sourceCwd` 不对就按它列表里的写法再试），在新会话上接着：终端里的原会话不变。 / The import sheet and the wizard list the sessions on each of your Grok accounts (`session/list`) without the app's own (held by the app, in the workspace, in a `deskfolk-call-*` folder, as for agy), read from its stored updates: your lines and its answers at their real times, tool calls counted; one with no title (from `grok -p`) is named by your first line. The first run branches it (`_x.ai/session/fork`, retried with the listing's own spelling of its directory) and goes on in the branch: the terminal's session is left as it was.

11. **账号和额度用完 / Accounts and out of usage.** 会话的账号是设置里列的 Grok 账号目录或默认的 `~/.grok`，新开时选、输入框里换（一轮进行中不让换）。会话换了账号，新账号里打不开原会话：读出原会话最近约 6000 字的对话，新开一个会话、头一句带上它，写一行「之前的工具调用没有带过来」。额度挡下（-32003 或 `free-usage-exhausted`）时问 `_x.ai/billing`：额度用满或带 `free-usage-exhausted` 才记这个账号用完、到账期结束为止；别的 429 当限流，记一小时再试。还有别的 Grok 账号没用完就换过去接着做（ADR 0110 的说法，「Grok 账号……换到……接着做」）；都用完且知道账期结束就到点自己接着做；否则照普通失败。 / A session's account is one of the Grok account directories in Settings or the default `~/.grok`, picked when starting and changed in the composer (not during a run). A session moved to another account cannot open its session there: the last ~6,000 characters of the conversation are read from the old one and a new session starts with them, with a line that earlier tool calls did not come along. A usage limit (-32003 or `free-usage-exhausted`) asks `_x.ai/billing`: only a plan used up (or `free-usage-exhausted`) notes the account out until the period ends; another 429 is a rate limit, held an hour. With another Grok account not out the session moves there and goes on (ADR 0110's words, naming Grok); with every account out and the period's end known it picks up then; otherwise it fails as any failure does.

12. **任务地图 / The task map.** 实时的调用照别的 Agent 那样画（命令 `shell`、改文件 `write_file`、读 `Read`，子代理的调用是它自己的角色）。回放问 Grok 要这个会话和它每个子代理的存下的更新：调用的起点是 Grok 报它的时间，到结果为止；你的话落在真实时间。Grok 不记权限决定，`decision` 为空。 / Live calls are drawn as for the other agents (`shell`, `write_file`, `Read`; a subagent's calls are its own character). The replay asks Grok for the session's stored updates and each subagent's: a call starts when Grok reported it and lasts until its result; your lines land at their real times. Grok records no permission decisions, so `decision` is null.

## 取舍 / Trade-offs

- **挂卡最多约十分钟 / A card holds a call about ten minutes.** Grok 的钩子最多等 600 秒，过了就照做，所以应用在约 590 秒时回「还在等批准」。你之后才批准，Grok 要再试一次那一步；在这之间它可能先做了别的。 / Grok waits on a hook 600 s at most and then runs the call, so at about 590 s it is told the step still waits. Approving later means Grok tries that step again, and it may have done other things meanwhile.
- **钩子出错就放行 / A hook that fails lets the call through.** 应用和 Grok 之间的连接断了、应用回得太晚，Grok 照做；这时 Grok 在你的 always-approve 下不会再问。应用总在超时之前回答，连接断了这一轮也就结束了。 / If the link to the app fails or the answer comes too late, Grok runs the call, and under your always-approve it asks nothing more. The app always answers before the timeout, and a broken link ends the run.
- **定时和自动目标用不了 / No schedules or autonomous goals.** 每一轮一个 Grok 进程，它们会随这一轮悄悄停掉，所以拒绝并说明。 / A Grok process per run would end them silently, so they are refused with the reason.
- **换账号就是新会话 / Another account is a new session.** 新会话只拿到之前对话的摘要，拿不到工具调用的细节。 / The new session gets the conversation's summary, not its tool calls.
- **价钱偶尔是估算 / The price is sometimes an estimate.** Grok 不报价钱的那一轮按公开 API 价估算，订阅下实际花的可能不同。 / A turn Grok gives no price for is estimated at the public API rate, which may differ from what a subscription spends.
- **列表靠启发式 / The list is a heuristic.** 和 agy 一样，你自己在工作区里开的 Grok 会话会被当成 Bot 的藏起来。 / As for agy, your own Grok session in the workspace folder is hidden as a Bot's.
