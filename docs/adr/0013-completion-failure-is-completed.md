# 补全失败是完成，不是中断

「上次断了」只跟守护进程死亡：超时或 4xx/5xx 若标成 `interrupted`，下一轮会像刚崩过，而且会吞掉真正崩过时那一次通知。失败跳也不值得第五个终态——芯片、Stop、搜索、本机接口都要跟着改。所以补全失败把轮次打成 `completed`，转录只插一条 `kind: system`（不触发判断）。守护进程死亡留下的中断行才可以点「继续」新开一轮。

同轮自动重试覆盖首包前失败，以及已经开流但还没有可用正文 / 完整工具调用的中途卡住；最多 3 次。已经流出可用正文或完整可执行 `tool_calls` 时，中途静默或连接被掐就收下这一跳，不当失败。注释心跳会续上等待钟。同一端点同时最多两条补全 / 判断流，其余排队，避免群里多人并行把流饿死。4xx（除 429）和 `content_filter` 仍不重试。
