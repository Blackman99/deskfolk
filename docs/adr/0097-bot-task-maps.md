# Bot 会话的任务地图：应用记下每次调用在哪干的 / Task maps for Bot conversations: the app keeps where each call worked

Status: implemented 2026-10-21. Builds on [ADR 0096](0096-task-map.md) (the task map) and [ADR 0095](0095-project-sessions.md) (places of a call).

2026-10-21 任务地图合进去以后，你问普通 Bot 为什么没有。原因在 ADR 0096 的取舍里：项目会话的回放读的是 Claude Code 自己的会话文件，每次调用的参数都在；Bot 的调用应用只记了工具名和成没成（`tool_executions`），shell 和 MCP 另有命令（`turn_runs`），读写文件的路径哪里都没留，原型里 110 次写文件只有 4 次靠文件时间找回位置。你说「做」：应用从此记下每次调用在哪干的，Bot 的会话也能开地图。

On 2026-10-21, with the task map in, you asked why plain Bots had none. The reason was ADR 0096's trade-off: a project session's replay reads Claude Code's own session files, every call's arguments in them; for a Bot's calls the app kept only the tool and whether it worked (`tool_executions`), with commands besides for shell and MCP (`turn_runs`), and a file tool's path nowhere — the prototype found 4 of 110 writes by their files' times. You said go: the app now keeps where each call worked, and a Bot's conversation gets a map too.

## 决定 / Decisions

1. **每次调用记一行地点 / A row of place for every call.** 新表 `tool_places`：Bot 每轮的每次工具调用一行，记会话、轮、Bot、工作和任务，调用 id、工具名，从参数读出的地点（`AgentToolPlace`，和项目会话同一套：工作区里的相对路径、工作区外、测试或类型检查、git、MCP 服务、无处），shell 的动作、文件名、这一轮的模型、成没成、错误码和耗时。只记地点，不记参数：写文件的内容、命令的原文、消息正文都不进这张表。调用开始时建行，结束时补结果；没有外键，删会话、清空记录时一起删，每个会话留最新的 20000 行。Bot 读不到这张表（`describe_data` 不列）：它是地图的，Bot 跑过什么在 `turn_runs` 和 `tool_executions` 里。 / A new table, `tool_places`: one row per tool call of a Bot's turn, with its conversation, turn, Bot, job and ticket, the call's id and tool, the place read from its arguments (an `AgentToolPlace`, the same as a project session's: a path in the workspace, outside it, a test or type check, git, an MCP service, or none), the shell action, the file's name, the turn's model, whether it worked, its error code and how long it took. The place only, never the arguments: a write's content, a command's words and a message's text stay out of it. A row is made as the call starts and closed as it ends; no foreign keys; a conversation's rows go when it is deleted or cleared, and each keeps its newest 20000. Bots cannot read the table (`describe_data` leaves it out): it is the map's; what a Bot ran is in `turn_runs` and `tool_executions`.

2. **记在所有运行方式都经过的地方 / Kept where every runner passes.** 应用引擎、Claude Agent 和本机 CLI Agent 发出的 `turn.tool` 开始和结束帧都经过 local API 的发布口，记录就挂在那里：开始帧读工具名和参数算地点、写一行，结束帧补结果，并把地点作为 `ToolFrame.bot_call` 发给窗口（老窗口不认这个字段，照旧当成工具帧）。三种运行方式各在开始帧上带上这一轮的模型。文件工具的路径从工作区根读，shell 从它的 `cwd`（没写就是这一轮的工作目录）读命令里的路径，MCP 工具落在它的服务上，消息、提问、排任务这类不落地的调用算在工作区；宣布一轮结束的 `end_turn` 不算一步。 / The `turn.tool` start and end frames of the app's engine, Claude Agent and the local CLI agents all pass the local API's publisher, and the record hangs there: a start reads the tool and its arguments into a place and writes the row, an end closes it, and the place goes to the windows as `ToolFrame.bot_call` (an older window does not know the field and reads a tool frame as before). Each runner now puts the turn's model on its start frame. A file tool's path is read from the workspace root, a shell command's paths from its `cwd` (the turn's work dir when it names none), an MCP tool works at its server, and calls that name no place — a message, a question, a ticket — count at the workspace; `end_turn`, how a turn says it is done, is not a step.

3. **卡片上的回答也记下 / Your answers on cards too.** 等你批准的调用和它的卡关联；你回答之后补上结果。Claude Agent 先问再开始调用，卡比开始帧早：开卡时按卡上写的地点先建一行，调用真开始后换成它自己的地点；你拒绝的那次也在地图上。提问（`ask_user`）在你回答后算完成。等过卡片的调用不算长调用，那段时间是在等你；项目会话的地图也一样。 / A call waiting on your card is tied to the card and closed with your answer. Claude Agent asks before its call starts, so the card comes before the start frame: the row is made at the place the card names and takes the call's own place once it starts, so a call you refuse is on the map too. A question (`ask_user`) is done once you answer it. A call that waited on a card is not a long call — the wait was yours — on a project session's map too.

4. **回放接口 / The replay route.** `GET /v1/sessions/:id/replay` 返回 `SessionReplay`：这段对话最新的 5000 次调用（更多时标 `truncated`），每次带上你在卡上的回答（允许是 `user_temporary`，拒绝是 `user_reject`，应用规则拦下是 `hook`）；你说的话（应用替你执行的「停」这类不算）和你对 Bot 提问的回答，带上问的是哪个 Bot；Bot 按第一次干活的先后。项目会话用自己的回放接口。 / `GET /v1/sessions/:id/replay` returns a `SessionReplay`: the conversation's newest 5000 calls (`truncated` when there are more), each with your answer on its card (allowed as `user_temporary`, refused as `user_reject`, stopped by the app's rules as `hook`); what you said there (a stop and the other lines the app carried out apart) and your answers to its Bots' questions, with the Bot that asked; the Bots in the order they first worked. A project session keeps its own route.

5. **地图上 Bot 都是主角 / Every Bot a lead on the map.** 除了文件投送，每段对话都能开地图（右键菜单「打开任务地图」，窗格顶栏和标签 ⋯ 的「地图」）。私聊里是那一个 Bot，群里是每个干过活的 Bot，从头到尾都在图上、一样大，还没干活的站在工作区；每个 Bot 是侧栏一张卡。身体是它自己的 folk 形象（不是 folk 的头像按名字生成），名牌上是它模型的来源 logo（端点的厂商、Claude Agent 的火花、本机 Agent 的 logo）、名字和这一步的模型。在 Bot 的地图上，项目根叫「工作区」，项目外叫「工作区外」，仓库别处叫「工作区别处」，小镇的名字是工作区的文件夹名。 / Every conversation but the file drop can open a map (Open task map in its context menu, Map in its pane header and tab ⋯). A direct has its Bot, a group every Bot that worked, each on the map from start to end at full size, one that has not worked yet standing at the workspace; each Bot is a card at the side. Its body is its own folk figure (a name's folk when its avatar is not one); its badge carries its model's source (the endpoint's vendor, Claude Agent's spark, a local agent's logo), its name and the step's model. On a Bot's map the project root is called 「工作区」 (Workspace), outside the project 「工作区外」 (Outside), the little-used folders 「工作区别处」 (Elsewhere), and the town is named for the workspace folder.

6. **MCP 服务是一栋楼 / MCP services are a building.** `AgentToolPlace` 多了 `service`：MCP 工具落在它的服务上，项目会话里 Claude Code 的 `mcp__服务__工具` 也一样。地图在浮岛上加一座中继站，所有服务共用，只用了一个服务时牌子写服务名；浮岛宽了一格，每个岛的标签写岛上有的地点。 / `AgentToolPlace` gains `service`: an MCP tool works at its server, a project session's `mcp__server__tool` calls too. The map adds a relay station on the floating island for every server, its plate the server's name when only one was called; the island is a tile wider, and each island's label names the places on it.

## 取舍 / Trade-offs

- **之前的工作画不出来 / Earlier work cannot be drawn.** 这一版之前的调用没有记地点，补不回来；没有记录的对话，地图说明从这一版起才开始记。 / Calls before this version kept no place and cannot be recovered; a conversation with no record yet says the map starts from this version.
- **地点是从参数读的 / A place is read from the arguments.** 和项目会话一样只看调用的参数，不看磁盘：命令里不带斜杠也不像文件的词不算路径，这样的命令算在它运行的目录。 / As for a project session, only the call's arguments are read, never the disk: a word in a command with no slash that does not look like a file is not a path, and such a command counts where it runs.
- **多一次写库 / One more write per call.** 每次调用多一次插入和一次更新；写失败不影响调用本身。 / Every call costs an insert and an update; a failed write leaves the call as it was.
- **手机上仍然没有 / Still not on a phone.** 和 ADR 0096 一样只在宽窗口有工作台时给出。 / As in ADR 0096, only where a workbench holds it.

## 2026-10-21 修订：按这件事画 / Revised: drawn by plan

用了一阵你说：Bot 视角的地图有问题，应该和流程一样按「这件事」画——一件事可能涉及几个 Bot，跨群、私聊和 Bot 之间的私聊，这些都要体现。于是：

On using it you said the map from a Bot's point of view was wrong: like the flow, it should be drawn by the plan (这件事), which may take several Bots, across groups, your directs and the Bots' directs with each other, and all of that should show. So:

1. **一张图是一件事 / A map is a plan.** 从 Bot 的对话打开地图，画的是一件事（规划），和流程同一个口径：没指定时是这段对话最新的那件工作，地图上方的切换器（和流程同一个）能换；流程页顶栏多了「地图」，打开的就是这件事的地图，地图窗格记着它（`taskId`，和流程的标签页一样）。一段对话还没有一件事时，地图画它里面的全部工作。 / A map opened from a Bot conversation draws one plan, the same one the flow would: with none asked for, the conversation's newest work, switched in the switcher above the town (the flow's own); the flow's header gains Map, opening that plan's map, and the map's tab remembers it (`taskId`, as the flow's tab does). A conversation with no plan yet draws all its work.
2. **一件事的工作在哪都算 / A plan's work wherever it was done.** 它所有轮次的调用，不管在哪段对话里，按轮次现在属于哪件事算：中途才归进这件事的轮次，早先的调用一起算。`GET /v1/tasks/:id/replay` 读回，每次调用带上它的对话；你说的话取归到这件事下的和唤起它轮次的（流程里你的卡片），回答取它的轮次里的提问。 / Every call of its turns, in whatever conversation, by the plan the turn is in now: a turn filed into it mid-turn brings its earlier calls. `GET /v1/tasks/:id/replay` reads it back, each call with its conversation; your lines are the ones filed under it and the ones that woke its turns (your cards on the flow), your answers the ones to its turns' questions.
3. **对话都体现出来 / Every conversation shows.** 每个 Bot 的卡片写着它这一步在哪段对话里，为你哪一句干活按那段对话里你最新的一句；「交代给它的事」每句标出在哪说的；一个 Bot 第一次在某段对话里做这件事是值得看的时刻（「在和你的私聊里开始做这件事」「转到群「视频组」里接着做」）；顶上写着它在几段对话里；小镇以这件事的文件夹命名。 / Each Bot's card says which conversation its step is in, and the line it works for is your newest one in that conversation; each line you said is tagged with where; a Bot working on the plan in a conversation for the first time is a moment (“took this up in its direct with you”, “carried on in the group “视频组””); the top says how many conversations; the town is named for the plan's folder.
4. **实时按轮次归 / Live by the turn.** 实时的调用按它那一轮现在属于哪件事归到地图上：窗口里的轮次记着它属于哪件事；帧上的 `task_id`（这一轮开始那一刻的）只在窗口不认得这一轮时用。 / A live call joins the map by the plan its turn is in now, as the window's copy of the turn says; the frame's `task_id` (the plan when the call started) is only for a turn the window does not hold.

## 2026-10-21 修订：每个角色一个造型 / Revised: a figure for each character

你看了说：每个 Bot 应该用不同的 3D 模型，它自己的头像也要体现出来——原来人人都是同一个 folk 小人，两个默认头像的 Bot 在图上一模一样。于是角色换成和楼一样建模的小人偶：机器人、宇航员、巫师、小熊、骑士、电视头、厨师、小猫八种造型，八种配色，按角色（Bot 的 id，子代理的 id）稳定地分，一张图里不重样，用完才轮回。人偶总是脸朝你（按自己的固定朝向画，不随地图转），光照跟着地图的时辰；干活时轻轻颠，等你时跳，出错时晃一下。Bot 的头像（侧栏里那个）挂在它胸前，也放在名牌最前面，名牌上的模型 logo 挪到模型名旁边；侧栏卡片也用它的头像。项目会话的 Agent 和子代理也是人偶，名牌照旧是 Agent 的 logo。

You said each Bot should be a different 3D model, and its own avatar should show: until then every character was the same folk figure, so two Bots with default avatars looked the same. Characters are now little figures modelled like the buildings — robot, astronaut, wizard, bear, knight, TV head, cook and cat, in eight colours — given by the character (a Bot's id, a subagent's), the same every time and never two alike on one map until all are used. A figure always faces you (drawn at its own turn, not the map's), lit by the map's hour; it bobs while working, hops while waiting on you and shakes on a failure. A Bot's own avatar (the sidebar's) is on its chest and leads its badge, the model's logo moving beside the model; its card at the side wears it too. A project session's agent and subagents are figures as well, their badges still the agent's logo.

## 2026-10-21 再修订：从布丁和麻薯长出来 / Revised again: grown from Pudding and Mochi

你看了说：每个 Bot 的 3D 模型要以麻薯、布丁为基础延伸设计，不能完全从头做，细节也不够。于是八种从头搭的人偶换成吉祥物本身：都是 folk 头像那副身体（同一个 Blender 网格：蛋形身体、腮红、小短手、小脚），在地图的相机下（离地 30°，和楼一样；转 -25°，露出一点右侧）渲成透明图层，各有口味配色和行头——布丁（芥末色，天线）、麻薯（白，毛线帽和热饮）、芋泥（耳机和写字板）、樱花（贝雷帽、调色盘和画笔）、抹茶（厨师帽和打蛋器）、焦糖（安全帽和锤子）、芝麻（眼镜、耳后的铅笔和书）、蓝莓（巫师帽和魔杖）。分法照旧：按角色稳定地分，一张图里不重样。脸是共用的图层：头像是 folk（布丁）的 Bot，角色的眼睛和嘴照它头像的，其余是布丁本来的点点眼和微笑。头像放进胸前一枚圆徽章（徽章正对镜头，头像是个正圆），不再是贴在胸口的小圆片。手臂单独成层、绕肩膀转：干活时两手交替动，回复时更快并张嘴说话，等你时举手挥，出错时撇嘴；平时眨眼，各角色错开。时辰的光不再逐面重算颜色，而是在角色上盖一层颜色，按不透明度混进去、用它自己的图做遮罩，算法和楼墙一样。新角色更宽，一个门口站几个时间距从 30 拉到 38，名牌按各自帽顶的高度放。为了放大后看得清细节，角色和名牌一样按屏幕上的尺寸排版、再缩回 1/k，单独成一层（`will-change`）；图层是 HTML 图片。在应用的 WKWebView 里量过（Playwright 看不出这个差别）：画进小镇那一层的东西是按打开时的倍率画好再拉伸的；套了 SVG 滤镜的图也一样，所以时辰的光不用 SVG 滤镜。

You said each Bot's 3D model should be designed out from Mochi and Pudding, not made from scratch, and had too little detail. So the eight made-from-scratch figures became the mascots themselves: every one is the folk avatar's body (the same Blender mesh: egg body, cheeks, stubby arms, little feet), rendered as transparent layers from the map's camera (30° above the ground like the buildings, turned -25° so a little of its right side shows), each in a flavour and outfit of its own — Pudding (mustard, its antenna), Mochi (white, a beanie and a mug), taro (headphones and a clipboard), sakura (a beret, palette and brush), matcha (a chef's hat and a whisk), caramel (a hard hat and a hammer), sesame (glasses, a pencil behind its ear and a book), blueberry (a wizard's hat and a wand). They are given as before: by character, the same every time, never two alike on one map. The face is a shared layer: a Bot whose avatar is a folk (Pudding) gives its character that folk's eyes and mouth; any other gets Pudding's own dot eyes and smile. The avatar sits in a round pin on the chest (square to the camera, so the avatar is a true circle) instead of a small disc. The arms are layers of their own turning about the shoulders: they take turns while it works, faster and with its mouth talking while it replies, one waves while it waits on you, and it frowns at a failure; every character blinks now and then, out of step. The hour's light is no longer worked out face by face but one colour laid over the character at an opacity, masked by its own pictures, the same arithmetic as a building's wall. The new characters are wider, so neighbours at one door stand 38 px apart instead of 30, and each badge sits over its own hat. So that zooming in shows the detail, a character is laid out at its size on screen and scaled back by 1/k in a layer of its own (`will-change`), as the labels are, its layers HTML images. Measured in the app's WKWebView (Playwright does not show the difference): anything painted into the town's layer is drawn at the zoom the map opened at and stretched, and so is a picture under an SVG filter, so the hour's light is not an SVG filter.

## 2026-10-21 三修订：各干各的活 / Revised a third time: each at its own work

你看了说：每个角色正在工作的样子要按它自己的外形特征单独出一个。原来干活时人人一样，两手交替。现在在一处干活（不是走在路上）时各干各的：布丁敲键盘，天线摇着收信号（天线单独成层、绕根部转，顶上的球发光，往外冒信号弧）；麻薯的热饮冒热气，隔一会儿把杯子送到嘴边喝一口，闭上眼；芋泥跟着耳机里的歌点头，眼睛笑眯，音符往外飘，写字板上一个个打勾；樱花挥笔，笔尖甩出颜料点和一道道彩色笔触，调色盘端起来；抹茶从手腕使劲打蛋，打蛋器两侧有速度线，奶油和抹茶沫往外溅；焦糖慢慢把锤子抡到肩后、在身侧狠狠砸下，火花四溅，砸下那一下闭眼、身子一沉；芝麻端起书看，隔一会儿翻一页、推一下眼镜，镜片一闪；蓝莓飘起来，用魔杖画圈，星星从杖头洒下。只转手臂的话，拿在手里的东西只能跟着绕肩膀转——锤子会扫过自己的脸，杯子会离嘴越来越远——所以手里的东西从手臂图层拆出来单独成层，套在手臂里、绕手转（`<id>-held-l/r`）；渲染时同时记下每件东西出活的点（杯口、笔尖、锤头、杖头的星星……），特效从那里冒，跟着手和东西一起动。走路时还是大家一样摆手。一个门口站几个时，原来右边的盖住左边那个的右手，而大多数东西拿在右手；现在每个站在右边那个的前面，手上的活露出来。动的幅度按角色的尺寸算，不随缩放变；系统设了减少动态时都停住，特效不出现。

You said each character's working state should be a design of its own, from what it looks like. Until then every character at work did the same, its hands taking turns. Now a character at work in a place (not walking between places) does its own work: Pudding types while its antenna sways and picks up signals (the antenna is a layer of its own turning about its foot, its ball glowing and sending out arcs); Mochi's coffee steams, and now and then it brings the mug to its mouth and sips, eyes shut; taro nods to the music in its headphones, eyes smiling, notes drifting off, and ticks its clipboard; sakura strokes with its brush, paint flicking off its tip in strokes of colour, its palette held up; matcha whisks hard from the wrist, speed lines either side of the whisk, cream and matcha flying; caramel slowly swings its hammer back over its shoulder and brings it down hard at its side, sparks flying, eyes squeezed shut and its body giving at the blow; sesame holds its book up to read, turns a page now and then and pushes up its glasses, which glint; blueberry floats, drawing circles with its wand, stars trailing off its tip. Turning only the arms, what a hand held could only swing about the shoulder — the hammer swept across its own face and the mug moved away from the mouth — so the held things left the arm layers for layers of their own, nested in the arm and turning about the hand (`<id>-held-l/r`); the render also marks where each thing's work comes out (the mug's rim, the brush's tip, the hammer's head, the wand's star…), and the effects start there and move with the hand and the thing. Walking, every character still swings its arms alike. At a door with several characters each used to cover its left neighbour's right hand, where most things are held; now each stands in front of the one on its right, so the work in its hand shows. Motions are sized by the figure, not by the zoom; with reduced motion everything stands still and no effects show.

## 实现 / Implementation

守护进程：`tool-places.ts`（地点规则 `botPlaceOf`、卡片的地点 `cardPlaceOf`、记录器 `createToolPlaceRecorder`，挂在 `local-api.ts` 的 `publish`）、`store/tool-places.ts`（建行、补结果、关联卡片、`sessionReplay`），`engine/tools.ts` 的 `openApprovalCard` / `openAskCard` 关联卡片和补结果，三个运行方式在开始帧上带 `model`；`claude-code/tool-place.ts` 认 MCP 工具，也认媒体和办公文件的扩展名。协议：`bot-replay.ts`（`BotToolInfo`、`SessionReplay`），`ToolFrame.bot_call`，`turn.tool` 的 `model`。信使：`taskmap/map-data.ts` 的 `fromSessionReplay`、`MapCharacter.lead`，`characters.ts`（名字、形象、脸、模型来源），`scene/figures.ts`（摆图层、`figureFace`、`figureTint`、`assignFigures`），`MapFigure.svelte`（一个角色的图层、动作和它自己的活），角色图层由 `apps/messenger/scripts/map-figures/figures.py`（Blender 5.2，引用 folk 头像的 `render.py`）渲出、`build.py` 打包成 `scene/figure-assets.ts`，`MapLogo.svelte`，`TaskMap` 按会话种类读回放，入口在 `Shell.svelte` 的 `chatTabActions` 和 `sidebar/session-context-menu.ts`。
