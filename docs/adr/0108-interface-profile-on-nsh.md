# 界面方案搬到 NSH：令牌进主题，样式改挂钩子上的类名 / The interface profile on NSH: tokens into the theme, a stylesheet becomes classes on hooks

Status: accepted 2026-11-07; milestone 1 implemented in `apps/desktop-nsh` (`nsh-spike` branch), milestone 2 waits on the daemon. For the NSH app it replaces [ADR 0106](0106-the-interface-is-yours-too.md)'s stylesheet layer, its floor check on the page and its window report; the Svelte app keeps 0106 as written until it is retired. Follows [ADR 0107](0107-spike-native-desktop-on-nsh.md)'s decision of 2026-11-06 that customisation goes through NSH's own means.

ADR 0106 的界面方案有四层：令牌、用法、自定义 CSS、改过的字，外加代码把守的底线。它的做法处处靠页面：令牌和 CSS 写进最后一个 `<style>`，底线靠 `getComputedStyle` 和 `elementFromPoint` 查，回报列出没选中东西的选择器，目录从加载的样式表里读。NSH 没有 DOM 也没有 CSS：界面是原生视图，样式是 Tailwind 类名，颜色来自主题令牌（shadcn 的 `cssVars`，应用的 `theme.json` 由 `tokens.css` 生成）。2026-11-06 你定了：自定义界面走 NSH 自己的机制。外壳搬过来时，界面方案的套用被留在了外面（`Shell.tsx` 注明，`shell-state.ts` 没接 `wireInterface`），设置 › 界面 能改方案，NSH 这边什么都不变。

ADR 0106's profile has four layers — tokens, behaviour, a stylesheet of your own, changed words — and a floor kept by code. All of it leans on the page: tokens and the stylesheet go into the last `<style>`, the floor is read off `getComputedStyle` and `elementFromPoint`, the report lists selectors that matched nothing, the catalog is read off the loaded sheets. NSH has neither a DOM nor CSS: views are native, styles are Tailwind classes, colours come from theme tokens (shadcn's `cssVars`; the app's `theme.json` is generated from `tokens.css`). On 2026-11-06 you decided customisation goes through NSH's own means. When the shell moved over, applying the profile was left out (`Shell.tsx` says so, `shell-state.ts` skips `wireInterface`): Settings › Interface could change the profile and nothing in the NSH app changed.

## 决定 / Decisions

1. **同一份方案，两种应用各读各的层 / One profile; each app reads the layers it can.** 守护进程里的方案不变，所有窗口和手机读同一份。NSH 的窗口读令牌、用法和字；CSS 层只给 Svelte 应用，NSH 不读它。第二步给方案加一层 `classes`（按钩子写的类名，决定 7），NSH 读它，Svelte 不读。第一步不改守护进程。 / The daemon's profile is unchanged and every window and phone reads the same one. NSH windows read the tokens, the behaviour and the words; the stylesheet is the Svelte app's alone. Milestone 2 adds a `classes` layer (Tailwind classes per hook, decision 7) that NSH reads and Svelte does not. Milestone 1 changes nothing in the daemon.

2. **令牌进 NSH 的主题，运行时换 / Tokens become NSH theme tokens, swapped at run time.** 方案的令牌照 `theme-from-tokens.ts` 的规矩改名：去掉 `--`，`--accent` 是 `brand`，`--muted` 是 `ink-muted`，值里的 `var(--accent)`、`var(--muted)` 一样改。浅色的进 `light`、深色的进 `dark`，叠在应用的 `theme.json` 上，再照同一张表重算 NSH 自己的令牌（`background`、`primary`、`ring`……，`nsh/base` 的组件读它们），所以改了强调色，按钮、焦点环、开关都跟着走；`--you` 没设时照 0106 跟着强调色（浅色就是强调色，深色是强调色在 oklab 里和黑色七三开）。这张表是脚本里那张的副本（脚本在 Bun 里读文件，应用导入不了它），空方案重算出来必须和 `theme.json` 一模一样，测试核对。主题里没有位置的令牌（阴影、时长、字号、`--content-glass`）第一步不起作用。值先交给引擎读一遍：读不了的不进主题，否则 NSH 会拿另一种外观的值顶上，或者让 `bg-pane` 这样的类整个失效；互相引用成环的也不进。方案关掉（`enabled`）或在这个窗口暂停时，主题回到 `theme.json`。 / Token names follow `theme-from-tokens.ts`: no `--`, `--accent` is `brand`, `--muted` is `ink-muted`, and `var()` references inside values the same. Light values go into `light`, dark into `dark`, over the app's `theme.json`, and NSH's own tokens (`background`, `primary`, `ring`, …, which `nsh/base` components read) are worked out again from the same table, so a new accent reaches buttons, focus rings and switches; `--you` left unset follows the accent as 0106 has it (light the accent itself, dark the accent mixed 70% with black in oklab). The table is a copy of the script's (the script reads files under Bun and the app cannot import it); an empty profile must come out as `theme.json` exactly, and a test checks it. Tokens the theme has no place for (shadows, durations, type sizes, `--content-glass`) do nothing yet. Each value is read by the engine first and left out when it cannot be: otherwise NSH fills that look from the other one, or drops a class like `bg-pane` altogether; values naming each other in a ring are left out too. With the profile off (`enabled`) or paused in a window, the theme is `theme.json` again.

3. **经内部的 `setup()`，只在一个模块里 / Through the internal `setup()`, in one module only.** 换主题用 NSH 渲染模块 `nsh:rt` 的 `setup(null, 主题, null, null)`：入口第一句就是用它装 `nsh.json` 的主题，运行时再调一次照样生效，`token()`、类名和 `nsh/base` 都跟着变，桌面和 web（`web/browser/environment.js`）都有。它是 NSH 的内部接口（`nsh-js` 的 `dom.rs` 标着 `Ts::Internal`，没有生成类型），所以只有 `src/ui/interface/theme.ts` 调它，类型在旁边的 `nsh-rt.d.ts`。没用 `AppView::set_theme_overrides`，三个原因：它只在 Rust 里（TSX 要经 `host.call` 让外壳调），它解析 `var()` 时对着 shadcn 的默认值而不是应用的令牌（`var(--brand)` 读不到应用的强调色），web 播放器没有它，无头测试也看不见它。给 NSH 上游提一个公开的 `setTheme`（文字见文末），合并后换过去。 / The theme is swapped through `setup(null, theme, null, null)` of NSH's renderer module `nsh:rt`: the entry's first statement loads `nsh.json`'s theme with it, and calling it again at run time takes — `token()`, classes and `nsh/base` follow — on the desktops and on the web (`web/browser/environment.js`) alike. It is internal (`Ts::Internal` in `nsh-js`'s `dom.rs`, no generated types), so only `src/ui/interface/theme.ts` calls it, typed by `nsh-rt.d.ts` beside it. Not `AppView::set_theme_overrides`, for three reasons: it is Rust-only (TSX would need the shell to call it over `host.call`); it resolves `var()` against shadcn's defaults rather than the app's tokens (`var(--brand)` would not find the app's accent); and the web player has nothing like it, nor do headless tests see it. A public `setTheme` is to be asked of NSH upstream (text at the end) and taken once merged.

4. **用法照镜像的代码走 / Behaviour runs on the mirrored code.** 回车还是 ⌘/Ctrl+回车 发送、消息时间 24 还是 12 小时、专注模式、窗口从哪打开：镜像的读取处（输入框、`formatMessageTime`、`focus-mode`、`open-placement-store`）照旧读 `interfaceBehaviour()`，窗口的控制器把方案写进去。动效：NSH 的 `reduceMotion()` 只听系统，盖不过，所以应用里读它的地方都改读 `src/ui/interface/motion.ts` 的 `reduceMotion()`，方案说「一直减弱」或系统要求减弱时为真；`motion-reduce:` 类只跟系统（应用里现在没有这种类，新写动效用这个函数）。主题和语言照旧在设置里。代码配色（`code_theme`）、内容区玻璃（`content_glass`）、整体缩放（`scale`）留到第二步：NSH 的代码高亮配色是固定的，玻璃要外壳的材质和窗格的几层底，缩放要原生的缩放先做。 / Enter or ⌘/Ctrl+Enter to send, 24- or 12-hour times, focus mode, where windows open: the mirrored readers (the composer, `formatMessageTime`, `focus-mode`, `open-placement-store`) read `interfaceBehaviour()` as they do in Svelte, and the window's controller writes the profile into it. Motion: NSH's `reduceMotion()` hears only the system and cannot be overridden, so every reader in the app reads `reduceMotion()` from `src/ui/interface/motion.ts` instead, true when the profile says always reduced or the system asks; `motion-reduce:` classes follow the system only (the app has none; new motion reads the function). Theme and language stay in Settings. Code colours (`code_theme`), glass content (`content_glass`) and a whole-window `scale` wait for milestone 2: NSH's code highlighting has fixed colours, glass needs the shell's material and the panes' layers, and scale needs native zoom first.

5. **改过的字 / Changed words.** `runtime.ts` 的 `copy()` 把方案里这种语言的字叠上去（`copyFor(locale, interfaceController.copyIn(locale))`），规矩和 0106 一样：只换应用本来有字的键，占位符一个不少，方案关掉或地址要默认时不换，按键暂停和底线停掉时照旧。 / `copy()` in `runtime.ts` lays the profile's words for the language over the app's (`copyFor(locale, interfaceController.copyIn(locale))`), on 0106's terms: only keys that hold plain words, every placeholder kept; not with the profile off or the default asked in the address, kept through a key's pause and a floor's.

6. **回路 / Ways back.** ⌥⇧⌘U（Windows、Linux 是 Ctrl+Alt+Shift+U）由窗口启动时用 `keymap` 绑上，`when: "always"`，输入框里也接得到；没有别的绑定用这个键，NSH 按「新绑定优先」，所以它不会被别处抢走。按一次这个窗口回到应用自己的样子（令牌停掉，字和用法照旧），再按一次恢复。web 上地址里的 `?ui=default` 照旧；桌面窗口没有地址，靠这个键、设置里的开关和「全部恢复默认」。撤销和修改记录不变。 / ⌥⇧⌘U (Ctrl+Alt+Shift+U on Windows and Linux) is bound with `keymap` when the window starts, `when: "always"`, so an input does not swallow it; nothing else binds that key and the newest binding wins in NSH, so nothing takes it over. Pressed, this window shows the app's own look (tokens off, words and behaviour kept); pressed again, yours. On the web `?ui=default` in the address still works; a desktop window has no address and has the key, Settings' switch and "put everything back". Undo and the history are as before.

7. **钩子是 `ui()`，底线是 `floor()` / Hooks are `ui()`, floors are `floor()`.** 钩子的名字照 `UI_HOOKS`，写在那个部位的视图上：`class={ui("composer", "flex-col …")}`，返回应用自己的类名，第二步再接上方案给这个钩子的类名。不用 `testID`（测试在用它，一个视图只有一个）也不用 `nativeID`（NSH 0.4 的普通视图上它什么都不做）。第一步只在要动的几处挂上（发送按钮、批准卡、提问卡、手机底栏）；全部挂上、加一条像 `hooks.test.ts` 那样核对每个钩子都在的源码测试，跟 `classes` 层一起做：没有类名层之前挂上没有用处，却要同时改二十来个文件。底线照 `UI_FLOORS`：停止、批准按钮、提问卡、去设置的入口、暂停自定义界面、撤销界面修改，各自带 `ref={floor(名字, 颜色)}`，颜色写明字或图标用哪个令牌、底下从下往上是哪几层；共用的 `Button` 有 `floor` 属性，按样式自己报颜色。 / Hook names are `UI_HOOKS`', on the view of that part: `class={ui("composer", "flex-col …")}` gives back the app's own classes, and in milestone 2 the profile's classes for that hook after them. Not `testID` (tests use it, and a view has one) nor `nativeID` (it does nothing on plain views in NSH 0.4). Milestone 1 hooks only the parts it touches anyway (the send button, the approval and ask cards, the phone's bottom bar); hooking all of them, with a source test like `hooks.test.ts` that each is there, comes with the `classes` layer — before it a hook does nothing, and the sweep touches some twenty files. Floors are `UI_FLOORS` — Stop, the approval buttons, the ask card, the way to Settings, pausing the custom interface, undoing a change — each with `ref={floor(name, colours)}`, naming the token its words or glyph are drawn in and the grounds under it, bottom up; the shared `Button` takes a `floor` prop and reports its variant's colours itself.

8. **令牌层的底线查对比度 / The token layer's floor checks contrast.** 在 NSH 里令牌只能改颜色（和几处圆角），藏不了、缩不了、盖不住一个视图：没有 `display`、`opacity`、`pointer-events`、层叠这些令牌。所以第一步查的是令牌能弄坏的：每个已经排好版（`measure()` 有结果、至少 12×12）的底线元素，它的字（或图标）叠在它的几层底上（带透明度的一层层混合，最底下垫窗口的 `bg`，再垫白或黑），对比度至少 3:1（WCAG 1.4.11 给界面部件的最低值：底线首先是个要点得到的控件）。只算方案造成的：同一个元素在应用自己的主题下要过得去（应用主题的值每种外观只读一次：引擎在同一轮里换成应用主题读完再换回来，屏幕上看不到）。在当前外观下查，套用之后、底线元素出现时、换外观时各查一次。不过关：这个窗口停掉令牌层，字和用法照旧，提示一次；方案再变就重新给它机会。0106 原来对比度不查（「底线查不到对比度」），这一条在 NSH 上反过来了；看得见、点得到、没被盖住由第二步的类名层来查（类名能藏能盖），用 `measure()` 量。 / In NSH a token can change colours (and a few radii) and nothing else: no token hides, shrinks or covers a view. So milestone 1 checks what tokens can break: each floor that is laid out (`measure()` answers, at least 12×12) must have its words or glyph reach 3:1 against its grounds (blended layer by layer with their alpha, over the window's `bg`, over white or black) — WCAG 1.4.11's minimum for interface parts, as a floor is a control first. Only what the profile causes counts: the same element must pass under the app's own theme (its values are read once per look, the engine switched to it and back within one turn; nothing shows). Checked in the look in force, after each apply, when a floor appears and when the look changes. A failure drops the token layer in that window, keeps words and behaviour, and says so once; the next profile gets its chance again. 0106 did not check contrast; on NSH it is the one thing tokens can break. Shown, clickable and uncovered become milestone 2's checks with the classes layer (classes can hide and cover), measured with `measure()`.

9. **web（手机和平板）同一份 / The web (phone and tablet) runs the same code.** web 包是同一份 TSX，跑在页面的主线程上，`setup()` 在 web 播放器里也有，所以令牌、用法、字、键和底线都一样。镜像的控制器因此不能碰页面：原来的 `apply()` 会把方案的 CSS 塞进 NSH 自己的页面，`report()` 会把 NSH 页面的样式表当成应用的目录报给守护进程。镜像改成由平台把这几件事交给它（套用、底线、键、窗口类型），自己不碰 `document` 和 `window`。 / The web package is the same TSX on the page's main thread, and the web player has `setup()` too, so tokens, behaviour, words, the key and the floor work alike. The mirrored controller therefore must not touch the page: as ported it would put the profile's stylesheet into NSH's own page and report NSH's sheets to the daemon as the app's catalog. The mirror now takes those from the platform (painting, floors, the key, the kind of window) and touches no `document` or `window`.

10. **回报和目录留到第二步 / Reports and the catalog wait for milestone 2.** 现在的回报形状是页面的（没选中的选择器、浏览器丢掉的规则、`CSS.supports`），目录从样式表读；NSH 的窗口第一步什么都不报，设置里的「各种窗口的回报」照旧只有 Svelte 窗口的。 / The report's shape is the page's (unmatched selectors, dropped rules, `CSS.supports`) and the catalog is read off stylesheets; NSH windows report nothing in milestone 1, and Settings' reports stay the Svelte windows'.

## 第二步要守护进程做的 / What milestone 2 needs from the daemon

- **`classes` 层**：`profile.classes: Partial<Record<UiHook, string>>`，补丁 `classes: { [hook]: string | null }`，`reset` 认 `"classes"`；校验：钩子在 `UI_HOOKS` 里，每串不超过 2000 字、总共不超过 64 KB，只收 Tailwind 类名的字符（字母、数字、`-_:/.[]()#%,`），没有 `url(`；修订、撤销、恢复、`ui-edit` 卡逐项列出，和其余三层一样。`describe_interface` 列出钩子、各自是什么、NSH 认哪些类名（深浅用 `dark:` 写在同一串里）。 / **A `classes` layer:** `profile.classes` per hook, a `classes` patch with null to remove, `reset` taking `"classes"`; checked: hook in `UI_HOOKS`, each string at most 2000 characters and 64 KB in all, Tailwind class characters only, no `url(`; revisions, undo, restore and the `ui-edit` card list it like the other layers. `describe_interface` lists the hooks, what each is, and that NSH reads classes (`dark:` in the same string for the dark look).
- **NSH 窗口的回报和目录**：回报加 `client: "svelte" | "nsh"`，守护进程按 `(client, surface)` 各存一份；NSH 的回报写：不认识的类名（按钩子）、主题里没有位置的令牌、引擎读不了的令牌值、底线失败和量到的对比度或尺寸；目录写 NSH 的令牌（照方案的名字，`brand` 报回 `--accent`）和它们在两种外观下的默认值。 / **NSH reports and catalog:** a `client` field and one report kept per client and surface; an NSH report lists unknown classes per hook, tokens with no place in the theme, values the engine could not read, and failed floors with the contrast or size measured; its catalog lists NSH's tokens under the profile's names with both looks' defaults.
- **工具说明**：`edit_interface` 说明 NSH 窗口读 `classes` 不读 `css`，方案只写了 CSS 时在结果里提醒。 / **Tool text:** `edit_interface` says NSH windows read `classes`, not `css`, and its result says so when a change only touches the stylesheet.
- 不用守护进程的：`code_theme`（要 NSH 的高亮能换配色，先提上游）、`content_glass`（外壳的材质和窗格的底）、`scale`（原生缩放）。 / Not the daemon's: `code_theme` (NSH's highlighter must take a palette, asked upstream first), `content_glass` (the shell's material and the panes' grounds), `scale` (native zoom).

## 后果 / Consequences

- **改一个令牌整个应用都跟着变，NSH 的组件也一样 / A token changes the whole app, NSH's own components too.** 重算的 shadcn 令牌把强调色带进 `nsh/base` 的按钮、输入框焦点和开关。 / The derived shadcn tokens carry an accent into `nsh/base`'s buttons, focus rings and switches.
- **依赖一个内部接口 / One internal interface.** NSH 升级时 `setup()` 的参数可能变；只有 `theme.ts` 一处要改，`interface.test.tsx` 会先失败。 / `setup()`'s arguments may change in an NSH update; only `theme.ts` would change, and `interface.test.tsx` fails first.
- **启动时先是应用自己的样子 / A window starts in the app's own look.** Svelte 把上次的 CSS 存在本机、第一帧就画出来；NSH 的窗口等守护进程回答再换，连上之前看到的是默认。要的话以后照样缓存主题。 / The Svelte app caches the last stylesheet and paints it in the first frame; an NSH window switches once the daemon answers and shows the default until then. Caching the theme the same way can follow.
- **还没做 / Not done.** `classes` 层、钩子全部挂上、NSH 窗口的回报和目录、`code_theme`、`content_glass`、`scale`、Bot 写的 TSX 界面模块（ADR 0107 的第三层）。 / The classes layer, every hook in place, NSH's reports and catalog, `code_theme`, `content_glass`, `scale`, and Bot-written TSX modules (ADR 0107's third layer).

## 取舍 / Trade-offs

- **内部接口，而不是等上游。** `set_theme_overrides` 是公开的，但对不上应用的令牌、web 和测试都没有；等上游加一个公开接口要多久说不准。用内部的 `setup()`，一个模块包住，换的时候改一处。 / **An internal interface rather than waiting.** `set_theme_overrides` is public but misses the app's tokens, the web and the tests; a public call upstream may take a while. `setup()` is wrapped in one module and swapped in one place.
- **底线只查对比度。** 令牌层能弄坏的只有颜色，查别的没有意义；类名层来了再查尺寸和遮挡。3:1 偏松：浅一点的幽灵按钮能过，看不见的过不了。 / **The floor checks contrast only.** Colour is all a token can break; size and covering come with classes. 3:1 is lenient: a quieter ghost button passes, an invisible one does not.

## 实现 / Implementation

- `apps/desktop-nsh/app/src/ui/interface/`：`theme.ts`（改名、叠加、重算 NSH 自己的令牌、先让引擎读一遍、`setup()`）、`nsh-rt.d.ts`、`floor.ts`（`floor()` 和底线检查）、`contrast.ts`（混合和对比度）、`motion.ts`（`reduceMotion()`）、`hooks.ts`（`ui()`）、`look.ts`（给控制器的平台一侧和 `wireInterfaceHere`）。 / The `interface/` module: the theme, its internal call's types, the floor, contrast, motion, hooks, and the platform side handed to the controller with `wireInterfaceHere`.

## 跟进 / Follow-ups

给 NSH 上游的请求（还没提，等你看过） / The request for NSH upstream (not sent; for you to look at first):

> **A public `setTheme(theme)` for TS apps.** Apps load their theme once, from `nsh.json`'s `"theme"`, through `setup()` of `nsh:rt`, which is internal. Apps that let users change their colours at run time (a user theme, a brand per workspace) need to swap the theme while running. `AppView::set_theme_overrides` exists for embedding hosts, but (1) it is Rust-only, so a TS app must route through `host.call`; (2) it resolves `var()` against the default theme rather than the app's tokens, so an override like `"primary": "var(--brand)"` cannot reach the app's own tokens; (3) the web player has no counterpart; and (4) `nsh test` cannot observe it. Proposal: export `setTheme(theme: string | object | null)` from `nsh` — same `cssVars` format as `nsh.json`, resolved over the app's theme as `setup()` does, `null` back to `nsh.json`'s — on every platform including the web player and the test host, plus a way to check a theme without applying it (`parseTheme(theme): { errors: Array<{ token, look, message }> }`), since today a value the parser cannot read silently takes the other appearance's value or drops the token.
