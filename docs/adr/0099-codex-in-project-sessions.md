# 项目会话里的 Codex / Codex in project sessions

Status: implemented 2026-10-23. Builds on [ADR 0095](0095-project-sessions.md) (project sessions), [ADR 0079](0079-local-agents.md) (local agents) and [ADR 0092](0092-permission-modes.md) (permission modes).

2026-10-23 你问 agent 能不能支持其他的了。查下来 Bot 早就能跑 Codex、Grok、OpenCode 这些（ADR 0079），项目会话还只有 Claude Code。我提议先给项目会话加 Codex，只做在应用里新开，导入终端会话等查清 Codex 把会话存在哪再做；你说「加」。

On 2026-10-23 you asked whether agents other than Claude Code were supported yet. Bots had run on Codex, Grok, OpenCode and the rest since ADR 0079; project sessions still had only Claude Code. I proposed adding Codex to project sessions, started in the app only, with carrying on a terminal session left until it was clear where Codex keeps its sessions; you said "add it".

查下来（Codex 0.153.4，`codex app-server`）：

- `thread/start` 带 `ephemeral: false` 开出的线程 Codex 自己存着；换一个新的 app-server 进程 `thread/resume { threadId }` 就接得上，上下文都在（问它上一轮列过哪些文件，它答得出）。
- `approvalPolicy: "untrusted"` 加 `sandbox: "read-only"` 时，每条命令（读的也算）和每次改文件都先问，新开的线程和接着的线程一样；拒绝的改动不会写出来。和 Bot 的 Codex 测到的一样（ADR 0079）。
- 你的 `config.toml` 里的默认模型 `gpt-6-astra` 在 ChatGPT 账号上被拒（「not supported when using Codex with a ChatGPT account」），这一轮失败，错误的 `message` 是服务返回的一整段 JSON。这个账号的 `model/list` 列的是 `gpt-5.6-terra`（默认）和 `gpt-5.6-luna`。
- 本机没有 `~/.codex/sessions`：线程的记录在 `state_5.sqlite`，旧的 rollout 文件迁走了。app-server 自己能列和读：`thread/list`（可按目录、来源筛）、`thread/read`、`thread/fork`。
- Codex 有计划模式（协作模式，`collaborationMode/list`，`turn/start` 的 `collaborationMode`），标着 EXPERIMENTAL。

What was there (Codex 0.153.4, `codex app-server`):

- A thread started with `ephemeral: false` is kept by Codex; a new app-server process picks it up with `thread/resume { threadId }`, context and all (asked which files it had listed the run before, it could say).
- With `approvalPolicy: "untrusted"` and `sandbox: "read-only"`, every command (reads too) and every file change asks first, on a new thread and a resumed one alike; a declined change is not written. The same as measured for a Bot's Codex (ADR 0079).
- The default model in your `config.toml`, `gpt-6-astra`, is refused on a ChatGPT account ("not supported when using Codex with a ChatGPT account"); the turn fails, and the error's `message` is the service's whole JSON. The account's `model/list` lists `gpt-5.6-terra` (the default) and `gpt-5.6-luna`.
- There is no `~/.codex/sessions` on this machine: threads are recorded in `state_5.sqlite` and the old rollout files were migrated. The app-server lists and reads them itself: `thread/list` (filterable by directory and source), `thread/read`, `thread/fork`.
- Codex has a plan mode (collaboration modes: `collaborationMode/list`, `collaborationMode` on `turn/start`), marked EXPERIMENTAL.

## 决定 / Decisions

1. **项目会话的 Agent 是 Claude Code 或 Codex / A project session's agent is Claude Code or Codex.** `ProjectAgent` 多了 `codex`（`PROJECT_AGENTS`），存在 `sessions.project_agent`。侧栏「项目」段头的「+」里每个 Agent 一项（「新开 Claude Code 会话…」「新开 Codex 会话…」），在窗口里各自直接打开系统的文件夹选择；目录行的「+」改成一个小菜单，选了 Agent 就在那个目录开：原来这两条路都不经过选 Agent 的面板，默认就是 Claude Code，Codex 在窗口里会选不到。新开面板先选 Agent，从哪一项打开就选中哪个；Codex 也列你最近干活的目录（Claude Code 终端会话和应用里各个项目会话出现过的），只是不列终端会话。导入面板只有 Claude Code。侧栏、标签、面板头、窄栏和任务地图上是 Codex 的标志。 / `ProjectAgent` gains `codex` (`PROJECT_AGENTS`), kept in `sessions.project_agent`. The Projects section's "+" offers one item per agent (New Claude Code session…, New Codex session…), each opening the system folder dialog straight away in the window, and a directory row's "+" became a small menu that starts the picked agent's session in that directory: both paths used to skip the sheet where the agent is picked and start Claude Code, so Codex could not have been chosen in the window. The new-session sheet picks the agent first, opening on the one whose item was chosen; for Codex it lists the directories you worked in lately (where Claude Code's terminal sessions and the app's project sessions ran) without the terminal sessions under them. The import sheet offers Claude Code only. The sidebar, tab, pane header, rail and task map wear Codex's mark.

2. **像在 Codex 自己的应用里 / As in Codex's own app.** 每一轮起一个 `codex app-server`，按 Bot 的 Codex 那样找（设置 › Agent 里的路径，系统代理）。第一轮 `thread/start`（不是临时的，`serviceName: "deskfolk"`），线程 id 记成会话的 `project_agent_session`；之后每一轮 `thread/resume` 它，只发你的新话。不加开发者指令、不给应用的工具、不关你的配置：你的 `config.toml`、AGENTS.md、MCP 服务器、skill 和 hook 都照常。模型在开线程、接线程和每次 `turn/start` 时带上，思考等级在 `turn/start` 带上；改了从下一个 turn 起生效，不在一个 turn 中途换。没选就是你的 Codex 设置。清空记录后下一轮开新线程。 / Each run starts a `codex app-server`, found as a Bot's Codex is (the path in Settings › Agents, the system proxy). The first run calls `thread/start` (not ephemeral, `serviceName: "deskfolk"`) and the thread id becomes the session's `project_agent_session`; every later run resumes it with `thread/resume` and is sent only your new line. No developer instructions, none of the app's tools, nothing of your config switched off: your `config.toml`, AGENTS.md, MCP servers, skills and hooks all apply. The model goes with opening or resuming the thread and with every `turn/start`, the thinking level with `turn/start`; a change takes effect from the next turn, not mid-turn. No pick is what your Codex settings say. After the history is cleared the next run starts a new thread.

3. **权限和 Claude Code 的一样由应用管 / Permissions are the app's, as for Claude Code.** 开线程和接线程都带 `approvalPolicy: "untrusted"`、`sandbox: "read-only"`，每条命令和每次改文件都来问应用；应用按 Bot 的本机 Agent 那套规则（`decideAction`）、以项目目录为工作区、按应用的权限模式回答：自动、全部允许下直接放行，改动先问下出批准卡，只读下拒绝；每个 Agent 的凭据（包括 `~/.codex`）一律碰不到。要更多沙箱权限、MCP 的 elicitation、要你输入的请求，和 Bot 的 Codex 一样回绝。Codex 读文件也走命令，所以只读模式下它连 `cat` 也跑不了，和 Bot 的 Codex 一样。`/review` 是例外，见文末补记。 / Opening and resuming the thread both pass `approvalPolicy: "untrusted"` and `sandbox: "read-only"`, so every command and file change comes to the app; the app answers with the rules a Bot's local agent goes by (`decideAction`), the project directory as the workspace, under the app's permission mode: auto and allow all let it run, ask first puts up a card, read-only refuses; every agent's credentials (`~/.codex` among them) stay off limits. Requests for more sandbox access, MCP elicitations and requests for your input are declined, as for a Bot's Codex. Codex reads files through commands too, so under read-only even a `cat` is refused, as for a Bot's Codex. `/review` is the exception; see the addendum at the end.

4. **你的话 / Your line.** 图片按路径作为 `localImage` 放在你的话前面，Codex 自己打开；别的文件写成「附件：」加绝对路径。一个 turn 在跑时你再说话，用 `turn/steer` 送进这个 turn，和 Codex 自己的 steer 一样；没赶上的（turn 已经结束）由下一个 turn 带上；两个 turn 之间到的几句一起作为下一个 turn。`/` 开头的话里，应用能替 Codex 执行的命令和 skill 见文末补记，别的原样当文字发出。 / Pictures go ahead of your words as `localImage` by their path, for Codex to open; other files as "Attached:" with their absolute path. A line sent while a turn is going is steered into it with `turn/steer`, as Codex's own steer does; one that misses it (the turn has ended) goes with the next turn, and lines that arrive between turns go together as the next. Of the lines starting with `/`, the commands the app can carry out for Codex and its skills go as the addendum at the end says; any other is sent as text.

5. **回复、失败和 Stop / Reply, failure and Stop.** 一个 turn 的 final answer 是回复；它边干活边说的话显示在工作气泡里。失败时写「Codex 出错停下了：」加 Codex 自己的话（服务返回的 JSON 取出里面的 message）；没登录写「在终端里运行 codex login」。Stop 先 `turn/interrupt`，再结束它的进程组。 / A turn's final answer is the reply; what it says beside its work shows in the working bubble. A failure reads "Codex stopped:" with Codex's own words (the message inside the service's JSON); signed out, it says to run `codex login` in a terminal. Stop sends `turn/interrupt`, then ends its process group.

6. **工具帧 / Tool frames.** 命令叫 `shell`、改文件叫 `write_file`（应用给 Bot 的 Codex 调用起的名字），MCP 调用叫 `mcp__<服务器>__<工具>` 并带 `mcp_server`/`mcp_tool`，搜索叫 `WebSearch`；聊天里的命令卡片、工作行和任务地图照读，地点仍由 `placeOfCall` 算。子代理线程上的调用 `agent_id` 是那个线程的 id。 / Commands are `shell` and file changes `write_file` (the names the app gives a Codex Bot's calls), MCP calls `mcp__<server>__<tool>` with `mcp_server`/`mcp_tool`, searches `WebSearch`; the chat's command card and working line and the task map read them as they are, and `placeOfCall` still gives the place. A call on a subagent's thread has that thread's id as its `agent_id`.

7. **还没有的，一张表说了算 / What it does not have yet, said in one table.** `PROJECT_AGENT_CAPS` 按 Agent 列计划模式、`/` 命令、选账号、导入和回放；Codex 起初五样都没有，`/` 命令后来补上了（文末补记）。界面照表不显示（计划开关、Shift+Tab、账号那一列、导入面板里的 Codex），路由照表拒绝（`mode`、`config_dir`、`import` 回 422）或给空的（回放，Codex 会话因此不会起 Claude Code）。任务地图只画实时的 Codex 调用。 / `PROJECT_AGENT_CAPS` lists, per agent, plan mode, the `/` commands, an account to pick, carrying on a terminal session and the replay; Codex had none of the five at first; the `/` commands came later (the addendum at the end). The windows leave the rest out by the table (the Plan switch, Shift+Tab, the account column, Codex in the import sheet) and the routes refuse them (`mode`, `config_dir`, `import` answer 422) or answer empty (the replay, so a Codex session never starts Claude Code). The task map draws Codex's calls live only.

8. **文案 / Copy.** 任何会话里都会出现的话写这个会话的 Agent（「和 Codex 说点什么…」「Codex 在等你批准」「按你的 Codex 设置」）；删除确认两个都提。 / A line shown in any session names its agent ("Say something to Codex…", "Codex is waiting for your approval", "As your Codex settings say"); the delete confirmation names both.

## 取舍 / Trade-offs

- **每一轮一个进程 / A process per run.** 和 Claude Code 一样，一轮结束就关掉 app-server，下一轮再接线程；接线程要一两秒。 / As for Claude Code, the app-server ends with the run and the next run resumes the thread; resuming takes a second or two.
- **中途改不了模型 / No model change mid-turn.** 改模型或思考等级从下一个 turn 起生效。`turn/settings/update` 以后可以接上。 / A model or level change waits for the next turn; `turn/settings/update` can come later.
- **你的默认模型可能用不了 / Your default model may not work.** 没选模型就照你的 Codex 设置；设置里的模型这个账号用不了时，这一轮失败并写明原因，在输入框底部选一个列出来的模型就好。 / With no pick, your Codex settings decide; when the model there is not available to the account, the run fails saying so, and picking a listed model at the bottom of the composer fixes it.
- **拒绝的原因 Codex 看不到 / Codex does not see why.** app-server 的批准只有接受和拒绝，应用拒绝的原因（比如碰了凭据）它只看到「被拒绝了」。 / The app-server's approvals take only accept or decline, so Codex sees only that a call was declined, not the app's reason (credentials, say).

## 以后 / Later

- **导入终端里的 Codex 会话 / Carrying on a terminal Codex session.** 经 app-server：`thread/list`（按目录，来源 cli、vscode、exec，不含归档）列出，`thread/read` 读出你说的话和它的回复，第一轮 `thread/fork`。不读 `state_5.sqlite`，也不读 rollout 文件：应用只问 Agent 本身（ADR 0079）。 / Through the app-server: `thread/list` (by directory, sources cli, vscode and exec, not archived) to list them, `thread/read` for what you said and its replies, `thread/fork` on the first run. Not by reading `state_5.sqlite` or rollout files: the app only asks the agent itself (ADR 0079).
- **回放 / The replay.** 经 `thread/turns/list` 和 `thread/items/list`。 / Through `thread/turns/list` and `thread/items/list`.
- **计划模式 / Plan mode.** 等 Codex 的协作模式不再是实验接口。 / Once Codex's collaboration modes are no longer experimental.
- **Codex 的几个账号 / Codex accounts.** 按会话选 `CODEX_HOME`。 / A `CODEX_HOME` per session.

2026-10-25 补 / Addendum：你问「codex 的命令没接吗」。头一轮没接，是因为 Codex 的 app-server 不执行斜杠命令：一句 `/status` 原样发过去，它当成普通的话，自己跑 `git status` 拼出一份「状态」。查下来（Codex 0.153.4）能用的是几个单独的请求。`thread/compact/start` 压缩：结果是一个只有 `contextCompaction` 的 turn，没有交过话的线程也行，turn 的 id 只在 `turn/started` 里给。`review/start` 审查：从 `enteredReviewMode` 到 `exitedReviewMode`，审查结果在后者的 `review` 里，之后又作为一条没有 phase 的消息出现一次。`thread/start` 在同一个进程里再开一个线程。`skills/list` 不用开线程就列出这个目录下 Codex 会加载的 skill，有你的、插件的、项目里 `.codex/skills` 和 `.agents/skills` 的、Codex 自带的；这台电脑上 57 个，80 毫秒。点名用一个 skill，就在 `turn/start` 里带上 `{type: "skill", name, path}`、话里写 `$名字`。审查和别的不一样：它跑的命令不来问应用，`untrusted` 下也不问（试了 5 条，一张卡也没有），只在只读沙箱里跑（`py_compile` 没写出 `.pyc`）。

于是：

- **打 `/` 列出的 / What `/` lists.** `compact`、`review`、`new`（别名 `clear`），说明用 Codex 终端里的原话；后面是 skill，按名字排，关掉的和与这三个重名的不列。列表按目录记 10 分钟，问不到 skill 时这三条照列。`PROJECT_AGENT_CAPS` 里 Codex 的 `commands` 改成有。 / `compact`, `review` and `new` (also `clear`), described in the words of Codex's terminal; then the skills by name, leaving out the ones turned off and any named as one of the three. The list is kept per directory for 10 minutes; when the skills cannot be had, the three are listed still. Codex's `commands` in `PROJECT_AGENT_CAPS` is on.
- **`/compact`.** 压缩当前线程，工作行写「正在压缩上下文」，完了加一行「已执行 /compact：…」。Stop 按 `turn/started` 给的 id 打断。 / Compacts the thread; the working line says Compacting the conversation, and a line "Ran /compact: …" follows. Stop interrupts it by the id `turn/started` gives.
- **`/review`.** 不带字审查未提交的改动，带字按你写的审查（`custom`）；回复就是审查结果，审查里的命令照样出工具帧。它的命令不经过应用，所以应用的权限模式在开始前决定一次：自动、全部允许下直接开始；改动先问下先出一张卡（「review 未提交的改动」，写明审查时不再逐条问），批准才开始，拒绝就写一行「没有执行 /review：你拒绝了」；只读下不执行，写明原因。审查期间应用的规则管不到它的命令，凭据那一条也一样：只读沙箱只挡写，不挡读，Codex 能读到沙箱让它读的任何文件，项目外的也算（试的时候它读了 `~/.codex/memories` 和插件缓存）。卡上写的「不再逐条问」就是这个意思。另一条路是把 `/review` 当成 Codex 自带的 `review-agent` skill 发出去，那样每条命令都会来问，但没有 Codex 的审查模式，审查结果的样子也不一样；没选这条。 / Alone it reviews the uncommitted changes; with words after it, what they say (`custom`). The reply is the findings, and the review's commands still show as tool frames. Its commands do not come to the app, so the app's permission mode decides once, before it starts: under auto and allow all it starts; under ask first a card comes first ("review the uncommitted changes", saying it will not ask command by command), approval starts it and a denial leaves the line "Did not run /review: you said no"; under read-only it does not run, saying why. While it reviews, the app's rules do not reach its commands, the one on credentials included: the read-only sandbox stops writes, not reads, so Codex can read whatever the sandbox lets it, outside the project too (in the probe it read `~/.codex/memories` and the plugin cache). That is what the card's "without asking for each" means. The other way was to send `/review` as Codex's own `review-agent` skill, so that every command asks, but without Codex's review mode and with findings of another shape; it was not taken.
- **`/new`、`/clear`.** 写一行「已执行 /new：…」，下一个 turn 开一个新线程，记成这个会话的线程，之后的轮次都接着它；后面写的字是新线程的第一句话。新线程不在执行 `/new` 时就开：Codex 只存跑过 turn 的线程，开了没用的线程，换个进程就接不上（「no rollout found」，实机检查时碰到的）。 / Leaves a line "Ran /new: …", and the next turn opens a new thread, recorded as the session's so later runs carry it on; words after it are the new thread's first line. The thread is not opened when `/new` runs: Codex keeps a thread only once it has had a turn, so one opened and left unused cannot be resumed by another process ("no rollout found", met in the live check).
- **skill.** `/名字` 是 skill 时，话里的 `/名字` 换成 `$名字`，再带上 skill 本身，和 Codex 自己的 `$` 一样。 / When `/name` is a skill, the line goes with `$name` in its place and the skill itself, as Codex's own `$` sends one.
- **别的 / Anything else.** 别的 `/` 开头的话照旧当文字发出：Codex 没有的命令，应用不拦，也不替它解释。 / Any other line starting with `/` is still sent as text: a command Codex does not have is neither stopped nor explained by the app.
- **命令不插队 / A command waits its turn.** 命令不送进正在跑的 turn：Codex 干活时发的命令，和排在它后面发的话，等这个 turn 完了再按顺序来，命令自己一个 turn。命令不给会话起名。 / A command is not steered into the turn going on: one sent while Codex works, and the lines sent after it, wait for that turn's end and go in order, the command as a turn of its own.
