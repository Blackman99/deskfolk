# Bot↔Bot 私聊一次发起一条，用户只能看

Bot↔Bot 私聊原本和你↔Bot 私聊同一套：`create_direct` 先找有没有旧会话，有就复用，于是每对 Bot 攒出一条无限长的线程；用户能往里打字，侧栏把这些会话和你自己的聊天平铺在一起，看不出哪条是被什么开起来的。两个毛病：一条线程里混着几件不相干的事，Bot 读到的 40 条转录窗被别的事占着；用户插话会让一场本来是两个 Bot 之间的交接变成三方对话，而用户并不是参与者。

改成：`create_direct` 每次调用新开一条会话，并记下来源——叫醒发起方那一轮的那条消息（`turns.trigger_message_id`）。同一轮里对同一个 Bot 重复调用返回同一条，所以模型喊两次或重试不会刷屏。会话上多两列 `origin_session_id` / `origin_message_id`，随 `GET /v1/sessions` 和 `session.upsert` 一起走，前端不需要新接口。入口不再只靠侧栏：来源消息下方直接挂一张卡片，点开就是那条私聊；侧栏只留最近活跃的几条，每行标出来源并可点回触发消息。

用户只读的闸门放在 `store.postMessage`——它硬编码 `author = USER_MEMBER`，是用户所有写入路径（JSON、附件、回答提问）的唯一收口，不在场就 403 `not_a_member`。只拦「往转录里注入内容、会唤醒 Bot」的动作；标记已读、归档、清空历史、Stop、放行审批全部保留，因为那些是用户对自己视图和自己机器的操作，Stop 更是跑飞时唯一的闸。连带必须改的是 `ask_user`：在用户不在场的会话里提问会把轮次停在 `waiting_ask` 上等一个永远到不了的回复，所以直接拒掉并让 Bot 回到用户在场的会话去问。

不加跳数或条数熔断（`CONTEXT.md` 三处明令禁止）。刹车是四个顺着代码本来长法的东西：按触发消息去重、`isNoWorkCloser` 让没新东西的一方自然收尾、没有用户在场时第二条消息改道而非分叉（群里对 Bot 早就这么做）、以及保住 Stop。`list_sessions` 同时截到 30 条并带上 `updated_at`，否则同一对 Bot 的二十条私聊会变成二十行分不清的记录白烧上下文窗。

升级即时可见的变化只有一个：已有的 Bot↔Bot 私聊变成只读。它们的来源是空的，侧栏照常列出，只是那一行写「来源未知」，也不会在任何消息下方长出入口——没有可挂的消息。
