# 内置模型 / Built-in models

Status: implemented 2026-10-10, at every engine level; where it is set moved on 2026-10-11 to the Roles page of [ADR 0082](0082-roles-page.md), which supersedes decision 6. Extends [ADR 0075](0075-organizing-model.md), which gave the organizer, the scribe and the picture checks one model of their own, and [ADR 0055](0055-lines-read-by-a-model.md), which did that for reading lines; runs a Claude model of yours the way [ADR 0061](0061-claude-agent-runner.md) runs a reading.

## 背景 / Context

你问的是（2026-10-10）：「内置的模型指定只有两种吗，一个读句，一个整理模型？如果有其他的都要加上，分类放在一起，不要拆开。」接着又说：「而且要支持选择 agent 里的那些。」问到细处时你定了三条：替 Bot 做的那几个调用也放进来，不单独设时跟随 Bot；每个调用各一项，按类分组；语音识别单独留着。

在这之前，应用自己发起的模型调用里，只有读句和「整理模型」能单独选，整理模型还一口气管着整理器、书记员和看图判定三处，只能选端点上的模型。输入建议、判断下场、反思、完工复盘、压缩上下文都没法换：前一个跟默认端点，后四个跟 Bot 自己的模型。

You asked (2026-10-10): are reading and the organizing model the only built-in models one can choose? Whatever else there is should be there too, grouped together by kind, not split apart. Then: and the Claude models of the Agent settings have to be offered as well. Asked about the details, you settled three things: the calls made on a Bot's behalf go in too, following the Bot when not set; one choice per call, grouped by kind; speech recognition stays where it is.

Until now, of the calls the app makes on its own, only reading and the organizing model could be chosen, and the organizing model covered three calls at once (the organizer, the scribe, the picture checks), from endpoint models only. The composer's suggestions, judgements, reflections, retrospectives and compaction could not be moved: the first followed the default endpoint, the other four the Bot's own model.

## 决定 / Decisions

1. **每个调用一项，分四组 / One choice per call, in four groups.** 九个调用：读你的话——读句（`reader`）；整理与检查——整理器（`organizer`）、书记员（`scribe`）、看图判定（`judge`，照样片和衔接一致）；输入——输入建议（`composer`）；以 Bot 身份——判断下场（`judgement`）、反思（`reflection`）、完工复盘（`retrospective`）、压缩上下文（`compaction`）。没放进来的：选模型（`route_pick`，7 级起不跑，ADR 0048）、纠偏复盘和学习（`route_review`、`route_learn`，8 级起不跑，ADR 0050）——不跑的调用给个选项只会让人以为它在用；语音识别有自己的服务和密钥（ADR 0073）；测速测的就是你点的那个模型。/ Nine calls: reading your lines — reading (`reader`); organizing and checking — the organizer, the scribe, the picture checks (`judge`: against the sample and between parts); the composer — its suggestions (`composer`); as a Bot — joining in (`judgement`), reflection, retrospective, compaction. Left out: the route pick (not run from level 7, ADR 0048) and the route review and learning (not run from level 8, ADR 0050) — a choice for a call that never runs reads as if it were used; speech recognition, which has a service and key of its own (ADR 0073); the speed test, which measures the model you pressed it on.

2. **形状和存法 / Shape and storage.** `Settings.builtin_models` 是九个调用各自的 `ReaderModel | null`：端点上的模型 `{ provider_id, model }`，或你的 Claude 模型 `{ runner: "claude_code", model, config_dir }`。存成 `<call>_provider_id`、`_model`、`_runner`、`_config_dir` 四个设置项，读句和整理器用的还是原来那几个键。补丁 `builtin_models` 只改给出的几项，整份先校验再写：不认识的调用、名单上没有的模型、没列出的 Claude 账号都 422，一项错了一项都不写。端点删掉或名单不再列这个模型时读成 null。旧的 `reader_model`、`organizer_model` 两个字段还在，给旧窗口用：`organizer_model` 从此只管整理器，整理器选了 Claude 模型时它读成 null。迁移一次（`builtin_models_split`）：之前选过的整理模型照抄给书记员和看图判定，升级后什么都不换地方跑。/ `Settings.builtin_models` holds each call's `ReaderModel | null`: an endpoint's model, or a Claude model of yours. It is kept as four settings per call, `<call>_provider_id`, `_model`, `_runner`, `_config_dir`; reading and the organizer keep the keys they had. A `builtin_models` patch sets only the calls it names and is checked whole before anything is written: an unknown call, an unlisted model or an unlisted Claude account is a 422 and nothing changes. A choice reads as null while its endpoint is gone or no longer lists the model. The old `reader_model` and `organizer_model` stay for older windows; `organizer_model` now means the organizer alone and reads null when the organizer runs on a Claude model. One migration (`builtin_models_split`) copies a previously chosen organizing model to the scribe and the picture checks, so nothing runs anywhere new after the update.

3. **不设就照旧 / Unset runs as before.** 没选的调用一个字不变：读句、整理器、书记员、看图判定跟默认端点的默认模型；输入建议跟默认端点里名字带 flash/mini/lite/fast 的那个；判断下场、反思、完工复盘跟 Bot 自己的模型，压缩上下文跟这一轮自己的模型，这四个照旧不指定思考档。/ A call left unset is unchanged: reading, the organizer, the scribe and the picture checks on the default endpoint's default model; the composer on the default endpoint's flash/mini/lite/fast model; judgements, reflections and retrospectives on the Bot's own model and compaction on the turn's own, with no thinking level named for those four, as before.

4. **每个调用都能选 Claude 模型 / A Claude model for every call.** 选了 Claude Agent 里的模型，这次调用就在你本机的 Claude Code 上跑一次，和读句一样（ADR 0061）：没有工具、只有一轮、系统提示换成这个调用的提示、用你选的账号。读句以外的调用另有一组 3 个名额（`CLAUDE_BUILTIN_SLOTS`），不占读句的 2 个，一次长整理拖不住你下一句话的读句。要看图的调用把图作为同一条消息里的图片块发过去；Claude 模型都能看图，所以看图判定选了 Claude 模型就全用它。一次调用的时限是这个调用原来的首字时限再加 180 秒（Claude Code 是一次答完，不是流式）。失败分三种记：Claude Code 没装或没登录（`agent_missing`）、出错或没答（`agent_exited`）、超时（`overtime`）；各调用照它原来对失败的处理走。花费照这个调用原来的类别和用途记，按 Claude Code 报的估价，压缩上下文记到那一轮、判断下场记到那次判断。Bot 能把内置调用换成端点上的模型或 null，不能换成你的 Claude 模型（花的是你的套餐），和读句一样。/ A Claude model of the Agent settings runs the call once on your Claude Code, as a reading does (ADR 0061): no tools, one turn, the call's own prompt in place of Claude Code's, on the account you picked. Calls other than reading get three places of their own (`CLAUDE_BUILTIN_SLOTS`), apart from reading's two, so a long settle cannot hold up the reading of your next line. A call that sends pictures sends them as image blocks of its one message; every Claude model reads them, so picture checks on a Claude model always run on it. A call may take its old first-byte limit plus 180 seconds, since Claude Code answers all at once rather than streaming. A failure is one of three: Claude Code missing or signed out (`agent_missing`), an error or no answer (`agent_exited`), out of time (`overtime`); each call handles it as it handled a failure before. Spend is booked under the call's own kind and purpose at Claude Code's estimate, a compaction to its turn and a judgement to its judgement. A Bot can move a built-in call to an endpoint's model or null, never to your Claude model (that spends your plan), as with reading.

5. **想多深 / How hard it thinks.** 选了模型，才告诉它想多深，按调用要的来：等着它的（读句、输入建议、判断下场）取最轻的一档；常跑的（书记员、压缩上下文）取 `low`，没列就取 `none` 以上最轻的；要读整份、要判准的（整理器、看图判定、反思、完工复盘）取 `high`，规则同 ADR 0075。Claude 模型对应成 Claude Code 的思考强度：最轻的不指定（Claude Code 自己的默认，读句一直如此），`low`、`high` 原样给；模型做不到的 Claude Code 会自己降。/ Only a chosen model is told how hard to think, by what the call wants: the ones you wait on (reading, the composer, judgements) the lightest level listed; the frequent ones (the scribe, compaction) `low`, else the lightest above `none`; the ones that read the whole and must judge well (the organizer, picture checks, reflection, retrospective) `high`, by ADR 0075's rule. A Claude model gets the matching Claude Code effort: none for the lightest (Claude Code's own default, as reading always had), `low` and `high` as they are; Claude Code lowers what a model cannot do.

6. **设置里 / In Settings.**（已由 [ADR 0082](0082-roles-page.md) 取代：这些调用的模型现在在设置的「分工」页上，和它们的提示词一起。/ Superseded by ADR 0082: these calls' models are now on the Roles page of Settings, with their prompts.） 设置 → 模型服务里「读句用的模型」和「整理模型」两页合成一页「内置模型」，排在模型阶梯后面、语音识别前面。页上按上面四组各一张卡，卡里每个调用一行：名字、一句它做什么、一个下拉（跟随默认模型 / 跟随 Bot 自己的模型，加每个端点的每个模型，加 Claude Agent 一组）。Claude Code 的状态整页只问一次。手机的列表上这一行写「全部照旧」或「单独设了 N 项」。和旧版本的电脑配对时（设置里没有 `builtin_models`），只显示读句和整理器两行，存回旧字段，整理器不列 Claude 一组。/ The two pages "Model that reads lines" and "Organizing model" become one page, Built-in models, after the model ladder and before speech recognition. It has one card per group above and one row per call: its name, a line on what it does, and a picker (follow the default model / follow the Bot's own model, every model of every endpoint, and the Claude Agent group). Claude Code's status is asked once for the page. On the phone's list the row reads "All as before" or "N set apart". Paired with an older computer (no `builtin_models` in its settings), the page shows only reading and the organizer, saves to the old fields, and offers no Claude group for the organizer.

## 后果 / Consequences

- **花费 / Cost.** 选了才花，不选一个字不变。Claude 模型花的是你 Claude 套餐的额度，而且整理器这样的大调用，每个规划静下来都会跑一次；花费视图按原来的类别和用途记，Claude 的那几笔标着 Claude Agent。/ Nothing is spent until you choose. A Claude model spends your Claude plan's usage, and a big call like the organizer runs every time a plan goes quiet; the spend view books it under the old kinds and purposes, the Claude ones marked Claude Agent.
- **等待 / Waiting.** Claude Code 每次调用要起一个 `claude`，几秒才答（实测 haiku 带图约 3 秒）。读句、输入建议、判断下场是你在等的，选 Claude 模型会慢一些。/ Each Claude Code call starts a `claude` and answers in seconds (haiku with a picture took about 3 s). Reading, the composer and judgements are waited on, so a Claude model there is slower.
- **压缩上下文 / Compaction.** 端点上的模型说「超过上下文」时，压缩会只带一半记录再试一次；Claude 模型只说失败，不说为什么，所以不再试，这一轮照没压缩成的样子走（ADR 0068）。压缩的切分仍按这一轮模型的上下文窗口算。/ An endpoint's model refusing for a full context gets one more try with half the record; a Claude model only says it failed, so there is no second try and the turn goes on as an uncompacted one (ADR 0068). The split is still sized by the turn's own model's window.
- **取代 / Supersedes.** ADR 0075 的第 1 条（只收端点上的模型）、第 2 条（一个设置管三处）、第 5 条（单独一页）和「没做的」里按用途分别选、Claude 模型两项由这里取代；它的思考档规则和看图退回仍然有效。/ ADR 0075's decision 1 (endpoint models only), 2 (one setting for three calls), 5 (a page of its own) and the per-use choice and Claude model left undone there are superseded here; its thinking-level rule and picture fallback stand.
