# 模型选择的经验归 Bot 自己，记下每轮怎么结束

此前每轮选模型时用的「学习到的惩罚」是名册级一份 JSON（settings 里的 `route_learned`）：你对 Reviewer 说一句「换个模型」，Writer 下一轮同类消息也跟着改道。反馈的归属也只看会话里最近一条触发消息，群里多人发言时经常记到别人头上；轮次怎么结束（端点拒绝、回复不完整、被 Stop）完全不进记录，惩罚只加不减、没有上限，一句话就能把一个模型永久钉死。

现在：

- **经验按 Bot 存**（`route_learned` 表，主键 `bot_id + 消息类别 + 模型 + 思考等级`），选模型只看这个 Bot 自己的行。Bot 之间共用工作区、端点和 MCP，但「哪种活该用哪个模型」是各自的判断，和人设、钉的模型、技能一样属于这个 Bot。删除 Bot 一并删掉它的经验；升级时旧的名册级惩罚复制给当时在册的每个 Bot 各一份，升级当天没有 Bot 改选。
- **反馈按对象归属**：引用回复落在被引那一轮；`@` 了唯一一个 Bot 落在它最近那一轮；否则落在会话里最近可见（有回复、提问、批准卡或触发条）的那一轮。只有说到模型本身的话才算反馈，对内容的批评仍不记。
- **每轮记结果**：决策行带 `bot_id`、`provider_id`，结束时写 `outcome`（completed / failed / stopped / redirected / interrupted）和失败种类。端点拒绝或回复不完整算模型自己的错，记半分负面；连不上、忙、5xx、流卡住只记不学。干净完成记一分正面，按 0.25 抵扣负面；惩罚封顶 3，所以别的候选也失望之后它还能回来。
- 本机接口多一条 `GET /v1/sessions/:id/routes`，把每轮选了什么、怎么结束、收到哪些反馈原样列出来，对应路线图里「保留依据」。

不做的：不按时间衰减（需要注入时钟，收益不明），不做探索（被罚的组合只靠别的候选也被罚才回来），不把经验跨 Bot 汇总成名册先验。这些留给路线图第 2 节的逐次反思。
