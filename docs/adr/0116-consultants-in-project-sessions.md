# 项目会话里请参谋 / Consultants in project sessions

Status: implemented 2026-11-23. Builds on [ADR 0095](0095-project-sessions.md) (project sessions), [ADR 0099](0099-codex-in-project-sessions.md) (Codex), [ADR 0111](0111-antigravity-in-project-sessions.md) (Antigravity), [ADR 0115](0115-grok-in-project-sessions.md) (Grok), [ADR 0079](0079-local-agents.md) (the app's tools for local agents) and [ADR 0092](0092-permission-modes.md) (permission modes).

2026-11-22 你问「可以让项目会话具有能力可以按照用户要求发起不同 agent 模型的子会话进行方案讨论吗」。同一家的不同模型那时已经做得到：Claude Code 的子代理带 `model`，Codex 的 `spawnAgent` 也带。缺的是跨 Agent：在 Claude Code 的会话里请 Codex、Grok 或 Antigravity 看看方案，反过来也一样。出计划时你又说「Antigravity 也要支持」，于是四家都能发起、也都能被请来；参谋只看不改，各家用各自的办法；参谋反问时转给请它的 Agent。

On 2026-11-22 you asked "可以让项目会话具有能力可以按照用户要求发起不同 agent 模型的子会话进行方案讨论吗" (can a project session, when the user asks, start sub-sessions on other agents and models to talk a plan over?). Other models of the same agent were already there: Claude Code's subagents take a `model`, and so does Codex's `spawnAgent`. Across agents was missing: Claude Code asking Codex, Grok or Antigravity about a plan, and the other way round. While the plan was drawn up you added "Antigravity 也要支持" (Antigravity too), so all four agents can ask and all four can be asked; a consultant only looks, each agent in its own way; a consultant's question goes to the agent that asked it.

查下来（2026-11-23，这台 Mac：Claude Code 2.1.329、Codex 0.153.4、agy 1.5.14、Grok 1.0.92，探测脚本直接经各家协议问，没经过应用）：

- 项目会话以前不挂任何 MCP：Claude Code 的钩子把不认识的工具一律拒掉（ADR 0095 决定 4），agy 和 Grok 的 `mcpServers` 都是空的。
- Antigravity：stdio MCP 服务器在 `session/new`、新进程里的 `session/resume` 和 `session/load` 都挂得上；调用报成 `tool_call`，标题 `Run mcp_<服务器>_<工具>`、kind `other`，`rawInput` 是参数加一个 `toolSummary`；它不为这种调用请求权限。**任何 MCP 调用到 3 分钟就被它掐掉**（"MCP tool call … timed out after 3m0s"）。顺带的发现：Bot 在 agy 上的 `ask_user` 也受这 3 分钟管。
- Grok：stdio MCP 在 `session/new` 和 `session/resume` 都挂得上；它先 `search_tool` 再 `use_tool {tool_name: "<服务器>__<工具>"}`，钩子两步都过；直接挂的 MCP 调用撑过了 20 分钟。
- Codex：`dynamicTools` 只有 `thread/start` 收，`thread/resume`、`thread/fork` 都不收；线程的 `config` 覆盖三者都收，而且不存进线程。`config.mcp_servers.<名字>` 在 start 和 resume 都挂得上；工具声明 `readOnlyHint` 时，`approvalPolicy: untrusted` 下它也不要批准就调，报成 `mcpToolCall`；直接挂的调用撑过了 20 分钟（`tool_timeout_sec` 给足时）。`approvalPolicy: never` + `sandbox: read-only` 下 `rg`、`cat`、`ls` 照跑，写文件被系统沙盒挡下（Operation not permitted），resume 之后一样。
- Claude Code：计划模式下，声明 `readOnlyHint` 的进程内 MCP 工具照常能调；钩子回 allow 也作数。
- 守护进程的 stdio shim（`--agent-mcp`，把 stdio 转成对守护进程的 HTTP 请求）：一次请求到大约 6 分钟就断（6 分钟的回来了，12 分钟的在第 6 分钟报 "The operation timed out."）。
- agy 和 Grok 的会话标题是模型自己概括的（"Call Probe Wait Tool"），不是第一句原文，所以没法靠第一句的固定开头认出参谋的会话。

What was there (2026-11-23 on this Mac: Claude Code 2.1.329, Codex 0.153.4, agy 1.5.14, Grok 1.0.92; probe scripts spoke each agent's protocol directly, not through the app):

- Project sessions mounted no MCP at all: Claude Code's hook refused any tool it did not know (ADR 0095 decision 4), and agy's and Grok's `mcpServers` were empty.
- Antigravity: a stdio MCP server is mounted on `session/new`, on `session/resume` in a new process and on `session/load`; a call is reported as a `tool_call` titled `Run mcp_<server>_<tool>`, kind `other`, with the arguments plus a `toolSummary` as `rawInput`; it asks no permission for it. **It cuts any MCP call at 3 minutes** ("MCP tool call … timed out after 3m0s"). In passing: a Bot's `ask_user` on agy is held to those 3 minutes too.
- Grok: a stdio MCP server is mounted on `session/new` and `session/resume`; it calls `search_tool`, then `use_tool {tool_name: "<server>__<tool>"}`, and the hook sees both; a directly mounted call held 20 minutes.
- Codex: only `thread/start` takes `dynamicTools`, not `thread/resume` or `thread/fork`; all three take a `config` override, which is not saved into the thread. `config.mcp_servers.<name>` is mounted on start and on resume; with `readOnlyHint` the tool runs under `approvalPolicy: untrusted` without asking, reported as `mcpToolCall`; a directly mounted call held 20 minutes (with a long `tool_timeout_sec`). Under `approvalPolicy: never` and `sandbox: read-only`, `rg`, `cat` and `ls` run and a write is stopped by the OS sandbox (Operation not permitted), after a resume too.
- Claude Code: in plan mode an in-process MCP tool marked `readOnlyHint` runs; a hook's allow holds as well.
- The daemon's stdio shim (`--agent-mcp`, which turns stdio into HTTP requests to the daemon) loses a request at about 6 minutes (a 6-minute call came back; a 12-minute one failed at minute 6 with "The operation timed out.").
- agy and Grok title their sessions with a summary of their own ("Call Probe Wait Tool"), not the first line, so a consultant's session cannot be told apart by a fixed first line.

## 决定 / Decisions

1. **应用给项目会话的 Agent 一个工具：`consult` / The app gives a project session's agent one tool: `consult`.** 每一轮都挂上（发起方是参谋的除外），说明里写明只在你开口时用，从不自己去请。用谁、问什么、问几轮、怎么跟你说，都是它的事；应用不读你的话。这是 ADR 0095「应用只管……」之外的第一样东西，也是决定 4「项目会话里 MCP 工具一律拒绝」唯一的例外。/ Mounted on every run (except a consultant's own), its description says to use it only when you ask, never on its own. Whom to ask, what, how many rounds and what to tell you are the agent's; the app reads none of your words. It is the first thing past ADR 0095's "the app only keeps…", and the one exception to decision 4 (MCP tools are refused in project sessions).
2. **参谋是挂在这个会话下的一个项目会话 / A consultant is a project session under this one.** 同一个目录，那家 Agent 默认的账号，`model` / `effort` 照请它时说的；`sessions.project_parent_id` 指回请它的会话。它由同一套 runner 跑，所以模型、计费、Stop、回放都照项目会话的来。第一句是应用写的开场白（谁请它、它能做什么、可以反问），后面接请它的 Agent 的话；之后每一次请教是它的下一句。/ Same directory, that agent's default account, `model` / `effort` as asked; `sessions.project_parent_id` points back. The same runners run it, so model, spend, Stop and replay work as for any project session. Its first line is the app's opener (who asks, what it may do, that it may ask back) followed by the asking agent's words; each later call is its next line.
3. **只看不改，各家用各自的办法 / It only looks, each agent in its own way.** `projectPermissionMode` 让参谋读作只读，你的设置不动。Claude Code、Grok：应用的只读模式，能读能搜，改文件、跑命令、调 MCP 都被拒。Codex：`approvalPolicy: never` + `sandbox: read-only`，命令在它自己的系统沙盒里跑，写不了；你的 MCP 服务器、插件带来的服务器和 apps 在它这条线程里都关掉（它们在沙盒外面跑，`never` 下也没有别的东西拦它们）。Antigravity：读和搜索放行；改文件、跑命令、调任何 MCP，事后发现就停下这一轮（它从不先问），这次请教以失败告终，开场白先说清楚别跑命令。参谋不开计划模式，不放后台。/ `projectPermissionMode` reads a consultant as read-only; your setting is untouched. Claude Code, Grok: the app's read-only mode — read and search; writes, commands and MCP are refused. Codex: `approvalPolicy: never` and `sandbox: read-only` — its commands run in its own OS sandbox and cannot write; your MCP servers, those plugins bring and your apps are off for its thread (they run outside the sandbox, and under `never` nothing else holds them). Antigravity: reads and searches pass; a write, a command or any MCP call is found after the fact and stops the turn (it never asks first), the consultation failing — its opener tells it not to run commands. A consultant never plans and sends nothing to the background.
4. **参谋反问，转给请它的 Agent / A consultant's question goes to the agent that asked it.** 它的提问照常记成提问行，但不弹给你：这次请教的结果就是它的问题和选项。Agent 带着回答、`consultant=<id>` 再调一次，这句话由提问台当作回答收下（和你在卡片前打字一样）；答不了的，它问你。/ Its question is kept as an ask line but never shown to you: the call's result is the question and its options. The agent calls again with its answer and `consultant=<id>`; the question desk takes the line as the answer (as your typing does before a card); what it cannot answer it asks you.
5. **一次请教最多等多久，按发起方定 / How long one call waits, by the asking agent.** Claude Code 30 分钟（进程内，超时是应用自己设的）；Codex、Grok 4 分钟（经 stdio shim，6 分钟会断）；Antigravity 150 秒（它 3 分钟就掐）。到了还没答完，结果说「还在想」；Agent 只带 `consultant` 再调一次接着等。/ Claude Code 30 minutes (in process, its timeout is the app's); Codex and Grok 4 (through the stdio shim, which breaks at 6); Antigravity 150 seconds (it cuts at 3). Past that the result says it is still working, and the agent calls again with only `consultant` to wait on.
6. **怎么挂 / How it is mounted.** Claude Code：进程内的 `deskfolk` MCP 服务器，和 Bot 的一样，钩子和 `canUseTool` 先放行它（计划模式、只读下也放，子代理不许）。Codex：线程 `config.mcp_servers.deskfolk`，经 stdio shim，`tool_timeout_sec` 给足；不用 `dynamicTools`，免得存进线程、以后在 Codex 自己的 app 里接着时没人回答。Antigravity、Grok：ACP `mcpServers` 里的 stdio shim，三处开会话的地方都带；agy 按标题 `Run mcp_deskfolk_consult` 放行，Grok 按 `deskfolk__consult` 在钩子里、`decide` 之前放行。每一轮一个令牌，轮结束就作废。MCP 服务器在 `initialize` 时说明自己（`instructions`），给把工具藏在搜索后面的 Grok 看。/ Claude Code: the in-process `deskfolk` MCP server, as a Bot's; its hook and `canUseTool` let it through first (plan mode and read-only too; never a subagent). Codex: the thread's `config.mcp_servers.deskfolk` through the stdio shim, with a long `tool_timeout_sec`; no `dynamicTools`, which would be saved into the thread with nobody to answer when you carry it on in Codex's own app. Antigravity, Grok: the stdio shim in ACP `mcpServers`, wherever a session is opened; agy lets `Run mcp_deskfolk_consult` pass by title, Grok `deskfolk__consult` in its hook before `decide`. One token per run, gone when the run ends. The MCP server describes itself on `initialize` (`instructions`) for Grok, which keeps tools behind a search.
7. **在对话里像子代理 / In the conversation it is a subagent.** 每次请教是请它那一轮的一个任务（id `consult_<参谋会话>_<那一句>`，中继也放行，kind `subagent`，带 `agent`、`model`），写在 `agent_runs.tasks` 上；runner 发布自己的任务表时，这些任务原样留着。回复下面一行带那家的 logo 和模型，点开是子代理的弹窗：问了什么、它的模型、它答了什么。参谋不进会话列表（守护进程的 `listSessions` 就不列它，所以窗口、手机和 Bot 都看不到），也不进搜索和导入列表；它在那家 Agent 那边的会话 id 记在一个设置里，参谋删了也不会出现在「接着终端里的会话」里。/ Each call is a task on the asking run (id `consult_<consultant session>_<the line>`, one the phone's relay lets through, kind `subagent`, with `agent` and `model`), kept on `agent_runs.tasks`; a runner publishing its own list leaves them as they are. The row under the reply carries that agent's logo and the model, and opens the subagent popup: what it was asked, its model, what it answered. A consultant is in no list of conversations (the daemon's `listSessions` leaves it out, so no window, phone or Bot sees it), no search and no import list; its agent's session ids are kept in a setting, so a deleted consultant never shows among the terminal sessions to carry on.
8. **一起停 / It stops with the run.** 请它的那一轮结束（完成、Stop、失败、重启中断），它名下还在跑或还捏着问题的参谋都停下；捏着的问题作废，之后再带回答来，就作为新的一句。停下一个任务就停那个参谋。删掉会话或清空它的历史，参谋一起删；归档不动参谋（它们本来就不列出来）。额度用完时参谋不换账号、不等重置，这一轮失败，请教把原因带回去。/ When the asking run ends (completed, stopped, failed, cut by a restart), its consultants still working or holding a question stop; the question lapses, and an answer brought later goes in as a new line. Stopping the task stops that consultant. Deleting the session or clearing its history deletes its consultants; archiving leaves them (they are not listed anyway). Out of usage, a consultant neither moves to another account nor waits for the reset: the run fails and the call says why.

## 取舍 / Trade-offs

- **参谋只看到请它的 Agent 写下的话 / A consultant sees only what the asking agent writes.** 它不读主会话的历史，上下文全靠 Agent 在 `message` 里交代；好处是不把你的整段对话交给另一家。/ It does not read the session's history; the agent has to give it the context, and in return your whole conversation is not handed to another vendor.
- **Antigravity 的只读是事后的 / Antigravity's read-only is after the fact.** 它动了手才知道，这一轮停下时那一步已经做完；开场白要它别跑命令，多数时候够用，不是保证。/ The step has already run when the turn stops; the opener asks it not to run commands, which mostly holds, but is no guarantee.
- **几次「还在想」/ A few "still working" rounds.** 经 shim 的三家一次最多等 4 分钟（agy 150 秒），长的请教要 Agent 多调几次，每次花一点它的 token；换来哪家多久掐断都不出错。/ Through the shim one call waits 4 minutes at most (150 s on agy), so a long consultation takes a few calls, each a few of the agent's tokens; no agent's cut-off breaks it.
- **模型名不校验 / Model names are not checked.** 工具说明举了各家的例子；名字不对，参谋那一轮失败，错误原样带回去，Agent 换一个再请。/ The description gives each agent's examples; a wrong name fails the consultant's run and the error goes back as is, for the agent to try another.

## 补记 2026-11-23：输入框里的参谋开关 / Addendum 2026-11-23: the consultant switch in the composer

起因：功能上线后你说「要像计划模式一个可以开启 + 指定用几个分别什么模型」。问下来你定了三件事：开关开着时每句话都请；最多 3 位；参谋各自给意见，由主 Agent 汇总，不互相辩论。

Why: once it shipped you said "要像计划模式一个可以开启 + 指定用几个分别什么模型" (a switch like plan mode, saying how many and which models). Asked, you settled three things: while it is on, every line asks them; three at most; each consultant answers on its own and the agent sums up, with no debate between them.

决定 / Decisions:
