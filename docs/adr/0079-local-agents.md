# 本机 Agent：Codex、Grok、OpenCode、DSH、ZCode、Antigravity 和你自己的 ACP Agent / Local agents: Codex, Grok, OpenCode, DSH, ZCode, Antigravity and ACP agents of your own

Status: implemented 2026-10-10, at every engine level. Builds on [ADR 0061](0061-claude-agent-runner.md) (Claude Agent), [ADR 0076](0076-claude-models-on-the-model-ladder.md) (agent rungs on the ladder), [ADR 0077](0077-built-in-models.md) (built-in models) and [ADR 0078](0078-setup-on-claude-code.md) (setup without an endpoint).

## 背景 / Context

你说（2026-10-10）：「目前 agent 只支持了 Claude，其他的主流工具也要支持：Codex，Antigravity，Grok，DSH，ZCode，OpenCode 等等。」问到细处时你选了：全部一次做完；边界是「尽量在调用前拦，拦不住的事后检查、出界就停」；Antigravity 照 Claude 的做法接（只运行你装的原版 `agy`、用你自己的登录、不碰令牌，ADR 里写明条款现状）；不只是 Bot 的运行方式，内置调用、模型阶梯、用量和多账号也都要。

You said (2026-10-10): "Agents only support Claude so far; the other mainstream tools should be supported too: Codex, Antigravity, Grok, DSH, ZCode, OpenCode and so on." Asked about the details, you chose: all of them at once; a boundary that stops each call before it runs where it can, and checks afterwards — stopping the turn on anything out of bounds — where it cannot; Antigravity the way Claude was done (only the unmodified `agy` you installed, under your own sign-in, no tokens touched, the terms' state written down here); and not only running Bots, but built-in calls, ladder rungs, usage and several accounts too.

ADR 0061 里 Claude Agent 是唯一一种「本机 Agent」：一个 Bot 的每一轮由你自己装好、登录好的 Claude Code 跑，应用把它包在每一轮都有的东西里。这里把它推广到别的 Agent：同样是你装的、你登录的、原样运行的程序，同样的边界、批准、停住、副作用账、收尾契约和交付。不同的只是它们讲的协议。

In ADR 0061 Claude Agent was the one local agent: a Bot's turns run by the Claude Code you installed and signed in to, wrapped in what every turn has. This generalizes it: other agents, likewise installed and signed in by you and run unmodified, inside the same boundary, approvals, holds, effect ledger, end contract and hand-overs. What differs is only the protocol each speaks.

## 合规 / Compliance

应用对每个 Agent 都只做 ADR 0061 对 Claude Code 做的那些：运行你自己装的那个程序；不提供登录、不读不存不转发令牌（登录在终端里用它自己的命令做）；不改它的配置文件（一轮要的东西都在启动时传：参数、环境变量、协议里的设置）；只运行它、问它自己的事（版本、登录、模型）。各家条款（2026-10-10 读）：

For every agent the app does only what ADR 0061 does for Claude Code: it runs the program you installed; it offers no sign-in and never reads, stores or forwards tokens (you sign in in a terminal with the agent's own command); it never writes the agent's config (whatever a turn needs is passed at launch: arguments, environment, protocol settings); it runs the agent and asks it about itself (version, sign-in, models). Each vendor's terms as read on 2026-10-10:

- **Codex**：app-server 是 OpenAI 给「在你自己的产品里深度集成 Codex」用的协议，要求集成方设 `clientInfo.name`，应用名为 `deskfolk`。/ Codex's app-server is what OpenAI offers for "deep integration inside your own product"; integrators set `clientInfo.name`, here `deskfolk`.
- **Grok Build**：开源（Apache-2.0），`grok agent stdio` 是官方给编辑器和其他程序用的 ACP 入口。/ Open source (Apache-2.0); `grok agent stdio` is its official ACP entry for editors and other programs.
- **OpenCode**：开源（MIT），`opencode acp` 是官方 ACP 入口。/ Open source (MIT); `opencode acp` is its official ACP entry.
- **DSH**：你自己的 DeepSeek Harness（`dsh --profile acp`）。/ Your own DeepSeek Harness.
- **ZCode**：智谱的桌面应用，没有官方 ACP；这里走社区的 `zcode-acp` 桥，你自己装。/ Zhipu's desktop app has no official ACP; this goes through the community `zcode-acp` bridge, which you install.
- **Antigravity**：条款对「第三方工具调用 `agy`」没有明确说法；Google 论坛上的回答互相矛盾，有开发者提到过账号被封。你选了照 Claude 的做法：只运行你装的原版 `agy`、你的登录、按 Bot 手动开启。Google 给出明确禁止时撤掉。/ Antigravity's terms say nothing clear about a third-party tool running `agy`; answers on Google's forum disagree, and some developers mention suspensions. You chose Claude's way: only the unmodified `agy` you installed, your sign-in, a per-Bot opt-in. It comes out if Google says no.

## 决定 / Decisions

1. **运行方式 / Runners.** `bots.runner` 现在是 `claude_code`、`codex`、`grok`、`opencode`、`dsh`、`antigravity`、`zcode`、`custom` 之一（空：应用自己的循环）。`custom` 指向你在设置里列的一个 ACP 命令（`bots.agent_custom_id`）。`agent_model` 按各家的写法存（`nvidia/z-ai/glm-5.3`、DSH 的 `["deepseek-official","deepseek-v4-flash"]` 都行），`agent_effort` 按各家的档（`AGENT_KINDS[runner].efforts`：Codex 到 `max`，Grok 到 `xhigh`，DSH 有 `off`，OpenCode 没有档）。`bots` 表重建一次，去掉只认 Claude 的两个 CHECK（`migrateAgentRunners`，照 `migrateNullableTaskSession` 的做法）。旧版本读到不认识的 runner 当没有，回到端点上跑。Gemini CLI 不内置：个人 Google 登录已被它停用（「迁到 Antigravity」），要用的话用 API key 加成自定义 ACP Agent。/ `bots.runner` is one of eight agents (empty: the app's own loop); `custom` points at an ACP command you listed (`agent_custom_id`). `agent_model` is kept as each agent spells models, `agent_effort` as each agent grades effort. The `bots` table is rebuilt once without the two Claude-only CHECKs. An older build treats an unknown runner as none and runs the Bot on its endpoint. Gemini CLI is not built in: it retired personal Google sign-in ("migrate to Antigravity"); with an API key it can be added as a custom ACP agent.

2. **三种协议 / Three protocols.** Agent Client Protocol（Grok `grok agent --no-leader stdio`、OpenCode `opencode acp`、DSH `dsh --profile acp`、ZCode 的 `zcode-acp`、你自己的）；Codex 的 app-server（`codex app-server`，NDJSON 的 JSON-RPC，不带 `jsonrpc` 字段）；`agy` 的打印模式（`--input-format stream-json --output-format stream-json --print=`，一行一个提示、一个 `result`）。两种 JSON-RPC 共用一个小的 NDJSON 对端（`engine/agent/jsonrpc.ts`），不引入新依赖。一轮一个会话：Codex 用 `ephemeral` 线程，ACP 会话在收尾时 `session/close`，不在你的历史里留东西（OpenCode、Grok 会把会话记在它们自己的历史里，`session/close` 之后是否删掉看各家）。/ ACP for five, Codex's app-server, and `agy`'s print mode; both JSON-RPCs share one small NDJSON peer, no new dependency. One session per turn: an ephemeral Codex thread, an ACP session closed at the end.

3. **只给这一轮 / The turn's own process.** 启动参数让一轮不和你自己开着的会话混在一起：Grok `--no-leader`（不连共享的 leader 进程），Codex 自己起一个 app-server（从不 `--remote`、不连 `codex agents` 的守护进程），OpenCode 的 `acp` 自己起私有的 `serve --stdio`。Codex 线程的 `config` 关掉你 `~/.codex` 里会进来的东西：hooks、memories、子代理、插件、apps、`notify`、AGENTS.md（`project_doc_max_bytes: 0`），你的每个 MCP 服务器按名字设 `enabled: false`（插件带来的随插件关；`mcp_servers.<name>` 覆盖不了的那一项去掉再试）。环境变量照 ADR 0061：原样传，去掉嵌套会话标记和 `REAL_BOT_*`；加上命令所在目录到 PATH（Codex、DSH 是 npm 装的 Node 脚本，从访达起的守护进程 PATH 里没有 `node`）；没有代理变量时补系统代理。/ Launch flags keep a turn apart from your own open sessions. A Codex thread's `config` switches off what your `~/.codex` would bring in, each of your MCP servers by name. The environment as in ADR 0061, plus the command's own directory first on PATH (npm installs need the `node` beside them) and the system proxy when none is named.

4. **边界 / The boundary.** 每一种协议能在调用前拦的地方都拦，规则和卡片和 Claude Agent 一样（`engine/agent/policy.ts` 的 `decideAction`：区内直接跑，出界出卡、「总是允许」照认，递归搜家目录拒，顶层不存在的路径拒）：
   - ACP：应用声明 `fs` 和 `terminal` 能力，Agent 让应用读写和跑命令时，应用按规则判了再做（Grok 全走这条）；Agent 发 `session/request_permission` 时按同样的规则答，只答 `allow_once` / `reject_once`（`allow_always` 可能存进它自己的配置）。OpenCode 默认只在读区外文件时问，启动时用环境变量 `OPENCODE_CONFIG_CONTENT={"permission":{"*":"ask"}}` 让它每条命令、每次写都先问（不写你的配置文件）。命令按 Agent 包着的壳拆开再判（`bash -lc '…'` 读成里面那条）。
   - Codex：线程用只读沙箱、批准策略 `untrusted`：每条命令（读也算）、每次改文件都先发审批请求，应用按规则答 `accept` / `decline`，批准的那条在沙箱外照常跑。
   - Antigravity：打印模式没有任何回调，`agy` 的工具权限是你在它设置里定的（这台 Mac 上是 `always-proceed`），应用不改它；只能加 `--sandbox`（它跑的命令读不到 `~/.ssh` 这类地方）并在每个工具开始时检查。
   - 拦不住的（Agent 没问就做了、事后才报）：在它报完时检查，出界或碰了任何 Agent 的凭据就停下这一轮（新的失败 `agent_unguarded`，记进副作用账 `errorCode: unguarded`，监督器不自动重试）。
   - 凭据：所有 Agent 的配置和登录目录（`~/.claude*`、`~/.codex`、`~/.grok`、`~/.gemini`、`~/.dsh`、`~/.zcode`、OpenCode 的三个目录、钥匙串、你列的账号目录）对任何 Bot 一律拒，不出卡——Claude Agent 的规则也补上了别家的。Grok 自带的技能（`~/.grok/bundled`）可以读。
   / Each protocol is stopped before a call where it can be, with Claude Agent's rules and cards. ACP: the app offers `fs` and `terminal`, and decides before it reads, writes or runs for the agent; permission requests are answered by the same rules, once only. OpenCode is told per launch to ask for everything. Codex: a read-only sandbox and approval `untrusted` make every command and file change ask first. Antigravity: no callback at all; `--sandbox` and a check at each tool's start. A call reported only after it ran is checked then, and one out of bounds or on any agent's credentials stops the turn (`agent_unguarded`). Every agent's config and sign-in directories are off limits to every Bot, outright.

5. **应用自己的工具 / The app's tools.** Claude Code 照旧在进程内拿到。ACP Agent 通过 MCP 拿：守护进程在 `127.0.0.1:17890/v1/agent-mcp/<令牌>` 上为每一段开一个入口（令牌 32 字节随机、只给这一段、段结束作废、不写到任何地方；入口在应用自己的认证之前匹配，只认本机、不认浏览器来源，不在手机中继的白名单里；一次调用等批准卡等多久都行），Agent 不认 HTTP MCP 时走守护进程的 stdio 转接（`--agent-mcp`）。Codex 用它的 dynamic tools，在同一条连接上回调。Antigravity 拿不到：它的 Bot 只能用收尾回复，不能 `end_turn`、`submit`、`delegate`、`ask_user`；收尾被退回两次后这一段就算结束（它的话随第二次退回已经发出）。各家看到的工具名不同，前言按 Agent 说明怎么调：Grok 先 `search_tool` 再 `use_tool`（`deskfolk__end_turn`），OpenCode 在它的 `execute` 里写 `await tools.deskfolk.end_turn({})`，Codex 就是自己的工具名。/ ACP agents reach the app's tools over a per-segment loopback MCP route (or the daemon's stdio shim); Codex as dynamic tools on the same connection; Antigravity not at all, so its Bots answer with a closing reply only, and a segment ends after a second bounce. The preface tells each agent how its own client spells the tools.

6. **一轮怎么跑 / A turn.** 系统指令：Codex 放在 `developerInstructions`（在它自己的系统提示之后），ACP 和 Antigravity 没有系统提示参数，放在第一条提示的开头。第一条消息、转录窗口、图片照 ADR 0061（看不了图的 Agent 收到一句说明）。插话：Codex 用 `turn/steer` 当场插进去，插不进就跟着下一个工具结果；ACP 和 Antigravity 等这一步结束，Bot 调应用工具时跟在结果后面，都没有就到下一轮。直接插入（ADR 0069）：Codex `turn/interrupt`、ACP `session/cancel`，然后把那几句作为下一条提示；Antigravity 不能打断，那句排队。最后一条回复、收尾自检、退回、空回复提醒，和 Claude Agent 同一条路（`settleClosingReply`）。/ System text in Codex's `developerInstructions`, at the head of the first prompt for ACP and Antigravity. Lines meanwhile: steered into Codex, otherwise riding the next tool result or the next turn. Insert-now cuts Codex and ACP agents; Antigravity's lines queue. The closing reply goes the same way as a Claude Agent's.

7. **记录 / Records.** 选路 `reason_code` 是 `agent_<runner>`（不进 Bot 默认模型的推断）；花费按 Agent 名记（「Codex」「Grok」或你起的名字），Codex 和 Antigravity 有逐次的 token，ACP 只报上下文大小和费用（OpenCode 报 0，Grok 不报），所以只在给了费用时记；命令进 `turn_runs`，写的文件进本轮写入，有效果的调用进副作用账；Agent 进程和应用替它跑的命令都单独一个进程组、登记在 `live_procs`，Stop 结束整组。/ Route rows `agent_<runner>`; spend under the agent's name (tokens from Codex and Antigravity; ACP agents report only context size and cost, so only a cost is recorded); commands, writes and effects as for any Bot; every process in its own group on record.

8. **失败 / Failures.** `agent_missing`、`agent_signed_out`、`agent_limit`、`agent_exited` 用在每个 Agent 上，文字带上 Agent 的名字（Claude 的原文不变）；加 `agent_unguarded`。前三种和 `agent_unguarded` 只有你能处理，监督器不重试。分类：ACP 的 `-32000` 和登录类报错是没登录，余额、额度、限流是用量；Codex 按 `codexErrorInfo`（`unauthorized`、`usageLimitExceeded` …）；启动前先问 `account/read`。/ The four agent failures apply to every agent, named; `agent_unguarded` is new. The user-fix ones are not retried.

9. **设置 / Settings.** `GET /v1/runtime/agents`、`POST …/detect`、`PUT …/path`、`PUT …/accounts`、`PUT /v1/runtime/custom-agents`：本机和手机都能用，不记回执。状态只靠运行它问它：`--version`，Codex app-server 的 `account/read` 和 `model/list`，`grok models`（「You are logged in with …」和模型），`opencode auth list` 和 `opencode models`，`agy models`，ACP 的 `initialize`；DSH、ZCode、自定义 Agent 的模型从它们上一次会话报的选项记下。账号：有配置目录变量的 Agent（Codex `CODEX_HOME`、DSH `DSH_HOME`；Claude 照旧）能列多个账号，规则照 ADR 0061（有 Bot、阶梯或内置调用在用的拿不掉）。/ Settings routes for status, path, accounts and your own ACP agents, on the Mac and the phone, receipt-less. Status comes only from running each agent and asking it. Accounts for agents with a config-dir variable, under ADR 0061's rules.

10. **用量 / Usage.** `GET /v1/agent-usage`：Codex 问它自己（`account/rateLimits/read`，不经过模型、不花额度），给套餐窗口和剩余；别的 Agent 不报套餐窗口，只给应用自己记的今天轮数和 token——不编百分比。Claude 的照旧走 `/v1/claude-usage`。/ Codex reports its plan's windows itself; the others show today's records from this app, never an invented percentage.

11. **内置调用、阶梯和设置 / Built-in calls, the ladder and setup.** 九个内置调用都能选别的 Agent 的模型（`<role>_runner`、`_config_dir`、`_custom_id`）：在一个临时目录里跑一次、没有工具，它要动工具就被掐掉；读句、整理等的花费按 Agent 名记。模型阶梯的一档可以是任何 Agent 的模型和档位；爬上去的那一轮由那个 Agent 跑。只用 Agent 完成设置（ADR 0078）也推广了：向导第 2 步在 Claude Code 旁边列出找到且已登录的其他 Agent，选中的那个第 3 步选模型，九个内置调用都设成它；没有端点时，新建的 Bot 用读句所在的那个 Agent。/ Built-in calls and ladder rungs may name any agent; a call runs once in a scratch dir with no tools. The setup wizard's step 2 lists every other agent found and signed in beside Claude Code; the one picked takes a model on step 3 and all nine built-in calls. Without an endpoint a new Bot runs on whichever agent lines are read on.

12. **两个 runner / Two runners.** Claude Agent 保留自己的 runner（`engine/agent-runner.ts`，行为不变，测试原样通过），其余 Agent 走 `engine/agent/external-runner.ts` 加三个驱动（`drivers/acp.ts`、`codex.ts`、`agy.ts`）。共用的是规则、凭据、前言、失败、花费、批准卡、生效闸和收尾；两边各有一份约 300 行的记账代码。原计划是把 Claude 也做成一个驱动；为不碰正在用的 Claude 路径，这一步留到以后。/ Claude Agent keeps its own runner, unchanged; every other agent goes through the external runner and three drivers. Rules, credentials, prefaces, failures, spend, cards, the effect gate and endings are shared; about 300 lines of bookkeeping exist twice. Folding Claude onto the shared runner is left for later, so the live Claude path is not touched.

13. **各家 LOGO 和两级的模型选择器 / Each agent's logo, and a two-level model picker（2026-10-10 补）.** 你说：「每个 agent 加上自己的 LOGO，所有选择模型的地方都要能选对应的模型；agent 模型跟支持的端点模型过多，单下拉已经无法承载内容了，重新设计下下拉形式，移动端可以考虑改成 bottom sheet 嵌套选择。」每个 Agent 画自己的标（`AgentLogo.svelte`）：Codex、Grok、OpenCode、Antigravity 用 lobe-icons 的图，DSH 用 DeepSeek 的鲸鱼（它是 `@deepseek-ai/dsh`），ZCode 用 Z.ai 的 Z（智谱的），Claude 还是 Spark；你自己的 ACP Agent 只画一个提示符，不借别家的标。标只用来指明是哪家，和 ADR 0061、0072 的商标说明一样。选模型的地方都换成两级选择器（`ModelPicker.svelte`）：宽窗口是弹层，顶上搜索、「跟随默认」这类非模型的行在上面一横排，左边是来源（每个端点、Claude、每个 Agent，带标和数量），右边是指着的那个来源的模型，OpenCode 那种 `provider/model` 按 provider 分组；打字就在所有来源里搜。手机上是从底部升起的面板，一层一层进：来源 → 一个来源的组（模型多时）→ 模型，返回键退一层。列不出模型的（DSH、ZCode、你的 ACP Agent）可以在搜索里输入它认的名字直接用。Bot 面板里 Agent Bot 的模型、新建 Bot 时 Claude 和其他 Agent 的模型也都用它选（以前是输入框或没有）。/ Every agent wears its own mark (lobe-icons' drawings; DeepSeek's whale for DSH, Z.ai's Z for ZCode, the Spark for Claude, a plain prompt for your own ACP agents), naming it only, as ADR 0061 and 0072 say of marks. Every model choice is a two-level picker: a popover with a search over everything, sources on the left and the pointed source's models on the right, grouped by provider for `provider/model` lists; on a phone a bottom sheet entered level by level, Back going up. A source that lists no models takes a typed name.
14. **任务的模型也可以是 Agent 的 / A ticket's model can be an agent's.** 看板上给一张任务指定的模型（ADR 0049）现在也能是本机 Agent 的模型（存成和阶梯一级一样的 `{runner, model, effort, config_dir, custom_id?}`，按阶梯一级的规则检查）。规则是「任务的模型决定谁来做这张任务」：Agent 的模型，这张任务负责人的轮次由那个 Agent 跑，和爬到阶梯上那一级一样，不管这个 Bot 平时由谁跑；端点的模型，就在应用自己的循环里用它，即使这个 Bot 平时由 Agent 跑。审它的 Bot 照用自己的。/ The model set on a ticket may be a local agent's, shaped and checked as a ladder rung; the ticket's model decides who does it: an agent's runs the owner's turns there, as a rung would, an endpoint's runs them in the app's own loop, whatever the Bot usually runs on.
