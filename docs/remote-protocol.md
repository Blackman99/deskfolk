# Experimental remote cryptography contract / 实验性远控密码契约

Status: **proposed, default-off security prototype**. `@real-bot/remote` exports `REMOTE_DEFAULT_ENABLED = false`; it opens no sockets and enables no application feature. Relay, daemon and client integrations must keep their own remote/public-pairing admission closed until release gates pass. A constant is not a security boundary or a substitute for those admission checks.

## Implementation and gates

One implementation: the restricted standard `Noise_IK_25519_ChaChaPoly_BLAKE2s` state machine in `src/noise.ts`, over exactly pinned `@noble/{ciphers,curves,hashes}` 2.4.0. No alternate suite, homemade transport KDF, plaintext fallback, or WebCrypto X25519 dependency. Noble libraries have independent audit history (curves 2.3.0 / 1.6.0, ciphers 1.0.0, hashes 1.0.0); **these exact dependency versions and this integration are not independently audited**. JavaScript JIT/GC provides neither guaranteed constant time nor reliable whole-process secret erasure. `destroy()` overwrites owned key buffers, not all engine copies. Retained keys/pins and returned byte copies use fresh plain `Uint8Array` allocations, including for Bun/Node Buffer and offset-view inputs; successful Split, failure and close must never overwrite caller identities. Binary readers honor the supplied view boundaries. Noise's two-output HKDF and byte concat/hex codecs reuse the pinned Noble implementations. CBOR uses pinned `cborg` 4.3.2 with duplicate-key rejection, bounded input, definite lengths and strict decoding; RSA verification uses platform WebCrypto.

| Gate | Automated evidence | Still required |
| --- | --- | --- |
| L1 | Official Noise wiki's Cacophony **and** noise-c IK vectors; two real Rust snow 0.10.0 peers exercise both roles, this prologue, signed Hellos, and 1 MiB duplex transport. | iOS 16.4+ installed PWA bundle/time budget on physical hardware. Desktop Chromium smoke is not this gate. |
| S1 | Wrong roles, altered prologue, pinned DH/signing keys, AEAD, expiry, replay, revocation callback, version, nonce ordering, frame bounds, all pre-Split transport types fail closed. | Daemon/relay integration must implement atomic replay/trust callbacks and connection teardown. |
| S-rev | Not passed. Protocol tests and AI review are not an audit. | Independent review of actual integration and pairing before public default-on. |
| G-uv | Generated software-key ES256/Ed25519/RSA positive and negative signature tests. | Real iOS home-screen and Android Chrome create/get; no supported-OS claim yet. |

No Keychain, personal DB, authenticator, model endpoint, push service or external device is used by this package's fixtures. Fixed test seeds and official vector private keys are public **test material**, never production identities. Fixture source commits, SHA-256 and licenses are in `test/fixtures/provenance.json` and `THIRD_PARTY_NOTICES.md`.

## Exports and transport ownership

Import from `@real-bot/remote`; receipt-only consumers can use `@real-bot/remote/canonical` without pulling in Noise/WebAuthn. Raw `NoiseIK`/`CipherState` are internal (no package subpath export); applications use `DeviceSession` / `HostSession`. The barrel explicitly exports adapter-facing APIs/types and UTF-8/base64url/hex/random-byte conversions. Validation helpers, integer writers, `Reader`, `pairingKey` and `pairingAssociatedData` remain internal source-only details. Source has no Node-only imports or I/O. `build` emits ESM JS plus declarations; consumers in this monorepo use TypeScript exports.

- `generateIdentity`, `identityPublic`: independent random 32-byte X25519 DH, Ed25519 identity and Ed25519 enrollment secrets. Never convert Ed25519 to DH or reuse key seeds.
- `encodePrologue(SessionBinding)`: u16 UTF-8 byte-length fields `RB-REMOTE-v1`, host ULID, device ULID; u32be trust epoch; u16be version **1**; exact canonical HTTPS origin (no trailing slash). Version mismatch is fatal.
- `DeviceSession.start()` returns the **208-byte** message 1. `HostSession.accept(message1)` authenticates static DH and signing identities, calls trust/replay hooks, then returns the **144-byte** message 2. `DeviceSession.accept(message2)` authenticates the pinned host signature before exposing transport. Message 1 includes random session ID; Hello signatures bind the respective ephemeral key and the prologue, and responder signature binds Noise's actual message-1 `h`.
- `send(type, body)` / `receive(ciphertext)` require authenticated Split. Any failure destroys that session; close the underlying socket. One WS binary frame is exactly one Noise message. No caller-controlled transport nonce: independent directional counters begin at 0, encoded as Noise's 32 zero bits + u64le, with the all-ones nonce forbidden. Application u64be seq must equal the receive counter, and session ID must match. Type 7 closes both local cipher states.
- Host `isTrusted()` must read current non-revoked device, current trust epoch **and** pinned key validity; it is called on handshake and every send/receive. Host must proactively close sessions when revoking, not wait for traffic.
- Host `claimReplay({deviceId, ephemeralPublic, sessionId, minimumTtlMs})` must atomically reserve **both** `(deviceId,e_pk)` and `sessionId` across all handshakes, before returning `true`. TTL ≥ max(120s, 2× recent RTT). Full cache refuses admission; never evict live entries to admit a replay. Clock/TTL, bounded storage and teardown belong to host, not this pure library. Rejected/replayed message 1 produces no response or second Principal. Relay enrollment nonces do not replace this cache. Replay reservations must survive any process/reconnect boundary for which the host claims replay protection; alternatively close remote admission until that window elapses after losing the cache.

Example call order (host persistence/transport functions are application-owned, not package implementations):

1. Create device with paired host keys and host with the stored device keys plus mandatory trust and replay callbacks.
2. Send `device.start()` as one WS message; send the result of `host.accept(message1)` as the response.
3. Call `device.accept(message2)`; only now call `send` / `receive` and dispatch returned frames. A host may send after producing its authenticated response; it must queue it in order after that response.
4. On disconnect/exception call `close()`, drop in-flight commands, reconnect with fresh state, and consult durable receipts. Never dispatch Hello payloads or queue offline approvals.

## Byte codecs and limits

`encodeFrame` / `decodeFrame`: `session_id:16 || seq:u64be || type:u8 || body`. **Total plaintext ≤32768 bytes**, so `MAX_BODY=32743`; encrypted maximum here is 32784, below Noise's 65535. This intentionally resolves the draft's contradictory body-vs-total wording in favor of the stricter total. Unknown/reserved types fail.

Types: 1 request, 2 response, 3 event, 4 fragment, 5 file, 6 stream cancellation (exact u32be ID), 7 close (empty), 8 snapshot. Logical JSON parsing/schema validation remains adapter-owned.

`fragmentMessage(type,bytes)` emits direct or fragmented messages for original types 1/2/3/8. Fragment body: original type:u8, message ID:16, index:u32be, count:u32be, chunk. Chunk ≤32718; non-final chunks have that exact size; logical message ≤1 MiB (maximum 33 fragments). `Reassembler.accept(body, monotonicNowMs)` permits one contiguous bounded message per instance, no interleaving, duplicate, gap, count/type/ID changes or >30s assembly. Hosts schedule `expire(nowMs)` to release idle buffers at 30s and `clear()` on disconnect; subsequent partial messages cannot resume. Larger snapshots require pagination, not larger frames.

`encodeFileChunk` / `decodeFileChunk`: stream ID:u32be, offset:u64be, flags:u8, chunk ≤32730. Only EOF bit 0 allowed. File permissions, realpath/symlink checks, ETag, sequential offset, 50 MiB transfer limit, 1 MB text PUT, two streams/device, cancellation state and backpressure are **file-adapter responsibilities**, not granted by successful decryption.

## Pairing, grant and relay admission

- `sealPairing` / `openPairing`: random 24-byte nonce prefix, XChaCha20-Poly1305, key = keyed BLAKE2s-256(secret, UTF-8 `rb-pair-v1`), never BLAKE2b/personalization. Use 32 random secret bytes; minimum accepted is 16. AD = u16-length pairing ULID, host ULID, expires:u64be. Host supplies authoritative pending context/time; expired or >10-minute future window fails. JCS plaintext has exactly `device_id,name,ua_hint,device_e_pk,device_s_pk,enrollment_pk`; canonical unpadded base64url keys are exactly 32 bytes. Confirm name and full SHA-256 signing-key fingerprint locally before signing a grant. Pair expiry/one-use consumption and Mac user presence remain host-owned.
- `encodeGrant` / `decodeGrant` / `signGrant` / `verifyGrant`: length-prefixed `RB-GRANT-v1` is **11 UTF-8 bytes** (`000b52422d4752414e542d7631`), not 10. Then host/device ULIDs, signing/DH/enrollment public keys (32 each), epoch:u32be, version:u16be, origin field, issued:u64be. `verifyGrant` compares every field with the expected pending pair before verifying Ed25519; callers must use the QR-pinned host signing key. No arbitrary grant acceptance by credential ID.
- `encodeEnrollmentProof` / `signEnrollmentProof` / `verifyEnrollmentProof`: role/id length fields, raw nonce_c/nonce_s (16 each), timestamp:u64be, relay ID field. Role host/device only. Relay looks up the **stored enrollment key**, not a key submitted with the proof. Relay supplies its stored issued challenge; verifies <10s and consumes the exact challenge atomically via mandatory callback. Successful enrollment authorizes a relay slot, not business RPC. Bound text-frame limits before parsing, forbid text after EnrollOk, and close on wrong phase/opcode.

### Relay integration transport

`apps/relay` now implements the default-off enrollment/opaque transport layer. Its [exact HTTP/WS and management contract](deploy-remote.md#httpws-contract-for-host-and-client-adapters) uses one authenticated host control socket plus a separately authenticated outbound host link for each online device. Data sockets preserve one binary frame per Noise message without headers; only the dedicated control socket carries binary canonical JSON routing/enrollment metadata after Ok. The host binds each server-generated route ID to its current device trust before opening the link. Revocation/control loss terminates dependent sockets and drops relay-owned buffers; the host still owns current trust, proactive Noise teardown and durable IK replay reservation. This replaces the draft's ambiguous one-host-socket multiplexing; it is not a new Noise suite or a business plaintext path. Docker/TLS deployment, daemon/client integration and external gates are not passed by local relay tests.

### Terminals: watched streams, and no receipts

`/v1/terminals*` is admitted for a paired device with the same reach the window has. The gate is remote itself — `REMOTE_DEFAULT_ENABLED = false` plus native activation — not a second one on top; `GET /v1/host/tree` already let a device read outside the workspace, so this is not a new frontier. Workspace root still cannot be changed remotely.

Terminal writes **do not write request receipts**. Receipts are keyed `(device_id, request_id)` and stored, which is right for a message and wrong for a keystroke; `POST /v1/models/probe` set the precedent for a non-replayed POST. Say the cost plainly: a keystroke lost to a dropped link is lost, retrying one is not idempotent, and a device reconnecting should resume from a byte offset rather than replay input. `GET /v1/terminals/:id/scrollback?from=<offset>` is that resume for raw bytes; a current client attaches with `GET /v1/terminals/:id/screen` instead — `{offset, data, rows, cols}`, the daemon's serialized screen (base64, at most 640 KiB before encoding, so one logical message holds it) and the stream offset live frames resume from. The client reads that first and then watches from its `offset`: the ring still holds every byte since, so none fall between, and the device is not sent the ring's whole backlog only to cut it. `POST /v1/terminals/:id/clear` (`{}`) clears that screen for every client, and `POST /v1/terminals/:id/colors` (`{foreground, background, cursor?, palette?}`, `#rrggbb`, palette at most 16) reports the attaching client's colours, which the daemon answers programs' colour requests with. The daemon, not the client, answers terminal requests (DA, DSR, DECRQM, colours), so a phone and the window never both answer one.

Output travels as ordinary type 3 events but outside the sequenced cursor: a `{type:"stream", id, offset, data, skipped?, closed?}` frame, where `offset` is a byte offset into that stream. It is never added to the event ring — that ring is 2000 frames / 16 MiB and an overflow costs every client a resnapshot, which a single build's output would trigger. A device receives a stream only after `POST /v1/terminals/:id/watch` and until `/unwatch`, so output from a panel nobody has open never reaches the radio. The host coalesces a 50 ms window into at most one frame of 8 KiB per stream, a pace the relay's 64 KiB per-socket buffer takes without the Mac seeing the device's radio. Output that comes faster waits, up to 128 KiB per stream, for the windows after, so a burst (a full-screen program redrawing, a long listing) arrives whole and a little late; only output that outruns the pace for longer loses its oldest bytes, reported as `skipped`. Dropping those is deliberate, because the alternative — the link's ordinary backpressure — would close the session over scrollback. Frames are cut by offset, so each one's `offset` names its first byte, and a watcher that joins a stream others already watch is sent that backlog alone.

### Unregistered pairing mailbox: no enrollment deadlock

`PAIR_MAILBOX_CONTRACT` fixes `/v1/pair/mailbox`, 64 KiB encrypted envelope, 600s lifetime, **no device enrollment prerequisite and no business traffic**. Authenticated host opens one bounded, locally authorized pending-pair mailbox. Unregistered device POSTs/polls using pairing ID in a bounded request **body**, never a URL/query; mailbox carries the XChaCha envelope only, no pairing secret, device private key, WebAuthn registration or control traffic. Relay must rate-limit guessing and cap slots/bytes/TTL; ID knowledge alone cannot create host mailboxes or bypass host confirmation. The QR secret stays device↔Mac out-of-band and must never be navigated as a URL or logged.

After local confirmation the host durably grants trust, installs device enrollment public key through its authenticated relay management channel, and sends the signed grant through the mailbox using the shared direction-bound `sealPairingGrant` envelope. Grant polling cannot require the not-yet-received device grant. Device verifies the QR-pinned signature and every expected field; **then** it can pass the normal enrollment handshake and Noise IK. Host cancels/consumes the pending pair atomically and removes the mailbox. New devices cannot reach business or UV APIs before Split.

## Canonical hashes / ticket 02 compatibility

`canonicalize`, `canonicalBytes`, `canonicalHash` implement RFC8785 using ECMAScript finite-number formatting and UTF-16 key sorting. Reject lone surrogates, undefined, nonfinite numbers, bigint, accessors, exotic objects, sparse/decorated arrays, cycles and >64 nesting. Inputs must already be parsed/validated JSON (duplicate member rejection at raw ingress belongs to parsers). Hash = lowercase SHA-256 hex of canonical UTF-8.

`requestDigestBytes({method,path,body,encoding,files?,conditionalHeaders?})` defines the exact receipt preimage; `requestDigest` is its lowercase SHA-256 hex. Both package root and `@real-bot/remote/canonical` export these same functions and `RequestDigestInput`, `AttachmentDigest`, `ConditionalHeaders` types, without circular imports. `sha256Hex(string | Uint8Array)` hashes raw UTF-8/bytes (not JCS); `normalizeAttachmentDigests<T extends AttachmentDigest>(readonly T[])` validates and returns a sorted copy retaining attachment references and multiplicity. The digest functions also accept an optional trusted `CanonicalEncoder` argument for the daemon's existing test injection; default production encoding is always `canonicalize`, and no caller-controlled HTTP option selects an encoder. Both encoded fields must return primitive strings synchronously; non-string/Promise results are rejected before constructing the preimage. Native Promise rejections are observed without awaiting results or invoking arbitrary thenables. Attachment arrays must have an own entry at every index; sparse lists are rejected rather than filtered or treated as empty.

`method || 0x1f || path || 0x1f || JCS(body) || 0x1f || encoding || 0x1f || sortedFiles || 0x1f || JCS(conditionalHeaders)`

- `encoding` is `json` or `multipart`; JSON forbids file digests. An empty list encodes as an empty field, not `[]`.
- sortedFiles is `filename || 0x1e || lowercase_sha256`, sorted by filename **UTF-8 bytes**, then SHA-256 ASCII hex, joined with 0x1f. Legitimate duplicate basenames are allowed, even identical digest/name pairs; multiplicity is preserved, upload order is not. Adapters must execute the same canonical attachment multiset, not derive different effects from the original order. Control/separator-bearing filenames and malformed digests fail.
- `conditionalHeaders` is a plain string-to-string record, omitted means `{}`. Header names are ASCII-case-insensitive and canonicalized to lowercase, then JCS sorted. Allowed names: `if-match`, `if-none-match`, `if-modified-since`, `if-unmodified-since`, `if-range`. Duplicate names after case folding, unknown names, accessors, empty/non-string values and control/separator bytes are rejected, never silently discarded. Values are preserved exactly (including ETag quotes); adapters must pass the effective values used for the actual operation. No HTTP precondition grammar or evaluation is performed by hashing.
- The daemon receipt adapter now consumes this exact canonical subpath for JCS, the complete preimage/hash and attachment normalization; client/transport adapters must use it too, **not** method/path/encoding/body order or a separate If-Match suffix. The daemon retains its stricter canonical-route and strong quoted lowercase-SHA256 If-Match validation (the protocol's `"rev-1"` vector is not a valid daemon file ETag). The mandatory final JCS field changes the previous unpublished digest even when no condition is present. There is no compatibility fallback to the old five-field digest.
- Bind authoritative method/path, all execution-changing body params/revisions, file digests and actual conditional headers. Fresh UV `operationDigest` must include the same preconditions: an assertion for `If-Match: "rev-1"` cannot authorize `"rev-2"`. Hashing does not validate authorization.

Pinned inputs, exact JSON-escaped preimages and outputs are in [`request-digest.json`](../packages/remote/test/fixtures/request-digest.json). SHA-256 values were independently generated with Python hashlib and are tested through both exports. `US=0x1f`, `RS=0x1e`; `a×64`/`b×64` below mean exactly 64 lowercase letters, not literal notation:

| Input | Exact preimage (US/RS notation) | SHA-256 |
| --- | --- | --- |
| POST `/v1/messages`, body `{b:2,a:1}`, json, no files/conditions | `POST US /v1/messages US {"a":1,"b":2} US json US US {}` (no spaces around US) | `caf582f4423c2c5b8e82a222afecb70514aa0d3f5ac1dadfbf8be33b6cceeddf` |
| PUT `/v1/workspace/file`, body `{content:"hello"}`, json, no files, `{"If-Match":"\"rev-1\""}` | `PUT US /v1/workspace/file US {"content":"hello"} US json US US {"if-match":"\"rev-1\""}` | `d191012ae4c6be32ceb47e651854eabb56e927e327f3603f8309a4795803c251` |
| POST `/v1/messages`, body `{body:"photos"}`, multipart, three `photo.png` entries with digests b×64,a×64,a×64, no conditions | `POST US /v1/messages US {"body":"photos"} US multipart US photo.png RS a×64 US photo.png RS a×64 US photo.png RS b×64 US {}` | `a1a7458b04e2eafa6945ac1b646d90a8d59d81b7bcabdc783f2351614b25f657` |

## WebAuthn verification and host transactions

Algorithms are deliberately allowlisted: COSE EC2/P-256/ES256 (-7, DER signatures including valid high-S), OKP/Ed25519/EdDSA (-8), RSA 2048–4096/RS256 (-257). Reject mismatched curves/types, private or unexpected key fields, malformed points, duplicate CBOR fields, and invalid RSA exponents/moduli. No algorithm fallback. `verifyCredentialSignature` verifies authenticator bytes, not a credential ID.

`createUvChallenge(binding,kind,nowUnix)` uses random nonce and SHA-256 of domain-separated JCS. Binding contains **deviceId, sessionId, trustEpoch, requestId, action, targetId, operationDigest**. The host stores this record; TTL exactly 60s. `operationDigest` must be computed from the authoritative complete operation, not supplied unchecked by the client. This strengthens the draft's action/target-only binding: e.g. `force:false` UV cannot authorize `force:true` or different registration material. The challenge must be issued and used only in authenticated Split sessions; bind `base64url(session.authenticatedSessionId)` from the authenticated session, never a client-supplied ID. The getter throws before Split and returns a defensive copy.

`verifyAssertion(response, storedCredential, context, commit)` checks exact type `webauthn.get`, pinned HTTPS origin, exact RP hostname (not parent domain), no embedded/cross-origin flow, RP hash, UP **and** UV, flags/extensions, actual signature and signCount. Zero/zero skips clone detection; otherwise count must increase. It returns an opaque in-process `VerifiedUv` only after `commit(...) === true`. `clientDataJSON` must pass both strict platform JSON grammar and duplicate-member rejection, including escaped/nested duplicate keys. Signatures hash the original bytes, not reserialized JSON; genuinely signed trailing commas, malformed numeric literals and invalid escapes are rejected before commit. No `uv:true` input and no mock production verifier.

Mandatory host `commit` must atomically: re-read active device/trust/session; match and consume stored challenge, binding, expiry; compare old credential/count (CAS); update count; authorize only this operation. Recheck current time inside that transaction after asynchronous signature work. Return false on races/revocation/expiry; do not execute the effect before success. Package consumes no persistent state itself. Execution receipts and an operation's transactional effect remain daemon-owned.

### First registration and replacement

`verifyRegistration(response, RegistrationContext, authority, commit)` accepts only `attestation:"none"`, actual CBOR attested credential data, exact create client data/RP, UP/UV and an allowed valid COSE key. None attestation **does not prove hardware provenance**; initial authorization is the Mac-approved pair, not trusted client assertions.

- First registration requires server-sourced `existingCredentialId:null` and a live `pendingPair` matching pairing ID, device ID, actual Split session ID and trust epoch. Host creates/binds this short-lived permission from the locally confirmed pairing; transaction must atomically require no credential, consume pending-pair permission + registration challenge, and persist key/count. Missing/expired pending state is rejected even if a caller supplies the kind string. If onboarding expires, re-open first-registration permission with fresh local Mac presence; a stolen device key cannot mint it. Ordinary chat can still work without UV, but high-risk actions remain disabled.
- Replacement first stages the newly created registration response under a create challenge (never installs it). Then issue an **assertion** challenge to the existing credential, with all the same binding fields but `operationDigest = registrationOperationDigest(stagedResponse)`. Verify it with `verifyAssertion`; pass its live `VerifiedUv` to `verifyRegistration`. The verifier requires the existing credential ID, a fresh one-use opaque authorization, and the hash of the **exact new response**. Host transaction rechecks that existing credential, consumes the create challenge and commits replacement atomically. Fake JS objects, an assertion for different params/material, and consumed authorizations fail. Do not serialize `VerifiedUv` or store it as a boolean; combine verification/registration in one request, or require a new assertion.
- Browser create options: `attestation:'none'`, `userVerification:'required'`, `rp.id` equal pinned relay hostname, allowed algorithms above. Get also requires UV. Store COSE and signCount, not just credential ID. On UV failure deny the high-risk action; never downgrade to a click or device signature.

## Browser trust and privacy integration checklist

Trusted web origin can replace JavaScript and read browser secrets; E2EE protects against ciphertext relay substitution, not malicious origin code/XSS. This is not permission to ignore XSS. Treat Markdown/model output, HTML/SVG/files, filenames, tool results, URL schemes, JSON error text and third-party scripts as untrusted. Use text rendering/sanitization, URL allowlists, CSP without unsafe eval/inline handlers, and opaque-origin previews (`sandbox` without `allow-same-origin`); scope blob/worker permissions. Remote production must not expose local bearer/dev discovery, persist application plaintext, cache API responses in the service worker, or put secrets/file paths in URLs/query/logs.

Ticket 08 implements that client in `apps/messenger/src/lib/remote/`. `RemoteApi` matches the LocalApi method surface and is selected mutually exclusively: hosted production (`REAL_BOT_HOSTED=1`) aliases local discovery/API to stubs so `__local-api` and the loopback bearer are not in the bundle; desktop/Vite-dev keep local discovery. Pairing pins host DH+signing publics and relay origin, shows the full signing fingerprint, and stores only device identity/pins/enrollment in IndexedDB. Transcript, snapshots, drafts, commands and files are not persisted. Remote URLs may hold session/overlay/attachment ids (`?s` `?o` `?b` `?a`) and forbid `?p=` / `?w=`. The service worker caches `/_app/immutable/` only. Disconnect shows host unreachable with no offline command queue; unsent in-memory drafts require confirm on reconnect; unknown results keep `{id, method, path, fingerprint}` in memory across reconnect and look up the same `request_id` receipt (never a new mutation id). Hosted/remote settings and onboarding do not PATCH `workspace_path`. WebAuthn `create`/`get` are real, `rpId` is the pinned relay hostname, UV is required, and registration happens only after Split via `/remote/uv/register*`. UV failure still allows ordinary chat and never falls back to click-to-confirm. S-rev / G-uv / physical L1 are **not passed**; public pairing stays default-off. Desktop Chromium is not iOS home-screen.

## Daemon adapter and downstream client contract (ticket 07)

`apps/daemon/src/remote/controller.ts` exports `RemoteController` and constructor options for Store/LocalApi, relay metadata and test-only dependency injection. Production uses `remoteNative`, WSS and fetch; no env fake exists. Runtime loads existing `remote_host` public metadata, never bootstraps from arbitrary environment secrets. No metadata means `off` without native reads. Native denial yields `native_unavailable`; a present production provider with its release admission still disabled yields `activation_gated` before material reads; mismatch yields `trust_mismatch`; connection states are `connecting`, `online`, `disconnected`. `RuntimeSnapshot.remoteStatus` is optional, redacted and has **no public enabled flag**. Default local boot/chat is unchanged. G-pack remains a real implementation blocker, not a passed runtime gate.

### Pairing/setup

The trusted bundled window uses Tauri `remote_local_setup({request})`; accepted requests are `{operation:'status'}`, `{operation:'initialize',config:{hostId,origin,relayId},bootstrap?}`, `{operation:'list_devices'}`, `{operation:'prepare_remove_device',deviceId}`, `{operation:'confirm_remove_device',proof}`, `{operation:'open_pair'}`, `{operation:'prepare_pair',pairingId}`, `{operation:'confirm_pair',pairingId,proof}`, `{operation:'prepare_recovery'}`, `{operation:'confirm_recovery',proof}`, `{operation:'prepare_uv_renewal',deviceId}`, `{operation:'confirm_uv_renewal',proof}`, `{operation:'prepare_change',change}`, `{operation:'confirm_change',proof}`. `change` is exactly `{kind:'reset_identity'|'change_relay',config:{hostId,origin,relayId}}` or `{kind:'change_workspace',path:<absolute local path>}`. Replies are `{ok:true,value}` or fixed `{ok:false,error}`. Native authenticated FD3/socketpair is the only ingress; local bearer/dev/PWA/tools cannot call it. First native identity creation and `ready` use existing Tauri confirmation API. Initialize stores only relay/host metadata; bootstrap is a one-shot body value, never stored in SQLite/URL. On unknown bootstrap result reconnect using the stored enrollment key, not a second bootstrap. Source builds have no working native setup bypass.

`list_devices` returns active devices as `{id,name,lastActiveAt}`. `lastActiveAt` is Unix seconds and advances on a successful encrypted connection and each accepted encrypted request. `prepare_remove_device` binds the selected device's immutable trust fingerprint and current host generation into a local confirmation action; `confirm_remove_device` consumes the fresh native proof, advances the trust high-water, revokes that device, and closes its sessions. `open_pair` returns shared `PairingQr={v:1,pairingId,hostId,expiresUnix,relayOrigin,relayId,hostDhPublic,hostSigningPublic,trustEpoch,issuedAt,secret}`. Secret32 is ephemeral; all other keys are public. Expiry≤600s/four windows. Grant issued time is fixed at QR creation so the browser can verify **every field**, rather than trusting a response-chosen value. Device submits `sealPairing` and polls the same-origin unauthenticated mailbox no faster than10s. Host `prepare_pair` reads bounded chunks and binds every device/host key, ID, relay, generation and time into the native action. Tauri `ready` must precede prepare; Tauri `confirm` returns proof, then daemon `confirm_pair` consumes it. Trust commits before relay registration; lost registration acknowledgement is repaired idempotently from durable pending metadata. A lost consumed mailbox reply requires local re-pair/recovery, never automatic phantom grants.

Shared exports `SignedDeviceGrant`, `sealPairingGrant`, `openPairingGrant` reuse the existing pairing KDF, with AD `pairingAssociatedData(context) || field('RB-PAIR-GRANT-v1')`. Plaintext is strict binary `encodeGrant(grant) || signature64`. Opening requires pinned host signing key and full expected grant and performs `verifyGrant`. Request/reply AEADs are mutually non-interchangeable. No new relay crypto or plaintext grant is introduced.

First-UV renewal never follows a browser key claim: prepare binds the existing device's immutable pins, current generation/credential version and **current live Split session**, then confirm consumes fresh Mac proof and grants only that session a new120s window while deleting prior challenges. An existing UV credential cannot use renewal. Disconnect, changed pins or another generation invalidates confirmation. There is no remote renewal route.

Reset/relay change bind complete old host/public-key fingerprint/device pins, new exact configuration and generation into native action. Reset calls the existing native `reset(action,challenge,proof,expected)` (rotating all identity/enrollment material and high-water); relay change consumes proof and advances high-water. Both pause admission and persist `remote_transition` before uncertain native work. `native_done` intents carry new public pins and reconcile only with exact next native high-water; `native_uncertain` remains closed until new local recovery, never repeating a reset. Metadata plus all-device revocation commits together. A changed relay or reset identity requires an intentionally fresh relay enrollment database/bootstrap (same config initialize with bootstrap); no attempt is made to overwrite relay06's one-use host enrollment. Bootstrap material is never in transition rows. Workspace capability checks canonical directory/device/inode, old workspace and settings revision again after proof, then commits through the same settings Store method;09 owns directory browsing/UI, not the native authorization itself.

### RPC and synchronization

Pure shared exports: `RemoteRequest`, `RemoteResponse`, `RemoteReady`, `AssertionWire`, `RegistrationWire`, `parseRemoteRequest`, `REMOTE_RPC_VERSION=1`, `REMOTE_FILE_LIMIT=50MiB`, `REMOTE_FILE_STREAMS=2` in `@real-bot/remote`. JSON is canonical UTF8; unknown fields, arbitrary URLs/methods/headers, GET bodies and noncanonical input close/reject. Request type1 is `{v:1,id:<ULID>,method:'GET'|'POST'|'PATCH'|'PUT'|'DELETE',path,query?,body?,ifMatch?}`. Paths are literal `/v1/...` or `/remote/...`, query is an encrypted string record (not a relay URL). Only strong SHA256 If-Match is accepted. All mutations require a stable ID; `POST /v1/models/probe` is explicitly **nonqueued/non-replayed**, uses the shared probe implementation with a 12s timeout per try (one more try only after a timeout) and transport cancellation, and rechecks authority after stored-credential hydration immediately before each fetch, the retry's included (redirects refused). Repeating its ID is a new probe, not a receipt replay. Digest for receipt mutations uses the existing six-field shared algorithm including sorted query and conditional headers. PATCH needs entity `if_revision`/settings revision; destructive entity actions require revision; file PUT requires If-Match. Remote DM Stop returns204 for live, missing and already-terminal direct turns, saved in its receipt; group Stop and local behavior remain unchanged. Workspace root changes are not permitted by ordinary remote settings PATCH.

Response type2 is `{v:1,id,status,body,headers?:{etag?,contentType?,contentRange?,originalSize?},file?:{streamId,size,bytes?}}`. When that response still fits in one Noise frame, `file.bytes` is base64url of the whole file, `streamId` is `0`, and no type5 frames follow. A larger file omits `bytes` and streams. Errors contain a fixed message and allowlisted original category, not exceptions/tokens/paths/keys. The same policy applies to returned errors, thrown failures and receipt queries: `draining`, `conflict`/`revision_conflict`, `credential_superseded`, `receipt_expired`, `key_write_pending`, `request_unknown`/`request_pending`, `not_found`, `probe_failed`/`no_models`, and lifecycle pending/failed/unknown stay distinct; unknown codes become `rejected`, never status-derived fake pending keys. Type3 first sends `{type:'ready',protocol:'remote-v1',event_instance_id,watermark_seq,deviceId,trustEpoch}` **after Noise response**, then existing `SyncFrame` events. `turn.tool`/token are excluded by the same EventStream. Client installs its subscription before requesting `/v1/snapshot`, buffers events, applies the snapshot watermark then only contiguous newer events; catchup is the existing `/v1/events/catchup`. A device that reconnects to the same event instance it last applied (the `ready` frame names the instance and watermark) resumes instead: it asks `/v1/events/catchup` from its applied cursor, requires those events and whatever the new link buffered to continue that cursor without a gap, keeps its in-memory state and open transcripts, and re-reads only a conversation whose reply was `running` (streamed tokens are not events). Another instance, `resnapshot`, a gap, or more than 300 missed events falls back to the full snapshot. Snapshots carry no `spend` rows (served by `GET /v1/spend`), and every Bot portrait in snapshots, `bot.upsert` events and Bot responses is a 128 px copy marked `;rb-display=<hash16>` in its data URI; a create or patch that sends a marked portrait back never stores it over the original (patch drops it, create strips the mark). `POST /v1/sessions/:id/read` answers with the session summary, not the transcript. `GET /v1/sessions/:id/snapshot` takes an optional `limit` (1..200) for its first page of history; the device asks for 20, pages back 20 at a time, and retries once without `limit` on a 422 from an older Mac. Receipts are `GET /v1/requests/:id`, scoped by the authenticated device. No reconnect replay/offline command queue.

Right after `ready`, a device asks `POST /remote/features` with `{compress:["deflate-raw"]}`; the host answers `{compress:"deflate-raw"}` and from then on sends each JSON answer (type2 without `file`/`upload`, and type8) of 1 KiB or more as a 0x00 marker byte followed by that message alone in raw deflate, when that is smaller. JSON cannot begin with 0x00, so the frame codec is unchanged, and the device inflates synchronously so frame order holds. An older host answers 404 and nothing is compressed. File bytes, uploads, events and everything the device sends are never compressed. Compression under encryption lets ciphertext length hint at content (the CRIME class); it is limited to answers, which carry no credential of their own (keys never leave the Mac), and each message is compressed independently. A transcript can still contain text someone pasted, so this is a deliberate trade-off recorded here for S-rev, not a claim that lengths reveal nothing.

Snapshot responses use type8 with the same response envelope. Above512KiB, bounded pages carry `body:null,snapshotPage:{transferId,index,count,bytes:<base64url canonical snapshot slice>}` with the same request ID. Each page independently fragments through type4; collect exact ordered pages into at most16MiB, parse only after all pages, and retain buffered sequenced events until installation. Changed transfer/duplicate/gap/timeout requires a fresh snapshot. Generic logical messages remain≤1MiB, each type4 assembly≤30s; disconnect clears buffers. The adapter serializes request processing; clients must wait for response/EOF before the next request rather than pipeline unknown outcomes.

File GETs on `/v1/workspace/file` and `/v1/attachments/:id/content` accept encrypted query `range` with a single HTTP byte range (`bytes=0-262143`, `bytes=262144-`, `bytes=-1024`). Valid ranges return status 206 and `headers.contentRange` (`bytes start-end/total`); `file.size` is the selected length and `headers.etag` hashes only that range. Invalid or unsatisfiable ranges return 416 and `contentRange: bytes */total`. Loopback HTTP also accepts the `Range` header and returns `Content-Range`, `Content-Length` and `Accept-Ranges: bytes`. The daemon reads only the requested bytes, retains workspace/attachment path checks and the 50 MiB original-file remote limit, and rejects combining `range` with an image `size`.

Remote media previews use an ephemeral same-origin `/__remote_media/<random-id>` URL resolved by the Service Worker to its requesting window via MessageChannel. That page alone maps the id to an authenticated RemoteApi file read. Each pull requests at most 256 KiB over Noise, supports seeking to unbuffered offsets, and cancels on player cancellation or source disposal. Media responses use `no-store`; bytes never enter Cache Storage or IndexedDB. The host path stays inside the encrypted RPC. A browser without an active media-capable Worker, or a host rejecting the range query, uses the existing complete-file preview. Browser codec support and remote activation gates remain applicable.

File GETs reuse real local byte responses, permissions/realpath and ETags. `size=thumb` (256 px long edge) or `size=preview` (1600 px) on `/v1/workspace/file` and `/v1/attachments/:id/content` asks for a scaled copy of a larger PNG/JPEG/WebP/BMP picture (GIF only as `thumb`), made on the Mac with `sips`: opaque pictures become JPEG, transparent ones stay PNG, and copies are cached by path, size and mtime. A scaled answer carries `headers.originalSize` (the original's bytes; `X-Original-Size` on loopback) and an ETag over the bytes actually sent; anything else — not a raster, already within the size, off macOS, a failed conversion — is the original with no `originalSize`. The device client asks for `thumb` on chat chips and pictures inside notes (each fetched once it is scrolled near) and `preview` for enlargements and image previews, offers the original from `originalSize`, and retries once without `size` on a 422 from a Mac that predates it. A non-empty file whose type2 response still fits in one Noise frame travels as `file.bytes` on that response, so opening it is one frame. Anything larger, and an empty file, sends metadata first and then type5 sequential chunks; max50MiB, chunk format is shared `FileChunk`. Empty files keep the stream so a download of nothing is still cancellable and still ends on an explicit EOF. The sender waits out socket backpressure only when the next ciphertext would pass the 64 KiB buffer, not whenever a previous frame has not yet reported a completely empty buffer. Cancellation uses type6 u32 stream ID; stream state survives until actual sent EOF/cancel, including the pump's current awaited frame. Active cancel receives a type6 echo only after the pump has dropped its pending/current frames; client waits for that echo before sending its next serialized RPC. The device client orders that serialized queue in two lanes: background reads (chat thumbnails) are sent only while no foreground request waits, and a foreground file GET (opening a preview, enlarging a picture) cancels a background stream already in progress, waits for the echo, runs, and then re-sends that background GET with the same ID (GETs have no receipt). A read whose caller aborts leaves the queue, or cancels its stream once one is named; a disconnect rejects everything still queued with `request_unknown`. Last32 completed stream IDs accept and echo harmless late cancel; genuinely unknown IDs fail closed. Already transmitted bytes cannot be recalled. The baseline serializes reads (at most one active transfer, below the two-stream ceiling), bounds send queues and clears data on disconnect. Ticket 09 adds duplex uploads: POST `/v1/sessions/:id/messages` may declare `{filename,size,sha256}` files; Mac opens tmp streams, device sends type 0x05 sequential chunks, and the receipt commits only after EOF hash. Cancel/disconnect/revoke delete tmp and mark cancelled. `GET /v1/host/tree` lists host directories with `classifyPath`/realpath; other-user homes and TCC denials return `host_permission`. Changing the workspace root still uses class-1 `change_workspace`. Remote Finder actions are download / copy relative path. Real TCC and physical-phone download are **not passed**.

One host-wide FIFO transmission budget paces all link/control ciphertext at1,500,000 B/s plus64-byte/frame reservation, below relay's2,500,000 B/s/256KiB burst, leaving1,000,000 B/s for inbound requests/control replies. Control commands are spaced≥75ms (<14/s), queue≤16; transfer queues remain bounded and abort clears pending waits. This is adapter cooperation, not weakened relay limits. Device08 senders must likewise pace aggregate incoming traffic rather than burst arbitrary uploads; hostile over-budget senders still cause relay fail-close. The messenger's device transport paces upload chunks at 900,000 B/s plus the same 64-byte/frame reservation, and holds the next chunk while the browser's send buffer is above 256 KiB so a slow radio cannot bank a burst; a paced upload still handing chunks to the socket counts as link activity for its 30s stall check. Before this the whole file was sent at once and the relay closed the route mid-upload. Revoked tombstones retain rollback evidence but only `relay_pending=1` rows reconcile; acknowledgement durably clears that flag, so >70 lifetime tombstones complete and later reconnect does not replay history.

### Spend ledger reads

`GET /v1/spend/summary` returns `{totals, groups, categories}` from daemon aggregation. Metrics include call count, five token fields, separate `reported_usd_ticks` and `estimated_usd_ticks`, their coverage counts and missing-usage count. Each group carries its display name and deletion flag, using current names for live entities and recorded names after deletion. Six kinds map to five categories: turn, judgement, decision routing (`route_pick`), feedback routing (`route_review`, `route_learn`), and other (`composer_suggest`). Null numeric values remain unknown. Days use the requested IANA timezone; `to` is exclusive. The encrypted query dictionary uses comma-separated kinds.

`GET /v1/spend` returns bounded descending pages. Rows include frozen attribution, nullable Bot for composer suggestions, separate reported/estimated amounts, trigger message id when still available, and deletion flags. Snapshot responses omit `spend`; clients treat legacy absent fields as empty and refresh open summaries on `spend.created` without retaining event rows. Clearing/deleting chats and deleting Bots retains the ledger. No `spend.removed` is emitted.

Provider model entries accept optional `pricing: {input:number, output:number, cached_input?:number}` in USD per million tokens. Values are finite non-negative numbers; both input and output are required. Omitting pricing from a replacement catalog clears it. `price` remains an independent routing reference. An estimate is frozen on insertion only when reported amount is absent and token inputs are sufficient; paired clients use existing configuration permissions.

**Annotation crop budget.** A crop travels inline as base64 inside the JSON request, so it shares that request's transport limit rather than the local 1 MB (`ANNOTATION_CROP_MAX_BYTES`). The whitelist admits at most 1,000,000 base64 chars (≈750 KB decoded), which keeps a whole request inside one ≤1 MiB logical message (`MAX_LOGICAL_MESSAGE`) for a client that fragments. The hosted messenger does not fragment: every RPC is one type-1 frame whose canonical JSON must be ≤`MAX_BODY` (32,743 B). `RemoteApi` measures the create/PATCH request with the transport's own canonicalization and, past `MAX_BODY − 512`, re-encodes the crop (shorter long side, JPEG at falling quality) into the bytes left; if even the smallest step does not fit, the annotation is saved without a crop (a draft PATCH sends `crop:null`, since a new box with the old picture would mislead). A crop saved from the phone is therefore at most ≈24 KB decoded.

### UV and lifecycle

Encrypted endpoints: `GET /remote/status`; `GET /remote/diagnostics`; POST `/remote/uv/register-challenge` empty body; `/remote/uv/register` `{challenge,response,replacement?}`; `/remote/uv/replacement-challenge` `{challenge,response}`; `/remote/uv/challenge` `{operation,force?}`; `/remote/action` `{operation,challenge,assertion}`; `/remote/runtime/restart` `{operation,challenge,assertion,force?}`; `/remote/runtime/stop` `{operation,challenge,assertion}`. Byte fields in shared AssertionWire/RegistrationWire are canonical base64url. `operation={action:'device.revoke'|'quiesce.begin'|'quiesce.cancel'|'quiesce.force'|'runtime.restart'|'runtime.stop'|'diagnostics.download',targetId,requestId}`; target is device ULID or `runtime`, action request ID must equal envelope ID. Host computes authoritative full digest. Ordinary chat works without UV; these high-risk actions do not. Restart default `force=false` waits for the captured live set, records the receipt, then this caller exits 0 without a latch. Force requires a new UV and never auto-upgrades from timeout or disconnect. Stop writes the latch then exits. No `/remote/*` write routes exist on loopback `:17890`. Registration replacement uses exact staged response digest and existing credential. Challenges are60s, at most8/device, durable and session-bound; every asynchronous signature completion rechecks trust/session/credential/key/count/time in the committing transaction.

`api.quiesce` exposes `begin()`, `state()`, `wait(signal?)`, `cancel()`, `force()`, `close()`. State is `{phase:'running'|'draining'|'drained',remaining:[turnIds],forced}`. Wait cancellation cancels the wait only; explicit cancel resumes admission/scheduler. Force is an internal capability requiring caller authorization, never a public bearer action. `SupervisorControl={kind:'window'|'standalone'|'none',writeStopLatch(),clearStopLatch()}` defines the downstream lifecycle owner; `RuntimeHandle.lifecycle` supplies `RuntimeLifecycle` with private fsynced atomic stop-latch writes, durable reads and directory-fsynced clear (no automatic job installation or exit). Ticket 11's maintenance caller owns restart/stop exit after shared quiesce returns. Window-supervised restart is enough; if the window is gone and independent mode is off, restart is `unavailable` and no agent is installed. The window supervisor will not spawn while `runtime.stop` exists. Shared quiesce still never exits. Standalone processes refuse to serve when the latch exists; window-supervised processes still start. Local `GET /v1/runtime/drain` and `POST /v1/runtime/{quiesce,handoff,stop}` are window/handoff callers: quiesce never exits, handoff exits without a latch, stop writes the latch then exits. Production independent-runtime enablement stays gated; see [ADR 0023](adr/0023-independent-runtime.md). Existing approvals/ask replies finish while new message bodies/routine firing/joins/handoffs are rejected before their effects. Captured turns may edit routine configuration without firing it during drain; failed runners release their live entries. Force fences each not-yet-started tool and post-await mutation; `unsettledTurnIds` keeps started runners/approved tool work visible even after DB interruption, so force may return `draining` indefinitely until started work settles; repeated rejected delegation is terminated with a visible draining reason, not an infinite hidden retry.

Lifecycle assertions commit only authorized pending intents/202 receipts, not success before effects. Begin/cancel finalize204 after the phase changes; force waits for the captured live/unsettled set to drain before204. Effect errors finalize503 `lifecycle_failed`; restart marks unfinished intents409 `lifecycle_unknown` without rerunning force/tools or claiming a volatile drain survived. Same-ID retries return that durable outcome;202 pending receipts are excluded from pruning. Ordinary revoke receipt completion belongs solely to its trust transaction.

Trust/replay/challenges share the actual Store database. Every revocation bumps native high-water then SQLite generation, closes all affected links and invalidates old principal pins. Survivors retain signed grant epochs but reconnect against their new generation. Native-ahead or unknown errors fail closed; no automatic epoch adoption. Durable revocation intents repair a crash before native advance when epochs still match; mismatched epochs require explicit authorized recovery. Trusted-window prepare_recovery→fresh native confirm→confirm_recovery consumes a digest binding host/current generation/high-water/all device pins, advances high-water first when it equals the DB generation (or adopts an already-ahead native generation), then revokes every device; no device can preserve authorization through recovery. Tests use constructor-generated native fixtures, actual Bun relay/Noise and real software WebAuthn signatures; no real Keychain/LA or production port is touched. Frontend08/native deployment/physical gates are not claimed complete.
